# /canon-check — 正典整合チェック

差分を CLAUDE.md の規約で点検し、**DoD（§7）判定**を返す。機械層（lint/型/schema/test）と判断層（UI文言・正典整合・テスト網羅・不変条件）の両方を回す。これは `npm run review`／CI の置き換えではなく、**判断層の自動化・再現化**。

## 手順

### 1. スコープ確定
- 引数があればそれを範囲とする（パス指定や `working`＝作業ツリーのみ／`develop`＝`origin/develop` との差分。既定は両方）。
- 変更ファイル一覧を取得して提示：
  ```
  git fetch -q origin develop; git --no-pager diff --name-only origin/develop...HEAD; git --no-pager status -s
  ```
- 変更が無ければその旨を述べて終了。

### 2. 機械層（DoD ①②：テスト緑・型/lintなし）
- フロント差分があれば `npm run check:frontend`（lint→typecheck→test→validate:schemas）を実行。Rust 差分（`src-tauri/**`）があれば `npm run check:rust` 系も。
- 重い/不要なら引数 `--skip-mechanical` で省略可。結果（緑/赤と要点）を記録。**赤があれば最優先の🔴**。

### 3. 判断層（4レビュアを並列実行）
変更ファイル一覧を渡し、**1メッセージ内で4つの Agent を同時に**起動する（並列）。各 `subagent_type` と担当：
- `ui-terms-reviewer` … §2-3 UI技術用語 ＋ §2-5 エラー文言（`src/app/**` の表示文字列のみ）
- `canon-schema-reviewer` … §2-7/§6 直書き・§5/§9 正典/schema整合・§4 依存方向
- `tests-reviewer` … §7 「必ず書く対象」の未テスト変更・golden/スキーマ検証
- `correctness-reviewer` … §2-1/§2-2 データフロー・11.2/11.6 採番/継承・§2-6 外部送信などの不変条件

各エージェントへは「変更ファイル一覧」と「自分の担当次元だけを、根拠（正典の条項）付きで指摘。読み取り専用。指摘なしなら『指摘なし』」を渡す。差分が UI を含まない等で無関係なレビュアは省略してよい（省略したら明記）。

### 4. 統合してDoD判定
4レビュアの結果＋機械層を集約し、重複を畳んで、**CLAUDE.md §7 の DoD 5項目**にマップした表で返す：

```
## /canon-check 結果（範囲: <files n件>）
| DoD | 項目 | 判定 |
|---|---|---|
| ① | 該当テストが緑 | ✅/❌ |
| ② | 型エラー/lintなし | ✅/❌ |
| ③ | UIに技術用語が漏れていない（§2-3/§2-5） | ✅/❌ |
| ④ | 正典(11/12/schemas)と矛盾しない（§5/§9） | ✅/❌ |
| ⑤ | エラー文言が「次の行動」を示す（§2-5/15） | ✅/❌ |

### 指摘（重大度順）
- [🔴] path:line — §x-y — 内容 — 修正案
- [🟡] …
- [ℹ️] …

### 総合判定: 合格 / 要修正（🔴n / 🟡n / ℹ️n）
次の行動: <🔴を直してから再実行 / PR可 など>
```

## 原則
- **事実ベース。** 各指摘は正典の条項と file:line を根拠に。確証がなければ ℹ️＋「要確認」とし、断定しない。
- **直さない。** これは検査スキル。修正は結果を見てユーザー判断、または別途。`--fix` 等の自動修正はしない。
- **誤検出を出さない。** 各レビュアの「誤検出しない」節（クレジット画面の技術語許可、定義元/テストの直書き許可など）を尊重。
- 重大度記号はリポジトリ慣習に合わせる：🔴 ブロッカー／🟡 直すべき／ℹ️ 軽微・要確認。
