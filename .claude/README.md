# `.claude/` — すたりお（stario）の Claude Code 運用ツール

正典（`CLAUDE.md` の §2 絶対原則・§7 Definition of Done）を**「実行可能なチェック」として固定**し、引き継ぎ後・別オペレーターでも毎PRの判断層レビューを再現できるようにするためのスキルとサブエージェント。**機械層（`npm run review` / CI）の置き換えではなく、人が目視していた判断層の自動化・補完**。

## スキル（`skills/`）
| 呼び出し | 役割 |
|---|---|
| `/canon-check` | 現在の差分を DoD（§7 ①〜⑤）で点検。機械層（lint/型/test/schema）＋判断層4レビュアを並列実行して判定表を返す。**PRを出す前・レビュー対応の前**に回す。 |
| `/adr-new <タイトル>` | ADR を採番・ハウススタイルで起票し、**ADR索引（`adr/README.md`）と `CLAUDE.md §11` の同期まで**行う。設計判断はコードより先に（§8）。 |

## レビュア・サブエージェント（`agents/`、いずれも読み取り専用）
`/canon-check` が並列起動するほか、単体でも「○○-reviewer で差分を見て」と呼べる。

| エージェント | 担当する正典 |
|---|---|
| `ui-terms-reviewer` | §2-3 UI技術用語の漏れ ／ §2-5 エラーは「次の行動」（`src/app/**` の表示文字列のみ。クレジット画面の必須表記は除外） |
| `canon-schema-reviewer` | §2-7/§6 enum・定数の直書き ／ §5 不変条件・schemaVersion ／ §9 正典>例示・推測禁止 ／ §4 依存方向 |
| `tests-reviewer` | §7 「必ず自動テストを書く対象」の未テスト変更・golden/スキーマ検証の欠落 |
| `correctness-reviewer` | §2-1/§2-2 データフロー（AI→検証→補正→変換）／ 11.2 採番・11.6 継承 ／ §2-6 外部送信の事前確認 |

重大度はリポジトリ慣習に合わせる：**🔴 ブロッカー／🟡 直すべき／ℹ️ 軽微・要確認**。

## 注意
- **新規スキル/エージェントはセッション開始時に読み込まれる。** 追加した直後の同一セッションでは未登録のことがあるため、使うときは**新しいセッション**で（または再読込後）。
- レビュアは**直さない**（検出のみ）。修正は結果を見て判断する。
- `launch.json` はプレビュー（Claude Preview）用。`settings.local.json` はローカル設定でコミットしない。
