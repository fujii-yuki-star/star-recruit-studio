# MV-0005: 外部 AI の操作口（最小）＝操作の一覧・取引・MCP とコマンド

- **状態**: Accepted（2026-11-26・γ0.1 の段階⑤。ADR-0074 決定3 を形にした技術の決定）
- **日付**: 2026-11-26
- **関連**: ADR-0074 決定3（C-1〜C-4）・MV-0001（プロジェクトの形）・MV-0003（描画の核）・MV-0004（画面なしの書き出し）

## コンテキスト

ADR-0074 決定3 で、外部 AI（Claude・Codex など）が γ を操作する口を **MCP とコマンドの2つ**にし、**操作の一覧を正典**にし、**まとめて反映（取引の単位）**にすると決めた。
γ0.1 の段階⑤では、その**最小**（中身を見る・レイヤーを足す・1コマ描く・検査する・まとめて反映）を作る。
まだ画面が無い（画面は段階⑦⑧）ので、ここで作るのは**画面なしで動く中身**と、2つの入口。

## 決定

### 決定1：中身は1つ（`crates/mv-ops`）、入口は2つ

- 操作の中身は `crates/mv-ops`。MCP（`stario-mv-ai mcp`）とコマンド（`stario-mv-ai call <操作> <引数の JSON>`）は、**同じ関数**を呼ぶ。
- 入口ごとに違うのは**絵の渡し方**だけ：
  - MCP は、1コマの絵を応答に**画像として含める**。
  - コマンドは、絵を `<動画のフォルダ>/cache/frames/` に保存して場所を返す。
- 1回ごとに動画のフォルダを指定する（状態を持たない）。MCP は起動時に `--project` で既定のフォルダを渡せる。

### 決定2：操作の一覧を正典にする（`docs/stario_mv_docs/schemas/mv-operations.json`）

- 操作の名前・説明・引数の JSON Schema を1つのファイルに書く。
- MCP の `tools/list` はこのファイルをそのまま返す。呼ばれたときの引数も、まずこのファイルの形で確かめる（1段目）。
- 画面のボタンも、後でこの一覧の操作を呼ぶ（ADR-0074 決定3 の補足）。
- γ0.1 の操作：

| 操作 | 何をするか | 書き換え |
|---|---|---|
| `inspect` | 中身の要約（コンポジションとレイヤーの一覧・版）。指定すればコンポジションやレイヤーの JSON 全体 | しない |
| `validate` | 検査（形と中身の2段）の結果 | しない |
| `renderFrame` | ある時刻の1コマを描いて PNG で返す（長辺の上限を指定できる） | しない（`cache/` に置くだけ） |
| `newIds` | 新しい ID を発行する（取引の中で後の操作から指すため） | しない |
| `applyTransaction` | 一連の編集をまとめて試す／反映する | する |
| `createProject` | 新しい動画のフォルダを作る | する |
| `exportVideo` | MP4 に書き出す（MV-0004） | 出力だけ |

- 取引の中の編集（`applyTransaction` の `ops`）：
  - レイヤー：`addLayer`／`updateLayer`／`removeLayer`／`moveLayer`／`splitLayer`（今のフレームで2つに分ける＝MV-0008 で追加）
  - コンポジション：`addComposition`／`updateComposition`／`removeComposition`
  - 動画全体：`updateProject`
  - 素材：`importAsset`／`removeAsset`（段階⑥で足した＝MV-0006 決定1）。
- `update*` は **JSON Merge Patch（RFC 7386）**で書く。直したい項目だけを書けば、ほかは変わらない。`null` を書くとその項目を消す。
  - ID は変えられない。
  - コンポジションの `layers` は、レイヤーの操作で変える（`updateComposition` では触れない）。
- `addLayer` は、書かなかった項目に**既定**を入れる（AE が新しいレイヤーに入れる値に合わせる）：
  - 有効で、ロックなし。
  - コンポジションの全体の長さに置く。
  - 位置はコンポジションの中心。
  - 単色のアンカーは中身の中心、ほかは (0,0)。
  - 大きさは 1 倍、回転は 0、不透明度は 1、描画モードは通常。
  - 単色の大きさを書かなければ、コンポジションと同じ大きさにする。
  - 置く場所は既定で**最前面**（`index` で指定できる。0＝最前面＝MV-0001 決定6）。

### 決定3：取引＝全部が通ったときだけ反映する

- `ops` を順に、動画の写しに当てる。当てたあと、**形の検査（正典の JSON Schema）と中身の検査（MV-0001 決定7・8）**をする。
- 次のときは**何も反映しない**。どの操作か、どこを直せばよいかを返す。
  - 1つでも当てられない操作がある（指したレイヤーが無い など）。
  - 検査に問題が1つでも残る（まだ描けない機能も含む＝書き出せない状態を作らない）。
- `dryRun: true` なら試すだけで、反映しない。どちらの場合も、次のものを返す。
  - 差分：足した・消した・変わった ID の一覧。
  - 新しく発行した ID。
  - 検査の結果。
  - 頼めば反映後の1コマの絵。
- 反映するときは、`updatedAt` を今の時刻にする。保存は書きかけで落ちても壊さない形で行う（`mv-core::io::save_project`）。
- **版（revision）＝ `project.json` の中身の SHA-256**。
  - `inspect` が返す版を `baseRevision` に入れて送ると、その間に誰かが変えていたら反映を断る（`conflict`）。
  - 反映中は `project.json.lock` を置き、ほかの書き込みは待たずに断る（`locked`）。10 分より古い錠は、落ちた残りとみなして捨てる。
- 1つの取引＝後で「元に戻す」1回にする（記録の仕組みは段階⑨）。

### 決定4：AI に許す範囲（C-4）

- 読む・編集する・1コマ描く・検査するのは自由。
- **書き出しと新しい動画のフォルダ作り**は、利用者が許したフォルダの中だけ。1コマの絵の保存は、動画のフォルダの `cache/` か許したフォルダの中だけ。
  - 許したフォルダは、設定ファイル（`%APPDATA%\jp.star-system.stario-mv\ai-settings.json` の `allowedFolders`）に書く。
  - 足すのは**利用者がコマンドで**行う（`stario-mv-ai allow <フォルダ>`）。この操作は MCP の一覧に載せない。
  - 素材の取り込み（段階⑥）も同じ許可を使う。
- 消すのはデータの中のレイヤー・コンポジションだけで、ファイルは消さない。ファイルを消す操作ができたら、ごみ箱へ送る。
- **ネットへは送らない**。MCP は標準入出力だけで話す（待ち受けの口を開けない）。
- フォント（描くとき）と FFmpeg（書き出すとき）の場所は、設定ファイルの `fontDirs`・`ffmpeg` か、環境変数 `STARIO_MV_FONTS`・`FFMPEG_PATH`。

### 決定5：MCP は自前で小さく実装する

- 標準入出力の JSON-RPC 2.0（1行1通）。応じる要求は5つ。
  - `initialize`・`ping`・`tools/list`・`tools/call`
  - `notifications/initialized` は受けるだけ。
- 公式の Rust SDK（非同期の実行環境を丸ごと入れる）は使わない。使う要求が少なく、同期で足りるため。
- GPU とフォントは最初に描くときに用意し、そのあとは使い回す（2コマ目からは速い）。
- 操作の失敗は MCP の作法どおり `isError: true` の結果で返す。AI が読んで直せるよう、文に**次にすること**を書く。

## 結果・影響

- γ0.1 の目標「AI に素材を並べさせて書き出せる」の、素材以外（単色・図形・文字）が通しでできる。素材は段階⑥から（MV-0006 で足した）。
- 操作を足すときは、正典の `mv-operations.json` と `mv-ops` の両方を変える。両者の食い違いは検査が落とす（一覧の全部の操作に中身があること）。

## 未解決の論点

- **アプリが開いているとき**（C-3）：画面と AI の変更を1本の列に並べる仕組み。画面ができる段階⑦⑧で決める（そのときも取引と版の約束は変えない）。
- 「反映の前に利用者に見せる」設定：画面が要るので段階⑧以降。
- 1コマの点検（はみ出し・画面外）を絵と一緒に返す：γ0.2 以降。
- 取引の記録と「元に戻す」：段階⑨。
