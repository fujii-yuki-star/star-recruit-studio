# MV-0002: プレビューは「ネイティブの窓に描き、画面を上に重ねる」

- **状態**: Accepted（2026-11-26・利用者判断＝方式 (b)）
- **日付**: 2026-11-26
- **関連**: ADR-0074 決定2（技術の前提＝描画は Rust の wgpu・プレビュー＝書き出し）／MV-0001／試作の結果 [2026-11 プレビュー方式の試作](../research/2026-11-preview-spike.md)・試作のコード `apps/stario-mv/spikes/preview/`

## コンテキスト

ADR-0074 決定2 は「描画は Rust（wgpu）で書き、同じコードを画面のプレビュー（WebGPU）と、書き出し・画面なしの描画（ネイティブ）で動かす」とした。
γ0.1 の段階②で、プレビューの方式を2つ試作して同じ PC で測った（Intel 内蔵 GPU・リモートデスクトップ経由＝絶対値ではなく比と構造の限界を見る）。

- **(a)** Rust の描画を WebAssembly にして、画面（WebView2）の中の WebGPU で描く。
- **(b)** Rust の描画を窓に直接描き（wgpu→Vulkan/DX12）、透明にした画面（WebView2）を上に重ねる。

## 判断軸

- **プレビュー＝書き出し**（読む・描く・書き出すが同じ道を通る）。
- 映像の素材を実時間でプレビューできる。
- 速さ（上位 PC 前提でも、無駄に遅い道を選ばない）。
- 描けなかったコマが見える（黙って間引かない＝黙って別の結果にしない）。

## 検討した選択肢（測った結果）

| 観点 | (a) | (b) |
|---|---|---|
| GPU の速さ（画面なし・1920×1080） | 基準（64,000 個で 93 ms／コマ） | **約 2 割速い**（76 ms／コマ） |
| 映像のコマをプレビューへ（1920×1080 RGBA） | **約 75 ms＝13 コマ／秒が上限**（4K は 3） | **約 1.6 ms**（Rust から GPU へ直接） |
| 同じ絵になるか（同じコード・画素で比べた） | 差は最大 1／255・PSNR 89 dB | 同じ |
| 描けなかったコマ | ブラウザが間引いて隠れる | 正直に落ちる |
| 重ね合わせ | もともと画面の中 | 透明な画面の下にネイティブの絵が見え、部品が上に重なることを確かめた |

(a) で映像を実時間で流すには画面側で別に読む（WebCodecs）しかなく、**読む道がプレビューと書き出しで分かれる**（ProRes など読めない形式もある）。

## 決定

### 決定1：プレビューはネイティブの窓に描き、画面（WebView2）を透明にして上に重ねる

- 描画は Rust（wgpu）のネイティブ1系統。**プレビュー・書き出し・画面なしの描画・外部 AI の「1コマ描く」が全部同じコード・同じ道**（映像の読み込みも同じ）。
- 画面（React）は操作の部品だけを描き、プレビューの欄は**透明に抜く**。操作（クリック・ドラッグ）は画面が受けて Rust へ伝える。
- WebAssembly の組み立ては持たない（1系統）。

### 決定2：ADR-0074 決定2 の技術の前提を改める

- 「プレビュー（WebGPU）とネイティブで同じコードを動かす」→「**プレビューもネイティブで描く**（同じコードを1系統で）」。描画のコードを1つにする狙いは変わらない。ADR-0074 に追補を書く。

## 結果・影響

- γ0.1 の段階③（描画の核）・④（画面なしの書き出し）はネイティブだけを考えればよい。
- 段階⑦（プレビュー画面）でやること：
  - プレビューの欄の位置・大きさ（画面の座標）を Rust へ送り、その矩形にだけ描く。
  - 欄の配置の変更・窓の移動と大きさの変更に追従する。
  - 窓を透明にする（`transparent: true`）ことの副作用（影・角の丸み・ほかの欄の背景）を確かめる。
  - ⚠️ **追補（2026-11-26・MV-0007）**：段階⑦で作った。窓の枠・影はそのまま出て、ほかの欄は地の色を塗れば透けない（実機の窓の画像で確かめた）。
- 試作のコードは `apps/stario-mv/spikes/preview/` に残す（γ の CI では組み立てない・上位 PC で測り直すため）。

## 未解決の論点

- 上位 PC（専用 GPU・リモートでない画面）で測り直して、数字を追記する（試作の README の手順）。
- 別の窓（大きく見る・2画面目）へプレビューを出す方法（ネイティブの窓をもう1つ作る見込み）。
- 画面とネイティブの描画のずれ（欄を動かした瞬間の1コマの遅れ）の許容。
