# MV-0015: イージングのグラフ（値と速さ）

- **状態**: Accepted（2026-11-27・γ0.2 の段階⑥。AE のグラフエディターの型＝MV-0010 決定3・利用者判断 2026-11-27「値と速さの両方」）
- **日付**: 2026-11-27
- **関連**: MV-0010 決定3／MV-0003（補間＝cubic-bezier の取っ手）／MV-0014（キーの画面）／MV-0001（形＝`easeOut`・`easeIn`＝[時間の割合 0〜1, 値の割合]）

## コンテキスト

区間の進み方は、キーの出の `easeOut` と次のキーの入りの `easeIn`＝CSS の cubic-bezier の取っ手で決まる（値の割合は 0〜1 を超えてよい＝行き過ぎて戻る）。⑤で F9 などの決まった形は付けられるが、取っ手を自由に動かす画面が無い。

## 決定

### 決定1：タイムラインの帯の場所をグラフに切り替える（AE と同じ）

- タイムラインの上の「グラフ」（`Shift+F3`＝AE と同じ）で、帯の場所がグラフになる（時間の目盛りと今の時刻の線はそのまま＝同じ横の位置）。もう一度で帯に戻る。
- グラフに出す値は1つ＝**最後に押した値の行（名前か◆）**。何も押していなければ「値の行を押してください」と出す。
- 「値」と「速さ」を切り替える（グラフの上のボタン）。縦の範囲は、出している曲線と取っ手が収まるように自動で合わせる。

### 決定2：値のグラフ

- 値の成分ごと（位置なら x と y）に、そのときの値を線で描く（描画の核と同じ計算＝cubic-bezier を画面側に写した関数で、Rust の検査と同じ数で確かめる）。
- 曲線の区間（`bezier`）には、出と入りの取っ手を描く（キーから取っ手の点まで線）。取っ手の点は（区間の始まり＋時間の割合×区間の長さ、始まりの値＋値の割合×値の差）。
- 取っ手を掴んで動かす＝そのキーの `easeOut`（または次のキーの `easeIn`）が変わる。時間の割合は 0〜1 に収める。値の割合は 0〜1 を超えてよい（行き過ぎ）。⚠️ 取っ手は区間で1つ＝成分ごとには持てない（値の差が 0 の成分では取っ手を出さない）。
- キーを掴んで上下＝そのキーの値（その成分）が変わる。横には動かさない（時刻はタイムラインの◆で動かす＝MV-0014）。

### 決定3：速さのグラフ

- 1秒あたりの変わり方の大きさ（成分が2つなら長さ）を線で描く。
- 曲線の区間の取っ手は、AE と同じく「影響（横）」と「速さ（縦）」で見せる：出の取っ手＝（始まり＋`easeOut[0]`×長さ、始まりの速さ＝`easeOut[1]`÷`easeOut[0]`×平均の速さ）・入りの取っ手＝（終わり−(1−`easeIn[0]`)×長さ、終わりの速さ＝(1−`easeIn[1]`)÷(1−`easeIn[0]`)×平均の速さ）。
- 取っ手を掴んで動かす＝影響と速さから `easeOut`／`easeIn` を逆に求めて書く（形は増やさない）。影響は 1〜100% に収める。

### 決定4：書くのは今の取引

- 掴んでいる間は試し（保存しない）・離すと1つの `updateLayer`（値の `keyframes` を置き換える）。錠のかかったレイヤーは動かさない。

## 結果・影響

- 画面：グラフの部品（SVG）・取っ手とキーの位置と、動かしたあとの `easeOut`／`easeIn`／値を求める純粋な関数（`graph.ts`）。cubic-bezier は画面側にも写す（`mv-core` の `cubic_bezier_ease` と同じ数で検査する）。
- `mv-core`・`mv-ops`・正典の形：変えない。

## 未解決の論点

- 位置の「縦横別々」（AE の「次元に分割」）＝成分ごとに取っ手を持つ形（要るなら形を足す＝別の ADR）。
- 複数の値を重ねて出す・キーを横に動かす・取っ手をそろえる（AE の「取っ手を分割」相当）。
