# MV-0004: 画面なしの書き出し（MP4・H.264）

- **状態**: Accepted（2026-11-26・γ0.1 の段階④の技術の決定）
- **日付**: 2026-11-26
- **関連**: ADR-0074 決定3（C-3＝アプリを閉じていても書き出せる）・決定4（書き出し）／MV-0002（プレビュー＝書き出しを同じ描画で）・MV-0003（描画の核）／α の ADR-0069（色ずれ）

## コンテキスト

γ0.1 の段階④。描画の核（MV-0003）で描いた1コマずつを FFmpeg に流し、画面なしで MP4 を作る。外部 AI の口（段階⑤）・画面の書き出し（段階⑦⑧）もこれを使う。

## 決定

### 決定1：流れ

- `crates/mv-export`。1コマずつ描画の核で描き、生の RGBA（sRGB）を FFmpeg の標準入力へ流す。プレビューと**同じ描画**を通る（近似の書き出し経路を作らない）。
- コマンド `stario-mv-export <動画のフォルダ> --out <出力.mp4>`（`--fonts`・`--ffmpeg`・`--composition`・`--encoder`）。出力の場所を標準出力に返し、終わりのコードは 0＝できた／1＝動画や環境の問題／2＝使い方の誤り（外部 AI が受け取りやすい形）。

### 決定2：守ること

- **中身の検査（2段目）に問題がある動画は書き出さない**（まだ描けない機能を含む＝黙って別の絵を出さない）。
- **書きかけで止まっても前からあるファイルを壊さない**：同じフォルダの `.<名前>.writing` に書き、できてから置き換える。失敗・中止の後片づけは1か所。
- 止める合図で止まり、書きかけを消す。

### 決定3：H.264 の道具と色

- 道具は上から順に**本当に動くか小さく試して**選ぶ：`libx264`→`h264_nvenc`→`h264_amf`→`h264_qsv`→`h264_mf`→`libopenh264`（一覧に載っていても GPU が無いと動かない道具があるため）。品質は上位 PC 前提で高め。
- ⚠️ α の同梱 FFmpeg（LGPL）には libx264 が無い。あれば使う（本人だけが使う道具＝配布の制約を持ち込まない・ADR-0074）。今は α の同梱を参照する（COPIED_FROM）。
- 色：sRGB → **BT.709・限定範囲**（yuv420p）。色の情報（VUI）を書かない道具がある（α で `h264_mf` が書かなかった）ので、**流れに直接書き込む**（`h264_metadata`）。

### 決定4：音

- 音のレイヤーを、見える範囲の時刻に置いて混ぜる（`amix` の `normalize=0`＝重ねても勝手に小さくしない）。長さは動画と同じ。AAC 320k。
- ⚠️ **モノラルの素材は左右にそのままの大きさで配る**（FFmpeg の既定は −3 dB 下げる・AE は下げない）。音の数は取り込みで調べた値（`meta.channels`）、無ければその場で調べる。
- 音量のキーフレームはまだ混ぜられない（γ0.3）＝2段目の検査で知らせる。映像のレイヤーの音は素材の取り込み（段階⑥）から。
  - ⚠️ **追補（2026-11-26・MV-0006）**：映像のレイヤーの音も混ぜるようになった（MV-0006 決定5）。H.264 の道具は、書き出す大きさで試して選ぶように改めた（Intel の道具は小さい画面を開けない）。

## 結果・影響

- 検査（本物の FFmpeg に通す）：見本を書き出して H.264・1920×1080・3 秒・BT.709 になり、**30 コマ目を取り出すと描画の核の絵と平均 2 未満のずれ・背景 ±3**／音は見える範囲の時刻だけ鳴り、−6 dB が元の半分・モノラルが左右にそのまま／直すところがあれば書き出さない／止めたら残さない／失敗しても前のファイルを壊さない／コマンドから書き出せる。
- 変異チェック：検査の関門・置き換え・止める・失敗時の後片づけ・モノラル・色の行列・音量・置く時刻＝すべて赤。
- CI（`mv-ci.yml`）は FFmpeg を入れてから回す（FFmpeg が無いと検査は**飛ばさず落ちる**）。
