# MV-0006: 素材の取り込みと、映像・連番・SVG の描き方

- **状態**: Accepted（2026-11-26・γ0.1 の段階⑥）
- **日付**: 2026-11-26
- **関連**: ADR-0074 決定2（B-3 素材はコピーが標準）・決定3（C-4 許す範囲）・MV-0001（素材の形）・MV-0003（描画の核）・MV-0004（書き出し）・MV-0005（操作口）

## コンテキスト

γ0.1 の目標は「AI に素材を並べさせて書き出せる」。段階⑤までで、単色・図形・文字は並べて書き出せるようになった。
段階⑥では素材（画像・SVG・映像〔透過付きも〕・連番画像・音）を取り込み、描けるようにし、書き出しに音も入れる。
外部 AI が使うので、取り込みも**取引の中の1つの編集**にし、検査を通らなければ何も残さない。

## 決定

### 決定1：取り込みは取引の中の編集 `importAsset`

- `applyTransaction` の `ops` に `importAsset` を足す。
  - 書くもの：元の場所 `path`、`mode`（`copy`＝標準／`reference`＝コピーせずに指す）。
  - 任意：`id`、`name`、連番なら `sequence: true` と `fps`（既定 30＝AE の既定と同じ）。
- 元の場所は、**利用者が許したフォルダの中だけ**（MV-0005 決定4）。参照で取り込むときも同じ。
- コピーの置き場は `assets/<素材の ID>/<元のファイル名>`（連番は全部のコマを同じフォルダへ）。ID で分けるので、名前がぶつからない。
- 順番：
  1. 取引を当てる。
  2. 検査が通ったら、ファイルをコピーする。
  3. `project.json` を保存する。
  - 途中で失敗したら、コピーしたファイルを消して元に戻す（何も残さない）。
  - `dryRun` では、調べるだけで写さない。
- `removeAsset` は**記録だけ**を外す。ファイルは消さない（ファイルを消すときはごみ箱へ＝ADR-0074 C-4。掃除の操作は後の版）。指しているレイヤーが残っていれば、検査で断る。

### 決定2：種類は拡張子で見分け、取り込みのときに中身を調べる

| 種類 | 拡張子 | 調べること（`meta`） |
|---|---|---|
| 画像 | png・jpg・jpeg・webp・bmp・tif・tiff | 幅・高さ・透過の有無 |
| SVG | svg | 幅・高さ（SVG に書かれた大きさ） |
| 映像 | mp4・mov・m4v・webm・mkv・avi | 幅・高さ・fps・長さ・コマ数・透過の有無・音の有無・音の数・標本化周波数 |
| 連番画像 | 画像の拡張子＋`sequence: true` | 幅・高さ・コマ数・fps（指定どおり）・透過の有無 |
| 音 | wav・mp3・m4a・aac・flac・ogg・opus | 長さ・音の数・標本化周波数 |

- 映像と音は ffprobe で調べる（ffmpeg と同じ場所にあるもの）。
- 連番は、先頭のファイル名の末尾の数字を手がかりにする。続く番号のファイルを、欠けるところまで数える。
- `sha256`＝中身の指紋。連番は、全部のコマの名前と中身から1つ作る。
- 知らない拡張子や読めないファイルは、取り込まずに知らせる（推測で別の種類にしない）。

### 決定3：素材のレイヤーの既定（AE と同じ）

- `addLayer` で `assetId` を書けば、`type` は省いてよい。
  - 映像・連番 → `video`、画像・SVG → `image`、音 → `audio`。
- アンカー＝素材の中心。位置＝コンポジションの中心（＝素材がちょうど真ん中に来る）。
- 長さの既定：
  - 映像・連番・音＝素材の長さ（コンポジションより長ければコンポジションの長さまで）。
  - 画像・SVG＝コンポジションの全体の長さ。

### 決定4：描き方

- **時刻の対応**＝そのコマで見せる素材の時刻は `(コマ − startFrame) ÷ コンポジションの fps` 秒。
  - 映像・連番は、その時刻に**表示されている素材のコマ**（`floor(時刻 × 素材の fps)`）を見せる（AE と同じ）。
  - 素材の始まりより前と終わりより後は、何も描かない。タイムリマップは γ0.2。
- **映像**＝FFmpeg で生の RGBA に読み出す。
  - 順に進む間は読み続ける。戻るか2秒より先へ飛ぶときは、その時刻から読み直す（正確な位置合わせ）。
  - 色の変換は、素材に書かれた色の行列と範囲どおりに行う。書かれていなければ、高さ 720 以上は BT.709、それ未満は BT.601 とみなす（取り込み時の判定と同じ）。限定範囲の扱いも同じ。
  - 透過付き：ProRes 4444・PNG・QuickTime Animation などは、そのまま透過を読む。WebM（VP8・VP9）の透過は libvpx の読み手で読む。その FFmpeg に無ければ、知らせて止める（黙って透過なしで描かない）。
  - 前提は一定のコマの速さ（CFR）。速さが変わる映像（VFR）は、取り込みのときに知らせる（扱いは後の版）。
- **連番**＝その番号のファイルを読む。
- **SVG**＝resvg で描く。拡大されても粗くならないよう、大きさの倍率ぶん細かく描く（図形・文字と同じ 1〜8 倍）。
- 参照で取り込んだ素材が消えていたら、知らせて止める（黙って別の素材にしない）。

### 決定5：映像のレイヤーの音も書き出す

- 音を持つ映像のレイヤーは、音のレイヤーと同じ規則で書き出しに混ぜる。
  - 混ぜる音：見えている範囲、`startFrame` に合わせた位置、`audio.volumeDb`。`audio.muted` なら混ぜない。
  - `audio` が無い映像のレイヤーは、0 dB で鳴らす（AE と同じ）。

## 結果・影響

- 外部 AI の操作の一覧（`mv-operations.json`）に `importAsset`・`removeAsset` が増える。
- 描画の核が FFmpeg を使うようになる（映像のレイヤーがあるときだけ）。場所は、書き出しと同じ探し方。
- 書き出しの検査（MV-0004）に、映像の音を足す。

## 未解決の論点

- 代理の映像（軽い映像に作り直してプレビューを速くする）・波形などの解析のキャッシュ：プレビュー画面（段階⑦）以降。
- 速さが変わる映像（VFR）・インターレース・HDR（PQ・HLG）・広い色域の素材。
- 使われていない素材の掃除（ごみ箱へ）。
