# MV-0014: レイヤー＋キーフレームの画面

- **状態**: Accepted（2026-11-27・γ0.2 の段階⑤。業界の型＝After Effects の約束に合わせる＝MV-0003・α の ADR-0034 と同じ考え方）
- **日付**: 2026-11-27
- **関連**: MV-0010（γ0.2 の段階・⑥グラフ・⑦道筋）／MV-0008（編集画面・決定5＝キーフレームを打つ）／MV-0009（取引と履歴）／MV-0012（タイムリマップ）

## コンテキスト

γ0.1 で前倒ししたのは「今の時刻にキーを打つ」だけ（値の欄のストップウォッチ・◆・◀▶）。キーはタイムラインの帯の下に◆で見えるが、選べない・動かせない・補間を変えられない。⑤で、AE の「レイヤーを開いて項目ごとの行にキーを並べる」画面にする。

## 決定

### 決定1：レイヤーを開くと項目の行が並ぶ（AE の「▸」）

- レイヤーの行の左の「▸」で開く／閉じる。開くと、そのレイヤーが持つ動かせる値（変形の5つ・図形の大きさと角の丸み・タイムリマップ）が1行ずつ並ぶ。
- `U`＝選んだレイヤーの**キーフレームのある値だけ**を開く（もう一度で閉じる＝AE と同じ）。
- 開いているかは画面の好み（保存しない＝動画の形に入れない）。
- 項目の行には、その値のキーを◆で並べる。名前の列には値の名前（変形の値は値の欄と同じ名前）。

### 決定2：キーを選ぶ・掴んで動かす・消す（AE の型）

- ◆を押すと選ぶ（`Shift` で足す・外す＝`Ctrl` は決定3の「直線に戻す」）。何も無い所を押すと選択を外す。レイヤーを選び直しても、キーの選択はそのレイヤーのものだけ残る。
- 選んだキーを掴んで左右へ＝まとめて同じフレーム数だけ動かす（吸着が入っていれば今の時刻へ吸い付く）。離すと1つの取引（試しは帯と同じ道＝保存しない）。
- 動かした先に同じ値の別のキーがあれば、**動かしたキーで置き換える**（AE と同じ）。
- `Delete`＝選んだキーを消す（キーが選ばれていればレイヤーより先）。最後の1つを消すと、その値は固定値（MV-0008 決定5 と同じ＝キーの無いキーフレームは形として置けない）。
- 書くのは今の取引（`updateLayer` で値の `keyframes` を置き換える）＝新しい編集の種類は足さない。

### 決定3：補間の切り替え（AE の型・形は変えない）

- 補間は「そのキーから次のキーまでの区間の進み方」（形の `interpolation`＝MV-0003）。⚠️ AE はキーごとに「入り」と「出」を別々に持つが、この形はキーの出の1つ＝**入りは前のキーの出で決まる**。
- `Ctrl+Alt+H`＝選んだキーを「止める」（停止）と「直線」で切り替える。
- `F9`＝イージーイーズ（選んだキーで、出は `easeOut` [1/3, 0]・入りは `easeIn` [2/3, 1]＝速さ 0・影響 33%）。入りを効かせるため、前のキーの補間が直線なら曲線にする（前のキーの出の取っ手は直線と同じまま）。`Shift+F9`＝入りだけ・`Ctrl+Shift+F9`＝出だけ（AE と同じ）。
- `Ctrl` を押しながら◆を押す＝直線に戻す（取っ手も消す）。
- ◆の形で補間を見せる（直線＝◆・止める＝■・曲線＝●）。

### 決定4：キーの間を跳ぶ（AE の型）

- `J`／`K`＝前／次のキーへ今の時刻を動かす（選んだレイヤー〔無ければ全部〕の、キーのある全部の値＝タイムリマップも。開いているかは見ない＝キーがあるのは必ずキーのある値の行なので、開き方で結果は変わらない）。

### 決定5：段階

- ⑤-1：決定1・決定2（開く・`U`・選ぶ・動かす・消す）。
- ⑤-2：決定3・決定4（補間の切り替え・イージーイーズ・`J`／`K`）。

## 結果・影響

- 画面：タイムラインの行を「レイヤーの行＋開いた値の行」の並びにする（見えている行だけ描くのはそのまま）。キーの選択・掴む・消す・補間の切り替えは純粋な関数（`keyframeOps` 等）にして検査する。
- `mv-core`・`mv-ops`・正典の形：変えない。

## 未解決の論点

- キーの写し・貼り付け（`Ctrl+C`／`Ctrl+V`）。
- 範囲で囲んで選ぶ（AE の四角で囲む）。
- 入りと出を別々に持つ形（要るなら形を足す＝別の ADR）。

## 追補（2026-11-27）＝⑤-1 の実装の記録

- **純粋な関数**（`src/edit/keyframes.ts`）：値の行（`propRowsFor`＝▸は持っている値・`U` はキーのある値・タイムリマップも）・開く（`toggleReveal`・`revealAnimated`＝選んだうちキーのあるものだけ・全部がもう `U` で開いていれば閉じる・▸で全部開いていたものは `U` でキーのある値だけに替える）・キーの名前（`keyId`＝「レイヤー|値|フレーム」）・今もあるキーだけ（`liveKeys`）・押す（`clickKey`）・動かす（`moveKeysOps`＝同じレイヤーの値はまとめて1つの `updateLayer`・動かした先の同じ値のキーは置き換える・錠は除く）・選択を動かした先へ（`movedKeyIds`）・消す（`removeKeysOps`＝全部消したら時刻のいちばん後のキーの値の固定値）。
- **タイムライン**：行を「レイヤーの行＋開いた値の行」の並びにした（見えている行だけ描くのはそのまま）。名前を掴んで重なりの順を変えるのは、行の数で数えて、その行のレイヤーの位置へ。◆は補間の形（直線＝◆・止める＝■・曲線＝●）。掴んで動かしている間は、選んだキーを動かした先で見せる（試しは帯と同じ道）。
- **画面の状態**（開いているレイヤー・選んだキー）は `App` が持つ（保存しない）。`Delete` はキーが選ばれていればキーを先に消す。
- **実機で確かめたこと（2026-11-27・開発版＋CDP）**：入れ子の中の赤を選んで `U` → 「位置」の行だけ開く／40 の◆を掴んで 5 フレーム右へ → 保存されたキーが 45・50、45 の◆が選ばれたまま／`Delete` → 50 だけ／元に戻す 2 回で 40・50 に戻る。⚠️ 画面の撮影はできなかった（画面の取り込みが断られた）＝見た目は検査（行の位置・◆の形の印）で確かめた。

## 追補（2026-11-27）＝⑤-2 の実装の記録

- **純粋な関数**（`keyframes.ts`）：`toggleHoldOps`（選んだキーが全部「止める」なら直線へ・混ざっていれば全部「止める」へ揃える・取っ手は外す）・`toLinearOps`（直線・取っ手を外す）・`easeOps`（`EASE_OUT`＝[1/3, 0]・`EASE_IN`＝[2/3, 1]・入りは前の直線のキーを曲線に・前が止めるなら変えない）・`adjacentKeyFrame`（`J`／`K`）。
- ⚠️ **選択に足すのは `Shift` だけ**にした（⑤-1 では `Ctrl` でも足せたが、AE と同じく `Ctrl`＋◆は補間の切り替え＝決定2 の書き方も直した）。
- ⚠️ `J`／`K` は開き方を見ない（決定4 の書き方を直した）＝キーがあるのは必ず「キーのある値」の行なので、開いていても閉じていても同じ結果になる（区別を書いたが、検査を書く段で違いが作れないと気づいた）。
- **実機で確かめたこと（2026-11-27・開発版＋CDP）**：入れ子の中の赤（40・50 が直線）で 50 の◆を選んで `F9` → 40 が曲線・50 が曲線で入り [2/3, 1]・出 [1/3, 0]・◆が●／`Ctrl+Alt+H` → 50 が止める・◆が■／40 を `Ctrl`＋クリック → 40 が直線／最初へ戻って `K`・`K`・`J` → 40・50・40／元に戻す 3 回で元どおり。
