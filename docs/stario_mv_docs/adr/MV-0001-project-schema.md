# MV-0001: すたりおMV のプロジェクトの形（project.json の正典）

- **状態**: Proposed（2026-11-26・利用者の確認待ち＝下の「確認してほしいこと」）
- **日付**: 2026-11-26
- **関連**: ADR-0074 決定2（データの形）・決定3（外部 AI の操作口）・決定6（版の割り振り）／ADR-0075（γ の資料の置き場・番号）／#1337 §15 ⑤／正典 [`schemas/mv-project.schema.json`](../schemas/mv-project.schema.json)・見本 [`schemas/examples/minimal.json`](../schemas/examples/minimal.json)

## コンテキスト

ADR-0074 決定2 で骨組み（コンポジションにレイヤーを積む・どの数値も同じ形・つなぎと式・素材はコピーが標準・時間はフレーム・長い一意 ID・JSON Schema が正典）を決めた。
γ0.1（土台）に入る前に、それを**機械が検査できる正典**にする。外部 AI が書き込む前提なので、**知らない項目・形の崩れは schema の段階で通さない**ことが要になる。

## 判断軸

- **外部 AI が間違えにくい**（単位が揃っている・同じ考え方の繰り返し・業界の型に近い）。
- **検査で落とせる**（`additionalProperties: false`／種類ごとに持てる項目を限る）。
- **後の版で足せる**（γ0.2〜0.8 の機能を、形を壊さずに足せる骨組み）。
- α の形式に引きずられない（ADR-0074 決定1）。

## 決定

### 決定1：動画1本＝フォルダ1つ

```
<名前>.stariomv/
  project.json   ← この schema の対象（正典）
  assets/        ← コピーした素材（B-3）
  cache/         ← 解析の結果（拍・波形・代理の動画）。消しても作り直せる＝正典ではない
```

### 決定2：時間は「そのコンポジションのフレーム番号」（整数）

- fps は分数（`{num, den}`・29.97 は 30000/1001）。入れ子のコンポジションは自分の fps で数える。
- レイヤーは `inFrame`（含む）〜`outFrame`（含まない）で見え、`startFrame` に素材の時刻 0 を置く（切り詰めても素材はずれない）。
- 素材の長さ（`meta.durationSec`）とタイムリマップの値は**秒**（素材の fps はコンポジションと違いうるため）。

### 決定3：ID は「種類の頭＋ULID」

- `prj_`・`ast_`・`cmp_`・`lyr_`・`fx_`・`msk_`・`mkr_` ＋ ULID（26 文字・Crockford Base32＝I・L・O・U を使わない）。
- 連番にしない（ADR-0074 決定2）。頭で種類が分かるので、取り違えた参照を schema で落とせる。

### 決定4：どの数値も同じ形（Animatable）

```json
{ "value": 1 }                                  // 固定値
{ "keyframes": [{ "frame": 0, "value": 0, "interpolation": "linear" }, ...] }
{ "expression": { "language": "…", "source": "…" } }
```

- **固定値・キーフレーム・式のどれか1つだけ**（2つ以上・0 個は通さない）。そこに任意で**つなぎ**（`links`）を足し込む。
- キーフレームの進み方＝`hold`／`linear`／`bezier`。bezier のハンドルは区間ごとに `[時間の割合, 値の割合]`（CSS の cubic-bezier と同じ考え方・値の割合は 0〜1 を超えてよい）。
- 位置は動きの道筋のハンドル（`spatialIn`／`spatialOut`・キーからの差分）も持てる。
- 単位：位置とアンカーは**ピクセル**（左上が原点・下が +y）、大きさは**倍率**（1＝そのまま・縦横別）、回転は**度**（時計回り）、不透明度は **0〜1**、音量は **dB**。

### 決定5：色は sRGB の 0〜1 で書く。合成の計算をする色空間はプロジェクトの設定

- 色の値は `[赤, 緑, 青, 不透明度]`・各 0〜1・**sRGB で書く**（作業用の色空間に関係なく同じ書き方＝AI も人も迷わない）。
- 合成・ぼかし・発光を計算する色空間は `settings.workingColorSpace`（`linear`／`srgb`）。**既定は linear**（光の足し算として正しい＝発光・ぼかし・描画モードが自然。γ の表現の中心になる発光系の質に直結する）。⚠️ 確認してほしいこと②。

### 決定6：レイヤーの並びは「先頭が最前面」

- `layers` の先頭＝レイヤーの一覧のいちばん上＝最前面（AE と同じ見え方）。描くときは末尾から。

### 決定7：検査は2段

1. **形の検査**（この schema）：項目・型・種類ごとに持てる項目・ID の頭・値の範囲。
2. **中身の検査**（γ0.1 で実装）：ID の重複が無い／参照先（素材・コンポジション・親・トラックマット・マスク）が実在する／親とトラックマットが同じコンポジションの中で循環しない／入れ子のコンポジションが循環しない／`inFrame < outFrame`／キーフレームのフレームが重ならず昇順／値の次元が項目と合う（位置は2つか3つ等）／エフェクトのパラメータが種類ごとの定義と合う。
- 外部 AI の書き込みは**両方を通ってから**反映する（ADR-0074 決定3 の「まとめて反映」）。

### 決定8：schema は全体の骨組みを最初から持ち、まだ作っていない機能は「入れ物だけ」

- レイヤーの全種類（映像・画像・文字・図形・単色・調整・ヌル・カメラ・音・入れ子）・マスク・トラックマット・エフェクトの重ね・つなぎ・式の**入れ物**を最初から置く。後の版で中身を足しても、既存の動画の形は壊れない。
- ⚠️ ただし**中身の決まっていない入れ物は、知らない項目を通さない**（例：つなぎは `kind` と `amount` だけ＝γ0.3 で足す。式は `language` と `source` だけ＝言語は別の ADR）。
- ⚠️ 入れ物はあっても**動かない機能は、中身の検査で「この版ではまだ使えません」と知らせる**（黙って無視して別の絵にしない）。⚠️ 確認してほしいこと③。

### 決定9：エフェクトは「種類の名前＋版＋パラメータ」

- 種類の名前＝標準は `stario.〜`（例：`stario.blur.gaussian`）、OFX は `ofx:〜`（ADR-0074 決定5）。
- 版（`version`）＝同じ種類でもパラメータの意味が変わったら上げる（古い動画を読み替える手がかり）。
- パラメータの中身は種類ごとの定義で検査する（2段目）。

## 結果・影響

- 正典：`docs/stario_mv_docs/schemas/mv-project.schema.json`（schemaVersion 0.1.0）・見本 `examples/minimal.json`。
- 検査：`apps/stario-mv/src/schema/projectSchema.test.ts`＝見本が通る＋見本を1か所ずつ壊した16通りが通らない（変異チェック済み：schema の「1つだけ」「知らない項目」「つなぎの閉じ方」「素材を指せるレイヤー」「ID の文字」を外すと、それぞれ赤）。
- 次（γ0.1）：2段目の検査・読み書き・描画の最小（決定6 の γ0.1 の表）。

## 確認してほしいこと（Proposed の理由）

1. 保存の形を「フォルダ1つ（project.json＋assets＋cache）」にしてよいか（決定1）。
2. 合成の色空間の既定を **linear** にしてよいか（決定5）。srgb は AE の既定と同じ見え方。
3. schema を「全体の骨組みを最初から・まだの機能は入れ物だけ」にしてよいか（決定8）。

## 未解決の論点

- 式の言語と隔離の方法（別の MV ADR）。
- つなぎの種類ごとの中身（γ0.3）。
- 文字の1文字ずつの動き・ルビ・縦書きの詳細（γ0.4）。
- 図形の重ね（グループ）・2.5D のカメラの詳細（γ0.2〜）。
- 書き出しの設定（形式・画質）をプロジェクトに持つか、書き出しのたびに選ぶか（γ0.1 の書き出しで決める）。
