## 1. 監査の結論（先に要点）

1. **元資料の主張はすべてコードと一致した**（§2）。「うちに無いもの」対照表（元資料 §3）の10項目・#683 の監査表を1件ずつコードで再確認し、**誤りは見つからなかった**。結論3つ（独自の操作を発明しない／Canva の不満を踏んでいる／モードを分ける・自由度を削らない）も支持する。
2. ただし**元資料は「何を作るか」の粒度で止まっており、「どう振る舞うか」の層が丸ごと欠けている**。ドラッグの中断・置けない位置の見せ方・選択モデル・分割の意味論・ズームの錨点など、**実装に入った瞬間に必要になる決めごと**が #684〜#687 のどこにも書かれていない（§5）。
3. **元資料に未記載の機能欠落がコードから追加で見つかった**（§2.2）。特に「**バラした後の文字・図形・写真の部品は中身を編集できない**」は、#684 で置けるようにした瞬間に「置けるのに直せない」として顕在化する。
4. **既存 α-5 Issue との重複整理が漏れている**（§4）。#686 の分割は #333 と、#684 の素材欄は #260 と重なる。
5. 元資料が「未確認」とした **nizima ACTION!! の実操作を裏取りした**（§3）。「普通の型に従う」結論はキーボードの次元でも裏付けられた。

## 2. 既存資料・#683 の監査結果

### 2.1 検証して一致した主張（抜粋）

| 主張 | コードでの確認 |

| キャンバスは絵を貼っているだけ | `dangerouslySetInnerHTML` のみ・イベントゼロ（`:503`）。**位置・大きさの setter は store にも無い**（`timelineStore.ts:128-234`） |

### 2.2 元資料に未記載だった事実（コードから新たに判明）

**機能の欠落（#684〜#687 のどれにも書かれていない）**

1. **バラした後の部品は中身を編集できない**。`kind='text'/'shape'/'slot'` の部品に出る節は「切り抜き」と「動き」だけ＝**文字の内容・色・フォント、図形の色、写真の差し替え、いずれも不可**（`TimelineProjectScreen.tsx:666-895` の節構成・素材 select は template の差し込み口専用 `:1178-1194`）。#684 で text/shape/slot を「置ける」ようにすると、**置いた文字を打ち直せない**という形で即座に露呈する。**#684 の受け入れ条件に「置いた部品の中身を編集できる」を含めるべき**。
2. **開始秒・長さの数値入力欄が無い**（表示のみ・`:633-635`）。移動は ±0.5秒固定ボタン（`NUDGE_SEC`・`:76`）＝0.5秒未満の調整が**そもそも不可能**。
3. **音・読み上げの置き先が `voiceTracks[0]` 固定**（`:1308-1309, 1329`）＝音の列を2本作っても2本目に置けない。見た目パターンだけ列を選べる非対称。
4. **列の名前を変えられない**（`Track.name` は型にあるが書き込む UI が無い）。
5. **複数選択でできるのは「まとめて消す」だけ**（`timelineStore.ts:875-881`）。**空白クリックで選択解除もできない**（`clearSelection` は store に定義済みだが**未配線**・`:404`）。
6. **帯に右クリックメニューが無い**（列の行と欄の見出しにはある）。帯にホバーの `title` も無い（場面形式の `TimelineView.tsx:176` は付けている）。

**実装品質の問題（#687 より深い層）**

7. **入力1文字＝1履歴**。数値・文字入力が生 `<input>`＋即時 `onChange` → `commit()` で、共有部品 `NumberField`（blur でクランプ・NaN 無視）を使っていない。履歴上限50なので**長文を打つと直前の編集が履歴から押し出される**。
8. **履歴のグルーピング機構が timelineStore に無い**（`useHistoryGroup` は場面形式 store 専用）。ドラッグ操作を入れる際の前提欠落（→ §7）。
9. **下書き state（キーフレーム・音量点の入力欄）を選択切り替えでクリアしていない**＝別の部品を選んでも前の入力値が残る。
10. **「消す」に確認が無い**一方、列削除と「バラす」には確認がある＝取り返しにくさの扱いが不揃い（→ §5-J）。
11. **`editBlocked` の理由が画面上端に出る**＝操作した場所（右の欄・下の並び）と離れている。列メニュー側は押す前に `disabledHint` で理由を出しており、**同じ画面に流儀が2つ**。
12. **「素材の画面で写真を取り込んでください」という行き止まり案内**（`:1197-1203`）。サイドバーの素材画面は場面形式 store 専用で、タイムライン文書の `doc.assets` には**何も取り込めない**。完全新規のタイムラインプロジェクトは素材ゼロから増やす手段が無い。
13. **未配線の残骸が既にある**：`.timeline-clip--editable`/`.timeline-clip-handle`（トリムカーソル）/`.timeline-clip--dragging`/`.timeline-playhead`/`.timeline-ruler--seekable` の CSS は定義済みだが**この画面のどの .tsx からも未参照**。`applyClipEdge`（端ドラッグの計算・#561）も domain に待機中。**帯ドラッグ・トリム・シークの「見た目と計算」は半分できていて、入口だけが無い**。
14. クリップの色分けは列の種別（映像/音）の2色だけ。`--telop`/`--bgm` の色も CSS に定義済み未使用。帯の中身はテキスト1行（12文字）のみ。
15. 「取り消す・やり直す・列を足す」ボタンが**欄の外**（ページ下端側）にあり、欄の中の作業と視線が分断される（欄コンテナは 76vh 固定）。

## 3. 「未確認」の裏取り結果（外部調査）

### 3.1 nizima ACTION!!（元資料 §7 の未確認①③を解消）

[マニュアル（タイムライン）](https://docs.nizima-action.com/manual/timeline/)と[ショートカット一覧](https://docs.nizima-action.com/manual/shortcut/)で確認：

- **分割**＝ハサミツール＋ **`S` キーで「選択中のレイヤーを再生位置で分割」**。動画は右クリックで音と映像に分離。
- **再生**＝`Space`/`Enter`。**フレーム送り＝`←`/`→`**。
- **キャンバスのナッジ＝矢印で1px・Shift+矢印で10px**（＝元資料 §3 の「キャンバスの型」と完全一致）。
- **ズーム＝`Alt`+ホイールで時間軸の拡縮**。**パン＝`Space`+ドラッグ or 中ボタンドラッグ**。
- `Ctrl+C/X/V`・複製・`Delete`・`Escape`（選択解除）・`Ctrl+G`（グループ）・右クリックメニュー（コピー/複製/削除/レイヤー追加/重ね順/ロック）。
- **作業範囲（work area）**＝範囲を帯で決めてループ再生・書き出し範囲に使う。

**含意**：矢印キーが「キャンバスではナッジ・タイムラインではフレーム送り」と**文脈で切り替わる**のは、うちに最も近い先行例でも当たり前になっている（→ §6 論点13）。「初心者向けでもショートカットは省かない」ことの裏付け。

### 3.2 タイムライン設計の具体数値（img.ly の設計記事）

[img.ly: Designing a Timeline](https://img.ly/blog/designing-a-timeline-for-mobile-video-editing/)（元資料の出典に載っていたが中身が引かれていなかったもの）：

- **トリムハンドルの当たり判定は見た目の2倍以上**に広げる。ハンドルは帯の外側に置き、これ以上伸ばせないときは**アイコンを変えて**伝える。
- **吸着対象は画面内に見えているものだけ**（画面外の端には吸わせない）。吸着位置は**点線**で示す。
- **トリム中は再生位置を動かさない**（画面が勝手にスクロールして混乱させない）。トリム位置は別のオーバーレイで見せる。
- 目盛りは**10秒未満は小数1桁（「4.2秒」）・1分超は 1:30 形式**。
- 帯の当たり判定は約1cm四方を最低線に。

### 3.3 ズームの錨点（Premiere の不満スレッドから）

[Ctrl+ホイール＝再生位置基準、Alt+ホイール＝マウス位置基準という使い分けの流儀がある](https://filmora.wondershare.com/video-editing-tips/premiere-pro-how-to-zoom-in-on-timeline.html)。[再生位置基準が無いことへの不満スレッド](https://community.adobe.com/questions-729/alt-scroll-wheel-to-zoom-in-on-playhead-in-timeline-1427285)もある＝**「どこを中心に拡大するか」を決めずにズームを作ると不満が出る**。推奨は §5-C。

### 3.4 キャンバス吸着の一時解除

[Canva は Ctrl（⌘）を押している間だけ吸着が切れる](https://www.magicslides.app/blog/how-to-change-snap-options-on-canva)（[別解説](https://www.trupeer.ai/tutorials/how-to-turn-off-snapping-in-canva)）＝元資料 §3「キャンバスの型」の裏付け。**うちの `FreeLayoutOverlay` にはこの機構が無い**（§5-E）。

## 5. 不足観点カタログ（本体）

> 各項目：**現状**（事実）→ **推奨**（提案）→ 紐づく先。ADR-0034 で決めるべきものは §6 に論点番号で再掲。

### A. 選択モデル（#683〜#687 のどこにも設計が無い）

- **現状**：Shift+クリックで複数選択はできるが、複数でできるのは削除だけ。**空白クリックで選択解除できない**（`clearSelection` 未配線）。矩形選択・Ctrl+A・Escape 解除・帯の右クリックメニュー、いずれも無し。
- **推奨**：
  1. **選択は1つのモデルに統一**する＝「帯で選ぶ」「キャンバスで選ぶ」「選んだ部品の欄」が**同じ選択状態**を指す（キャンバスで掴んだら帯もハイライト、逆も）。#685 と #686 を別々に作ると選択が2系統に割れる危険が高い。**最初に選択 store を1本化してから両方を繋ぐ**こと。
  2. 空白クリック・`Escape` で解除（配線するだけ）。`Ctrl+A` で全選択。
  3. **複数選択の同時移動**（同一Δで動かし、**1つでも V24 衝突したら全体を断る**＝「黙って一部だけ動かさない」ADR-0026④の流儀）。
  4. **帯にも右クリックメニュー**（消す／同じものを足す／分割／この位置へ…）。列の行・欄の見出しと同じ `ContextMenu` 部品を流用。⋮の逃げ道も同じ流儀（§2-5）。
  5. 帯に `title`（名前・時間帯）を付ける（場面形式 `TimelineView` は既にやっている＝同概念同挙動）。
- 紐づく先：#685・#686 の**前提作業**。論点10。

### B. 帯ドラッグの詳細設計（#686 の追補）

- **現状**：無し。ただし CSS（ハンドル・ドラッグ中の見た目）と計算（`applyClipEdge`）は待機済み（§2.2-13）。
- **推奨**（他社の型＝元資料 §3 と img.ly の数値を具体化）：
  1. **少し動かすまでは掴まない**（クリック＝選択と共存）・**`Escape` で中止**・**左ボタンのみ**＝**欄のドラッグ（ADR-0033 段階3）と同じ規則**。同じアプリ内でドラッグの作法を2つ作らない（ADR-0026②）。
  2. ドラッグ中は**半透明のゴースト**が実際に置かれる位置に出る。**置けない位置（V24 衝突・種別違いの列・固定列）では色を変えて「置けない」と分かる**ようにし、そこで離したら**元の位置へ戻す**（勝手に近くへ寄せない＝`TIMELINE_EDIT_OVERLAP` の文言と同じ思想）。
  3. **トリムハンドルの当たり判定は見た目の2倍以上**・カーソルは `ew-resize`（CSS は既にある）。これ以上縮まないときはハンドルの見た目を変える（img.ly）。
  4. **吸着**＝他の帯の端・再生位置・0秒。**画面内に見えているものだけ**。吸着した瞬間に**縦の点線**を出す。**`Ctrl`（または `Alt`）を押している間は吸着を切る**。
  5. **列またぎ**＝縦へドラッグ。**置ける列（種別が合う・固定でない）だけ**受け入れ表示。
  6. **ドラッグが画面の端に達したら自動で横スクロール**（edge scroll）。
  7. **トリム中は再生位置を動かさない**（img.ly）。トリム中の端のフレームをプレビューに出すかは任意（出すなら「シークと同じ経路」で＝パリティ）。
  8. **連動字幕**：読み上げの帯を動かす・伸ばすときは**必ず既存の domain 操作（`moveClip`/`trimClip`）を通す**＝連動字幕が同じ区間へ付いてくる保証（決定24）を入口で壊さない。ドラッグ用の別経路を作らないこと。
  9. 複数選択ドラッグ（A-3）と `Alt`+ドラッグ複製は**後回し可**（複製は「同じものを足す」がある）。
- 紐づく先：#686。論点3（既存）＋論点11・12。実装の落とし穴は §7。

### C. ズーム・ナビゲーション（#686 の追補）

- **現状**：`PX_PER_SEC=40` 固定。5分の動画でレーン幅 12000px。目盛り間隔は尺依存の3段階のみ。
- **推奨**：
  1. **場面形式の `TimelineView` に既にあるズーム段階（`ZOOM_LEVELS` ＋ ± ボタン）と同じ型**にする（同概念同挙動）。加えて **`Ctrl`+ホイール**でズーム。
  2. **錨点はマウス位置**（ズームしてもマウス下の時刻が動かない）。再生位置基準は「ヘッドが画面外にあると迷子になる」不満が知られている（§3.3）。
  3. **「全体を表示」**（fit）ボタンを置き、**開いた直後の既定は fit**（長い動画で潰れない・短い動画で間延びしない）。
  4. **横スクロール＝`Shift`+ホイール**（通常ホイールは欄の縦スクロールを奪わない）。
  5. 目盛りは**ズーム倍率に応じて**密度を変える（現状の尺依存から変更）。表記は「4.2秒」「1:30」の流儀（img.ly）。
  6. **ズーム状態は覚えない**（開くたび fit）を推奨＝ADR-0033 の「配置」と違い、ズームは文書の長さに依存するので覚えると崩れる。→ 論点14（既存論点4の決着案）。
- 紐づく先：#686。

### D. ルーラー・再生ヘッド（#630 の上に積む）

- **現状**：シークは `<input type="range">` のみ。ルーラーは飾り（クリック不可）。レーンを貫く縦線ヘッドが**無い**（CSS は既にある・場面形式は実装済み）。フレーム送り・追従スクロール無し。
- **推奨**：
  1. **ルーラークリックでシーク・ドラッグでスクラブ**（場面形式 `TimelineView` の `--seekable` と同じ挙動へ）。
  2. **全列を貫く再生ヘッドの縦線**＋ルーラー上のつまみ。
  3. **`←`/`→` で1フレーム送り・`Shift`+`←`/`→` で1秒**（格子は `frameTimeSec` を共有＝プレビューと同じ時刻に止まる）。
  4. **再生中の追従**＝ヘッドが表示範囲を出たらページ送り（スムーズスクロールで追い続けない・Premiere 型のページ送りが実装も軽い）。
  5. 現在時刻／全体尺の**数字表示**（「12.4秒 / 3分05秒」）。range スライダーは廃止してよい（ルーラーが代替）。
- 紐づく先：#686（または #630 の追補）。

### E. キャンバス直接操作（#685 の追補）— 流用で足りるもの・足りないもの

- **現状**：表示のみ。幾何の setter が store に無い。
- **流用元（場面編集 `FreeLayoutOverlay`＋`freeLayoutOps`）に既にあることを確認済み**：ドラッグ移動・角ハンドル拡縮・回転（Shift で15°刻み）・**整列ガイド（`freeSnap`＝中央・端に吸着してピンクの線）**・矩形選択・矢印ナッジ・**ダブルクリックのドリルイン（グループの中の要素を選ぶ）**・**テキストのインライン編集（二度押し）**・重ね順操作・複製。**#685 の「流用」方針は成立する**。
- **流用元にも無いもの（新設が必要）**：
  1. **`Escape` でドラッグ中止**（欄ドラッグにはある＝アプリ内で不揃い）。
  2. **`Ctrl` で吸着の一時解除**（Canva の型・§3.4）。
  3. 追加するなら**流用元（場面編集）にも同時に入れる**＝2画面で操作感を割らない（ADR-0026②）。ただし場面形式は凍結対象なので、**「FREE の拡張」でなく「共有部品の修繕」として扱えるか**を ADR-0034 で明示しておく（凍結の線引き＝ADR-0032）。
- **タイムライン特有の適応（流用だけでは決まらないこと）**：
  4. キャンバスに映るのは**再生位置に生きている部品だけ**。選択中の部品が再生位置に居ないときは**ハンドルを出せない**＝「選んだ部品」欄に**「この部品の時間へ」ジャンプ**を置く（音量点の「この位置へ」と同じ流儀）。
  5. **キャンバスの「前へ/奥へ」の翻訳問題**：クリップは `zIndex` を持たず**重ね順は列の並びだけ**（ADR-0032 決定）。キャンバスで「前へ」を出すなら、それは**列の移動（または列の新設）**になる。→ **論点9**（α-5 では出さない、が最小。出すなら「上の列へ移す」という言葉で出す）。
  6. **数値欄**：横・縦・幅・高さ・傾き・濃さを「選んだ部品」に追加（clip の語彙は `FreeElement` と同じなので schema は既に持っている）。**必ず共有部品 `NumberField` を使う**（§2.2-7 の再発防止）。
- 紐づく先：#685。論点1（既存）・論点9。

### F. テンプレの中の要素を触る（既存論点2の深掘り＝データモデルの帰結を先に見る）

- **現状**：テンプレクリップの上書きは**差し込み口の素材と文字だけ**（`setClipAssetRef`/`setClipText`）。**個別要素の幾何（位置・大きさ）の上書きは schema に存在しない**。触る手段は「中身をバラす」（戻せない・決定23）のみ。
- **選択肢**（ADR-0034 の本丸）：
  - (a) **クリップに per-要素の幾何上書きを足す**（schema 追加・timeline 版バンプ）。バラさず触れるが、「見た目パターンを差し替えたら上書きはどうなる」問題を新設する。
  - (b) **触った瞬間に自動でバラす**。データは増えないが、**暗黙の破壊的変換**（決定23「操作の前に断る」と衝突）。
  - (c) **ダブルクリックでドリルイン→触れるのは差し込み口の中身まで。幾何を触りたければ明示的に「バラす」**。場面編集のグループ・ドリルインと同じ型＝発明が要らない。
- **推奨**：**α-5 は (c)**。バラすの敷居を下げる（帯とキャンバスの右クリックから1操作・確認文は現行のまま）。(a) は「差し込み口の位置調整」の要望が実際に出てから。**利用者判断（2026-08-04「テンプレの中の要素も個別に触れる」）を (a) と読むか (c)+バラすで満たすかは、ADR-0034 で利用者に確認する**こと。
- 紐づく先：#685。論点2（既存）の具体化。

### G. 分割の意味論（#686/#333 の追補＝「切る」は見た目より深い）

- **現状**：domain に関数が無い。
- **決めるべきこと**（kind ごとに意味が違う）：
  1. **絵系（template/slot/text/shape）**＝時間を2つに切るだけ。ただし**キーフレームはクリップ相対秒**なので、**後半の点は再基準化**（時刻から分割位置を引く）し、**分割点の補間値を両半の端に焼く**（切った瞬間に絵が変わらない＝「前後で絵が変わらない」のバラすと同じ検査方法が使える）。
  2. **音（audio）**＝後半の `sourceStartSec` を進める（`speed` を掛けた素材時間で）。フェードは**前半に入り・後半に出しを残す**（分割点に新しいフェードを作らない）。音量点はキーフレームと同じ再基準化。
  3. **読み上げ（voice）**＝**α-5 では分割対象外を推奨**。作成済み音声と文が1対1で、切った後半の「文」が決められない（音声だけ切ると文と音がずれる＝ADR-0026①違反の芽）。断るときは理由を出す（「読み上げは切れません。文を分けて2つ置いてください」）。
  4. **連動字幕**＝読み上げに追従しているので単独では切らない（3 と同じ理由）。
- **操作**：再生位置×選択中の帯。選択が無いときは何もしない（全列一括のブレード分割は入れない＝初心者の誤爆が多い）。キーは `Ctrl+K`（他社標準）か `S`（nizima）＝ADR で決める。
- 紐づく先：#686（#333 統合後）。**論点8**。

### H. 隙間の管理（マグネティック不採用の帰結）

- 元資料の「マグネティックは採らない」は**支持**。ただし不採用の帰結として「**消したら隙間が残る**」に答えが要る（他社は ripple delete で解く）。
- **推奨**：α-5 は**吸着（隣の端に吸い付く）＋手動移動で様子見**。「間を詰める」コマンド（列単位/全体）は α-6 候補として温存。**押しのけ（ripple 移動）は入れない**（V24 の「置けない」規則と喧嘩する）。→ 論点12。

### I. クリップの見た目・情報密度（#332 と分担）

- **現状**：色は映像/音の2色（種別色 `--telop`/`--bgm` は CSS 定義済み未使用）。中身はラベル1行。ツールチップ無し。短い帯は `min-width:2px` で潰れる。
- **推奨**：**種別ごとの色分け＋小さなアイコン**（見た目パターン/写真/文字/図形/字幕/音/読み上げ）・`title` ツールチップ（名前と時間帯）・**短い帯でも掴める最小幅**（当たり判定だけ広げる）。波形・サムネ列は #332 の担当のまま。
- 紐づく先：#686 or #687（軽いので早く出す価値あり）。

### J. インスペクタ（#687 の追補）

- **現状**：§2.2-7〜11 のとおり（生 input・1文字1履歴・下書き残り・確認の不揃い・理由の表示位置）。
- **推奨**（#687 のアコーディオン・折り返しに追加して）：
  1. **数値欄を `NumberField` に統一**し、**確定（blur/Enter）で1履歴**にする。
  2. **選択切り替えで下書き state をクリア**する。
  3. **「消す」は確認なしのまま統一し、Undo を頼りにする**（トースト「消しました。元に戻すで戻せます」）。列削除（巻き添えが多い）とバラす（戻せない）だけ確認を残す＝**「確認は取り返しのつかなさに比例」**という規準を明文化（→ 論点15）。
  4. `editBlocked` の理由は**操作した欄の近く**に出す（列メニューの `disabledHint` の流儀に合わせて統一）。
  5. **開始秒・長さの数値入力**を最上段の節に足す（B のドラッグと同値を触るハイブリッド＝元資料 §5-4）。
- 紐づく先：#687（1・2・4 は #687 実装時に必ず）。

### L. 素材の取り込み（#684 の追補＝行き止まりの解消）

- **現状**：完全新規のタイムライン文書は `assets: []` で、**この画面から素材を増やす手段がゼロ**。案内文は場面形式の素材画面を指しており行き止まり（§2.2-12）。

  3. 取り込み時の検証・コピー先は**焼き出しが使う `bakedFilePaths` の流儀**（素材はプロジェクト内へコピー＝ADR-0024 (6) 自己完結）と揃える。

### M. 空の状態・導入（新規タイムラインの最初の1分）

## 6. ADR-0034 論点の追補（元資料 §6 の7論点に足すもの）

元資料の論点1〜7 は維持。以下を追加：

8. **分割の意味論**＝kind 別の可否（voice/連動字幕は断るか）・キーフレーム再基準化・フェードの分配・キー割り当て（§5-G）。
9. **キャンバスの重ね順操作の翻訳**＝zIndex 無し（列の並びだけ）の世界で「前へ/奥へ」を出すか・出すならどう言うか（§5-E-5）。
10. **選択モデルの一本化**＝キャンバス⇄帯⇄欄の同期・複数選択でできること・解除の作法（§5-A）。
11. **ドロップで列を自動で足すか**＝最上段の上・列の間に落としたとき（`TIMELINE_EDIT_OVERLAP` の文言「列を足して重ねてください」をドラッグでも実現する形）。
12. **隙間の管理**＝「間を詰める」を持つか・いつか（§5-H）。
13. **矢印キーの文脈分岐**＝フレーム送り／ナッジ／（帯の時間移動は割り当てない案）（§5-K）。
14. **ズーム状態の持ち方**＝覚えない（開くたび全体表示）案の採否（§5-C-6・既存論点4の決着）。
15. **確認と Undo の規準**＝「確認は取り返しのつかなさに比例」の明文化（消す=確認なし+Undo／列削除=件数つき確認／バラす=確認・§5-J-3）。
16. **テンプレの中を触る方式**＝(a) 幾何上書き／(b) 自動バラし／(c) ドリルイン＋明示バラし（§5-F・既存論点2の決着。**利用者確認が要る**）。
17. **語彙**＝§3（用語置き換え）に無い言葉を決める：スナップ→「吸い付く」？ 分割→「切る」？ ズーム→「拡大/縮小」「全体を表示」？ ドラッグ&ドロップの案内語。**画面に出す言葉を ADR で確定してから実装**（§2-3 違反を後から拾わない）。
18. **共有部品の修繕と場面形式凍結の線引き**＝`FreeLayoutOverlay` へ Esc 中止・Ctrl 吸着解除を足すのは「凍結（FREE の拡張）」か「継続（共通核の修繕）」か（§5-E-3）。

## 7. 実装上の落とし穴（実装AIへの申し送り・事実ベース）

1. **HTML5 Drag and Drop は使わない**。WebView では `<button>` 上の `dragstart` が発火しない既知問題があり（過去の並び替え実装で確認済み）、帯は現に `<button>`。**Pointer Events（`setPointerCapture`）で作り、実操作の統合テストを書く**こと。OS からのファイルドロップだけは Tauri の file-drop イベント（別経路）。
2. **ドラッグ＝1履歴**。`timelineStore` に履歴グルーピングの口が**無い**（`useHistoryGroup` は場面形式専用）。推奨は**グルーピング機構を足すのではなく、「ドラッグ中はローカル state だけ動かし、`pointerup` で1回 `commit`」**＝機構が不要になり、自動保存（800ms デバウンス）とも自然に噛み合う。ドラッグ中のプレビュー更新はローカル値で `layoutTimelineAt` を呼ぶ（rAF スロットル）。
3. **既存の「1文字＝1履歴」も同根**（§2.2-7）。#687 で `NumberField`＋確定時 commit へ寄せる。
4. **編集で再生が止まる**（決定21・`timelineStore.ts:840`）＝**ドラッグ開始時に止める**（`pointerup` の commit 時では、再生しながら掴めてしまう）。**書き出し中はドラッグ開始自体を断る**（`blockedByExport` と同じ入口で）。
5. **V24 その他の検証は必ず domain の同一関数**（`isFreeSpan`/`validateTimelineDoc` から export 済みの判定）を UI 側のゴースト表示でも使う＝「置けそうに見えたのに置けない」を作らない（パリティの流儀＝preview と export の関係と同じ）。**連動字幕の同時移動も既存 `moveClip`/`trimClip` を通す**（§5-B-8）。
6. **`Space`・矢印などのグローバルキーは、入力欄フォーカス中と IME 変換中（`isComposing`/`keyCode 229`）は奪わない**。判定は `useUndoRedoShortcuts.ts:64-72` の流儀を共有関数に切り出して使い回す。
7. **ズーム可変化の性能**：`pxPerSec` を上げると 5分動画でレーン幅が数万 px になり得る。帯の DOM 数は当面問題にならない見込みだが、**ルーラー目盛りは可視範囲だけ描く**こと。
8. **`assetSizes` の実測 `useEffect`（`TimelineProjectScreen.tsx:299-315`）は全素材を毎回走査**している。素材欄（#684）で素材が増えると効くので、取り込み時に1回測ってキャッシュへ。
9. **半分できているものから繋ぐ**：`.timeline-clip-handle` 等の CSS・`applyClipEdge`・`.timeline-playhead`・`.timeline-ruler--seekable`・`clearSelection` は**既にある**。新造の前にこれらを配線する（残骸のまま増やさない）。
10. **段階の出し方**：#687（折り返し・アコーディオン・NumberField）と §5-I（色分け・ツールチップ）は他と独立で軽い。**最初に出して実機の見通しを良くしてから B〜E に入る**のが安全（#687 自身も「先に出せる」と書いている）。

## 8. 優先順位の提案（「3手順が案内なしで通る」を完了条件に）

初心者の最短路（元資料 §4）＝**①並べる → ②長さを詰める → ③文字と音を足す**。

| 順 | 作業 | 3手順との対応 |
|---|---|---|
| 0 | 選択モデルの一本化（§5-A）＋ #687＋帯の見た目（§5-I） | 土台。軽くて独立 |
| 1 | #684 置ける（**取り込み含む**・**置いた部品の中身編集含む**＝§2.2-1） | ①と③の入口 |
| 2 | #686 のうち **ドラッグ移動・端トリム・ルーラーシーク＋再生ヘッド・ズーム** | ①② |
| 3 | #685 キャンバス直接操作＋数値欄 | ③の仕上げ |
| 4 | #686 の残り（吸着・分割・列またぎ） | 質の向上 |

- 吸着と分割を後ろに回すのは、**無くても3手順は通る**ため（ドラッグと数値欄が先）。
- 各段階で `/canon-check`。**語彙（論点17）を ADR-0034 で先に確定**しないと、段階1 の文言から手戻りする。

### 実装側から足す5点（ADR-0034 の材料）

1. **削除の確認は `06 §2` の統一規約と突き合わせる**。§5-J-3 の「消す＝確認なし＋Undo」は、統一規約1
   （「編集キャンバス上の単体要素は即時＋取り消し／複数まとめて消すときだけ確認」）と**整合する**が、
   ADR-0034 で**その条項を引いて**決めること（新しい規準を並立させない）。
2. **ドラッグ中の「置けない」の見せ方は、直近の決定と噛み合わせる**。操作したその場の返事は
   **欄のすぐ下に貼り付けて常に見える**ようにしたばかり（PR #682）。ドラッグ**中**はゴーストの色で示し、
   **離したときだけ**その場所へ理由を出す、が自然（ドラッグのたびに文言が明滅しない）。
3. **「覚える/覚えない」の規準を明文化する**。ADR-0033 は「配置は画面ごとに覚える」。監査の
   「ズームは覚えない」（§5-C-6）と合わせて、**文書の中身に依存する状態は覚えない／画面の好みは覚える**
   という線を ADR-0034 に書くと、次に迷わない。
4. **キーボードだけで到達できるか**を論点に足す。ADR-0033 の未解決4（キーボードだけの配置操作）と同根で、
   **ドラッグでしかできない操作を作らない**（置く・動かす・分割・列またぎに、それぞれキーかメニューの道を用意）。
5. **帯のドラッグは ADR-0033 段階3 の実装をそのまま流用できる**。Pointer Events・しきい値・`Escape` 中止・
   `pointercancel`・アンマウント時の後始末・**掴んだ指だけを見る**（`pointerId`）は `PanelLayoutView` に既にある。
   §7-1（HTML5 DnD を使わない）は**実績として裏付け済み**＝新造せず、この規則を共有すること。
