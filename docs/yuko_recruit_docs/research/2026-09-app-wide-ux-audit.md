- **日付**: 2026-09-03
- **位置づけ**: **調査資料**（決定ではない）。利用者要望「利便性・自由度・初心者へのやさしさ（文章の注釈でなく配置・直感で伝わるか）を α 完了までに決着させたい／有名ツールを参考にしてよい」に応える総合レビュー。**別セッションの UX レビュー（[`#997`](https://github.com/fujii-yuki-star/star-recruit-studio/issues/997) EPIC・2026-09-02）の後続**として、①全画面を実機で巡回 ②6観点（画面群1〜5＋横断）で並列レビュー ③**#997 系の既存起票と照合し、重複を排した"純粋な追加分"だけ**を残す。

## 0. 結論（先に要点）

1. **主フローは最後まで通る**。ホーム→ウィザード（5段）→AI送信確認→生成→たたき台→場面編集→仕上がり確認→公開前チェック→書き出し、を実機で通過。空状態・失敗状態にも「次の行動」があり、削除確認・押せない理由の事前提示・取り消しの見える化（`EditorToolbar`）は**型どおり徹底**されている。**基盤の作法は良い。**
2. **ただし利用者の懸念「文章の注釈で補っている」はコードでも裏付けられた**。説明文の実数は SceneEdit 103・Timeline 90・Home 35 が突出（横断 §表1）。中でも**選ぶものが「名前の `<select>`」でサムネが無い**（差し込み口・見た目パターン・素材）と、**「置く」導線が名前とボタンだけでドロップ領域が無い**の2つが、有名ツールが軒並み採る「サムネで選ぶ／落として置く」型からの最大の差分。
3. **#997 系が既に相当をカバーしている**。私の指摘の約6割は #989/#991/#995/#1023/#1026 と重複。**本資料は残り約4割＝#997 系に無い追加分（§2）に絞る**。
4. **追加分の背骨は1つ**＝「**見て選ぶ・落として置く**」への転換（サムネ化・ドロップ領域・タブ集約）。これは新機能でなく**既存部品（`ScenePreview`/`ColorPicker`/`FontPicker`/`PickerList`）の再配置**で大半が成立し、場面形式の凍結（＝操作性・配置は「続ける」側）にも抵触しない。

## 2. 追加分（#997 系に無い・本資料の本体）

> 重大度は #997 の慣習（🔴 ブロッカー／🟡 直すべき／ℹ️ 軽微）。すべて **file:line＋H番号＋有名ツールの型** つき。凍結との関係を各項に明記。

### A. 「見て選ぶ」への転換（最重要・横串）

- **[🔴] 場面編集：素材差し替えに"見える入口"が無い**（`SceneEditScreen.tsx:1595-1610`）— H1/H5/H9。左欄「素材一覧」のタイルは**表示専用**（onClick も draggable も無い・サムネは種別アイコンのみ）。AI 生成動画の直しで最頻の「この場面の写真を差し替える」に、開いた瞬間の画面から使える入口が無く、右欄の畳まれた「使用素材」を開いて**名前の `<select>`** で探す文章依存の経路しか無い。左欄1面が「押しても何も起きない」で埋まる。**#997 系はタイムライン側のドロップ（#1026）は挙げるが、場面編集の素材タイルの死活は挙げていない。** → タイルをクリック=空き差し込み口へ／プレビューへドラッグ、タイルに実画像サムネ、「使用素材」は空き口があれば既定で開く。**凍結＝操作性の改善で「続ける」側。**

- **[🟡] 選ぶものが軒並み「名前の `<select>`」でサムネが無い** — H2/H9。差し込み口の素材（`SceneEditScreen.tsx:2125-2141`）・見た目パターン（`:1989-2013`）・場面カードのサムネ（`:1802` は `PhotoIcon` 固定）・見た目パターン一覧（`LooksScreen.tsx:259-275` は名前＋カテゴリ文字だけ）。**見た目で選ぶものを名前で当てさせる＝試し打ち**になる。Canva/CapCut は全てサムネ格子。**既に `ColorPicker`/`FontPicker` は候補を実物で見せている**のに、素材・見た目だけ名前。→ `ScenePreview`（=`layoutScene` の縮小静止画・描画核は書き出しと同じで不変）をカード/選択肢に出す。**パリティ注意＝`layoutScene` 以外で描かない。**

- **[🟡] タイムライン「置く」欄が4分割で各欄が小さくスクロール必須**（`TimelineProjectScreen.tsx:653-664`＋`panelLayout.ts:84`）— H1/H9。左 0.28 幅を4欄で等分＝1欄の中身高さが 70〜80px 程度で、3手順①の入口（素材一覧・見た目一覧）が既定配置で視界に入らない。**#1026 はドロップを挙げるが、4分割そのものは挙げていない。** ADR-0033 は「再生位置と選んだ部品が同時に見える」だけを既定と決めており、4分割は #684 の実装判断（ADR で保護されていない）。型（CapCut/Canva/YMM4）は**「置く」は1欄＋タブ**。→ 1欄「置く」にタブ（素材／文字・図形／見た目/音/読み上げ）。案内文・「置く列」select も1つに畳める。

### B. 認知負荷（progressive disclosure の穴・#997 系が触れていない画面）

- **[🟡] 設定画面：上級項目が最上段・常時展開**（`SettingsScreen.tsx:139-234`）— H3。接続キー・モデル名の自由入力・音声ソフトの接続先 URL が先頭で開きっぱなし。「通常は変更不要です」「通常は空のままで大丈夫です」と**文で読み飛ばしを頼む**。畳む作法（`<details>`）は同ファイル `:420` に既にある。→ モデル/接続先URLを「上級者向け」`<details>`へ、既定値は placeholder に出す。

- **[🟡] 設定画面：アプリ全体の設定と"この動画"の設定が同カードに混在**（`SettingsScreen.tsx:237-386`）— H2/H3/F。接続先・キャラクター（`appSettings`＝全動画）と、速さ・高さ・抑揚（`meta.voiceSettings`＝今の動画だけ）が混じり、区別は `:363` の一文だけ。**キャラクターを変えると全動画に効く**のに読まないと分からない。→「この動画の声／アプリの声の設定」に分けるか範囲バッジ。

- **[🟡] 場面編集「見た目・フォント」節の中身が見出しと合わない**（`SceneEditScreen.tsx:1968-2108`）— H2/H3。節名は「見た目・フォント」なのに中に**この場面のBGM**（`:2068`）と**動画全体フォント**（`:2044`・触ると全場面が変わる）がある。→ BGM は独立節へ、動画全体フォントは見出しで区別。

- **[🟡] 自由配置の要素カードだけ畳みが無い**（`SceneEditScreen.tsx:2425-2509`）— H3/H4。通常場面の体裁は既定で畳む（`:958`）のに、同じ画面の自由配置は文字12項目がフラット全展開。開閉の規準が同一画面内で割れている。→「体裁の詳細」「位置と大きさ」「動き」を `CollapsibleSection` で。同じ穴が Timeline 側 `:3666-3682`（文字部品12項目初期展開）にもある＝両形式で共有の課題。

### C. 「選んだものを最初に見せる」配置（ADR-0033 の意図と逆）

- **[🟡] 場面編集：選択中カードが欄の"後ろ"に出る**（`SceneEditScreen.tsx:2169-2422`）— H1。ヒント文→追加ボタン→パーツ→トグル→重ね順一覧（要素数で伸びる）→…の**後**に選択中の設定。ADR-0033 の「選んだ部品を同時に見られる」の逆で、キャンバスで選ぶたびスクロール（実測：要素5で節だけ3492px）。→ 選択中カードを節の先頭へ。

- **[🟡] タイムライン：書き出しがトランスポートに混在**（`TimelineProjectScreen.tsx:3024-3060`）— H1/H9。「再生」（primary）と「動画を書き出す」（primary）が同じ行＝主ボタン2つ隣接。型（CapCut/Canva/Premiere）は書き出しは画面右上固定、プレイヤー直下はトランスポートだけ。→ 書き出し・中止・進捗を `PageHead` の actions（保存状態の隣＝視線内）へ。同種の「primary 2つ隣接」が場面編集トップバー（`:3005/3014` 保存/仕上がり確認へ）にもある。

- **[ℹ️] 欄を戻す・注意バッジがタイムライン器（76vh）の下＝視界外**（`TimelineProjectScreen.tsx:4919-4927/4888-4917`）— H5/H6。「⋮→閉じる」は視界内なのに戻す道は視界外。恒常警告も件数の文だけで該当部品へ跳べない（error-state と重なる）。→ `PageHead` に「欄」メニューと「注意 N件」バッジ（押すと該当部品を選択）。

### D. 出口・仕上げ（画面群3で新規／#992 と別レイヤー）

- **[🟡] 仕上がり確認：Space で再生できない**（`PreviewScreen.tsx:533-563`）— A⑩/D。「見る」画面なのに keydown ハンドラが1つも無い。#989 はタイムライン/場面のキーだが、Preview は対象外。→ Space で再生⇄停止（入力欄/IME 除外）、title にキー併記。

- **[🟡] 公開前チェック：主流れの中で「戻る」だけ場面編集へ飛ぶ**（`PrecheckScreen.tsx:239-242`）— H1/F。仕上がり確認→公開前チェック→書き出しの流れで、Export の戻るは「公開前チェックへ戻る」なのに、ここだけ `scene-edit`。仕上がり確認の主ボタンから来た人が別画面に着く。→ 「仕上がり確認へ戻る」か returnTo 方式。

- **[🟡] 書き出し失敗の通知に行動ボタンが無い**（`ExportScreen.tsx:684-688`）— H6。他画面向け `ExportResultNotice` は「書き出しの画面へ」を持つのに、書き出し画面自身の失敗表示は文だけ。→ 失敗通知内に「公開前チェックを開く」「もう一度書き出す」。

- **[🟡] 見わたすタイムライン（TimelineScreen）の読み取り専用が伝わらない**（`TimelineScreen.tsx:35-38`）— H2/G。「見るだけ」を desc の一文だけで伝え、タイトルは「タイムライン」、TimelineView に錠/バッジが無い＝帯を掴もうとして空振り。→ タイトル「タイムラインを見わたす」、カードに「見るだけ」バッジ、変換パネルを主導線に。

- **[ℹ️] 生成中の進捗が見せかけ**（`GeneratingScreen.tsx:27-34`）— H6/H9。180ms ごと+6 で約2.5秒で90%到達し、実待ち時間の大半を「90%停止」で過ごす。「100%で止まる」を「90%で止まる」に移しただけ。→ 実段階が取れないなら不定バー＋経過時間で切り替わる状態語（「構成を考えています」…）。

### E. 見た目パターン一覧・編集（画面群4で新規）

- **[🟡] 見た目パターン一覧にサムネ・絞り込み・向き表示が無い**（`LooksScreen.tsx:259-275`）— H4/H9。名前＋カテゴリ文字だけ。標準18種＋向き混在で、素材画面は種類タブ＋検索＋サムネなのに一覧の作法が割れる。→ カードに見本、カテゴリ/向きのセグメント、5件超で検索。※実機確認済み：一覧は文字カードで、複製元を選ぶのも文字から。

- **[🟡] 「複製して自分の見た目を作る」が secondary で埋もれる**（`LooksScreen.tsx:245-247 vs 316-326`）— H5。主ボタンは「ゼロから作る」（空キャンバス=難路）、初心者の常道「複製して作る」は4本目の区切り線の下＋「標準（編集するには複製します）」というバッジ文章頼み。→ 見本直下に「この見た目をもとに作る」を primary。※実機確認済み：複製導線は右パネル下部で発見に手間。

- **[🟡] 新規見た目の向きが常に横型固定**（`LooksScreen.tsx:78`）— G/H1。動画の `aspectRatio` を取得済み（`:58`）なのに既定に使わず、縦型の人は注意文を読んで直さないと横型の見た目ができる（後から変えられない）。→ 既定を `aspectRatio` から導く。

### F. ブランドキット等の入口（画面群4で新規）

- **[🟡] 「いつものロゴ・色・フォント」の設定入口が設定画面の奥だけ**（`SettingsScreen.tsx:134`＋素材/見た目画面に入口無し）— H5。ロゴは素材、色・フォントは見た目、で触るのに、設定画面4番目の `BrandKitSection` にしか入口が無く、説明も「AI やナレーターの声など」だけ。→ 素材画面/見た目画面に「会社の見た目を決める」リンク。

## 3. 「文章依存」を減らす3つの型（有名ツール比較・横断 §より）

利用者の懸念に直接答える「うちだけ文章で伝えている代表例」と置換案：

1. **切り替え（トランジション）**＝`<select>`＋「※上の『切り替えを見る』で確認できます」（`SceneEditScreen.tsx:2913-2930`・※3件中2件）。Canva/CapCut/iMovie は効果をサムネで動かして見せる → 効果を絵つきタイルにし選択で `TransitionPreview` を自動再生。
2. **吸着とその解除**＝「Ctrl を押しながら動かすと吸着しません」（`TimelineProjectScreen.tsx:3208-3210`）。CapCut/Premiere は磁石トグル → ツールバーに吸着 `Switch`＋スナップ線（#1026/#991 の周辺だが磁石トグルは未提案）。
3. **置き場所の説明**＝「再生位置から置きます。塞がっているときは次に空いている時刻へ…」（`TimelineProjectScreen.tsx:4538`。**冒頭の「再生位置（…秒）から置きます。」は4欄で共通**〔:4538・:4605・:4642・:4683〕で、後半は欄ごとに違う＝PR #1029 レビュー 🟡）。他社は再生ヘッドにゴースト → 「置く」ボタンのホバーで列上に半透明の帯。

いずれも**新機能でなく既存の描画・部品の再配置**。①③はタブ化（§2-A-3）と同時に案内文がまとめて消える。

## 4. 実機で確認できたこと（記録）

- 全16画面をコンソールエラーなしで通過。ウィザードは既定値のまま「次へ」連打で1本完成（H8 良好）。**ただしステップ⑤「準備ができました」→確認画面「この内容で作ります」は入力の無い"押すだけ"画面が2連続**（#995 と重なるが、⑤廃止＋④の次へを確認へ直行、が具体案）。

- 見た目パターン「複製して編集」→編集画面まで到達。**複製の入口が右パネル下部で、初回は探す**（§2-E）。

## 5. 実装セッションへの引き継ぎ

- **本資料の §2 だけが新規**（§1 は #997 系で起票済み・§3 は §2 の補強）。#997 EPIC の配下に「アプリ全体 UX の追加分（サムネ化・progressive disclosure・配置）」として束ねるのが素直。
- **背骨は「見て選ぶ・落として置く」**＝ §2-A（🔴1＋🟡2）を先頭に。`ScenePreview`/`layoutScene` のサムネ化はパリティ注意（描画核を分けない）。
- **凍結との関係**＝すべて「操作性・配置・文言」の改善で、場面形式凍結の「続ける」側（ADR-0032）。Scene への新フィールド・新編集能力の追加は含まない。
- α 完了の位置づけ＝利用者は「α で機能・UI/UX をほぼ決着」を望む。§2-A の🔴（場面編集の素材入口）は**AI生成動画を直す主戦場の死活**なので、α 内で対応する価値が高い。残る🟡は #997 の実施順に混ぜて判断。
