### [🔴] `src/app/screens/TimelineProjectScreen.tsx:819` — resilience — ドリルインの欄が消えると `Escape` の名乗りが返らず、その画面のキー操作が全滅する

**CONFIRMED**（検証者が React 19.1 / jsdom の実スタックで実測＝unmount 時の `onBlur` 呼び出し **0回**）。

#832 が新設した `drilledFieldFocused` は欄の `onBlur`（`:3863` / `:3938`）でしか `false` に戻らない。**フォーカス中の欄が消えると `blur` は来ない**ため、`useEscapeOwner(drilledFieldFocused)`（`:820`）の名乗りが返らず `hasEscapeOwner()` が真のまま固着する。画面の window キーハンドラは `:713`・`:720` で早期 return するので、**`Escape` / `Ctrl+A` / `Ctrl+K`（分ける）/ `Space`（再生）/ `Delete` / 矢印が無言で全部死ぬ**（`Ctrl+Z`・`Ctrl+Y` は別フックなので生き残る）。

**再現**（4手順すべて成立を確認）
1. 見た目パターンのクリップを列へ置く
2. キャンバスで差し込み口を二度押し（ドリルイン → `:3859` の `<select data-slot-field>` へ自動フォーカス）
3. そのまま `Ctrl+Z`（`<select>` は `isTextEntryTarget` に当たらないので届く）
4. `restore` が消えたクリップを選択から落とす → `selected` が `undefined` になりパネルごと unmount → 以後キー操作が全滅

**範囲の補正**（検証で判明）
- **画面を離れると直る**（`TimelineProjectScreen` の unmount で `useEscapeOwner` の cleanup が走る）＝固着はその画面滞在中に限定。他画面へは波及しない。
- ただし**復帰口が無い**：取り消し直後は選択が空でドリルインの欄が存在しないため、**見た目パターンのクリップを置き直して選び直すまで**戻らない。

**修正の方向**：選択が変わる効果（`:611`〜`:633`）で `setDrilledFieldFocused(false)` も落とす。⚠️ **その効果は既にこの穴のために在る**＝`:619` のコメントが「文字欄はフォーカス中に消えると `blur` が来ない…欄が入れ替わるここで必ず畳む」（#708）と明記し、`kfDraft`／`volumeDraft`／`lockedSkipNotice`／`drillBlockedNotice` を片づけている。#832 の新 state だけがその designated cleanup point に載っていない。

### ② [🟡→REFUTED] ドリルインの `Escape` が IME 変換中を見ていない（ux-model）
- 出荷先は **Windows / WebView2（Chromium）単独**（`tauri.conf.json:44` の `targets: ["msi"]`）。この経路では IME が食べたキーは **`VK_PROCESSKEY`（229）に差し替わり `key === "Process"`** になる（Chromium CL 109533002＝「IME に食べられた**あらゆる**キー」・TSF モードでも同様）。変換中の `Escape` は MS-IME が確実に食べるので、`if (e.key === "Escape")` は**変換中に一度も真にならない**＝`blur()` は走らない。
- 「同型」の前提が誤り。`FreeLayoutOverlay.tsx:865` の guard は `fix(review): PR#184 IME変換確定の **Enter** でインライン編集が抜けるバグ修正` で入ったもので、Escape は同じ early-return に**巻き込まれた**だけ。あちらは Enter に意味を割り当てた `<textarea>`、こちらは Enter を扱わない単行 `<input>`。
- リポジトリの流儀は**逆で一貫**＝`HomeScreen.tsx:399-403` は同じ `onKeyDown` 内で **Enter だけ** `isComposing` で守り Escape は守らない（しかも `blur()` より重い「下書きを捨てる」）。`GroupList.tsx:83`・`SceneEditScreen.tsx:1923` も無ガード。**#832 が持ち込んだ差ではない。**
- 仮に発火しても「打ちかけが飛ぶ」は不正確（制御コンポーネントで composition update ごとに store へ入る／Chromium は blur 時に composition を**確定**する）。

### ③ [🟡→REFUTED] 「再生位置」の欄が再生中に止まらないのは ADR-0026② 違反（ux-model）
- 機構的な前提（`disabled` 無し・制御コンポーネント・`_advancePlayhead` が毎フレーム書く）は**すべて事実**だが、**症状が起きない**。range のネイティブドラッグは `pointermove` ごとに**指の位置から値を導き直す**ので線は指に追いてくる。「離すと再生位置が勝つ」も誤り（最後のシークが `seekNonce` で時計に反映され、そこから再生が続く）。
- 「往復」は `step=0.1` と `playbackTick` の `floor(t*30)/30` 量子化に吸収され、**指が動いている限り見えない**（ずれるのは指を約67ms以上止めたときだけ＝上記 ℹ️6）。
- **正典がこの欄を「止める」対象に含めていない**。ADR-0032 決定21 追補は対象を**目盛りのシークに限定**し、キーのシークは止めない（`11 §7.6.2.1`＝再生継続シークが前提）・帯は理由が別、と明示的に線を引く。`06 §12.1` はこの欄を `followPlayhead` の一族（止めない側）にだけ挙げている。
- **「止めない」は回帰テストで固定済み**（`TimelineProjectScreen.test.tsx:270-279`「再生中に位置を動かしても戻らない（時計を測り直す）」がまさにこの欄）。
