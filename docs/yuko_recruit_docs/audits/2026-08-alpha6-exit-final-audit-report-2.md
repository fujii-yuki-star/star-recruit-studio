## 🔴（いずれも修正済み・実コードで再現筋を確認）

### 1. 立ち絵に入れた動画がプレビューに配線されていない（parity）

`TimelineProjectScreen` は当てるアイテムを `role === "slot"` で絞っており、立ち絵のアイテムは
`layoutScene` が `role:'character'` で作るので**必ず一致しない**。置き場所ごと落ちるので、
**プレビューは代表フレームで静止・元の音も無音**なのに、**書き出しは実映像＋元の音**になる（ADR-0001 の破れ）。
穴あけ（`videoSceneSplit`）も同じ絞り込みだった。元の音の欄も差し込み口だけに絞っており、
**書き出しにだけ効く設定**になっていた。

→ 「どの置き場所のアイテムか」は `isItemOfPlacement` 1本に委ね、役割で絞らない。

### 2. 取り消しで戻る場面が指す素材を「未使用」と数え、実体ごと消す（resilience）

`unusedAssetIds` は**いま生きている場面だけ**を見る。場面を消す・写真を外すはどちらも取り消せるのに、
その直後に「まとめて消す」を押すと `assets` から外れ、**ファイルも削除される**（`assets` は履歴の外＝ADR-0020）。
取り消すと場面は戻るが素材は戻らず、死んだ参照と灰色の枠だけが残る（取り込み直しても番号が変わる）。
読み上げ音声の剪定（`_doSave`）は**同じ理由で** `past`/`future` を数えている＝素材だけ規則が違った。

→ 履歴スナップショットの場面も「指されている」に数える。

### 実アプリの動かし方（次回のため）

1. `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222` を付けて
   `src-tauri/target/debug/star-recruit-studio.exe` を起動する（開発サーバは別に立てておく）。
2. `http://127.0.0.1:9222/json/list` で画面を見つけ、`Runtime.evaluate` で操作する。
   `__TAURI_INTERNALS__` が居るので**本物のコマンドがすべて呼べる**。

⚠️ **限界（ここは越えられなかった）**

- **ネイティブの「開く／保存」は自動で答えられない**＝`__TAURI_INTERNALS__.invoke` は
  **`writable:false, configurable:false`**（外側の `window.__TAURI_INTERNALS__` も同じ）で差し替えられない。
  `Page.addScriptToEvaluateOnNewDocument` も WebView2 では効かず、`DOM.setFileInputFiles` も入らなかった。
  よって**書き出し**（保存先を聞く）と**ファイルの取り込み**は自動化できない。
  素材は**ディスク上に用意して開く**ことで代替した。
  ⚠️ **逃げ道は検討したうえで見送った**（PR #944 レビュー）＝Rust の `export_video` は
  `output_path: Option<String>` で**保存先を省略できる**が、**先に聞くのは画面側**
  （`ExportScreen.tsx:190` で `showSaveVideoDialog` → `null` なら何もせず戻る）なので、
  ここを飛ばすには `export_video` を**直接呼ぶ**しかない。それは**画面が組み立てたコマ（`SceneInput`）を
  使わない**＝項目3・11 が確かめたい「画面の描画から書き出しまで」が抜け落ちるので、
  **確かめたことにならない**。よって「自動化できない」のまま残す（Rust だけの検査に格下げしない）。
- **同梱の VOICEVOX（`run.exe`）はアプリを強制終了しても生き残り、次の `cargo build` を
  ファイルロックで失敗させる**（`os error 32`）。ビルド前に `run.exe` も落とすこと。
- 画面を操作するときは**必ず節の中だけを探して押す**。文書全体からボタンを文字で探すと、
  別の確認（例：接続キーの削除）に触れうる。
