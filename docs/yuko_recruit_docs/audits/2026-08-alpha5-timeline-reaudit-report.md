## この再監査で分かったこと（要点）

**指摘の大半が「前回の修正が持ち込んだもの」**だった。個々の実装ミスというより、**直し方の型**に
共通の弱さがある。

1. **片側だけ直す**（🔴 canon-schema）＝#815 は「#512 の到達点を1つに揃える」と言いながら
   `CLAUDE.md` の ADR-0032 行しか直さず、同じファイルの ADR-0019 行と `adr/0019` が旧到達点のまま。
   **#815 が消したはずの「正典が自分自身と矛盾」が、別の場所で生き残った。**
2. **穴を塞ぐと反対側へ倒れる**（🔴 resilience）＝#817 は「まとめが開いたまま取り消すと積まれない」を
   直したが、場面形式には世代を入れなかったため、今度は**1ドラッグで上限50を流し切る**（積み過ぎ）。
3. **出口まで追わずに案内を足す**（🟡 error-state ×3）＝TODO の条件が満たされたから足した／変種を
   用意したが、**その行動が本当にできるか**を画面で確かめていない（#812 と同型が3件）。
4. **テストが境界を突いていない**（🟡 correctness・🟡 ux-model）＝門の `>=` を `>` にしても緑、
   中止の印を時間で消しても緑（テストが同期で `click` を撃つため）。**変異チェックの当て先が甘い**。

## 指摘（重大度順）

### 🔴

1. **`CLAUDE.md:160` と `adr/0019:109` が #512 の旧到達点のまま**（canon-schema）
   実物確認＝#512 は **CLOSED**・#809（立ち絵の動画・α-6）は **OPEN**。それでも「**別起票しない**」
   「段階的に land 中」「閉じるかは利用者判断」と書いてある。ADR-0032 側（今回追記）と正面から矛盾。
2. **場面形式の履歴が1ドラッグで上限を流し切る**（resilience）
   #817 で `undo`/`redo` の畳みを入れたが、**畳んだことを持ち主へ伝える手段（世代）が場面形式に無い**。
   到達＝場面編集のスライダーを**掴んだまま `Ctrl+Z`**（`range` は入力欄扱いでも掴み中扱いでもない）→
   そのまま動かすと `pushHistory` が毎tick記録し、最大100件で上限50を流し切る。
   **畳む前は「積まれない」・畳んだ後は「積み過ぎ」**＝この差分が持ち込んだ退行。

### 🟡（11件）

- **correctness**: 分割の門の境界（`advanced >= limit`）がテストで固定されていない
  （`>` へ変えても緑＝**実測で SURVIVED を確認済み**）。実害＝**使い切るちょうど**の位置で分けると
  反転レンジが復活し、切り捨てたはずの先が流れ出す（#816 で直した退行そのもの）。
- **error-state**: ①音量の点の断りに足した「部品を分けてください」が**読み上げでは実行できない**
  （voice は分割そのものが断られる）②背景の動画の断りが**立ち絵にも出る**が、画面に立ち絵を触る欄が
  無く完全な行き止まり ③`lockedTrackMessage("duplicate")` が**production から呼ばれない**（複製時は
  "content" の文が出る＝同じ状況に3通り）
- **ux-model**: ①文字の層へ入ると `Escape` が効かない（正典は「どれでも抜ける」と書いた）
  ②同じ所へ入り直すと手が移らない ③当て先が畳まれた節・しまった欄・固定のときに**飲み込む**
  ④中止の印を `setTimeout(0)` で消すため、**実機では離した位置で上書きされる**（テストは同期で緑）
  ⑤再生中も掴める合図が出たまま＋`onClick` は生きている ⑥掴んで枠の外へ運んでも送りが無い
- **canon-schema**: `TIMELINE_TEMPLATE_NOT_FOUND` の文言が画面に手書き（**禁止語の検査の外**）＝
  同じ差分が `lockedTrackMessage` を新設した理由と矛盾

### ℹ️（7件）

`15` の注記の移設先が節をまたいだ／走査対象の記述が実装より狭い／`layerOps` の層種別が直書き／
分割の門の直接置き枝が実質デッドコードで誤読を招く／締めを返してから一時置き場を消す順／
見た目パターン編集の矢印タイマを画面離脱で片づけていない／「入れること」の発見手段が無い。
