## コンテキスト

統合タイムライン編集（ADR-0023）を「上位の仕上げ編集面」へ育てるにあたり、素材の扱いを整理する（利用者提案 2026-07-02）。

### 現状の事実
- `Asset.clip`（sourceStart/End・元音声・音量・速度）は存在するが**素材ごとに1つ**＝「同じMP4から複数範囲を別々に使う」は不可能。
- `scene.slotFits`（schema 1.13）が **per-use（場面×スロット）上書き**の先例。
- `timelineOverlay.clips`（`OverlayClip`・schema 1.15）は**使用単位モデルそのもの**（id・track・アンカー/絶対配置・区間）。現状 track は telop のみ。
- 素材解析は `AssetMetadata`（長さ/解像度/音声有無）＋サムネイル＋動画 probe が実装済み。波形・サムネイル列は無い。
- 書き出しは「場面ごとMP4（音声は場面内で完結）→結合→テロップ overlay→BGM amix」＝**グローバル音声レーンには後段 amix パスの新設が必要**（テロップ/BGM でパターン確立済み）。

## 判断軸

1. **場面正準・AI 親和性の維持**（ADR-0018/0007）：使用単位の導入が AI 生成・簡易編集の経路を一切壊さないこと。
2. **正典の単一参照と後方互換**（`§2-7`/`§5`）：既存 `Asset.clip` との関係が「null=継承」の流儀（`11 §6`）で一意に説明できること。
3. **段階出荷可能性**：一括の大改造でなく、使用箇所ごとの実装PR（schema マイナーバンプ＋無変換移行）で段階的に足せること。
4. **非破壊**：元素材ファイルを書き換え・分割しない（同じ素材の再利用と「やり直し」が常に利く）。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) 現状維持（`Asset.clip` のみ） | 実装ゼロだが「同じMP4から複数範囲」が構造的に不可能（clip が素材ごとに1つ）。統合タイムライン編集（ADR-0023）の上位仕上げ要件を満たせない。**不採用** |
| (B) 新規 `ClipInstance` モデル（タイムラインネイティブの使用単位を新設） | 自由度は最大だが、場面正準との**二重管理**・AI 経路との境界設計・schema 大改造が必要＝ADR-0018 選択肢(A)（時間軸ネイティブ化）で退けた方向へ近づく。**不採用**（利用者合意 2026-07-02） |
| **(C) 既存2系統に載せる（場面側 per-use 上書き＋`OverlayClip` 拡張）【採用】** | `slotFits`（1.13）の先例どおり正準安全・段階出荷可・AI 経路不変。使用単位が2系統に分かれる複雑さは「場面に紐づく使用（映像スロット）」と「タイムライン固有の使用（SE/テロップ等）」という**役割の違いそのもの**であり自然。per-use を独立コレクションに切り出す変種も、先例（場面に持つ）との一貫性・null=継承の説明しやすさで場面側保持が優る |
| (D) 物理分割（素材ファイルを切り出してコピー） | ディスク消費・元に戻せない・再編集不可・書き出し前処理の複雑化。**不採用**（分割ニーズは決定3「場面の分割」で非破壊に代替） |

## 決定（Proposed）

> **素材（Asset）は元ファイルの源泉として保持し、「どの範囲を・いつ・どこで使うか」は使用単位が非破壊に持つ。物理分割はしない。使用単位の担い手は新モデルを発明せず、既存の2系統に載せる。**

1. **場面側の使用単位＝per-use 上書き**：動画スロットの再生範囲等は `scene.slotFits` と同型の**場面×スロットの上書き**（例 `scene.slotClips`・**schema は実装PRで確定**＝マイナーバンプ＋無変換移行）。これにより同じMP4を場面ごとに別範囲で使える。`Asset.clip` は既定値として残る（未上書き時に継承＝null=継承の流儀 `11 §6`）。
2. **タイムライン側の使用単位＝`OverlayClip` の拡張**：SE・音声等のタイムライン固有クリップは track enum の拡張（`se`/`audio` 等・schema バンプは実装PRで）＋必要フィールド（`sourceAssetId`・`sourceStartSec/EndSec` 等）を追加して表現する。
3. **分割は「編集情報の複製」**：再生ヘッドでの動画分割は**場面の分割**（同素材・範囲を調整した2場面へ複製）として実現＝場面正準を壊さない。
4. **素材解析キャッシュ**：波形・サムネイル列・音量目安は**正準外の再生成可能キャッシュ**（既存サムネイルと同じ扱い・project.json に持たない）。
5. **将来の複数ナレーション（VoiceClip 方向）**：`scene.lines` は簡易編集＋AI の正準として**不変**（ADR-0015）。将来のタイムライン native な音声クリップ＋字幕/テキストの紐付け（移動追従）は本モデルの (2) の延長として設計する。**前提＝書き出しにグローバル音声の後段 amix パスを新設**すること。α-5 では実装しない（構造の余地のみ）。
6. **プロジェクト自己完結の原則**（周辺整理 2026-07-02）：プロジェクトフォルダは**素材込みで自己完結**を原則とする（取込時にコピー・正準は相対パス）。**例外＝ユーザーテンプレとその既定素材（グローバル保存・ADR-0021）と同梱物（BGM/フォント）**。持ち出し/アーカイブ（素材込みで1つにまとめる）は ADR-0021 の将来 bundle と合流して扱う（当面対象外）。

## 結果・影響
- schema 影響は**本ADR時点では無し**（方針のみ）。(1)(2) の各実装PRで `schemaVersion` マイナーバンプ＋`11` 追補＋無変換移行（`§5`/`§1`）。
- 対象外（将来・§10 と同旨）：音声認識の自動字幕・自動シーン検出・複数ナレの完全実装・波形の高度編集・カラー補正・クロマキー・マルチカム・**破壊的な素材分割**。
- **拡張余地（枠のみ記録・実装は将来）**：per-use 上書き（決定1）への**クロップ/リフレーム用フィールド**追加（α-6/α-7 再編〔2026-07-02〕でも将来のまま）、`timelineOverlay` への**マーカー**任意追加（同再編で **α-7 余力バッファ候補**＝#356・着手しない判断も正）——いずれも schema マイナーバンプで後付け可能な設計とする。
