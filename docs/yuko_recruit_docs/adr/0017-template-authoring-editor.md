## コンテキスト

ADR-0016 ②で「利用者が見た目パターン（テンプレ）を作る」＝§10「本格テンプレ作成エディタ」の緩和を決めた。ヒアリング（#213 着手時）で **深さ＝「ゼロから作成も可（フル）」／保存＝「グローバル（全プロジェクトで再利用）」** に確定。これを実装可能な設計へ落とす。

### 現状（調査）
- **Template**（`template.schema.json` v1.0）＝ `templateId`(`^[a-z0-9_]+$`) / `name` / `category`(10種) / `aspectRatio`(16:9・9:16) / `canvas` / `aiHint` / `defaults` / `layers`(≥1)。
- **Layer** ＝ `type`(background/slot/text/subtitle/character/logo/shape/decor) ＋ `x/y/w/h/zIndex` ＋ 型別フィールド（textKey/slotType/fit/defaultPoseTag/fillColor/`shapeType`＝`rect`/`ellipse`/`line` ほか・11 §3.4）。
- **保存**：テンプレは**同梱＋セッションのみ**（`loadBundledTemplates`／`addTemplatePack`）で**永続化されていない**。
- **FREE エディタ**（`scene.freeLayout`＋`FreeLayoutOverlay`）が既に**自由配置の編集UX**（選択/ドラッグ/リサイズ/整列/吸着/重ね順/複数選択/Undo＝α-3 ①）を持つ。

---

## 決定の判断軸

1. **既存の流用**：①で作った編集UX（オーバーレイ）と `template.schema` を最大限流用し、新規実装を最小化。
2. **単一パイプライン非汚染**（ADR-0007 M-A）：ユーザーテンプレも**通常の Template と同一**＝AI/簡易/詳細・描画が同じ経路に乗る（別データ・別描画を作らない）。
3. **正典の最小変更**：`template.schema` は据え置き（ユーザーテンプレ＝普通の Template）。採番・保存先・§2-4/§10 のみ追補。

## 検討した選択肢

### 深さ（確定済み・ヒアリング）
- 浅（複製＋微調整）／中（＋レイヤー追加削除）／**深（ゼロから作成も可）【採用】**。

### 保存範囲（確定済み・ヒアリング）
- プロジェクト内（project.json）／**グローバル（全プロジェクト再利用）【採用】**。

### 編集UIの実装
- **(A) FREE オーバーレイの編集UXを流用【採用】**：レイヤーの幾何編集（選択/ドラッグ/リサイズ/整列/吸着/重ね順/Undo）は①の資産をそのまま使う。`Layer[]` と `FreeElement[]` は別型だが、**幾何編集は共通**ゆえオーバーレイを一般化 or アダプタで載せる。
- (B) 専用エディタを新規実装：重複が大きく不採用。

## 決定

> **フルのテンプレ作成・編集エディタを入れる。ユーザーテンプレは「普通の Template」としてグローバルに永続化し、AI/簡易/詳細・描画は既存経路を共有する。編集UXは①（FREE オーバーレイ）を流用する。**

### 機能（深さ＝フル）
- **新規作成（ゼロから）**：向き（16:9/9:16）・カテゴリ・キャンバス・名前・`defaults` を決め、**任意のレイヤー**を**追加/削除/配置/書式設定**して保存。
  - 開放するレイヤー型＝ **background / slot / text / subtitle / character / logo / shape の7種**。`layer.type` enum（11 §3.4）は計8種だが、**`decor` は本エディタでは開放しない**（静的装飾は `slot`／`shape` で代替＝同梱テンプレ専用の特殊レイヤーゆえ MVP 外）。
- **複製して編集**：既存（同梱/ユーザー）テンプレを複製し、上記を編集して別名保存。**同梱テンプレ自体は読み取り専用**（複製してから編集）。
- **編集UX**：①のオーバーレイ（選択/ドラッグ/リサイズ/整列・吸着/重ね順/複数選択/Undo）を**レイヤー編集に流用**。型別の設定（slotType/textKey/fit/defaultPoseTag 等）はサイド編集パネルで。

### 保存（グローバル）
- **アプリ共通のユーザーテンプレ置き場**に永続化（同梱テンプレと別ディレクトリ・1テンプレ=1ファイル想定）。`loadBundledTemplates()` に**並べて `loadUserTemplates()`** を読み、`store.templates` に統合（同梱→ユーザーの順）。**project.json には保存しない**（テンプレは横断資産＝現状踏襲）。
- 削除/改名もエディタから。

### 採番・識別（11 §2.1 拡張）
- ユーザーテンプレの `templateId` ＝ **`user_tmpl_NNN`**（3桁ゼロ詰め・グローバル一意）。`^[a-z0-9_]+$` に適合（schema 変更不要）。同梱（記述的id）と名前空間で区別。
- **採番**：**最大連番+1（空き番号は埋めない）**＝scene/part の §2.1 gap-fill とは**別方針**。**削除した番号を再利用しない**（別プロジェクトの `scene.templateId` 参照が後発の別テンプレに化けるのを防ぐ）。削除をまたいだ厳密な単調増加は、**永続層が「払い出し済みの最大連番」を保持**して担保する（EPIC #214 永続化サブPR）。**999超は桁上がり**（`user_tmpl_1000`・`^[a-z0-9_]+$` 適合）。読込時に万一 ID 衝突（手動コピー混入等）があれば **後勝ち＋ログ警告**（黙って取りこぼさない）。
- **`template.schema.json` は据え置き**（schemaVersion 1.0）。ユーザー/同梱の別は **ID 接頭辞 `user_tmpl_` で判定**（永続フラグは持たない）。

### 正典の追補（**②実装PR=#214 で実施**・ADR-0016 未解決5）
- **§2-4 改訂**：「通常テンプレは座標固定（毎回座標を触らせない原則は通常編集で維持）／テンプレの作成・編集は専用エディタで行う」。
- **§10 改訂**：「本格テンプレ作成エディタ」を MVP 外から**解除**（ADR-0016/0017 の注記）。
- **11 §2.1**：`user_tmpl_NNN`（ユーザーテンプレ・グローバル一意）を ID 表に追加。

### 崩さない不変条件
- ユーザーテンプレも **`template.schema` 準拠の Template**＝描画（layout/sceneSvg）・手動選択（簡易/詳細）は**既存のまま**。別パイプラインを作らない（ADR-0007 M-A）。
- **AI 入力にユーザーテンプレを混ぜない**（既定）：AI へ渡すテンプレ一覧の組み立て（`buildTemplateSummaries`／`12 §4`）で **`templateId` が `user_tmpl_` で始まるものを除外**する。AI は同梱から選ぶ＝ユーザーテンプレの誤選択を防ぐ（`aiHint.recommendedSceneTypes` 制御だけでは不十分なので一覧側でフィルタ）。**簡易/詳細の手動選択には出す**。
- **削除の参照整合**：ユーザーテンプレ削除後に既存プロジェクトが当該 `templateId` を参照していたら、**`11 §9` の補正ルール**（存在しない `templateId` → 同 category の標準テンプレへ置換）に委ねる（削除はこの補正対象＝壊れない）。
- 通常の場面編集では**座標を直接触らせない**原則は維持（自由配置は FREE／作成は本エディタに限定）。

## 結果・影響

- **新規**：(1) グローバル・ユーザーテンプレ永続化（load/save/delete・infrastructure）、(2) テンプレ作成エディタ画面（①オーバーレイ流用＋型別パネル＋メタ設定）、(3) テンプレ選択への統合（ユーザーテンプレを一覧へ）。
- **既存流用**：描画・選択・①の編集UX。`template.schema` 不変。
- **テスト（§7）**：採番（`user_tmpl_NNN`）・ユーザーテンプレの schema 検証（同梱と同じ ajv ゲート）・統合（同梱＋ユーザーのマージ/ID衝突）・（流用ゆえ幾何編集は①のテスト資産）。
- **段階出荷**：EPIC #214 をサブPRに分割（永続化 → エディタ骨格 → レイヤー型別 → 選択統合 → 正典追補）。

> **レビュー反映で決定へ格上げ（2026-06-27）**：旧・未解決1（AI選択）→ **既定で AI 入力から除外**（上記不変条件）。旧・未解決6（採番衝突）→ **最大連番+1／読込衝突は後勝ち＋警告**（上記採番）。`decor` 非開放・削除時の `11 §9` 委譲も決定済み。

## 未解決の論点（実装EPIC #214 で確定）

1. **編集UIの載せ方**：`FreeLayoutOverlay` を `Layer`/`FreeElement` 双方で使える形に一般化するか、テンプレ用アダプタを噛ませるか。
2. **型別コントロール**：slot/text/subtitle/character/logo の各レイヤー固有設定（textKey の扱い・slotType・defaultPoseTag 等）をエディタでどこまで開くか。**＋レイヤー id と束縛**：新規追加レイヤーは `layer_NNN`（§5 の慣習 id=`background`/`logo` 等と異なる）。描画・場面編集は `scene.assetRefs[layer.id]` のように **`layer.id` で束縛**するため機能はするが、④で slot/background/logo の内容設定 UI を作る際に id の扱い（慣習 id へ寄せるか `layer_NNN` のままか）を明確化する（PR#232 レビュー指摘）。
3. **検証**：ユーザーテンプレの最小要件（layers≥1・座標が canvas 内・必須レイヤーの整合）。保存時に schema＋意味検証。
4. **エディタ入口**：新規画面/ルート（同梱テンプレは読み取り専用＝複製のみ編集で確定）。
5. **保存先パス**：グローバル置き場の OS 別アプリデータ配置と初期化。
6. **将来**：ユーザーテンプレの `aiHint` を整備して AI 選択も可能にするか（当面は除外）。

## 実装で確定（EPIC #214 完了・2026-06-28）

①〜⑤のサブPRで上記の未解決を確定した：

1. **編集UIの載せ方** → **専用オーバーレイ `TemplateLayerOverlay` ＋ ①の純粋 ops 流用**（`moveFreeElement`/`resizeFreeElement`/`snapToTargets`）。`FreeLayoutOverlay`（FREE 専用）は無改変（③c）。
2. **型別コントロール／レイヤー id 束縛** → 文字/図形/素材/背景/ロゴ等の内容・見た目をエディタで編集可（④a）。場面編集のテキスト欄は**テンプレのテキスト層の `textKey` から生成**（④b・`usedTextKeys`）。**レイヤー id は `layer_NNN` のまま**（慣習 id へ寄せない）＝描画・場面編集は `layer.id` で束縛。新規テキスト層は既定 `textKey`（text→title／subtitle→subtitle）を付与し追加直後から場面テキストに紐づく。図形種別は `LAYER_SHAPE_TYPE`（rect/ellipse/line・FREE 図形と別系統）。
3. **検証** → 保存時に `template.schema`＋レイヤー≥1 を担保（最小の意味検証）。
4. **エディタ入口** → 「見た目パターン」画面にドラフト式エディタを内蔵（同梱は読み取り専用＝複製のみ編集）。
5. **保存先パス** → OS 別アプリデータ下のユーザーテンプレ置き場（Tauri コマンド `save/load/delete_user_template`・`is_safe_template_id` で `^[a-z0-9_]+$` 検証）。
6. **将来（aiHint で AI 選択）** → 当面**除外のまま**（`buildTemplateSummaries` で `user_tmpl_` を除外）。
