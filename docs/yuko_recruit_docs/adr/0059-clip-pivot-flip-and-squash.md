# ADR-0059: 部品の回転・拡縮の軸と、反転・縦横別々の大きさ（タイムライン形式）

- **状態**: Accepted
- **日付**: 2026-10-09
- **関連**: #1186 ①（キーフレームを人にも AI にも扱いやすくする）／ADR-0019（キーフレーム）／ADR-0001（プレビュー＝書き出し）／ADR-0032（場面形式は凍結）／ADR-0034（業界の型）／ADR-0054（動きを付けた部品をキャンバスで掴む）／`11_TIMELINE_REFERENCE.md §7.6`／`schemas/timeline-project.schema.json`・`schemas/project.schema.json#/$defs/Keyframe`

## コンテキスト

#1186 で、キーフレームでは**書けない動き**が2つあると分かっている（実装を読んで確認済み・#1135 の作例で実際に踏んだ）。

1. **回転と拡縮の軸が常に部品の中心**（`applyInterpolatedTransform`・`sceneSvg.ts` の `rotate(r cx cy)`）＝「足元を軸に倒れる」「下を支点に伸び上がる」が書けない。#1135 では、ずっこけが中心で回って体が浮いた。
2. **拡縮が一様**（`scale` 1つ）＝**潰す・伸ばす**（着地で縦に潰れる等）と**左右反転**（立ち絵の向きを変える）ができない。

利用者の指示（2026-10-09「1〜6を順に」）で着手する。#1186 の行き先は general-backlog だったが、利用者が指示したので α の中で行う。

いまの描画は、部品にかかる変形を**相似変換**（一様の拡縮・回転・平行移動）として取り出し（`similarityBetween`）、見た目パターンの中身（層が複数）へまとめて乗せている。

- 回転・拡縮の**軸を変える**のは、相似変換のまま表せる（軸まわりの回転は「中心まわりの回転＋平行移動」）。
- **反転と縦横別々の大きさ**は相似変換では表せない。見た目パターンの層が回転していると、ずれ（せん断）が出るので、層ごとの x/y/w/h/回転では書けない。

## 判断軸

- **ADR-0001**＝プレビューと書き出しは同じ描画核（`layoutToSvg`）を通す。近似で書き写さない。
- **ADR-0034**＝業界の型（After Effects のアンカーポイント、Premiere の「水平方向に反転」、縦横比を固定しない拡大率）に合わせる。言葉は一般的な動画編集用語にする。
- **ADR-0032**＝場面形式は凍結。新しい操作はタイムライン形式だけに出す。
- 既に作った動画の絵を変えない（後方互換・無変換）。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) 層ごとの x/y/w/h/回転を縦横別々に直す | 層が回転していると、ずれが出て表せない。**不採用** |
| (B) **部品ごとに SVG の `<g transform="matrix(…)">` でくるむ**（相似変換で表せない残りだけ） | 描画核は1つのまま（プレビューも書き出しも同じ SVG）。切り抜き・合成の単位と同じ「連続する同じ鍵を1つの `<g>` で包む」流儀で足せる。**採用** |
| (C) 書き出しだけ FFmpeg で変形する | ADR-0001 違反（プレビューと別の経路）。**不採用** |

## 決定

### 決定1：軸（`pivot`）はタイムライン形式の部品が持つ・動きにだけ効く
- `TimelineClip.pivot`＝`{ x, y }`（**箱に対する割合** 0〜1・既定＝中心 0.5／0.5）。例：足元＝`{ x: 0.5, y: 1 }`。
- **キーフレームの回転と拡縮**だけがこの軸まわりに効く。
  - 素の箱の回転（`rotation`・キャンバスで回すもの）は今までどおり中心まわり。素の回転まで軸を変えると、キャンバスの取っ手（中心まわりの前提）がすべて食い違うため。
  - After Effects のアンカーポイントは素の回転にも効くが、ここは「動きの支点」として絞る。
- 相似変換のまま表せるので、見た目パターンの中身にもそのまま乗る（`similarityBetween` は変えない）。
- ⚠️ **喋っている間の「ふくらむ」**（ADR-0056）も同じ道（部品自身の動き）を通るので、支点まわりにふくらむ（足元を支点にすれば下から伸び上がる）。意図どおり＝「部品自身の動きの拡縮」はすべて支点まわり。
- 軸まわりに回すと、部品の中心は動く。動きの道筋（`motionPath`）も同じ関数で中心を出す＝線と実際の動きを割らない。

### 決定2：反転（`flipX`／`flipY`）はタイムライン形式の部品が持つ
- `TimelineClip.flipX`／`flipY`（真偽・既定 false）。Premiere の「水平方向に反転」「垂直方向に反転」と同じ。
- 部品の**変形後の箱の中心**まわりに鏡に映す（中身ごと＝見た目パターンの層・文字も鏡になる）。
- 描画は (B) の「ゆがみ」の `<g transform>` で行う。

### 決定3：縦横別々の大きさ（`scaleX`／`scaleY`）はキーフレームに足す（段階2）
- `$defs/Keyframe` に `scaleX`・`scaleY`（数・0 は不可・**負は反転**）を足す。`scale`（一様）に**掛け合わせる**。
- 一様の部分は今までどおり相似変換で、残り（縦横の比と符号）を「ゆがみ」で描く。
- `Keyframe` は場面形式と共有の定義なので、**両方の schema の版が上がる**。描画核も共有なので、場面形式でも同じ絵になる。ただし**場面形式の画面には出さない**（凍結・ADR-0032）。

### 決定4：「ゆがみ」の描き方（描画核に1つ）
- `LayoutItem.warp`＝`{ key, matrix: [a, b, c, d, e, f] }`。同じクリップの層は同じ `warp` を持つ。
- `layoutToSvg` は、**連続する同じ鍵**を1つの `<g transform="matrix(a b c d e f)">` で包む（`composite`・切り抜きと同じ流儀）。重なり順は「ゆがみ」が外側で、その内側で切り抜き・合成をする。
- 「ゆがみ」が単位行列なら持たない＝**既に作った動画の SVG は1バイトも変わらない**。

## 結果・影響

- schema：`timeline-project.schema.json` に `pivot`・`flipX`・`flipY` を足す（任意追加＝後方互換のマイナー＝**無変換**）。段階2で、共有の `$defs/Keyframe` に `scaleX`・`scaleY` を足し、`project.schema.json` と `timeline-project.schema.json` の両方の版を上げる。
- 正典：`11_TIMELINE_REFERENCE.md §7.6`（部品の項目・描き方）。`18_EXTERNAL_AGENT_CONTRACT.md §18.4` のキーフレームの落とし穴（軸は中心、が直る）。
- 描画核：`renderer/layout.ts`（`applyInterpolatedTransform` に軸）、`renderer/timelineLayout.ts`（反転・「ゆがみ」）、`renderer/sceneSvg.ts`（包む）。
- 画面：選んだ部品の欄に「左右反転」「上下反転」「動きの支点」（9か所から選ぶ＝上下左右・四隅・中心）。段階2でキーフレームの欄に「横の大きさ」「縦の大きさ」。
  - ⚠️ **追補（0.5.2 出口監査）**：「動きの支点」は**「動き」の欄**へ移した（効くのはキーフレームの回転・拡縮だけ＝効く相手のそばに置く。Premiere の「モーション」・After Effects の「トランスフォーム」の型）。反転は「見え方」の欄のまま。
- キャンバスで掴む（ADR-0054）：
  - 軸を変えた部品の逆算（`baseBoxPatchFromShown`）を、軸まわりの式に直す。
  - 反転・縦横別々の大きさが効いている間は、枠を素の箱（ゆがめる前）で出す（段階1は反転だけなので、箱の形は変わらない）。
- 外の AI（`18`）：書ける動きが増える。契約に足す。

## 未解決の論点

- **まとまり（グループ）の動きでは縦横別々の倍率は効かない**（まとまりの変形は相似変換で合成する）。画面からはまとまりに打てない。外の AI 向けの契約（`18`）に書いた。バラす（見た目パターンを要素に分ける）ときは、動きがまとまりへ移るので、反転・支点・縦横の倍率を持つ部品は**断る**（`TIMELINE_EDIT_EXPLODE_WARP`・PR #1414 レビュー 🔴）。
- **場面形式の動画の差し込み口では、縦横別々の倍率が「効く所と効かない所」に分かれる**（0.5.2 出口監査で書き直した＝前は「効かない」と書いていたが実装より弱かった）。止めているときの仕上がり確認と、書き出しの**動いている区間**（毎フレーム `layoutToSvg`）では効く。再生中の実映像（`SlotVideo`）と、書き出しの**動き終わった後の区間**（FFmpeg で重ねる）では効かない＝境目で絵が跳ぶ。場面形式は凍結で画面から書けないので、**手で書いた JSON でだけ起きる**（PR #1414 レビュー 🟡）。直すなら、差し込み口の `warp` を `VideoSceneSplitMulti.slots` に載せて `warpedPlacement` で置き、書き出しは焼く側へ回す（タイムライン形式の `drawnExtras` と同じ）。
