# ADR-0065: 止めた絵をファイルにしない（部品の設定で止める）

- **状態**: Proposed
- **日付**: 2026-10-20
- **関連**: [`ADR-0064`](0064-unused-file-cleanup.md)（使っていないファイルの片づけ）／[`ADR-0001`](0001-rendering-parity.md)（プレビュー＝書き出し）／[`ADR-0032`](0032-timeline-project-format.md)／[`ADR-0034`](0034-timeline-interaction-model.md)（業界の型）／#356 ②・#1137・`src/domain/timeline/freeze.ts`

## コンテキスト

タイムライン形式の「この瞬間で絵を止める」（#356 ②）は、**再生位置のコマを写真ファイルに切り出し**（`extractVideoFrame`）、分けた後ろ半分を**その写真の部品**に替える。

- 取り消すと部品は消えるが、写真のファイルは残る（やり直しのため）＝[`ADR-0064`](0064-unused-file-cleanup.md) の発端。
- 切り出しは FFmpeg を起こすので待ち時間があり、待っている間の変化を断る仕組み（`FREEZE_BLOCKED.changed`・#1136）や、上書き・取り違えの対策（#1137）が要った。

業界の型を調べると（2026-10-20）、**Premiere Pro の「フレーム保持」は部品の設定で、新しいファイルを作らない**。Final Cut Pro の「フリーズフレームを追加」も、再生位置で静止画にする操作（ファイルを作るかは資料で確かめられなかった）。

## 判断軸

- 業界の型（ADR-0034）。
- プレビュー＝書き出し（ADR-0001）＝止めた絵が両方で同じコマであること。
- ファイルを増やさない（ADR-0064 の発端を元から断つ）。
- 待ち時間と、それに伴う断り（#1136・#1137）を減らす。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) いまのまま（写真ファイルを作る） | 動いている。ファイルが残る・待ち時間・取り違えの対策が要る |
| (B) **動画の部品に「このコマで止める」（元の動画の何秒目か）を持たせる** | ファイルを作らない・待たない。描画は「動画のその秒のコマ」を毎回出すので、プレビュー（動画を止めて表示）と書き出し（FFmpeg でそのコマ）を同じ秒で合わせる必要がある。**有力** |
| (C) 速さ 0 で表す | 速さの意味（音・長さの計算）を壊す。不採用 |

## 決定（Proposed）

**(B) を有力とし、α の後に設計を詰める**（利用者判断 2026-10-20「ADR から検討・α後でも可」）。

詰めること：

1. timeline schema への欄の追加（例 `holdSourceSec`）と版の上げ方・移行（既存の「写真になった止めた絵」はそのまま残す）。
2. 描画：プレビューは動画要素をその秒で止める／書き出しは `videoPlacementsOf` がその秒の1コマを使う。**同じ秒の決め方を1か所に**（`videoSourceFrameAt` を共有）。
3. 音：止めた部品は元の音を鳴らさない（いまと同じ・`freezeStopsOriginalAudio`）。
4. 「止めた絵を写真として書き出す」は別の操作として残すか。

## 結果・影響

- 採用すれば、`freeze.ts` の切り出し・待ちの断り（`FREEZE_BLOCKED.changed`）・上書きの対策は不要になる。
- それまでは [`ADR-0064`](0064-unused-file-cleanup.md) の片づけで、残ったファイルを利用者が消せる。

## 未解決の論点

- 上の「詰めること」1〜4 すべて（α の後）。
