# ADR-0037: 読み方辞書（会社名・人名・専門用語の読みをナレーションに反映する）

- **状態**: Accepted
- **日付**: 2026-08-26
- **関連**: `#350`（α-6）／[`ADR-0005`](0005-voicevox-bundling.md)（VOICEVOX ENGINE 同梱・自動起動）／[`ADR-0003`](0003-narration-voice.md)（ナレーション音声）／[`ADR-0024`](0024-non-destructive-editing-model.md) 決定6（プロジェクト自己完結）／[`ADR-0035`](0035-user-asset-library.md)・[`ADR-0036`](0036-brand-kit.md)（**アプリがグローバルに持つものの流儀**）／`CLAUDE.md §2-3`（技術用語を出さない）・`§2-5`（次の行動）・`§4`（`infrastructure` に隔離）

## コンテキスト

採用動画では**固有名詞の誤読が頻出**する（会社名・人名・サービス名・業界用語）。読みを登録して VOICEVOX のナレーション生成に反映したい（#350）。

### 実機で確かめた事実（**推測ではない**・2026-08-26）

同梱している **VOICEVOX ENGINE v0.25.2（CPU）** を実際に起動し、OpenAPI と挙動を確認した。

| # | 事実 | 確かめ方 |
|---|---|---|
| 1 | **`user_dict` API は実在する**＝`GET /user_dict` / `POST /user_dict_word` / `PUT`・`DELETE /user_dict_word/{word_uuid}` / `POST /import_user_dict` | `/openapi.json` を取得して列挙 |
| 2 | **`accent_type` は必須**（integer・**既定なし**・説明は「アクセント型（音が下がる場所を指す）」）。`word_type`（固有名詞/普通名詞/動詞…）と `priority`（0〜10）は**任意** | 同上（`POST /user_dict_word` のパラメータ） |
| 3 | **辞書の保存先は `%LOCALAPPDATA%\voicevox-engine\voicevox-engine\user_dict.json`**＝**`run.exe` の隣ではない**。よって **packaged（Program Files 配下）でも書ける** | 語を1つ登録し、直近に更新されたファイルを走査して特定 |
| 4 | **保存先は OS 上の固定パスで、エンジンを共有する**＝`run.exe --help` に **`--user_dict_path` のようなオプションが無い**（あるのは `--setting_file` / `--preset_file` / `--disable_mutable_api` 等）。**保存先を分離できない** | `--help` の全オプションを確認 |
| 5 | 保存形式は `uuid → { surface, yomi, pronunciation, accent_type, cost, part_of_speech… }` | 登録後に `user_dict.json` を確認 |
| 6 | `POST /import_user_dict` の `override` は「**重複したエントリがあった場合、上書きするかどうか**」 | `/openapi.json` のパラメータ説明 |
| 7 | **`--disable_mutable_api` を付けて起動されたエンジンでは書けない** | `--help` |

> 確認に使った語は登録後に `DELETE` し、辞書が空（`{}`）に戻ったことを確認済み。エンジンも停止済み。

### 現状のアプリ側

- 合成は Rust の `synthesize_voice`（`src-tauri/src/voicevox.rs`）＝**`/audio_query` → `/synthesis`** の2段。辞書は `/audio_query` の時点で効く。
- 接続先の優先順＝**設定の `base_url`（上級者）＞ 同梱エンジン（自動起動・動的ポート）＞ 環境変数 ＞ 既定 50021**。
- グローバル設定は `appSettings.ts`＝**`localStorage`**（接続先・話者・欄の配置）。

## 判断軸

1. **事実4 が効く**＝辞書はアプリの外の共有物。**他の VOICEVOX（本体アプリ等）と同じファイルを触る**ので、こちらの都合で消したり総入れ替えしたりしてはいけない。
2. **アプリが持つものはアプリが正典を持つ**（ADR-0035／ADR-0036 と同じ流儀）＝エンジンを入れ替えても・別のエンジンを指しても同じ結果になる。
3. **技術用語を出さない**（§2-3）＝「アクセント型」「モーラ」を画面に出せない。
4. **黙って違う結果にしない**（§2-5・ADR-0026④）＝辞書を反映できなかったのに、そのまま誤読で作らない。

## 検討した選択肢

### 論点1：辞書の正典をどこに置くか

| 選択肢 | 評価 |
|---|---|
| (1-A) **ENGINE の `user_dict` をそのまま正典にする**（アプリは薄い UI） | 実装は最小。しかし事実3・4 より、正典が**アプリの外の共有ファイル**になる＝**アプリを消しても残り、他の VOICEVOX と混ざり、別PCへ移せず、バックアップの手立ても無い**。接続先を外部エンジンへ切り替えると**別の辞書**になり、同じ動画が違う読みで作られる。**不採用** |
| **(1-B) アプリが `appData/readingdict.json` に持ち、エンジンへ同期する** | 自前が正典＝エンジンを入れ替えても・外部エンジンを指しても同じ読み。バックアップ・別PC移行が効く。ADR-0035（`user_assets/`）・ADR-0036（`brandkit.json`）と**同じ流儀**。欠点＝二重管理と同期の失敗を扱う必要がある（論点2・論点4 で解く）。**採用** |

> ⚠️ `localStorage`（`appSettings`）に置かない理由は ADR-0036 論点1 と同じ＝**端末ローカルで移行もバックアップもされない**。読み方辞書は利用者が積み上げる資産なので、ファイルとして持つ。

### 論点2：エンジンへ同期するタイミング

| 選択肢 | 評価 |
|---|---|
| (2-A) アプリ起動時に1回 | 起動後にエンジンが再起動した／接続先を切り替えた場合に効かない＝**黙って誤読のまま作る**（判断軸4 に抵触） |
| (2-B) 声を作る直前に毎回 | 確実だが、1行ごとに辞書の突き合わせが走る |
| **(2-C) 編集したら即反映 ＋ 声を作る直前にそろえる** | 編集直後に**試し聞きできる**（登録した読みが効いたか、その場で分かる）。作る直前に一度そろえるので、エンジンが入れ替わっていても効く。**ADR-0032 の `loadExportFonts`「描く前にそろえる」と同型**の考え方。**採用**。⚠️ 「そろえる」は**差分だけ**（論点3） |

### 論点3：他のアプリの辞書を壊さない方法（**事実4 の帰結**）

| 選択肢 | 評価 |
|---|---|
| (3-A) `import_user_dict` で丸ごと入れ替える | 事実6 より `override` は「重複時に上書きするか」だが、**アプリの辞書＝エンジンの辞書と見なす**設計になり、**利用者が VOICEVOX 本体で入れた語**の扱いが曖昧になる。**不採用** |
| **(3-B) 自分が入れた語だけを、語ごとに操作する** | アプリは `readingdict.json` に**自分が入れた語の `word_uuid`** を持ち、追加＝`POST`／変更＝`PUT`／削除＝`DELETE` を**その uuid にだけ**行う。**エンジンにあってアプリが知らない語には触らない**。**採用** |

### 論点4：アクセントをどう決めるか（**事実2 の帰結・§2-3**）

`accent_type` は必須で既定が無いので、何かを送らねばならない。しかし「アクセント型」「モーラ」は画面に出せない。

| 選択肢 | 評価 |
|---|---|
| (4-A) 常に `0` を送る | 実装は最小。ただし多くの語で不自然になり、**「登録したのに変な読み」**が残る＝直す手立てが無い |
| (4-B) 「アクセント型」の数値を入力させる | §2-3 違反。非技術者に意味が伝わらない。**不採用** |
| **(4-C) 聞き比べて選ぶ** | 読み（カタカナ）を入れると、**音が下がる場所の候補を並べて、それぞれ試し聞きできる**ようにする（候補数は読みの拍数から作る）。画面に出す言葉は「**言葉／読み／どこで下げるか（聞いて選ぶ）**」で、数値も専門語も出さない。**採用** |

> ⚠️ 最小形として **(4-A) を既定値**（＝最初は先頭で下がる形）にしたうえで、**その場で聞き比べて直せる**のが (4-C)。「登録はできたが直せない」を作らない。

### 論点5：グローバルか、プロジェクトごとか

**グローバル**（#350 の方針どおり・`project.json` 不変）。読み方は「その利用者の語彙」であり、動画ごとに変わるものではない。

⚠️ ただし**プロジェクトを他人に渡すと読みは再現しない**（辞書は付いていかない）。これは ADR-0024 決定6（自己完結）の**例外ではない**＝**作成済みの声は WAV としてプロジェクト内に保存されている**ので、**渡した先で既存の動画は同じ音のまま**。違いが出るのは**渡した先で声を作り直したとき**だけ。

> ✅ **この宿題は決定8 で解く**（利用者判断 2026-08-26）＝**辞書の書き出し／読み込みを α-6 に入れる**。渡す相手に辞書ファイルも渡せば、作り直しても同じ読みになる。

### 論点6：AI 入力に含めるか

**特別な規則は要らない。** 読み方は音声合成の語彙であって、AI が返す `ai-video-plan` には現れない（AI は台本を書き、読み上げの音は作らない＝§2-1）。送信前確認（§2-6）の対象にもならない。

## 決定（Accepted・2026-08-26 利用者承認）

1. **正典はアプリが持つ**＝`appData/readingdict.json`（`brandkit.json` と同じ流儀）。中身は**言葉・読み（カタカナ）・音が下がる場所・種類（任意）・優先度（任意）**と、**エンジン側の `word_uuid`**。
2. **同期は「編集したら即反映 ＋ 声を作る直前にそろえる」**（差分だけ）。
3. **他のアプリの辞書を壊さない**＝**自分が入れた語の uuid だけ**を `POST`/`PUT`/`DELETE` する。**丸ごと入れ替えない**・**知らない語に触らない**。
4. **アクセントは聞き比べて選ぶ**（既定＝先頭で下がる形。数値も専門語も画面に出さない）。
5. **グローバル**（`project.schema` 不変）。⚠️ 他人に渡すと**作り直したときだけ**読みが変わりうる（作成済みの声は WAV で残るので既存の動画は変わらない）。
6. **AI の扱いに特別な規則を作らない。**
7. **反映できなかったら黙って作らない**（§2-5）＝エンジンが `--disable_mutable_api` で起動されている／接続できない等で辞書を送れなかったときは、**次の行動を出して断る**（`15 §6` に文言を新設）。**誤読のまま「成功」として音を作らない**。
8. **辞書の書き出し／読み込みを α-6 に入れる**（利用者判断 2026-08-26）＝`readingdict.json` をファイルとして出し入れできる。**論点5 の「渡した先で作り直すと読みが変わる」を解く道**であり、別PC への移行・チームでの共有にも効く。読み込みは**足す（マージ）**を既定とし、**同じ言葉が既にあるときは黙って上書きしない**（どちらを残すか選ばせる＝§2-5「黙って別の結果にしない」）。

**利用者承認（2026-08-26）＝2点とも YES。**
- **決定4（アクセントを聞き比べて選ぶ）を α-6 に入れる**＝「登録はできたが直せない」を作らない。
- **決定8（辞書の書き出し／読み込み）を α-6 に入れる**＝論点5 の宿題をこのリリースで解く。

## 結果・影響

### コード

- 新設＝`src/infrastructure/readingDictFs.ts`（`appData/readingdict.json` の読み書き。`userTemplateFs.ts` と同型）。
- 新設＝`src/infrastructure/voicevox/userDict.ts`（**`user_dict` API の呼び出しを `infrastructure` に隔離**＝§4）。Rust 側に置くか TS 側から叩くかは実装判断（現状 `synthesize_voice` は Rust・接続先の解決も Rust にある＝**接続先の決め方を二重に持たない**なら Rust 側が自然）。
- `domain` 側は**純粋な突き合わせ**（アプリの辞書とエンジンの辞書から「足す・直す・消す」を出す）＝テスト対象（§7）。
- 画面＝設定に「ことばの読み方」（一覧・追加・削除・**試し聞き**）。
- `15 §6` に**辞書を反映できなかったとき**の文言を新設（決定7）。

### 正典

- **`project.schema` は不変**（決定5）。`template.schema`・`timeline-project.schema` も不変。
- `readingdict.json` は**プロジェクトの正典ではない**（アプリの持ち物）＝`schemas/` には置かない。⚠️ **`11 §1` の3スキーマは増やさない**（ADR-0036 と同じ扱い）。
- `13_DEPENDENCIES_AND_LICENSING.md` に、**辞書の保存先が `%LOCALAPPDATA%` でエンジン共有である**事実（本 ADR の事実3・4）を記録する＝配布・アンインストール時の挙動に関わる。
- `CLAUDE.md §11` に本 ADR を **Accepted** として1行追記（本 PR で実施）。
