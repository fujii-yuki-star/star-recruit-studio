# ADR-0050: 仕上がり確認だけを別の窓に出し、そこで直接直せるようにする

- **状態**: Accepted
- **日付**: 2026-09-29
- **Issue**: #1263
- **関連**: [`ADR-0001`](0001-rendering-parity.md)（プレビューと書き出しは同じ描画核）／[`ADR-0020`](0020-undo-redo-model.md)（取り消しの持ち主）／[`ADR-0026`](0026-alpha4-behavior-consistency.md)（②同じ概念を画面で割らない）／[`ADR-0033`](0033-editor-panel-layout.md)（配置の好みは `localStorage`）／[`ADR-0034`](0034-timeline-interaction-model.md)（操作は業界の型）／[`ADR-0048`](0048-ux-first-editor-density.md)（UI/UX 優先）／[`ADR-0049`](0049-os-file-drop-to-timeline.md)（窓の外からの落とし込み）／調査 [`2026-09-os-drop-and-popout-research.md`](../archive/research/2026-09-os-drop-and-popout-research.md)

## コンテキスト

利用者要望（2026-09-29）：仕上がり確認の欄は**絵の上で部品を掴んで直接動かせる**作りなので、ここを**別の大きな画面（2画面目）**に出して、細かく・手早く位置を直したい。

調査（上記）の結論は次のとおりだった。

- **任意の欄を窓の外へ切り離す**のはプロ向けの製品だけ（Premiere Pro・VEGAS Pro・Kdenlive ほか・2025年9月以降の YMM4）。
  一般向け（Clipchamp・PowerDirector・Filmora・Camtasia）は**プレビューだけを全画面か2画面目へ**に絞っている。
  入れた直後には、どの製品でも「窓が画面の外へ消える」「別窓でキーが効かない」「戻せない」が出ている。
- **Tauri で技術的に不可能ではない**（v2 は複数の窓を公式にサポート）。ただし**窓ごとに JS の状態が別**で、
  窓の間は JSON のイベントでしか渡せない。互いに状態を送り合う方式は、採用例自身が「取りこぼしうる」と認めている。
- 調査の推奨は「読むだけの窓で止める（編集できる別窓は作らない）」だった。

利用者判断（2026-09-29）：**編集できる別窓を作る**（「1263 はその方向で設計し進めてください」）。
ADR-0048（UI/UX を優先し、決まりのほうを改める）に沿って、調査の推奨より利用者の使い方を取る。
そのうえで、調査が挙げた壊れ方（状態の食い違い・キー・戻せない・画面外）を**作りで防ぐ**のがこの ADR の中身。

## 決定

1. **別の窓に出せるのは「仕上がり確認」だけ**。任意の欄を切り離す仕組みは作らない（調査どおり）。
   別窓の中身は**本体の編集画面と同じ部品**を「仕上がり確認だけを広げた形」で描く＝描画核（ADR-0001）も、
   掴んで動かす・二度押しで文字を直す・中へ入る（ADR-0034）も、本体と**同じコード**を通る（ADR-0026②）。
2. **状態の持ち主は本体の窓ひとつ**。文書・選択・再生位置・取り消し・保存・書き出し・音・再生の時計は本体だけが持つ。
   - 別窓は本体から**写し**を受け取って描く。
   - 別窓で操作すると、**その操作の名前と引数を本体へ送り**、本体が自分の store で実行する（＝取り消しも自動保存も本体の1本の道を通る・ADR-0020）。
   - 別窓は**保存しない・書き出さない・音を鳴らさない・時計を回さない**（動画は写しの再生位置に合わせて音を消して映す）。
   - ⚠️ **本体の窓が隠れても再生を止めない**＝本体の時計は描く合図（`requestAnimationFrame`）で回るが、本体が最小化される・
     別窓の全画面に覆われると合図が来ない（Windows では止め方を変える設定 `backgroundThrottling` も効かない）。
     そこで**別窓が再生中に描くたび「進めて」の合図を送り**、本体はそれで時計を1歩進める（`playbackPulse`）。
     時計の持ち主は本体のまま＝位置は始めた実時刻から測るので、合図が重なってもずれない。
     本体が隠れたら再生を止める規則（`visibilitychange`）も、**別窓が見えている間は**効かせない。
     ⚠️ **両方の窓が隠れたら止める**（#1274 レビュー）＝別窓も隠れると合図が来ず、時計は止まるのに音だけ進む。
     別窓は隠れた・見えたを本体へ知らせ、本体が自分の隠れ方と合わせて決める。
3. **写しの送り方**＝本体の store が変わるたび、**変わった項目だけ**を送る（再生中は再生位置だけ・掴んでいる間は文書だけ）。
   取り消しの履歴などの重いもの・窓の中だけの印は送らない。
   ⚠️ **送る間合いは「いまの処理が終わった直後」**（同じ処理の中の変化は1通にまとめる）。描く合図で待つと、
   本体が隠れている間は**別窓に何も届かない**（実測で踏んだ）。
   ⚠️ **窓をまたげない物は落とす**＝操作の引数に混ざる**押した出来事**（画面は `onClick={play}` のように渡す箇所がある）・関数・
   循環する物は、送る前に落とす。混ざったまま送ると、運ぶ時点で投げて**黙って何も起きない**（実測で踏んだ：別窓の「再生」が効かなかった）。
   写しの側も、運べない項目があればその項目だけ落とす（1つのせいで写し全体を止めない）。
   ⚠️ **写しに回の印と通し番号を付ける**（#1274 レビュー）＝届く順が入れ替わっても古い写しを捨てる。本体が開き直したら回が変わる。
   受け取る側は、**中身が同じなら手元の物をそのまま使う**＝「同じ物か」で比べている箇所（例：中へ入った印）を写しで壊さない。
4. **選ぶ操作（選ぶ・まとめて選ぶ・選びをやめる）だけは、別窓の手元でも先に当てる**。
   別窓の画面には「選んだ直後に選択を読み直す」箇所があり、本体からの写しを待つと古い選択を読む。
   選ぶ操作は保存も時計も持たないので、手元で当てても持ち主は割れない（本体の写しが来れば同じ中身に揃う）。
   ⚠️ **古い写しで巻き戻さない**（#1274 レビュー）＝別窓の命令には通し番号を付け、本体は写しに「どこまで実行したか」を添える
   （中身が変わらなくても返す）。別窓は、最後に選んだ命令より前までしか実行していない写しの選択は当てない。
5. **本体が受けない操作を決めておく**＝動画を開く・閉じる・作る・消す・書き出す・保存など、**寿命と外への出口**の操作は、
   別窓から来ても実行しない。store に無い名前も捨てる。**`_` で始まる内部の操作は一覧に無くても受けない**（#1274 レビュー）。
   ⚠️ **store の操作はすべて「送る／手元でも当てる／受けない」のどれかに分類されている**ことを検査で固定する
   （操作を足したときに分類を忘れると、検査が赤くなる）。
6. **キー操作は別窓でも本体と同じ**。同じ画面部品なので同じキーの処理が走り、その先が命令として本体へ行く
   （Space で再生・Ctrl+Z で取り消し・矢印で少し動かす、など）。調査が挙げた「別窓でキーが効かない」を作らない。
7. **置き場所**：2画面目があれば**本体の居ない画面**に、無ければ本体の横に開く（最小の幅は上端の行の道具が1行に収まる 640px・
   **「この窓を閉じる」は上端の行の左端に固定**＝狭くても閉じる手が切れない・#1275 レビュー）。前回の位置と大きさを覚える
   （`localStorage`＝ADR-0033 の「配置の好み」の範囲を窓の位置まで広げる。`project.schema` には入れない）。
   開くときに**どの画面にも入っていなければ覚えた位置を捨てて**既定へ戻す（2画面目を外した後に見えない窓を作らない）。
   ⚠️ **隠して作ってから出さない**＝Tauri では、隠した状態で作った窓はファイルの落とし込みを受けない（tauri #14643）。
8. **閉じ方と戻し方**：別窓の×・本体の「別の窓で見る」ボタン（押し直しで閉じる）のどちらでも閉じられる＝**1手で全部戻る**。
   本体が動画を閉じる・画面を離れる・窓を閉じると、別窓も閉じる。
   ⚠️ 別窓が途中で消えたら（掴んだまま閉じた等）、**別窓が始めた取り消しのまとまりを本体が閉じる**＝以後の編集が1つの取り消しに飲み込まれない。
   別窓が読み込み直したとき（写しを頼み直したとき）も同じ。**本体が自分で始めたまとまりは閉じない**。
   ⚠️ **黙らない**（§2-5・#1274 レビュー）＝別窓を開けなかったら本体に `PREVIEW_WINDOW_OPEN_FAILED`、
   別窓が本体とつながらないまま8秒経ったら別窓に `PREVIEW_WINDOW_NOT_CONNECTED` を出す（`15 §6`）。
9. **別窓での窓の外からの落とし込みは「取り込むだけ」**（ADR-0049＝並びが見えていない所へは置かない）。
10. **別窓は本体の欄の配置を読まない・書かない**（`usePanelLayout` の `persist: false`）
    ＝同じ保存場所を共有しているので、書くと本体の配置を上書きし、読むと本体で閉じた欄を「閉じている」と見なして
    その場の返事を欄の外へ出してしまう。

## 採らなかった案

- **窓どうしで状態を送り合う**：取り消しと自動保存は持ち主が1つであることを前提にしている（ADR-0020）。2つの持ち主は、
  同じ編集を二重に積む・古い文書で上書き保存する、の元になる。
- **別窓用に軽い部品を別に書く**：掴む・直す・中へ入るの操作を二重に持つことになり、片方だけ直す・片方だけ壊れる
  （ADR-0026②・「近似で書き写さない」ADR-0001 と同じ理由）。
- **任意の欄の切り離し**：調査どおり（戻せない・画面外・キー）。今回の要望は仕上がり確認の大画面で満たせる。
- **読むだけの窓で止める**（調査の推奨）：利用者の目的が「大きな画面で直接直す」なので満たせない。

## 影響

- 権限：本体に**窓を作る権限**（`core:webview:allow-create-webview-window`）を足し、別窓（`preview`）に最小限の権限を与える。
- 別窓でだけ起きる不具合の芽：拡大率の違う画面の間で窓を動かすと大きさ・位置が乱れる（tauri #12043）。
  写しの往復で、別窓の操作は本体経由の分だけ遅れる（同じ機械の中のイベントなので数ミリ秒の見込み）。どちらも**実機で確かめる**。
- 本体の仕上がり確認は、別窓を開いている間も描き続ける（小さい方で全体を、大きい方で細部を、という使い方を妨げない）。
