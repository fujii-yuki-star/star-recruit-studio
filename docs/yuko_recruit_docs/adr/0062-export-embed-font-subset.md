# ADR-0062: 書き出しの文字を正しい字体で焼く（使う字だけを残した字体を絵に埋め込む）

- **状態**: Accepted
- **日付**: 2026-10-16
- **関連**: [`ADR-0001`](0001-rendering-parity.md)（プレビュー＝書き出し）／[`ADR-0004`](0004-rasterization-method.md)（静止レイヤーは WebView の Canvas で焼く）／[`ADR-0038`](0038-user-fonts.md)（持ち込みフォント）／[`ADR-0060`](0060-extension-packs.md)（拡張パックの文字の形）／`src/renderer/export/rasterize.ts`

## コンテキスト

2026-10-16、拡張パックの実機確認で、**書き出した動画の文字が選んだ字体になっていない**ことが分かった。
仕上がり確認では怪盗予告ゴシックで出ている文字が、書き出すと標準のゴシックになる。

調べると拡張パックの字体だけではなく、**同梱の Gen Interface JP・Gen Interface JP Display・怪盗予告ゴシック、持ち込みフォントのすべて**が同じだった。
書き出しは描画核の SVG を `<img>` に読ませて Canvas に焼く（ADR-0004）が、**`<img>` に読ませた SVG は文書の字体（`@font-face`・`FontFace`）を使えない**。
Windows に入っていない字体はすべて既定の字体へ倒れる（アプリの中で、同じ文を4つの字体で焼いて画素を比べ、4つとも同じ絵になることを確かめた）。
ADR-0001 の「プレビュー＝書き出し」が、字体については最初から守れていなかった。

字体の中身を SVG の中に `@font-face`（data URL）で書けば正しく焼けることも確かめた。ただし丸ごと入れると
**1コマあたり Gen Interface JP で約 0.13 秒・怪盗予告ゴシックで約 0.43 秒**かかる（毎コマ焼く動きのある場面で重い）。

## 判断軸

- **ADR-0001（プレビュー＝書き出し）を字体でも守る**＝字の形・字幅・詰め・合字が仕上がり確認と同じであること。
- 書き出しの速さを大きく落とさない（動きのある場面は毎コマ焼く）。
- 新しい依存を増やさない・CSP（`wasm-unsafe-eval` など）を緩めない。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) 字体を丸ごと埋め込む | 正しく焼けるが、1コマ 0.13〜0.43 秒の上乗せ |
| (B) 外部の字体の切り出し（fonteditor-core など）で、使う字だけの字体を作り直す | 小さく速いが、**字体を組み直す**ので詰め（GPOS）・合字（GSUB）が落ちるか壊れる（字の番号が付け直されるのに、表はそのまま）＝仕上がり確認と字の並びが変わりうる |
| (B') Rust の切り出し（typst の subsetter） | PDF 向けで**文字の表（cmap）を残さない**＝ブラウザで使えない |
| **(C) 字体の表はそのまま残し、使わない字の形（glyf）だけを空にする** | 字の番号を変えないので**詰め・合字・字幅・行の高さが元のまま**＝仕上がり確認と同じ並び。依存を増やさない（自前の数百行） |

## 決定

**(C) を採る。** 書き出しで SVG を焼く直前（`svgToPngDataUrl`）に、SVG の中の `<text>` から「字体と太さごとの使う字」を集め、
その字体の**使う字の形だけを残した字体**を data URL の `@font-face` として SVG に書き込む。

1. **残す字の形**＝使う字（cmap で引く）＋ **合字・置き換えで出てくる字**（GSUB を、横書きの既定の機能〔ccmp・locl・liga・clig・calt・rlig・rclt・rvrn〕に絞って閉じるまで辿る）＋ **組み合わせ字の部品**（glyf の composite）＋ 0 番（.notdef）。
2. **ほかの表はそのまま**（cmap・hmtx・GPOS・GSUB・vmtx など）。`glyf` と `loca` だけ作り直す。`post` は字の名前を持たない形（3.0）へ、署名（`DSIG`）は外す（中身を変えたので合わない）。
3. **字体ごと・使う字ごとに作った結果を覚えておく**＝毎コマ作り直さない（新しい字が出てきたときだけ作り直す）。
4. **glyf を持たない字体（CFF の OTF など）は丸ごと埋め込む**＝遅いが正しい（持ち込みフォント・パックの字体で起こりうる）。
5. 字体の中身は、同梱は `/fonts/…`、持ち込みとパックは今の読み口（`readFontBase64`）から取る＝仕上がり確認が使うのと**同じ実体**。

## 結果・影響

- 書き出し（場面形式・タイムライン形式とも `svgToPngDataUrl` を通る）で、選んだ字体が出る。**これまでに書き出した動画の字は既定の字体だった**＝作り直すと字体が変わる。
- 埋め込む字体は Gen Interface JP で約 0.5MB・怪盗予告ゴシックで約 1.3MB（使う字の数で増える）。
- 正典の変更は無い（schema・11・12 は変わらない）。`13`（依存）も変わらない（新しい依存なし）。

## 未解決の論点

- GSUB を既定の機能に絞っているので、**既定でない機能（縦書き・字形の切り替えなど）を使う表現を将来足したら**、残す字の形の範囲も広げる。
- CFF の字体の切り出し（今は丸ごと）。
