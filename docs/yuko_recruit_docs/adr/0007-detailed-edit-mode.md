## コンテキスト

現状の編集面は `SceneEditScreen`（＝実質「簡易編集モード」）で、AIが提案した構成に対し、場面ごとに **タイトル/字幕/セリフ/表示時間/見た目パターン/素材スロット割当/クリップ調整/トランジション/ゆうこ表示** を編集できる（※「ゆうこ表示」の場面トグルはその後 #171 で廃止＝表示有無はテンプレ依存・§7.3）。「AIがたたき台 → ほぼ完成まで簡易編集」という主動線には十分。

一方で利用者ヒアリングから次の要望が出た（本ADRの動機）:

1. **AIが構成を提案 → 簡易編集である程度仕上げ → それでも細かく気になる場面を微調整したい。**
2. 汎用動画編集ツールより **直感的**で、かつ **「もしもの時に困らない」程度の編集機能**は揃えたい。
3. （主想定ではないが）**AIを使わず手動で動画を作る**用途も想定。その場合は簡易編集より詳細編集の方が圧倒的に扱いやすい。

ここで本格的な編集機能を入れると `§10`（本格タイムライン編集・キーフレーム・複雑エフェクト・テンプレ作成エディタは MVP 外）と `§2-4`（テンプレ駆動＝座標を毎回触らせない）に抵触し得る。**「どこまでを詳細編集とするか」を先に決める**ためのADR。

### 不変条件（崩さない前提）

- **場面内レイアウトは静止**（ADR-0001）。動くのは動画スロットの中身と音声のみ。詳細編集を入れても**場面内アニメ／キーフレームは持ち込まない**。
- **描画は1経路**（ADR-0004：WebView Canvas で SVG→PNG）。詳細編集の結果も**同じ layout→SVG→PNG→FFmpeg パイプライン**を通す（新しい描画エンジンを作らない）。
- **テンプレ駆動**（§2-4）。通常テンプレの座標は固定のまま。

## 検討した選択肢

### モードの持ち方
- **(M-A) 同一データ・2モード**【採用】: 簡易/詳細は**同じ project.json を編集する2つのUI**。詳細モードは「より多くの操作を露出する編集面」であって、別のデータ形式・別の書き出し経路を持たない。AI→簡易→詳細→書き出しが**単一パイプライン**で繋がる。
- (M-B) 詳細編集専用の別ドキュメント／別データモデル — 二重管理になり、AI出力との往復・書き出しの整合が壊れる。不採用。

### 自由配置とテンプレ駆動の両立
- **(F-A) FREE テンプレートに自由配置を閉じ込める**【採用・利用者提案】: 「自由に置きたい場所」では **`category: free` のテンプレ**を使う。自由配置は**FREEテンプレを選んだ場面に限って**有効化し、通常テンプレは座標固定のまま（§2-4 を維持）。テンプレ作成エディタ（§10外）ではなく、**組み込みのFREEテンプレ**を1つ用意するだけ。
- (F-B) どのテンプレでも座標を直接編集可能にする — §2-4（テンプレ駆動）を実質無効化し、毎回座標を触らせることになる。不採用。
- (F-C) 自由配置を入れない — 要望2/3（もしもの時／手動制作）に応えられない。不採用。

## 決定

> **(M-A) 同一データ・2モード**＋**(F-A) FREEテンプレに自由配置を閉じ込める**を採用する。
> 詳細編集モードは、現行の簡易編集と**同じ project/scene データ**を、より細かく編集する UI とする。自由配置は **`category: free` テンプレを選んだ場面**でのみ有効化し、その場面のレイアウト上書きを **scene 側の新フィールド**に持たせる。場面内は依然「静止レイアウト＋（任意の）動画スロット＋音声」に限り、**タイムライン／キーフレーム／複雑エフェクトは入れない（§10 を維持）**。

### 詳細編集モードに含める機能（利用者の選択：4領域すべて）

1. **場面ごとの音声ミックス**（`scene.audioMix`、正典既設）
   - ナレ音量：**ドメイン・書き出しは既に対応済み**（`resolveNarrationVolume(scene.audioMix, …)`。`ExportScreen` も `scene.audioMix` を渡している）。**UI を足すだけ**で「場面ごと」になる＝**Phase 1**。
   - 元動画音量：クリップ調整で既に場面（素材）単位に編集可。
   - BGM音量（場面ごと）：現状 BGM は1本を全体に重ねる方式（ADR-0006/V-C3）。場面ごとに効かせるには**書き出し側で音量エンベロープ**（`volume=…:enable='between(t,…)'`）が要る＝別途実装（Phase 3-4）。それまで**no-op UI を作らない**（「置いてあるだけ未結線」を避ける）。

2. **場面の並べ替え・複製・分割**（構成編集）
   - 並べ替え（order 再採番）、複製（`createSceneId` で採番しコピー）、分割（1場面を2つに）。**場面リストの操作**でありタイムラインではない＝§10 の範囲内。
   - 既存 `addScene`/`removeScene`/`createSceneId` の延長で実装可。
   - **音声の扱い**：narration 音声は `voices/<sceneId>.wav`（sceneId 単位）。**複製・分割で生まれた新 scene は `narration.voicePath=null` / `status="none"` にリセット**し再生成待ちにする（複数 scene が同一音声を指す不整合を防ぐ。VOICEVOX V-C2 の永続化規約と一致）。
   - **分割（split）の具体仕様（Phase 2b・2026-06-15 確定＝選択肢A「セリフで分ける」）**：
     場面編集のセリフ入力欄の**カーソル位置**で `narration.text` を前半/後半に分け、元場面の直後に新場面を挿入する（1場面→2場面）。
     - 元場面＝前半テキスト、新場面＝元のコピー（見た目・素材・キャラ・clip・assetRefs を引き継ぐ）＋後半テキスト。
     - **表示時間は前半/後半の文字数比で按分**（合計尺は不変）。**#553（2026-07-17）で「各最低 `SCENE_MIN_DURATION_SEC`／尺が最小尺の2倍未満は分割不可」を撤廃**＝場面ごとの下限を持たなくなったため、守るのは**両側 >0**（0秒の場面を作らない）だけ（片側の文字数が0で比が潰れるときは等分）。按分値は 0.1 秒へ量子化し合計は差で厳密保持する。分割しないのは**尺が0以下**のときのみ。カーソルが端/無効なら、中央に最も近い文末記号（`。！？`・改行）で、無ければ中央で分割。
     - 両場面とも音声は作り直し（`status="none"`/`voicePath=null`）、`warnings` はクリア（複製と同じ規約）。
     - **新しい描画・スキーマは不要**（既存フィールドのみ）。タイムライン分割ではなく「セリフ単位で場面を2つにする」操作＝§10 の範囲内。純粋ロジックは `domain/project/sceneOps.ts`（`splitSceneInList`）に置きテストする。

3. **クリップの詳細調整**
   - トリム（開始/終了）・フィット：**既存**（`asset.clip`）。
   - 再生速度：新規（FFmpeg `setpts`/`atempo`。尺・音声との整合を要設計）。
   - 1場面に複数素材：**§10（複雑化）に近づくため要検討・原則は1スロット**。入れる場合もレイヤー数を絞る。

4. **テキスト/装飾の自由配置（FREE テンプレ）** — 最大の項目
   - `category: free` のテンプレを選んだ場面で、テキスト/画像/図形を**自由な座標・サイズ・色**で配置できる。
   - データ：通常テンプレの座標は固定のまま。**FREE場面のみ** scene 側にレイアウト上書きを持たせる（下記スキーマ案）。
   - 描画：自由配置でも**出力は静止レイアウト**＝既存の layout→SVG→PNG→FFmpeg を通る（ADR-0001/0004）。新しい描画は不要。

### スキーマ案（実装時に確定。本ADRは方針のみ）

- **`template.category` に `free` を追加**（11 §3 と同期）。FREEテンプレは「自由配置の器」を表す組み込みテンプレ。
  - **【共有 enum 整合・11 §3.2】** `scene.sceneType` と `template.category` は**同一の値集合を共有する**。よって `free` を入れるなら、(a) `sceneType`（project.schema の `SceneCategory`）にも `free` を加える（共有 enum へ追加）か、(b) FREEテンプレを既存 sceneType（例 `full_visual`）に紐づけ category だけ free 扱いにするか、を **Phase 4 前に確定**する。
  - **【補正・11 §9】** `category:free` の標準テンプレが無い環境（旧バージョン等）で置換先が不定にならないよう、FREE を選べるのは「標準 FREE テンプレが存在するとき」に限定し、無ければ警告して選択を促す。
  - **【AI 除外・12】** AI には FREE を選ばせない（`aiHint.recommendedSceneTypes` に `free` を含めない＋システムプロンプトで除外）。FREE は**利用者の手動選択専用**。
- **`scene.freeLayout`（任意）を新設**＝FREE場面のレイアウト上書き。**通常テンプレ場面は未設定**（後方互換：従来どおりテンプレ座標）。
  - 要素の `kind` は**テンプレ `layer.type`（11 §3.4：`slot`/`text`/`shape`/`decor` 等）の語彙に合わせる**。`image` は layer.type に無いため使わず、素材を受ける要素は **`kind:'slot'`**（`assetId`/`fit`）、文字は **`kind:'text'`**（`textKey` or `text`/`fontSize`/`color`）、図形は **`kind:'shape'`**（`shapeType`/`fillColor`）とする＝レンダラーが layer.type への変換テーブルを持たずに済む。
  - 各要素 `{ kind, x, y, w, h, zIndex, …kind別プロパティ }`。座標系はテンプレ canvas（1920×1080）基準。`null=継承`/未設定の規約は §2.2 を踏襲。
  - **素材参照（11 §5 との関係）**：`freeLayout[].kind:'slot'` の素材は **`assetId` で直接参照**し、**assetRefs バインディング（11 §5）は適用しない**（assetRefs は FREEテンプレ内の固定レイヤー〈background 等〉にのみ使う）。レンダラーは「assetRefs 経由（通常テンプレ）」と「`freeLayout[].assetId` 直接参照（FREE）」の **2 経路を分岐**する＝Phase 4 前の追補で確定。
- **schemaVersion（11 §1）**：`category:free` 追加・`scene.freeLayout`（任意）追加はいずれも**後方互換の追加**＝マイナー（`1.x`）で扱う。Phase 4 の正典反映時に確定。

### 簡易/詳細モードの関係（UX・要設計）

- 簡易編集モード＝現行 `SceneEditScreen` 相当（最小操作で仕上げる）。
- 詳細編集モード＝同じ場面に対し上記4領域を露出。**同一画面のトグルに確定（2026-06-15）**＝場面編集画面に「詳細編集」トグル（既存 `showAdvanced` を昇格）を置き、オンで詳細コントロールを表示（別画面は作らない）。状態はプロジェクトに保存しない**表示設定**（場面間で保持）。**→ #278（2026-07-03）でトグル撤廃**：4領域のうち FREE 自由配置は既に常時表示（ADR-0008）、タイムライン/キーフレームは別画面（ADR-0018/0019）へ移り、残る画面切替・動画クリップ詳細は**常時表示**にしたため（上記「状態」）。
  - **Phase 3a の振り分け**：詳細＝クリップの細かい調整（fit/使う範囲/元音声/元音声音量・将来の再生速度）＋画面の切り替え（transition）＋将来の FREE 自由配置。簡易（常時）＝タイトル・見た目・素材割当・セリフ＋声・分割・場面ごとの声の大きさ・字幕・表示時間。（※当初は「ゆうこ表示」トグルも簡易常時に含めたが、#171 で廃止＝表示有無はテンプレの character レイヤー有無による・§7.3）
- **AIなし制作（本ADRのスコープ外・別途設計）**：詳細編集＋FREEテンプレ＋手動の場面追加が揃えば原理的には AI なしでも作れる。ただし**ウィザード/AI生成のスキップ**は、必須フィールド（11 §7.1.2 `companyName` は必須）が未入力でも有効な project.json を生成できるか等の検討が要る。現行ロードマップ（02 / 09 §4）はウィザード→AI生成を必須フローとしているため、**この入口動線は本ADRでは扱わず別ADRで設計**する。本ADRは「編集機能」に集中する。

### §10 として入れないもの（線引き）

- タイムライントラックUI／キーフレームアニメ／場面内モーション（動画スロットの中身を除く）／複雑エフェクト・フィルタ合成／テンプレ作成エディタ（FREEは組み込みテンプレで代替）。場面は引き続き「静止レイアウト＋（任意の）動画スロット＋音声」。

## 結果・影響

- **段階実装（ロードマップ）**：
  - **Phase 1**：場面ごとナレ音量の UI（`SceneEdit`/詳細の音声セクション）。書き出し既対応＝小PR・即着手可。
  - **Phase 2**：場面の並べ替え・複製・分割（場面リスト操作）。
  - **Phase 3**：詳細編集モードの UI 骨格（簡易/詳細の切替）＋クリップ詳細（再生速度等）。
  - **Phase 4**：FREEテンプレ＋`scene.freeLayout`＋自由配置エディタ（スキーマ拡張・描画/書き出し結線。最大。**実装前に追補ADR or 本ADR改訂**でスキーマ確定）。実装前の追補/改訂では、スキーマ確定とあわせて **11 §8 検証ルールの拡張**（`freeLayout` 要素の `assetId` 実在・kind 別必須フィールド・座標/サイズ範囲チェック等）も確定する。
  - （場面ごとBGM音量：書き出しエンベロープ実装後に Phase 3-4 で。）
- スキーマ変更（`category: free`・`scene.freeLayout`）は **Phase 4 で正典（11/schemas）に反映**。それまでは本ADRの提案に留める。
- 書き出し・プレビューは原則無改修（FREE場面は「自由に置かれた静止レイアウト」を同パイプラインで描く）。再生速度・場面ごとBGMのみ FFmpeg 追加。

## 未解決の論点

1. ~~**簡易/詳細の UI 形態**~~ → **確定（2026-06-15・Phase 3a）**：同一画面の「詳細編集」トグル（`showAdvanced`・表示設定で非永続）。**→ #278（2026-07-03）で撤廃**：詳細編集の別画面化に伴い、残りの画面切替・動画クリップ詳細は常時表示へ（上記「状態」）。
2. **`scene.freeLayout` の確定スキーマ**：要素型・スタイルの範囲（フォント/枠/影をどこまで）、テンプレ層との関係（FREEテンプレは空の器か、初期要素を持つか）。
3. **FREE テンプレの位置づけ**：`category: free` 追加 vs 既存（full_visual 等）流用。AIの `recommendedSceneTypes` 対象外とするか。
4. **場面ごとBGM音量**の書き出し方式（`volume … enable='between(t,…)'` のエンベロープ）。
5. **再生速度**（`setpts`/`atempo`）と尺・ナレーション・字幕タイミングの整合。
6. **1場面複数素材**を許すか（§10 複雑エフェクトとの線引き）。
7. アクセシビリティ・操作の直感性（要望2）をどう担保するか（ドラッグ配置のキーボード代替等）。
