## コンテキスト

ADR-0016（詳細編集の完全化アンブレラ）の **③ 場面横断タイムライン／複数トラック**を設計する。`§10`「完全自由タイムライン」を段階的に緩和し、**場面列→時間軸 UI**・複数トラック（映像／テロップ／音声／BGM）を最終像に含める。

### 現状（調査）— モデルは「場面中心・逐次」
- **場面が時間の単位**：`project.scenes[]` は `scene.order` 順で**端から端へ逐次**。`scene.durationSec`（`>0`・**場面ごとの上限/下限なし**＝#553／`11 §4`）。場面間の重なりは**データに持たず**、書き出し時に `transitionTimeline()` が xfade overlap を計算（`src/renderer/export/buildExportScenes.ts`・`src/domain/project/sceneTransitions.ts`）。
- **場面内ミニタイムラインは既にある**（ADR-0015・schema 1.8）：`scene.lines[]`（`NarrationLine`）が `startSec`／自動逐次で区間化（`src/domain/project/lineTimeline.ts`）。ただし**行は重ならない**（V18 検証）。`sceneLines()` が単一 narration との差を吸収。
- **音声**：ナレーション（場面/行）＋音量解決（`11 §6`・`scene.audioMix`）。**BGM は動画全体に1本**（`project.bgmSettings`）＝**場面ごとBGMは無い**。
- **トラックの概念は無い**：1場面＝1レイアウト＋1ナレーション系列（行は逐次）＋全体BGM。平行音声・平行テロップ・場面内アニメは**未対応**。
- **描画は静止フレーム**（ADR-0001）：場面＝静止レイアウトの単一フレーム（動画スロットを除く）。per-frame 補間は**④（ADR-0019）**で扱う。

### 緩和したいギャップ（時間軸でしか綺麗に表現できないもの）
場面横断の重なり／平行トラック（テロップ・音声・BGM変化）／音量オートメーション／（将来）キーフレーム。これらは**場面という箱の中**には収まらず、**グローバル時間軸**を要する。

### 中心的な緊張＝「AI 親和性」と「時間軸の自由度」
- **AI 出力（`ai-video-plan`）は本質的に場面分割**（1ビート＝1レイアウト＋セリフ）。AI に自由時間軸（重なるクリップ列）を吐かせるのは脆く、**単一パイプライン（ADR-0007 M-A）を壊す**。
- 一方、**詳細編集の自由度**（場面横断の重なり・平行トラック）は時間軸でこそ素直。

→ **正準（AI が生成し永続する）モデルは場面ベースのまま**、**詳細編集だけ時間軸**にしたい。これが本 ADR の核心。

---

## 判断軸

1. **AI 親和性の維持**：AI が触るのは**場面ベースのみ**（`ai-video-plan`→検証→Scene の経路を変えない＝`12`）。
2. **単一パイプライン非汚染**（ADR-0007 M-A）：別データ・別描画を作らない。書き出しは1経路（ADR-0004 SVG→PNG→FFmpeg）。
3. **後方互換**：既存 `project.json`（場面ベース・逐次）はそのまま再生・編集できる。`schemaVersion` は**追加的・任意**で上げる（`11 §1`）。
4. **段階出荷**：重い③は十分設計してから着手、各版を出荷可能に保つ（ADR-0016 (B)）。
5. **③は静止のまま**（ADR-0001 維持）：③は**並べ方とトラック**の話。**場面内アニメ＝per-frame は④（ADR-0019）**で ADR-0001 を supersede する。混ぜない。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| **(A) 時間軸ネイティブ（全面再設計）** | project を「グローバル時間軸＋トラックにクリップ配置」へ作り替え、場面概念をクリップ/区間に解体。自由度は最大だが、**AI 親和性を壊し**（AI が時間軸を吐く必要）、後方互換破壊・移行が重く、ADR-0001/0007 を広範に置換＝**最重量**。**不採用**（αの段階出荷・AI 経路維持に反する）。 |
| **(B) render-only 射影** | 場面→時間軸は**読み取り専用の可視化**に留め、編集は従来の場面フィールド経由のみ。安全だが**場面横断の重なり・平行トラックを表現できない**＝③の要件を満たさない。**部分採用**（射影の仕組みは流用）。 |
| **(C) 2モデル方式＝場面正準＋時間軸コンパイル＋別UI【採用】** | **オーサリング=場面ベース正準**（AI/おまかせ/簡易/場面詳細が編集）を維持しつつ、**`compileTimeline(project)` で時間軸＋トラックへ機械的に射影**。射影を **export と「タイムライン編集UI（別画面）」が共有**。時間軸UIの編集は**場面アンカーの任意オーバーレイ層**に保存し、AI/簡易編集は無視。**AI 親和性・単一パイプライン・後方互換を保ちつつ自由度を別UIで提供**。 |

## 決定（Proposed）

> **2モデル方式を採る。場面ベースを唯一の正準（AI 生成・永続・場面編集の対象）として維持し、そこから機械的に射影した「タイムラインモデル」を書き出しと専用の「タイムライン編集UI（完全に別画面）」が共有する。時間軸での詳細編集は、場面にアンカーした任意のオーバーレイ層として保存する。場面は③では静止のまま（per-frame は④/ADR-0019）。**

### モデル
1. **オーサリングモデル（場面ベース・正準）＝現状の `project.json`**。AI（`ai-video-plan`→Scene）・おまかせ・簡易・**場面詳細編集**が編集する唯一の真実。**不変**（本 ADR でスキーマを変えない）。
2. **タイムラインモデル（時間軸＋トラック・コンパイル結果）**＝純粋関数 `compileTimeline(project): Timeline` が**機械的に射影**。トラックは少なくとも **映像／テロップ（字幕・テキスト）／音声（ナレーション）／BGM**。既存の `buildExportScenes()`＋`transitionTimeline()`＋`lineTimeline()` が**事実上この射影の一部を既に実装**しており、それを一般化・抽出する。
3. **タイムライン編集UI（別画面）**＝タイムラインモデルを表示・編集する**専用画面**（場面編集とは別 UI）。`§2-4` の「通常編集で座標を毎回触らせない」は維持し、時間軸の自由編集は**この画面に隔離**する（FREE 場面・テンプレ作成エディタと同じ「特殊編集は専用面」の方針）。

### round-trip（時間軸UIの編集をどう保存するか）＝中心的論点
- **採用（推奨）＝場面アンカーのオーバーレイ層**：場面を骨格として維持し、時間軸UIの高度編集（場面横断クリップ・平行トラック・音量エンベロープ等）を **`project` の任意・追加セクション**（例 `timelineOverlay`・**スキーマ追加は α-4 で確定**）に格納。`compileTimeline` が「場面射影＋オーバーレイ」をマージ。**AI/簡易編集はオーバーレイを無視**するため、AI 再生成と衝突しない（オーバーレイは場面 id にアンカーし、**AI 再生成時の整合は α-4 の未解決**）。
- 代替（記録のみ）：**(B) render-only**（編集は場面フィールドのみ＝自由度不足）／**one-way graduation**（「タイムラインへ変換」を一方通行にし、以後 AI/場面編集を無効化＝AI 親和性を失う）。

### 既存ADRとの統合
- **ADR-0015（掛け合い `lines`）**：場面内ミニタイムラインは**そのまま**＝`compileTimeline` で各行を**テロップ／音声トラックの区間**へ射影。重ならない行（V18）の不変条件は維持。
- **ADR-0009（トランジション）**：現状「場面入口の `transition.in`＋書き出し時 overlap」を、射影では**境界オブジェクト**（2場面にまたがる overlap）として表現。データの正準は引き続き場面側。
- **ADR-0001（静止・単一フレーム）**：③では**維持**。③は「並べ方とトラック」であり、場面内の時間補間は持ち込まない。**④（ADR-0019）が per-frame 描画で ADR-0001 を supersede**。

### 段階出荷（α-4 実装の優先順位・**提案**）
1. `compileTimeline` の抽出（現 export ロジックの一般化）＋**読み取り専用タイムラインUI**（まず可視化）。
2. **場面ごとBGM**（最も具体的で要望の強いギャップ・低リスク。`bgmSettings` の場面オーバーライド）。
3. **平行テロップ**（複数キャプション層）。
4. 平行音声・音量オートメーション → ④の前後で再評価。**キーフレームは④（ADR-0019）**。

## 結果・影響

- **コード（α-4）**：`compileTimeline(project): Timeline`（domain 純粋関数・テスト対象§7）／タイムライン編集UI（新画面・app 層）／（オーバーレイ採用時）`project.schema.json` への**任意 `timelineOverlay`** 追加＝`schemaVersion` マイナー＋無変換マイグレーション（`11 §1`・既存は未設定＝場面射影のみ）。
- **正典追補（実装着手時）**：`§10` の「完全自由タイムライン」を**段階解除**（ADR-0012/0015 と同型の注記）。`§2-4` に「時間軸の自由編集は専用タイムラインUIに隔離」を追記。`11` にタイムラインモデル／`compileTimeline` の契約と（採用時）`timelineOverlay` スキーマ・トラックごとのフィールド（未解決7）を追記。本 ADR は**設計のみ**ゆえ、これらは α-4 実装 PR で反映。
- **アンブレラとの整合**：[ADR-0016](0016-detailed-editing-completion-roadmap.md) §機能表③の「project モデルを場面ベースから時間軸ベースへ拡張」は、**本 2モデル方式（場面ベース正準＋時間軸射影の追加＝置換ではない）に読み替える**。0016 側の③行に本 ADR への参照注記を入れて齟齬を解消済み（実装者の「時間軸ネイティブへ書き換え」誤読を防ぐ）。
- **AI（`12`）**：**変更なし**（AI は場面ベースのみ）。タイムライン／オーバーレイは AI 入力・出力の対象外。
- **描画**：1経路維持（ADR-0004）。③は静止フレームのまま。

## 未解決の論点（α-4 EPIC で確定・一部は④/ADR-0019 と連動）

1. **round-trip の最終確定** → **③(3) で決着**：**場面アンカーのオーバーレイを採用**（利用者確認・2026-07-01）。`timelineOverlay.clips`（`OverlayClip`）は **場面アンカー（`anchorSceneId`＋相対秒）と絶対時間（`anchorSceneId` 省略＝startSec はグローバル秒）の両対応**。`compileTimeline` が「アンカー場面のグローバル開始＋startSec」（絶対は 0 基準）で該当トラックへ合成し、**不明/除外アンカーは描画で無視**（新 **V_overlay**・`11 §8`）。初期トラックは **telop（テロップ）のみ**（audio/bgm は将来の enum 拡張）。schema **1.14→1.15**（`11 §1`・任意追加＝無変換）。キーフレームは④で `timelineOverlay` に追加（未解決6）。
2. **AI 再生成 × オーバーレイの整合**：AI が場面を作り直したとき、場面 id にアンカーしたオーバーレイをどう扱うか（保持／部分破棄＋警告／再マッピング）。（ユーザー確認）
3. **タイムライン編集UI の範囲**：DAW 風フル編集か、「場面ストリップ＋場面ごとトラックレーン」程度か。`§2-3`（非技術用語）を保ったトラック/クリップの言い換え。（ユーザー確認）
4. **トラック種別と初期スコープ**：映像／テロップ／音声／BGM のどれを α-4 の最初に出すか（提案＝場面ごとBGM→平行テロップ）。
5. **ADR-0009/0015 の射影詳細**：トランジション境界オブジェクト・行区間の正準の置き場（場面側に保ち射影で展開）。
6. **④（ADR-0019）との境界**：per-frame 描画への移行点。③のオーバーレイが④のキーフレーム格納先を兼ねるか。→ **[ADR-0019](0019-keyframe-animation-model.md)（Proposed）で回収**：キーフレームは `timelineOverlay` に格納し**兼ねる**、と決定（④独自の新トップレベルは作らない）。
7. **正典追補の取りこぼし防止（トラックごと）**：段階出荷の各トラックは正典更新とセット。特に**場面ごとBGM**（段階出荷2）は `11 §7.4`＋`project.schema.json` に **`scene.bgmSettings`（場面オーバーライド・現 `scene.audioMix` の BGM 音量とは別物）** を追加し、**`schemaVersion` マイナーバンプ＋無変換マイグレーション**（`§5`/`§1`）が必要。平行テロップ・平行音声も同様にフィールド追加＋版上げを伴う。実装 PR で漏らさない。
