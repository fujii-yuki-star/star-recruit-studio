# ADR-0035: ユーザー素材ライブラリ（プロジェクト横断の素材の置き場）

- **状態**: Accepted
- **日付**: 2026-08-26
- **関連**: `#260`（EPIC・α-6）／[`ADR-0017`](0017-template-authoring-editor.md)（ユーザーテンプレのグローバル化）／[`ADR-0021`](0021-template-owned-assets.md)（テンプレ既定素材 `tmpl_asset_NNN`）／[`ADR-0024`](0024-non-destructive-editing-model.md) 決定6（**プロジェクト自己完結の原則**）／`CLAUDE.md §2-6`（外部送信）／`11 §2`（ID採番）／`#347`（再リンク・差し替え）／`#351`（ブランドキット）

## コンテキスト

同じ会社のロゴ・社員写真・オフィス写真・BGM を、**動画を作るたびに取り込み直している**。プロジェクト横断で再利用できる素材の置き場が欲しい（#260）。

### 現状（実コードで確認・2026-08-26）

| | 状態 |
|---|---|
| 素材の持ち主 | **プロジェクト内のみ**（`Project.assets: Asset[]`・`src/domain/project/types.ts:404`） |
| 素材のタグ | **実装済み**＝`Asset.tags?: string[]`（`types.ts:117`）。付与/削除UI は `MaterialsScreen.tsx:100,274`。**AI も使っている**（poseTag 解決＝`transformPlan.ts:103`／入力の語彙＝`videoPlanInput.ts:41`／送信文＝`assetSendText.ts:35`） |
| タグでの絞り込み | **無い**（`MaterialsScreen.tsx:87` は `assetType` の種類フィルタだけ）＝**付けられるのに探せない** |
| グローバル永続化の前例 | 2つ＝`userTemplateFs.ts`（ユーザーテンプレ・ADR-0017）／`templateAssetFs.ts`（テンプレ既定素材・`appData/user_templates/assets/tmpl_asset_NNN.<ext>`・ADR-0021） |

つまり **#260 の「タグ管理」の大半は既にある**。足りないのは①**横断の置き場**と②**タグで探せること**の2つ。

### なぜいま決めるか

α-6 は素材まわりを4件同時に触る（#347 再リンク・#348 未使用整理・#332 解析キャッシュ・#349 静止画切り出し）。**本 ADR の決定3（持ち込み方）次第で、その4件との結合の強さが変わる**（参照なら全部が影響を受け、コピーならほぼ独立）。実装は #857 の段階5 のままでよいが、**決定だけは段階2 より前に要る**。

## 判断軸

1. **プロジェクト自己完結**（ADR-0024 決定6）＝「プロジェクトフォルダは素材込みで自己完結・取込時にコピー・正準は相対パス」。**例外は既に列挙されている**（ユーザーテンプレとその既定素材・同梱の BGM/フォント）＝増やすなら理由が要る。
2. **同じ α-6 の中で自分の首を絞めない**＝#347（欠損復旧）の対象を増やす決定は、同じリリースで直す相手を増やす。
3. **役割の重複を作らない**＝会社のフォント・色・ロゴを1か所で持つ役目は **#351 ブランドキット**が担う。⚠️ **訂正（2026-08-26・[ADR-0036](0036-brand-kit.md)）**＝当初ここに「一元管理して**全プロジェクトへ反映**」と書いたのは**言い過ぎ**だった。#351 の射程は**新規プロジェクトへの既定適用**で、**既存には遡及しない**（自動で遡及させると `§2-5`「黙って別の見た目に差し替えない」に抵触し、**過去に書き出した動画と再書き出しが違う絵になる**）。ADR-0036 は既存へ**明示操作で適用し直す**導線を置くと決めた（**Accepted**・利用者承認 2026-08-26）ので、本 ADR の判断（コピー）はその形で支えられる。
4. **正典の単一参照**（§2-7）・**非技術者UX**（§2-3）。

## 検討した選択肢

### 論点1：グローバル素材の置き場

| 選択肢 | 評価 |
|---|---|
| (1-A) `templateAssetFs` を拡張（`user_templates/assets` に同居） | 実装は最小。しかし**持ち主が違うものが同じ棚に並ぶ**＝テンプレ既定素材は「テンプレが所有」で、テンプレを消したら孤立掃除の対象（#299）。ライブラリ素材は**利用者が所有**し、テンプレの生死と無関係。掃除の規則が2つ同居する。**不採用** |
| **(1-B) 別の置き場を建てる**（`appData/user_assets/`） | 持ち主と寿命が違うものを分ける。`userTemplateFs`/`templateAssetFs` と**同型のパターン**（Rust コマンド＋`is_safe_*` のパス検証）で書けるので実装コストの差は小さい。**採用** |

### 論点2：id 体系

| 選択肢 | 評価 |
|---|---|
| (2-A) `tmpl_asset_NNN` を流用 | 論点1 で置き場を分ける以上、id も分けないと**どちらの棚のものか id から分からない**。**不採用** |
| **(2-B) `lib_asset_NNN`**（3桁ゼロ詰め・`11 §2` 準拠） | プロジェクト内の `asset_NNN`・テンプレの `tmpl_asset_NNN` と衝突しない。**採用** |

> ⚠️ 決定3 で**コピー**を採ると、`lib_asset_NNN` は **`project.json` に一切現れない**（取り込み時に `asset_NNN` へ採番し直す）＝**`project.schema` は不変**。

### 論点3：プロジェクトへの持ち込み方（**本 ADR の要**）

| 選択肢 | 評価 |
|---|---|
| **(3-A) コピー**＝取り込み時にプロジェクトフォルダへ複製し `asset_NNN` を採番 | **ADR-0024 決定6 の原則そのまま**（例外を増やさない）。別PC・持ち出し・アーカイブで壊れない。**#347 の対象が増えない**。取り込み経路は既存（`importAssetByPath`）をそのまま使える。`project.schema` 不変。欠点＝「1か所直せば全部に反映」が無い／同じロゴが N プロジェクトに N 個（ディスク消費）。**採用** |
| (3-B) 参照＝グローバル id をそのまま `assetRefs` に置く | 利点＝一元管理・更新が伝播・ディスク節約。欠点＝**自己完結が一般ケースで壊れる**。別PCへ移すと**全プロジェクトが同時に欠損**し、#347 の負荷が跳ね上がる。タイムライン形式の焼き出し（`bakedFilePaths`＝ADR-0032 決定20）が運ぶ対象も増える。**不採用** |
| (3-C) 折衷＝既定はコピー、ロゴ等「ブランド資産」だけ参照 | 同じ画面に**2つの規則が同居**し、利用者はどちらの素材か区別できない（片方だけ別PCで消える＝§2-5 の「壊れて見える」）。しかも会社のフォント・色・ロゴを1か所で持つ役目は **#351 が担う**（ADR-0036）＝役割の重複。**不採用** |

> **(3-B) の利点（更新の伝播）を捨てて良い理由**＝そのニーズは #351 ブランドキット（[ADR-0036](0036-brand-kit.md)）が引き受ける。素材ライブラリで重ねて解く必要がない＝**「素材ライブラリ＝取り込み元の棚」「ブランドキット＝会社の既定を1か所で持つ場所」**と役割を分ける。
> ⚠️ **ただし「自動で全プロジェクトへ伝播する」道はどちらにも無い**（ADR-0036 決定3）＝既存の動画は**明示操作で適用し直したときだけ**変わる。黙って変わらないことのほうを優先している（`§2-5`）。

### 論点4：タグの持ち方

| 選択肢 | 評価 |
|---|---|
| **(4-A) ライブラリ素材もタグを持ち、コピー時にタグごと持ち込む** | 既存の `Asset.tags` と**同じ語彙**。取り込んだ後のタグ編集はプロジェクト側のコピーにだけ効く（ライブラリへ書き戻さない＝コピーの意味と一致）。**採用** |
| (4-B) ライブラリ側だけがタグを持つ | プロジェクト内でタグを直せない＝既にできることを奪う。**不採用** |

### 論点5：AI 入力に含めるか

ADR-0017 はユーザーテンプレを **AI 入力から既定で除外**しているが、**本件は特別な規則が要らない**。決定3（コピー）により、取り込んだ時点で**普通のプロジェクト素材**になるため、既存の経路（`assetSendText`／`buildVideoPlanRequest`／送信前確認＝§2-6）にそのまま乗る。**ライブラリに置いてあるだけの素材は AI へ送られない**（プロジェクトに入っていないので当然）。

## 決定（Accepted・2026-08-26 利用者承認）

1. **置き場は別に建てる**＝`appData/user_assets/`（`userTemplateFs`/`templateAssetFs` と同型のパターン・Rust コマンド＋パス検証）。
2. **id は `lib_asset_NNN`**（`11 §2` 準拠・3桁ゼロ詰め）。
3. **持ち込みは「コピー」**＝ADR-0024 決定6 の自己完結を守り、**例外を増やさない**。取り込み時に `asset_NNN` を採番し、ファイルをプロジェクトフォルダへ複製する。⇒ **`project.schema` は不変**。
4. **タグはライブラリ素材も持ち、コピー時に持ち込む**（書き戻さない）。
5. **AI の扱いに特別な規則を作らない**（コピー後は普通の素材＝既存経路・§2-6 の送信前確認を通る）。

**利用者承認（2026-08-26）＝2点とも YES。**
- **決定3「コピー」で良い**（＝ADR-0024 決定6 の例外を増やさない）。
- **「プロジェクト内素材一覧の改善」は別 Issue へ分けて前倒しする**（→ 下記「結果・影響」）。

## 結果・影響

### コード

- 新設＝`src/infrastructure/userAssetFs.ts`（`templateAssetFs.ts` と同型）＋ Rust コマンド。**パス検証は既存の流儀に揃える**＝`src-tauri/src/lib.rs` の `is_safe_template_id` 等と同型（ADR-0017 のパストラバーサル対策）。⚠️ **packaged では dev と挙動が違う**（`asset://` のキャッシュ・ビルド時のファイルロック・CSP）＝`13_DEPENDENCIES_AND_LICENSING.md` と #119/#120 の配布まわりの記録を実装前に確認する。
- ⚠️ **`asset://` で配れる場所の書き方は「置き場所の深さ」と合わせる**（#942・実機で確認）＝`$APPDATA/user_assets/**` と書くと**直下のファイルに当たらず 403**。`user_assets/` の中身は `lib_asset_NNN.<ext>` と `library.json` で**常に直下**なので `$APPDATA/user_assets/*` が正しい。実測＝`user_assets/lib_asset_001.png`（直下）は 403／`projects/<id>/assets/asset_001.png`（階層あり）は 200。⚠️ **隣の `projects/**` に見た目をそろえると再発する**うえ、#926 の作りは「読み込めなかったらその絵だけ落とす」ので**壊れた画像の印も出ず静かに絵が消える**（`src/test/assetScope.test.ts` で固定した）。
- 取り込みは既存の `importAssetByPath` を再利用（**ライブラリ→プロジェクトは「ファイルパスからの取り込み」に還元できる**＝新しい経路を作らない）。
- 画面＝素材画面に「ライブラリ」の導線（一覧・取り込み・削除・改名）。**技術用語を出さない**（§2-3）＝言い方は「素材の棚」等を UI 文言の一本化（`uiLabels`）で決める。

### 他 Issue への影響（**#857 の段階順に関わる**）

決定3 が **(3-A) コピー**である限り、素材ライブラリは段階2 の4件と**ほぼ独立**：

| Issue | 影響 |
|---|---|
| #347 再リンク・差し替え | **増えない**（欠損はプロジェクト内のコピーの話。ライブラリは「取り込み元」として差し替え候補に出せると便利＝任意） |
| #348 未使用素材の整理 | **増えない**（プロジェクト内の話。ライブラリ素材は「未使用」の概念が無い＝棚に置いてあるだけ） |
| #332 解析キャッシュ | ライブラリ素材にも波形・サムネが要るか＝**要検討**（一覧の見栄えに効く。無くても成立） |
| #349 静止画切り出し | 切り出した画像を**ライブラリへも入れられる**と便利＝任意の追加導線 |

⇒ **実装順は #857 の段階5 のままでよい**。決定3 が (3-B) 参照になった場合のみ、段階2 より前へ繰り上げる必要がある。

### 分離（**決定・利用者承認 2026-08-26**）

#260 本文の「**プロジェクト内素材一覧の改善**」（名前・タグで探せる／複数選択で一括追加／一括追加の進捗）は、**ライブラリとは独立に成立する**（いま付けられるタグで探せないのは単独の不備）。**別 Issue へ分けて前倒しする**＝ライブラリの大物を待たずに「付けたタグで探せない」を解消する。#260 からは当該節を落とし、#857 の段階2 の先頭へ置く。
