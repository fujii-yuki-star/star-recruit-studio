# ADR-0002: FFmpegビルドとH.264コーデック方針

- **状態**: Accepted（2026-06-10 承認）
- **日付**: 2026-06-10
- **関連**: `13_DEPENDENCIES_AND_LICENSING.md §3` / `ADR-0001` / `05_RENDERING_SPEC.md §4`

---

## コンテキスト

商用配布するWindowsアプリが **H.264 MP4 を出力（エンコード）** する。論点は2つ：
1. **FFmpegのライセンス**（LGPL 2.1+ ／ GPLオプション）。
2. **H.264の特許**（FFmpegライセンスとは別問題）。

方針として、**自前でのH.264特許ライセンス取得は行わない**（ユーザー確認済み）。

## 判断軸

特許ライセンス不要 ／ 互換性（採用サイト・YouTube・会社説明会のPowerPoint埋め込み）／ LGPL遵守 ／ 実装容易。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| libx264 | 高品質だがFFmpegの `--enable-gpl` が必要＝アプリ全体がGPL寄りになり、AVC特許も別途。**不採用** |
| **OpenH264（Cisco配布バイナリ）** | Ciscoが配布バイナリのAVC特許料を負担。LGPLビルドと両立。**採用** |
| ロイヤリティフリー（AV1/VP9/WebM） | 特許回避できるが互換性低下。**将来の任意出力として検討** |

## 決定

> **FFmpegは LGPLビルド（`--enable-gpl` 不使用）＋動的リンク＋ソース提供**（`ADR-0001`/`13 §3`）とする。
> **H.264 は `--enable-libopenh264` で OpenH264 を使用**し、**Ciscoが配布する公式バイナリ**を用いることで AVC特許料の自前取得を不要にする。音声は **AAC**。

## 結果・影響

- OpenH264エンコーダは概ね **Constrained Baseline プロファイル** → 採用動画には十分。libx264より圧縮効率は劣り、ファイルがやや大きくなる。
- **実装**：Cisco公式バイナリの取得（Ciscoの配布条件に従い同梱、または実行時取得）。FFmpegは `libopenh264` 有効ビルド。`infrastructure/ffmpeg` 越しに呼ぶ。
- 入力動画のH.264デコードはFFmpeg/OpenH264で対応。
- アプリ内「クレジット/ライセンス」画面に FFmpeg(LGPL)＋ソース入手手段を明記（`13 §9`）。

## 未解決の論点

- 商用配布における最終的な法務スキム（OpenH264のバイナリ取得方式の確定含む）。
- **AAC音声**も同様の特許背景（ソフトウェアでの実害は小）。完全な特許回避が要件化した場合は **AV1/WebM の任意出力**を将来追加する。
