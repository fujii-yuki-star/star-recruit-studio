## コンテキスト

ADR-0016 の **④ キーフレーム／場面内アニメ**を設計する。要素の移動・拡大・不透明度等を**時間で補間**し、場面＝連続フレームにする。`§10`「キーフレーム」を緩和し、**ADR-0001（場面内は静止・単一フレーム）を置換**する。④は ADR-0016 で**最重量**と位置づけられている。

### 現状と「既に用意された拡張点」
- ADR-0001（A2ハイブリッド）は **場面内を静止**とし、場面ごとに `layoutScene(scene, template)`→`layoutToSvg()`→PNG **1枚**を焼いて FFmpeg が尺ぶん保持する（`src/renderer/layout.ts`・`sceneSvg.ts`・`buildExportScenes.ts`）。動くのは動画スロットの中身と音声のみ。
- **重要**：ADR-0001 は**選択肢C＝「毎フレームをWeb描画してフレーム列→動画」を“Aの自然な拡張・将来オプション”として明記**（ADR-0001 の「選択肢C（将来オプション）」節・「決定」節）。**④はこの選択肢Cを発火させる**ものであり、描画方式の作り直しではなく**既存共有ロジックへの時間軸の導入**である。
- **パリティ**（ADR-0001 の生命線）：preview と export が**同一SVG＋同一ラスタライザ**（ADR-0004 WebView Canvas）を使えば一致は構造的に保証される（ADR-0001「スパイク結果」＝同一SVGを同一ラスタライザで描けば byte-identical）。④では**これをフレーム t ごとに拡張**する。
- **キーフレームの置き場**：ADR-0018（2モデル方式）で、時間軸の高度編集は**場面アンカーのオーバーレイ層**に保存し AI/簡易は無視、と決めた。④のキーフレームは**このオーバーレイに乗る**（ADR-0018 未解決6 を本ADRで回収）。

---

## 判断軸

1. **パリティ最優先の維持**（ADR-0001）：アニメでも preview＝完成品。**フレーム t の描画を preview/export で一致**させる。
2. **AI 親和性・単一パイプライン**（ADR-0007 M-A・ADR-0018）：キーフレームは**オーバーレイ**に置き、AI 出力・場面ベース正準は不変。AI はアニメを生成しない。
3. **後方互換・段階出荷**：**アニメの無い場面は従来どおり静止1枚**（経路・コスト不変）。アニメのある場面だけ毎フレーム化。
4. **非力PCでの速度**（`01 §15.2`）：尺×fps のコスト増を**選択的per-frame＋プレビュー軽量化**で抑える。
5. **§10 を必要分だけ緩和**：④は「要素の補間」。**口パク・3D・複雑エフェクトは引き続き §10 外**。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| **(A) 毎フレーム Web 描画＝ADR-0001 選択肢C の発火【採用】** | `layoutScene` に**時間 t** を与え、キーフレーム補間後のレイアウトを **SVG→PNG をフレームごと**に焼く。preview/export は同一経路・同一ラスタライザ＝**パリティをフレーム単位で構造保証**。既存共有ロジックの自然拡張。アニメ無し場面は静止1枚を維持。 |
| **(B) FFmpeg 側でアニメ（zoompan/rotate/fade フィルタ）** | 中間PNG不要で高速だが、**ブラウザの折返し・座標・体裁とズレ**＝ADR-0001 が選択肢B を退けた理由（パリティ破壊）と同じ。**不採用**。 |
| **(C) プレビューのみ CSS アニメ・書き出しは静止** | 実装は軽いが **preview≠export** で製品の生命線（パリティ）に反する。**不採用**。 |

## 決定（Proposed）

> **ADR-0001 の選択肢C（毎フレーム Web 描画）を発火させて場面内アニメを実装する。`layoutScene` に時間 t を導入し、キーフレーム補間後のレイアウトを SVG→PNG でフレームごとに焼く。キーフレームは ADR-0018 のタイムライン・オーバーレイに置き（AI/場面ベース正準は不変）、アニメの無い場面は従来どおり静止1枚を維持する。これにより ADR-0001 の「場面内静止」を（アニメ場面について）supersede する。**

### 描画モデル（per-frame）
- **`layoutScene(scene, template, timeSec?)`**：t 未指定＝従来の静止（後方互換）。t 指定＝**キーフレームを補間したレイアウト**を返す（domain 純粋関数・§7 テスト対象＝補間は決定論的）。
- **A2ハイブリッドは維持**：各フレームで「下PNG／動画スロット／上PNG」を ADR-0001 どおり分割。動画スロットは引き続き FFmpeg が合成。
- **選択的per-frame**：**キーフレームを持つ場面だけ** fps×尺ぶんのフレームを生成。持たない場面は**静止1枚**（経路・コスト不変＝後方互換）。
- **パリティ（フレーム単位）**：preview と export は**同一の `layoutScene(…, t)`＋同一SVG＋同一ラスタライザ**（ADR-0004）でフレーム t を描く＝ADR-0001 のパリティ保証を時間方向へ拡張。

### キーフレームのデータ（ADR-0018 オーバーレイに格納）
- キーフレームは **ADR-0018 の `timelineOverlay`**（場面アンカー・任意）に置く。**AI 出力・`project.scenes` 正準・簡易編集は不変**（AI はアニメを作らない＝`12` 変更なし）。
- 編集は**二層**（利用者合意 2026-07-02・ADR-0023 役割分担）：**簡易プリセット（「ふわっと表示」＝フェードイン等）は場面編集画面**（FREE 要素プロパティの隣で付け外し。FREE 要素は `§2-4` の座標例外＝そもそも手で配置する面）／**詳細なキーフレーム編集（複数KF・移動/拡縮/回転・イージング選択）は上位仕上げ＝タイムライン編集面**（別画面）に隔離する。データは同一の `timelineOverlay.animations`（どちらで触っても同じ・ADR-0023 の「両面で分断しない」）。当初 §54 は「編集はタイムライン別画面」としていたが、簡易プリセットに限り FREE の座標例外に沿って場面編集へ置くと明確化（`§2-4` の「通常編集で座標を毎回触らせない」は詳細キーフレーム編集に適用）。

### アニメ対象（初期サブセット・**決定**・利用者合意 2026-07-02）
- **プロパティ**：**位置（x/y）・拡大縮小（scale）・不透明度（opacity）・回転（rotation）** ＋ イージング（**linear / ease-in-out** で開始・他は将来）。
- **対象要素**：**FREE 要素＋グループ**（ADR-0022 のグループは元々アニメ対象として想定）。**通常テンプレのレイヤーは初期対象外**（テンプレ駆動 §2-4 との棲み分け＝座標はテンプレが決める。掛けたい要件が出たら別途拡張）。
- **見送り（§10 のまま）**：色トゥイーン・パス／モーション軌跡・マスク・**口パク**・3D。Ken Burns（背景のゆっくり寄り）は位置＋拡大の特例として表現可能。

### ADR-0001 の扱い
- 本ADR承認＋④実装時、ADR-0001 を **「Superseded by ADR-0019（アニメ場面の per-frame 描画について）」** に更新。**静止場面の A2 経路・パリティ原則・共有ロジックは存続**＝ADR-0001 の核は生きたまま、「場面内は常に静止」という制約だけを置換する。

## 結果・影響

- **コード（α-4）**：`layoutScene` に時間引数（または `layoutSceneAtTime`）＝補間の純粋関数（§7 テスト）／`renderer/export` がアニメ場面を**フレーム列**に展開（fps×尺）→ FFmpeg 連結（既存 concat/xfade を流用）／`renderer/preview` は同一補間で再生。**キーフレームのスキーマは ADR-0018 の `timelineOverlay` に内包**（④独自の新トップレベルは作らない）。
- **正典追補（実装着手時）**：`§10` の「キーフレーム」を**段階解除**（ADR-0012/0015/0018 と同型の注記）。`05_RENDERING_SPEC.md` に**per-frame 経路とフレーム単位パリティ**を追補。`11` にキーフレーム表現（オーバーレイ内）と補間契約を追記。`ADR-0001` の状態を Superseded（部分）へ。
- **パフォーマンス**：尺×fps（例 15s×30fps＝450フレーム/場面）。緩和＝**選択的per-frame**（アニメ場面のみ）／プレビューの**間引き fps・キャッシュ・スクラブ時オンデマンド**／長尺×多数アニメ場面の上限ガイド。`02` Phase 0 と同様に**小さく実証**してから本実装。
- **AI（`12`）**：**変更なし**（AI はアニメを生成しない）。
- **段階出荷**（利用者合意 2026-07-02・入口＝(1)）：
  - **(1) per-frame 基盤＋1アニメで end-to-end 実証**：`layoutScene(scene, template, t?)` の補間（t なし＝静止で後方互換）＋書き出しが**アニメ場面だけフレーム列**に展開（静止場面は1枚維持）＋プレビュー＝export の同一補間。最小アニメ＝**FREE 要素の不透明度フェードイン**1種でパリティを実証。**(1c) オーサリング【実装済】**＝場面編集の「ふわっと表示」プリセットで FREE 要素（図形/文字/画像）にフェードインを付け外し（`fadeInKeyframes`・`addAnimation`/`updateAnimation`/`removeAnimation`）。**opacity を text/image にも適用**（従来は fill のみ＝`sceneSvg` が `<g opacity>` で要素全体を敷く）＝図形以外の写真・文字もふわっと表示できる。
  - **(2) 移動/拡縮/回転＋イージング**（linear/ease-in-out）を FREE 要素＋グループへ。
  - **(3) 複数キーフレーム・グループ・Ken Burns/プリセット**（フェード/スライド/ポップ/ゆっくりズーム/写真パン）。
  - **(4) 音量キーフレーム**（将来・ADR-0023 統合再生と連動）。
  - 各版で `check:frontend` 緑＋**フレーム単位パリティ**確認。非力PC 向けにプレビュー間引き・キャッシュは (1) から織り込む。

## 決定済み（Accepted・2026-07-02）

1. **アニメ対象サブセット**＝位置(x/y)/拡縮(scale)/不透明度(opacity)/回転(rotation)＋イージング(linear/ease-in-out)。**FREE 要素＋グループ**（テンプレレイヤーは初期対象外）。（決定）
2. **プレビューのパリティ戦略**＝**二層**（正本＝再生/最終確認は export と同じ per-frame ラスタライズ／編集中スクラブは DOM 近似で軽く・**補間式は単一の `layoutScene(t)` を共有**して数値一致）。ADR-0023 の推奨に一致。（決定）
4. **fps**＝**30固定**（秒=正準・フレーム=量子化＝ADR-0023/0024 周辺方針）。プレビューは間引き・キャッシュ・スクラブ時オンデマンドで軽量化。（決定）
5. **要素の対象範囲**＝**FREE 要素＋グループ**（初期）。通常テンプレのレイヤーは §2-4 の棲み分けで初期対象外（要件次第で拡張）。（決定）
7. **口パク・3D・複雑エフェクト**＝§10 のまま**対象外**。（決定）
9. **アニメ編集UIの置き場**（利用者合意 2026-07-02・(1c)）＝**簡易プリセット（ふわっと表示）は場面編集画面／詳細なキーフレーム編集は将来タイムライン（上位仕上げ面・ADR-0023）**。上記「キーフレームのデータ」の二層。データは同一の `timelineOverlay.animations`。（決定）

## 未解決の論点（実装着手 PR で確定）
