# ADR-0044: 色の調整と描画モードを入れる（クロマキーとマスクは入れない）

- **状態**: Accepted
- **日付**: 2026-09-17（利用者判断）
- **関連**: [`ADR-0001`](0001-rendering-parity.md)・[`ADR-0032`](0032-timeline-project-format.md) 決定19・[`ADR-0043`](0043-alpha-beta-scope-and-general-backlog.md)・[#1192](https://github.com/fujii-yuki-star/star-recruit-studio/issues/1192)・#634

## 背景

[`audits/2026-09-17-video-editing-maturity.md`](../audits/2026-09-17-video-editing-maturity.md) で、
**カラー補正・クロマキー・マスク・描画モード**が**どこにも行き先を持たないまま消えていた**ことが分かった（#1192）。

⚠️ **外したときの理由（#634）が、いまは成り立たない。**

> プレビュー＝書き出しの一致を保つのが一気に難しくなるため（**Web 描画と FFmpeg で色が合う保証が要る**）

**書き出しは FFmpeg で絵を描いていない**（実装を読んで確認）：

```
layoutToSvg（プレビューと同じ）→ SVG 文字列 → <img> → canvas.drawImage → PNG → FFmpeg は PNG を並べるだけ
```

＝**FFmpeg は色を作らない**ので、**SVG の側で効く表現は、プレビューと書き出しで必ず一致する**。
⚠️ **既に証拠がある**＝**文字の影（#264）は SVG の `<filter>` で実装され、書き出しにも出ている**。

> ⚠️ **ただし「場面の中」の話です**（PR #1200 レビュー 🟡）。
> **場面をまたぐ切り替え（`xfade`）は、いまも FFmpeg が色を混ぜています**（`ffmpeg.rs` の `xfade_chain_args`）。
> これは**前からある例外**で、[`ADR-0001`](0001-rendering-parity.md)／[`ADR-0009`](0009-scene-transitions.md) が
> **パリティの約束を「場面の中」に限っている**ぶんです（本決定はそこを変えません）。
> ⚠️ **言い切ると誤読される**＝「FFmpeg は常に色を作らない＝切り替え中の色もプレビューと一致する」と
> 読まれかねないので、射程を書いておきます。
> #634 の「色が合う保証が要る」は、**①②（場面の中の色と混ぜ方）については崩れました**が、
> **`xfade` については今も現役の懸念**です。

### 実測（アプリと同じ道で焼いて、1画素を読んだ）

| 使った仕組み | 焼けた色（元は `255,0,0`） | |
|---|---|---|
| `feComponentTransfer`（明るさ 0.5） | `187,0,0` | ✅ |
| `feColorMatrix type="saturate" 0` | `127,127,127` | ✅ |
| **`mix-blend-mode: multiply`**（CSS） | `0,0,0` | ✅ |
| `feBlend mode="multiply"`（SVG） | `0,0,0` | ✅ |

⚠️ **`filter` の既定の色空間は linearRGB**（明るさ 0.5 が 127 でなく **187** になったのはこれ）。
**直感どおりの値にするなら `color-interpolation-filters="sRGB"` を付ける。この1行を忘れると見た目が合わない。**

## 決定

### ① **色の調整**を入れる（α）

**明るさ・コントラスト・彩度・色温度**の4つ。⚠️ **カーブ・ホワイトバランスのスポイトは入れない**（別の段）。

- 置き場＝部品（クリップ／FREE 要素）。`ItemBase` に `colorAdjust?` を持たせ、`sceneSvg` が `<filter>` を出す
- ⚠️ **影とまったく同じ形**＝`<defs><filter>` を中身から作った id で出し、同じ設定なら共有する
- ⚠️ **`color-interpolation-filters="sRGB"` を必ず付ける**

**なぜ α か**＝**安く、毎回使う**から。暗いゲーム録画を持ち上げる・素材の明るさを揃えるは**普通の編集で毎回やる**こと。
初心者にとっては**取り込んだ絵が暗い**が最初の壁で、そこで詰まると作り込み以前で終わる。

### ② **描画モード**を入れる（α）

**通常・乗算・スクリーン・加算・オーバーレイ**の5つ。⚠️ **それ以上は増やさない**。

- ⚠️ **合成の単位（ADR-0032 決定19）と噛む**＝合成の単位は「1枚に畳んでから α を掛ける」仕組みなので、
  **混ぜるのは畳む前**（部品どうしが混ざる）。畳んだ後に混ぜると、**フェード中だけ混ざり方が変わる**。

**なぜ α か**＝**演出の土台**だから。光・煙・集中線・グロウはほぼ全部これが要る。
これが無いとテンプレートをいくら増やしても（#1187）**光り物が作れない**＝「派手な実況系に耐える」が成立しない。

### ②-2 ⚠️ **場面形式では、動画に掛かると「毎フレーム描画」へ倒す**（実装前に見つけた穴）

> ⚠️ **この決定は実装時に変えました＝下の「追補1」を読んでください。**
> 穴の見立て（下の説明）はそのまま正しく、**塞ぎ方だけ**が「毎フレームへ倒す」から「場面形式には持たせない」に変わりました。

**上の「SVG で効く表現は必ず一致する」は、**場面形式の書き出しでは**そのままでは成り立ちません**。

場面形式の書き出しは、**実際の動画を FFmpeg で流す**ために絵を層に割って渡します：

```
below（PNG）→ 動画 → mid（PNG）→ 動画2 → above（PNG）   ← 重ねるのは FFmpeg
```

⚠️ **FFmpeg が重ねる所では、SVG の混ぜ方も色の調整も効きません**＝

- **動画の差し込み口に色の調整**を掛けても、**動画は PNG に焼かれていない**ので掛からない
- **動画の上の部品に描画モード**を付けても、FFmpeg は**普通の重ね方**でしか合成しない

→ **プレビューには出るのに、書き出しに出ない**（ADR-0001 が禁じている当のもの）。

**決定**＝**その場面を「毎フレーム描画」へ倒す**。
⚠️ **新しい仕組みではありません**＝**アニメのある場面は既にそうしている**（ADR-0019・`buildExportScenes`）。
⚠️ **ただし射程が違う**＝アニメは**動きが収まるまで**で済むが、こちらは**その場面の最後まで**倒す必要がある
（色や混ざり方は時間で収まらないため）。

**倒す条件**（実装で判定する）：

1. **動画の差し込み口**（または動画のクリップ）に**色の調整**が掛かっている
2. **動画より前面の部品**に**通常以外の描画モード**が付いている

⚠️ **タイムライン形式は関係ありません**＝あちらは**全部を毎フレーム描画**しているので、最初から一致します。

⚠️ **この但し書きが無いと、機能を足した瞬間に ADR-0001 が割れます。**
実装より先に見つけられたのは、書き出しの層分けを読んだからです（#634 の「色が合う保証」とは**別の問題**）。

### ③ **クロマキーは入れない**（β 含め）

**一応できる**（`feColorMatrix` ＋ `feComponentTransfer` で緑を抜く）。⚠️ **でも入れない。**

⚠️ **スピル除去も縁のぼかしも無い**＝**緑が残り、輪郭がギザギザ**になる。
しかも**直す道がこのソフトの中に無い**（スピル除去もマットの調整も無い）＝
**§2-5 の「次の行動が無い」状態を、機能として作ることになる**。

⚠️ **利用者にほぼ要らない**＝立ち絵は**最初から透明な PNG**、配信も**透過で出す**のが普通。
グリーンバックを使う人は**手前（OBS 等）で抜いている**。

**戻す条件**＝「**透過でない実写のワイプを合成したい**」という要望が実際に出たとき。
そのときは**抜く品質まで含めて**設計する（いまの SVG フィルタの範囲では足りない）。

### ④ **マスクは入れない**（β 含め）

⚠️ **安い版（四角で隠す）はもう在る**＝**切り抜き（クロップ）**（#634）＋**図形を重ねる**で同じことができる。
**高い版（自由な形・動くマスク・追尾）は別の段の製品**＝形を描く道具・時間で動かす仕組み・解析まで要る。

⚠️ **「マスク」という名前で安い版を出すと、高い版を期待した人が必ず落胆する**（名前が期待を作る）。

**戻す条件**＝**通常の編集と高度合成/MV 制作の境目**を引き直すとき。
そのときは「マスク」ではなく**何をしたいか**（丸く抜く／人物だけ残す／光を形に沿わせる）から決める。

## 結果

- ①② は **α** で実装する。⚠️ **ただし持たせるのはタイムライン形式だけ**（追補1）
  ＝場面形式は凍結（ADR-0032）なので欄そのものを足さない。②-2 の「毎フレーム描画へ倒す」は**実装しない**。
- ③④ は **`CLAUDE.md §10`（やらないこと）の表へ足す**＝⚠️ **「やらない」も実在する箱**（ADR-0043 決定③）。
- #634 の「色が合う保証が要る」という理由は**もう使わない**（前提が違っていた）。


## 追補1（2026-09-17・実装時）⚠️ **②-2 は「倒す」のではなく「持たせない」に変える**

②-2 は「場面形式で動画に効かないなら、毎フレーム描画へ倒して合わせる」という決定でした。
実装に入って**もっと安くて強い塞ぎ方**が見つかったので、そちらへ変えます。

**決定**＝`colorAdjust` / `blendMode` を**持てるのは `TimelineClip` だけ**にする。
`project.schema.json` の `FreeElement` には**足さない**（`$defs` は共有語彙の置き場として置いたまま＝写しを作らないため）。
場面形式の `schemaVersion` は **1.29 のまま**＝場面形式の文書が表せる中身は**1つも変わらない**。

**なぜ変えたか**

1. ⚠️ **凍結（ADR-0032）に反していた。** 場面形式で続けてよいのは**不具合修正・AI 生成の品質・テンプレ・素材と声・
   書き出しの共通核・文言と操作性**の6つで、**新しい編集能力は入っていません**。①② は明らかに新しい編集能力です。
   ②-2 は「凍結した形式へ新機能を足すための追加工事」になっていました。
2. ⚠️ **穴を塞ぐより、穴へ届く道を作らない方が強い。** 欄を足さなければ、場面形式の文書は**この状態を表せません**
   （`additionalProperties: false` が拒む）。判定も切り替えも要らず、**構造で** ADR-0001 が保たれます。
   判定を書いて分岐で守る形は、**判定を読み落とした瞬間に割れます**。
3. ⚠️ **書き出しのいちばん細い道に触らずに済む。** 毎フレーム描画への切り替えは `buildExportScenes`（#442/#444）
   に手を入れます。**凍結した形式のために**そこを触る利得がありません。
4. **費用差。** 倒す＝判定＋書き出しの分岐＋その場面の書き出し時間が数倍。持たせない＝schema に足さない（0行）。

**代わりに失うもの**（隠さずに書く）

- 場面形式では**取り込んだ絵が暗いときに持ち上げられません**（① の「最初の壁」は場面形式では残る）。
  ⚠️ **これは新しい制限ではありません**＝いまも出来ないことで、**出来るようにしないと決めた**だけです。
- 時間も色も触りたい人は**タイムライン形式へ焼き出す**（ADR-0032 の元々の道）。

**戻す条件**（将来これを覆すとき）

- 場面形式の凍結が解ける、または
- 実機試験（#1194）で「場面形式のままでも色の調整が要る」と分かる。

⚠️ **そのときは②-2 を捨てずに読み直してください**＝上に書いた**倒す条件2つ**（動画に色の調整が掛かる／
動画より前面で通常以外の描画モードを使う）は、判定としてそのまま使えます。

## 採らなかった案

| 案 | なぜ採らないか |
|---|---|
| **4つとも `general-backlog` のまま** | ①② は**安くて毎回使う**。将来枠へ置くと、テンプレを増やす作業（#1187）が**土台の無いまま進む** |
| **4つとも α で入れる** | ③④ は**中途半端なものを置く方が悪い**（上の理由） |
| **②-2 のとおり毎フレームへ倒す** | 追補1のとおり＝**凍結した形式へ新機能を足す**ことになり、書き出しの細い道にも触る（塞ぐより、届く道を作らない方が安い） |
| **FFmpeg のフィルタで実装する** | ⚠️ **描画核が二重になる**（ADR-0001 が禁じている当のもの）。SVG で足りるのに、合わない道を増やさない |
