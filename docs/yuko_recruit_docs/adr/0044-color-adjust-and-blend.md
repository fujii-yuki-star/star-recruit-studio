# ADR-0044: 色の調整と描画モードを入れる（クロマキーとマスクは入れない）

- **状態**: Accepted
- **日付**: 2026-09-17（利用者判断）
- **関連**: [`ADR-0001`](0001-rendering-parity.md)・[`ADR-0032`](0032-timeline-project-format.md) 決定19・[`ADR-0043`](0043-alpha-beta-scope-and-general-backlog.md)・[#1192](https://github.com/fujii-yuki-star/star-recruit-studio/issues/1192)・#634

## 背景

[`audits/2026-09-17-video-editing-maturity.md`](../audits/2026-09-17-video-editing-maturity.md) で、
**カラー補正・クロマキー・マスク・描画モード**が**どこにも行き先を持たないまま消えていた**ことが分かった（#1192）。

⚠️ **外したときの理由（#634）が、いまは成り立たない。**

> プレビュー＝書き出しの一致を保つのが一気に難しくなるため（**Web 描画と FFmpeg で色が合う保証が要る**）

**書き出しは FFmpeg で絵を描いていない**（実装を読んで確認）：

```
layoutToSvg（プレビューと同じ）→ SVG 文字列 → <img> → canvas.drawImage → PNG → FFmpeg は PNG を並べるだけ
```

＝**FFmpeg は色を作らない**ので、**SVG の側で効く表現は、プレビューと書き出しで必ず一致する**。
⚠️ **既に証拠がある**＝**文字の影（#264）は SVG の `<filter>` で実装され、書き出しにも出ている**。

### 実測（アプリと同じ道で焼いて、1画素を読んだ）

| 使った仕組み | 焼けた色（元は `255,0,0`） | |
|---|---|---|
| `feComponentTransfer`（明るさ 0.5） | `187,0,0` | ✅ |
| `feColorMatrix type="saturate" 0` | `127,127,127` | ✅ |
| **`mix-blend-mode: multiply`**（CSS） | `0,0,0` | ✅ |
| `feBlend mode="multiply"`（SVG） | `0,0,0` | ✅ |

⚠️ **`filter` の既定の色空間は linearRGB**（明るさ 0.5 が 127 でなく **187** になったのはこれ）。
**直感どおりの値にするなら `color-interpolation-filters="sRGB"` を付ける。この1行を忘れると見た目が合わない。**

## 決定

### ① **色の調整**を入れる（α）

**明るさ・コントラスト・彩度・色温度**の4つ。⚠️ **カーブ・ホワイトバランスのスポイトは入れない**（別の段）。

- 置き場＝部品（クリップ／FREE 要素）。`ItemBase` に `colorAdjust?` を持たせ、`sceneSvg` が `<filter>` を出す
- ⚠️ **影とまったく同じ形**＝`<defs><filter>` を中身から作った id で出し、同じ設定なら共有する
- ⚠️ **`color-interpolation-filters="sRGB"` を必ず付ける**

**なぜ α か**＝**安く、毎回使う**から。暗いゲーム録画を持ち上げる・素材の明るさを揃えるは**普通の編集で毎回やる**こと。
初心者にとっては**取り込んだ絵が暗い**が最初の壁で、そこで詰まると作り込み以前で終わる。

### ② **描画モード**を入れる（α）

**通常・乗算・スクリーン・加算・オーバーレイ**の5つ。⚠️ **それ以上は増やさない**。

- ⚠️ **合成の単位（ADR-0032 決定19）と噛む**＝合成の単位は「1枚に畳んでから α を掛ける」仕組みなので、
  **混ぜるのは畳む前**（部品どうしが混ざる）。畳んだ後に混ぜると、**フェード中だけ混ざり方が変わる**。

**なぜ α か**＝**演出の土台**だから。光・煙・集中線・グロウはほぼ全部これが要る。
これが無いとテンプレートをいくら増やしても（#1187）**光り物が作れない**＝「派手な実況系に耐える」が成立しない。

### ③ **クロマキーは入れない**（β 含め）

**一応できる**（`feColorMatrix` ＋ `feComponentTransfer` で緑を抜く）。⚠️ **でも入れない。**

⚠️ **スピル除去も縁のぼかしも無い**＝**緑が残り、輪郭がギザギザ**になる。
しかも**直す道がこのソフトの中に無い**（スピル除去もマットの調整も無い）＝
**§2-5 の「次の行動が無い」状態を、機能として作ることになる**。

⚠️ **利用者にほぼ要らない**＝立ち絵は**最初から透明な PNG**、配信も**透過で出す**のが普通。
グリーンバックを使う人は**手前（OBS 等）で抜いている**。

**戻す条件**＝「**透過でない実写のワイプを合成したい**」という要望が実際に出たとき。
そのときは**抜く品質まで含めて**設計する（いまの SVG フィルタの範囲では足りない）。

### ④ **マスクは入れない**（β 含め）

⚠️ **安い版（四角で隠す）はもう在る**＝**切り抜き（クロップ）**（#634）＋**図形を重ねる**で同じことができる。
**高い版（自由な形・動くマスク・追尾）は別の段の製品**＝形を描く道具・時間で動かす仕組み・解析まで要る。

⚠️ **「マスク」という名前で安い版を出すと、高い版を期待した人が必ず落胆する**（名前が期待を作る）。

**戻す条件**＝**通常の編集と高度合成/MV 制作の境目**を引き直すとき。
そのときは「マスク」ではなく**何をしたいか**（丸く抜く／人物だけ残す／光を形に沿わせる）から決める。

## 結果

- ①② は **α** で実装する。
- ③④ は **`CLAUDE.md §10`（やらないこと）の表へ足す**＝⚠️ **「やらない」も実在する箱**（ADR-0043 決定③）。
- #634 の「色が合う保証が要る」という理由は**もう使わない**（前提が違っていた）。

## 採らなかった案

| 案 | なぜ採らないか |
|---|---|
| **4つとも `general-backlog` のまま** | ①② は**安くて毎回使う**。将来枠へ置くと、テンプレを増やす作業（#1187）が**土台の無いまま進む** |
| **4つとも α で入れる** | ③④ は**中途半端なものを置く方が悪い**（上の理由） |
| **FFmpeg のフィルタで実装する** | ⚠️ **描画核が二重になる**（ADR-0001 が禁じている当のもの）。SVG で足りるのに、合わない道を増やさない |
