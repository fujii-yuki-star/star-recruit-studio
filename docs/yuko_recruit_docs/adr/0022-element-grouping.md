# ADR-0022: 要素のグループ化（groups＋独自transform）

- **状態**: Accepted（2026-06-30・利用者要望／α-3 追加・**v0.3.0 に含む**・実装は EPIC サブPRに分割）
- **日付**: 2026-06-30
- **関連**: [`adr/0008`](0008-free-layout-editor.md)（FREE 自由配置）/ [`adr/0017`](0017-template-authoring-editor.md)（テンプレ作成エディタ）/ [`adr/0001`](0001-rendering-parity.md)（描画パリティ・**本ADRが合成で維持**）/ [`adr/0007`](0007-detailed-edit-mode.md)（単一パイプライン M-A）/ [`adr/0019`](0019-keyframe-animation-model.md)（キーフレーム・グループ transform は将来の animation 対象）/ #300（回転グループリサイズ）/ `project.schema.json`・`template.schema.json`
- **対象**: 要素（図形/素材/文字／レイヤー）の**永続グループ化**。**FREE（`scene.freeLayout`）＋ テンプレ作成（`template.layers`）の両エディタ**。

---

## コンテキスト
利用者要望：選択した複数要素を「**グループ**」として束ね、**まとめて管理**（移動/拡縮/回転/非表示/ロック/重ね順）したい。見た目パーツ作成・場面編集の両方で使い勝手が大きく変わる。

### 現状（調査）
- **グループ概念は未実装**（`groupId`/`groups` なし）。
- **FREE エディタ**（`FreeLayoutOverlay`）：複数選択＋一時的な一括移動/拡縮はあるが、**選択解除で束ねは消える**（永続グループではない）。
- **テンプレ作成エディタ**（`TemplateLayerOverlay`）：**単一選択のみ**（複数選択・グループ操作なし）→ グループ化には**複数選択の追加が前提**。
- `FreeElement`＝id/kind/x/y/w/h/zIndex/rotation/assetId/hidden/locked/fit/text。`Layer`＝同種の幾何＋型別。

---

## 決定の判断軸
1. **パリティ堅持（ADR-0001）**：描画はプレビュー＝書き出しで一致。グループ transform も**共有 layout で前合成**して `LayoutItem` に落とす。
2. **単一パイプライン非汚染（ADR-0007）**：グループは**編集・描画の上位概念**。AI 出力にグループは無く、AI/簡易は従来どおり。
3. **両エディタ共通**：FREE と テンプレで同じグループモデル・操作を共有（純粋 ops 流用）。
4. **後方互換**：`groups` は任意追加（無ければ従来どおり）。

---

## 検討した選択肢（確定済み・ヒアリング）

### モデルと変形
- (a) flat `groupId`＋バインドのみ（メンバー座標を直接更新・描画不変） / **(b) `groups` 配列＋独自 transform【採用】**（グループが位置/回転/スケールを持ち描画で合成・SVG `<g>` 的・ネスト視野）。
  - **(b) 採用理由**：グループ transform を**単一の編集対象**にでき、将来 **α-4 のキーフレーム（ADR-0019）でグループごとアニメ**できる（自然な animation 対象）。バインド(a)はこの拡張性が無い。

### 対象
- FREE のみ / **FREE＋テンプレ両方【採用】**（テンプレは複数選択を新設してから）。

### タイミング
- v0.3.1 へ分割 / **v0.3.0 に含める【採用】**（リリースは急がない）。

---

## 決定

> **要素を「グループ」（独立オブジェクト・自前の transform を持つ）に束ねられるようにする。描画は共有 layout でグループ transform を前合成して `LayoutItem` に落とし、`sceneSvg`/書き出しは従来どおり＝パリティ維持。FREE とテンプレの両エディタで使え、テンプレ側は複数選択を新設する。**

### データモデル
- **`Group`**：`{ id（group_NNN・scene/template 内一意）, members: string[]（メンバー id＝要素/レイヤー、ネストでグループ id も可）, transform: { x, y, rotation, scale }, name?, zIndex?, hidden?, locked? }`。
- 保存：FREE＝`scene.groups: Group[]`、テンプレ＝`template.groups: Group[]`。
- メンバーは**最大1グループに属す**（木構造＝森）。`transform` は**グループ中心**（メンバー bbox 中心 or 保存アンカー）基準で回転/スケール。
- メンバー要素は**従来どおり自分の座標を保持**（canvas 基準）。グループ transform は**その上に合成**（ネストは親から順に）。**ungroup は transform をメンバーへ焼き込んで**解除。

### 描画の合成（最大の山・パリティ直結）
- **共有 layout**（`layoutScene` 等）で、各メンバーの最終 geometry ＝ 所属グループの transform を（ネストは親から順に・中心基準で）**合成**して算出 → `LayoutItem` の x/y/w/h/rotation に落とす。
- これにより `sceneSvg`/`buildExportScenes` は**従来の `LayoutItem` を描くだけ**＝**プレビュー＝書き出しが一致**（ADR-0001）。
- 合成数式（平行移動＋中心回転＋中心スケール＋ネスト合成）は**純粋関数にしてテスト必須**（回転リサイズ `resizeRotatedFreeElement` と同系統の数学）。

### 操作（両エディタ）
- **グループ化**（選択→束ね）/ **解除**（ungroup・transform 焼き込み）。
- **グループ選択**：メンバークリックで**グループごと選択**（個別編集へ潜るのはダブルクリック等＝将来）。
- 一括 **移動/拡縮/回転**（グループ transform を更新）。
- グループ単位の **非表示/ロック/重ね順**、複製/コピペ/削除。

### 段階出荷（EPIC サブPR）
1. **モデル＋描画合成**：schema（`groups`）＋ 合成ロジック（layout 前合成）＋ 純粋関数テスト。UI 無しで描画が通る土台。← **最大の山**
2. **FREE のグループ UI**：グループ化/解除・グループ選択・一括変形・非表示/ロック/重ね順（既存の複数選択を土台）。
3. **テンプレの複数選択 新設**：`TemplateLayerOverlay` に複数選択を追加（FREE の純粋 ops 流用）。
4. **テンプレのグループ UI**：3 の上にグループ操作。
5. **コピペ/複製/削除のグループ対応＋仕上げ**。

### 崩さない不変条件
- **パリティ（ADR-0001）**：合成は共有 layout で行い preview/export 同一。
- **単一パイプライン（ADR-0007）**：グループはエディタ/描画の上位構造。**AI 出力（ai-video-plan）にグループは無い**＝AI/簡易は従来どおり（グループは詳細編集で作る）。
- **後方互換**：`groups` 任意・無ければ従来描画。

### 正典の追補（実装PRで）
- `project.schema`：`scene.groups`（任意）＝**版上げ（1.13→1.14）**。`template.schema`：`template.groups`（任意・非破壊ゆえ**版据え置き**＝`11 §1`）。
- `11 §2.x`：`group_NNN`（scene/template 内一意）を ID 表へ。
- `06_UI_SPEC`：FREE/テンプレ編集にグループ操作を追記。

### ADR-0019（キーフレーム）との関係
- グループの `transform` は α-4 のキーフレーム（ADR-0019）で**アニメ対象**にできる（位置/回転/スケールを時間で動かす）。本ADRの独自 transform 採用はこの拡張性も見込む。

## 未解決（実装で確定）
1. `transform` の正確な表現（中心アンカーの保存有無・`scale` は一様/縦横別）。
2. グループ選択 UI（メンバー個別編集へ潜る操作＝ダブルクリック等）の確定。
3. ネストの深さ制限・循環防止。
4. グループと #300（回転要素の複数リサイズ）の整理（グループ transform で回転リサイズが自然に解決する可能性）。
5. コピペ時のグループ id 再採番・メンバー id 整合。
6. メンバーの存在検証（V_group）：`members` に存在しない id を含めてもサイレント無視（合成は空矩形＝堅牢性優先）。不正参照の検証は⑤[#308] で `§8` 検証ルール表に追補予定（#310 レビュー指摘）。
