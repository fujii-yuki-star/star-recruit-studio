# ADR-0033: 編集画面のパネル配置を利用者が変えられるようにする（ドッキング方式）

- **状態**: Proposed（2026-08-03・利用者ヒアリング完了／実装は承認後）
- **日付**: 2026-08-03

## コンテキスト

**利用者から3度目の同種の要望**（2026-08-03）。

> 今の画面レイアウトだと不便すぎます。前にもこれ関連で改善要望を別画面で出したのですが、スクロールが多すぎて手間にしかなりません。
> **特にタイムライン編集に関してはそういった必要ない手間を極限まで軽減しないととてもUXの悪いものになってしまいます。**
> **それぞれの項目のサイズの変更と、配置の変更を自由にできるようにするのをまず最低条件としたいです。**

**過去2回の対応は、いずれも「こちらが決めた形」で応えていた。**

| # | 要望 | 対応 |
|---|---|---|
| [#276](https://github.com/fujii-yuki-star/star-recruit-studio/issues/276) | 場面編集のレイアウト改善 | 左折りたたみ・右パネルの横リサイズ・節のアコーディオン**を実装した**（配置は固定） |
| [#550](https://github.com/fujii-yuki-star/star-recruit-studio/issues/550) | 右パネルのスクロール量が多い | 既定の開閉状態を絞った（**どこに何を置くかは変えられないまま**） |

同じ要望が繰り返し出ているのは、**「表示量を減らす」方向では解けていない**ということ。利用者が求めているのは
**自分の作業に合わせて画面を組み替えられること**（サイズ＋配置）であって、こちらが最適と考えた固定レイアウトの調整ではない。

**タイムライン編集（ADR-0032）は特に切実。** 現状の `TimelineProjectScreen` は**カードの縦一列**
（仕上がり確認＋再生位置 → 並び → 選んだ部品 → 見た目パターンを置く → 音を置く → 読み上げを置く）で、
**再生位置は画面上部・部品の編集欄は中ほど**にある。実際に #512 の実機確認で
「再生位置を動かす → 音量の点を置く」を繰り返そうとして、**1点ごとに上下スクロール**が要ることが露呈した。
時間軸の編集は「位置を決める → 値を置く」の反復そのものなので、この往復はそのまま作業効率になる。

## 判断軸

1. **反復操作の手数を減らす**（利用者の言葉＝「必要ない手間を極限まで軽減」）。とくに**再生位置と編集欄を同時に見られる**こと。
2. **自由度は利用者に渡す**（[[ux-bar-detailed-editing]] の方針＝詳細編集は利便性・自由度・直感性が大前提）。最適解をこちらで決め打ちしない。
3. **壊れた状態を作らない**（`§2-5`）。パネルが行方不明・画面外・幅0 になる操作を残さない。**必ず「既定に戻す」で復帰できる**。
4. **正典データを汚さない**（`§5`）。画面の見た目の好みは**動画の中身ではない**＝`project.schema` / `timeline-project.schema` に入れない。
5. **一度作って複数画面で使う**（`§6`）。画面ごとに別の操作感を作らない。
6. **段階出荷**（`CLAUDE.md §8`）。最初の1画面で価値が出ること。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) 現状の延長＝節の開閉・既定表示量の調整をさらに進める | #276/#550 で2回やって**同じ要望が再発**した。配置は変えられないままなので、判断軸1・2を満たさない。**不採用** |
| **(B) ドッキング方式【採用】** | 画面を**領域**（左・中央・右・下）に分け、**どのパネルをどの領域へ置くかをドラッグで決める**。領域の境界をドラッグして**幅・高さも変える**。VS Code / Premiere に近い。自由度が上がる一方で**壊れた配置になりにくい**（パネルは必ずどこかの領域に属し、画面外へ出ない）。判断軸1〜3を同時に満たす。**採用**（利用者判断 2026-08-03） |
| (C) 完全フローティング（小窓を自由配置・重ね置き可） | 自由度は最大。ただし**隠れて見つからない・画面外へ出る・重なって触れない**が起こり、そのための復帰導線（整列・すべて表示・画面内へ戻す）が別途要る。判断軸3のコストが大きい。**不採用**（将来 (B) の上に足すことは可能） |
| (D) 並び替え＋サイズ変更のみ（一列のまま） | 実装は軽いが、**再生位置と編集欄を左右に並べる**ができない＝今回いちばん困っている往復が解消しない。**不採用** |

## 決定（Proposed）

> **編集画面のパネルを「ドッキング方式」で利用者が組み替えられるようにする。パネルは領域（左・中央・右・下）へ
> ドラッグで移動でき、領域の境界をドラッグして大きさを変えられる。決めた配置は**アプリ全体で1つ**記憶し、
> **いつでも既定に戻せる**。仕組みは共通部品として作り、**まずタイムライン編集画面へ適用**する。**

### 決定事項（利用者ヒアリング 2026-08-03）

| # | 論点 | 決定 |
|---|---|---|
| 1 | 配置の自由 | **ドッキング方式**（領域は決まっている・どのパネルをどこへ置くかは自由）。完全フローティングは採らない |
| 2 | サイズ変更 | **領域の境界をドラッグ**して幅・高さを変える（最小値でクランプ・0 にはしない） |
| 3 | 適用範囲 | **共通の仕組みとして作り、まずタイムライン編集へ適用**。場面編集・見た目パターン編集へは順次広げる |
| 4 | 記憶の単位 | **アプリ全体で1つ**（動画を開き直しても同じ配置）。動画ごと・画面ごとには持たない |
| 5 | 保存先 | **アプリの設定**（`infrastructure/appSettings`＝`localStorage`）。**プロジェクトの schema には入れない**（判断軸4） |
| 6 | 復帰 | **「配置を既定に戻す」を常に用意**（壊れた配置から必ず戻れる・`§2-5`） |
| 7 | パネルの粒度 | いまのカード（見出しつきの塊）をそのままパネルにする＝新しい概念を増やさない |
| 8 | 表示/非表示 | 使わないパネルは**閉じられる**。閉じたものは「表示するパネル」から戻せる（消えたまま戻せない、を作らない） |
| 9 | 行の操作 | **右クリックのメニューへ畳む**（利用者指摘 2026-08-03＝「隠す・固定・消す」の常時表示は邪魔）。行に残すのは**名前と状態**だけ。**同じメニューを開く小さな「⋮」も置く**＝右クリックを知らない・使えない（タッチ/キーボード）ときの逃げ道（`§2-5`） |
| 10 | 欄の中身の量 | **欄からはみ出さない**。一度に見せるのは**既定5件**、残りは**欄の中のスクロール**で辿る。多いときは**絞り込み**を出す。**しまって終わりにしない**（隠れて選べないものを作らない）＝見えている数も出す |

### 言葉（`§2-3`＝技術用語を出さない）

- パネル → **「欄」**（既存の画面で使っている語に合わせる。`06_UI_SPEC §3` の置換語に追加する）
- ドッキング／レイアウト → **「配置」**
- リセット → **「配置を既定に戻す」**

## 結果・影響

### コード

- **新設**：欄の配置を扱う共通部品（`src/app/components/layout/` を想定）＝領域の定義・ドラッグでの移動・境界のドラッグ・
  閉じる/戻す・既定へ戻す。**状態は純粋なデータ**（どの欄がどの領域にいくつ目か・各領域の大きさ）として持ち、
  **並べ方の計算（正規化・クランプ・既定への復帰）は domain の純粋関数**に置く（`§4`・テスト可能にする）。
- **保存**：`infrastructure/appSettings` に配置の読み書きを足す（`localStorage`・プロジェクト非依存）。
  **読めない/壊れている値は既定として扱う**（起動できない状態を作らない）。
- **適用**：`TimelineProjectScreen` のカードを欄として登録する。**中身のコンポーネントは変えない**
  （配置の仕組みだけを外から被せる＝既存の編集機能に回帰を起こさない）。

### 正典

- **`06_UI_SPEC`**：`§3`（置換語）に「欄／配置」を追加。`§12.1`（タイムライン編集画面）に配置変更の仕様を追記。
  共通の節（画面共通の操作）に「欄の配置」を新設する。
- **`11_SCHEMA_REFERENCE`**：**変更なし**（配置は永続データではない＝プロジェクトの schema に入れない）。
- **`15_ERROR_STATE_MODEL`**：配置を保存できないときの扱い（黙って諦めない／次の行動）を必要なら追加。
- **`CLAUDE.md §11`**：本ADRを追記（本PR）。

### 段階（承認後）

1. **仕組み**（domain の純粋関数＋共通部品＋保存）＝どの画面にも依存しない形で作る
2. **タイムライン編集へ適用**（欄の登録・既定の配置を決める・「配置を既定に戻す」）
3. **反復操作に効く既定**＝**再生位置と「選んだ部品」を同時に見られる**初期配置にする（今回の実機確認で判明した往復を、既定でも起こさない）
4. 場面編集・見た目パターン編集へ展開（#276/#550 をここで畳む）

## 未解決の論点

1. **領域の構成**（左・中央・右・下の4つで足りるか／下段をさらに左右に割れるようにするか）。（ユーザー確認）
2. **欄を並べたときの中の並び順**（同じ領域に複数の欄を置いたときの上下の入れ替え方＝ドラッグで挿入位置を示すか、上下ボタンにするか）。
3. **画面が狭いとき**（小さいウィンドウ）の扱い＝領域を自動でたたむか、横スクロールにするか。**黙って欄を消さない**ことだけは決まり。
   （決定10 で**欄の中身**は収まるようにしたので、残るのは**欄そのもの**の畳み方。）
4. **キーボードだけで操作できるか**（ドラッグに頼らない代替導線）。少なくとも「配置を既定に戻す」はボタンで到達できる。
5. 将来のフローティング（選択肢C）を足すかどうか（本ADRの範囲外・足すなら別ADR）。
