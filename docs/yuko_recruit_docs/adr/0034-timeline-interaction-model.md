## コンテキスト

実機確認で利用者から**根本的な指摘**（2026-08-04）。

> **操作感が独特すぎて全然つかめない。自由度が無く窮屈。私ですら分からない操作をユーザーに求めることになる。**

調べたところ、**操作感の調整ではなく、中核機能が入っていない**ことが分かった（#683 の監査・上記の調査資料）。

- **置けない**：写真・動画・文字・図形を置く手段が無い（置けるのは見た目パターン／音／読み上げ／連動字幕の4つだけ）
- **動かせない**：位置・大きさ・回転を変える手段が、キャンバスにも数値欄にも domain にも無い
- **掴めない**：帯は「選ぶ」だけ。ドラッグ移動・端のトリム・列またぎ・吸着・ズーム・分割がすべて無い
- **中身を直せない**：バラした後の文字・図形・写真は、文言も色も差し替えもできない

一方、**ADR-0032 は「キャンバスは常に自由配置」「位置・サイズ・回転は α-5 の射程」と約束している**。
つまり本件は「作らないと決めたもの」ではなく、**約束したまま作っていないもの**である。
時間軸側（音量・キーフレーム・書き出し）を積み続け、空間側を一度も作らないまま画面を出したのが原因。

**救い**：描画と書き出しは**既に箱（位置・大きさ・回転）に対応済み**（`layoutTimelineAt` が `clip.x ?? 0` を見る）。
帯のトリムハンドル・再生ヘッド・シーク可能ルーラーの CSS と `applyClipEdge` も**実装済みで未配線**。
**足りないのは編集の入口**であって、描画基盤ではない。

## 判断軸

1. **独自の操作を発明しない**。利用者が他で身につけた手が、そのまま通ること。
2. **自由度を削らない**（ADR-0032 の最重視項目）。「簡単だが窮屈」は利用者が最も嫌う型（Canva の不満・調査 §2）。
3. **分かりやすさを最優先**（利用者判断 2026-08-04）。世界観より、言葉と操作が分かること。
4. **既にあるものを繋ぐ**（新造しない）＝描画基盤・CSS・`applyClipEdge`・場面編集の自由配置・ADR-0033 のドラッグ規則。
5. **アプリ内で作法を割らない**（ADR-0026②）。ドラッグ・確認・エラーの出し方を2通り作らない。
6. **段階で出す**。各段が単独で価値を持つこと。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) いまの操作（ボタン中心）を磨く | 実装は軽い。だが**他社と違う手**を覚え直させ続ける。利用者指摘の「独特すぎる」に真正面から反する。**不採用** |
| **(B) 他社の型に合わせる【採用】** | 置く＝ドラッグ＋ボタン／キャンバスは掴んで動かす／帯は掴んで動かす・端でトリム。**うちに最も近い先行例（nizima ACTION!!・ゆっくりMovieMaker4）も、キャラ中心・初心者向けでこの型に従っている**（調査 §2）。**採用** |
| (C) 台本（テキスト）中心へ寄せる（Vrew 型） | うちはセリフを持つので取りうる。ただしタイムライン形式は「時間と空間の自由」を担う形式で、**自由度を削る方向**。**補助としては将来検討**（本ADRの対象外） |

## 決定

> **タイムライン編集の操作を、一般的な動画エディタの型へそろえる。素材・文字・図形を「ドラッグでもボタンでも」置け、
> 置いたものはキャンバスで掴んで動かせ（数値でも触れ）、帯は掴んで動かす・端でトリムする。
> 独自の操作は発明しない。言葉は一般的な動画編集の用語をそのまま使う。**

### 決定事項

| # | 論点 | 決定 |
|---|---|---|
| 1 | 全体の方針 | **他社の型に合わせる**（選択肢B）。独自の操作を発明しない |
| 2 | 置き方 | **ドラッグとボタンの両方**（利用者判断）。ドラッグが使えない環境・人の逃げ道を必ず残す |
| 3 | 置けるもの | **素材（写真・動画）・文字・図形**を新設（いまは見た目パターン／音／読み上げ／連動字幕だけ） |
| 4 | **置いたものの中身** | **置いた瞬間から直せる**（文字の文言・色・フォント、図形の色、素材の差し替え）。**「置けるのに直せない」を作らない**（監査 §2.2-1） |
| 5 | 素材の取り込み | 素材の欄に**「取り込む」を必ず置く**。いまの案内（素材画面へ誘導）は**行き止まり**（あの画面は場面形式専用） |
| 6 | キャンバス | **掴んで移動・角で拡縮・回転**＋**数値でも同じ値を触れる**（ハイブリッド）。場面編集の自由配置（`FreeLayoutOverlay`／`freeLayoutOps`）を**流用**する |
| 7 | ハンドルの出し方 | **選んだら常に出す**（CapCut・Canva 型）。ダブルクリックで初めて出る Premiere 型は、初心者に「触れない」と誤解させる |
| 8 | **テンプレの中を触る** | **(c) ドリルイン＋明示的にバラす**（利用者判断 2026-08-04）。ダブルクリックで中へ入り、**差し込み口の中身**（素材・文字）はそのまま直せる。**幾何（位置・大きさ）を触りたいときは「バラす」**（戻せない旨は現行どおり操作前に断る＝ADR-0032 決定23）。幾何の per-要素上書き（案a）は schema を増やし「見た目パターンを差し替えたら上書きはどうなる」問題を新設するため**採らない** |
| 9 | 帯の操作 | **ドラッグで移動・端でトリム・別の列へドラッグ**。作法は **ADR-0033 段階3 と同じ**（少し動かすまで掴まない／`Escape` で中止／左ボタンのみ／掴んだ指だけ見る／`pointercancel` とアンマウントで後始末） |
| 10 | 置けない位置 | **勝手に寄せない**。ドラッグ中は**ゴーストの色で「置けない」を示し**、離したら**元の位置へ戻す**。理由の文言は**離したときだけ**出す（ドラッグ中に明滅させない・#682 の「その場の返事」と噛み合わせる） |
| 11 | 押しのけ（ripple）・マグネティック | **採らない**。`11 §8` V24（同一列で時間の重なり禁止）と喧嘩する。隙間は**吸着＋手動**で扱い、「間を詰める」は α-6 候補 |
| 12 | 吸着（スナップ） | **他の帯の端・再生位置・0秒**に吸着。**画面内に見えているものだけ**。吸着したら**縦の点線**で示し、**`Ctrl` を押している間は切れる**（Canva の型） |
| 13 | ズーム | **段階ズーム＋`Ctrl`+ホイール**。**錨点はマウス位置**。**「全体を表示」**を置き、**開いた直後は全体表示**。段階は場面形式の `TimelineView`（`ZOOM_LEVELS`）と**同じ型**にする |
| 14 | 覚える／覚えない | **文書の中身に依存する状態は覚えない**（ズーム・選択・再生位置）。**画面の好みは覚える**（欄の配置＝ADR-0033）。この規準を本ADRで明文化する |
| 15 | 選択モデル | **1つに統一**。キャンバス・帯・「選んだ部品」の欄が**同じ選択**を指す。空白クリックと `Escape` で解除、`Ctrl+A` で全選択、複数選択の同時移動は**1つでも置けなければ全体を断る**（段階4 で実装＝`moveClips`。掴んだ相手の動いた量を選択ぶんへ同じだけ当て、**列が変わるのは掴んだ相手だけ**。⚠️ **連動している字幕は時間を持たない**ので対象から外す＝選択に1つ混ざっただけで全体が動かせなくなる、を作らない）。**#685 と #686 に着手する前に一本化する** |
| 16 | 分割 | **再生位置×選択中の帯**。kind で意味が違う＝絵は時間を切るだけ（**キーフレームは再基準化し、分割点の値を両端に焼く**）／音は `sourceStartSec` を進めフェードは前後に残す／**読み上げと連動字幕は切れない**（文と音がずれるため断る・理由を出す）。全列一括のブレード分割は**入れない** |
| 17 | 重ね順 | **キャンバスに「前へ／奥へ」は出さない**。本形式の重ね順は**列の並びだけ**（ADR-0032）なので、出すと嘘になる。列の操作（手前へ／奥へ）で足りる |
| 18 | キーボード | `Space`（再生）・`←`/`→`（1フレーム・Shift で1秒）・`Delete`（消す）・`Escape`（解除・中止）・`Ctrl+A`・**`Ctrl+K`（分割）**・`Ctrl+Z`/`Y`。**矢印は文脈で分岐**（キャンバスで部品を選んでいる間はナッジ＝1px・Shift で10px／それ以外はフレーム送り）。**入力欄と IME 変換中は奪わない** |
| 19 | **ドラッグ専用の操作を作らない** | 置く・動かす・分割・列またぎは、**キーかメニューでも到達できる**こと（ADR-0033 未解決4 と同じ趣旨） |
| 20 | 確認と取り消し | **`06 §2` の統一規約を引く**（新しい規準を作らない）＝単体の部品を消すのは**即時＋取り消し**、まとめて消す・列を消すのは**確認**、バラすは**戻せないので確認**。ドラッグ1回＝**1つの取り消し**（`pointerup` で1回だけ確定する） |
| 21 | **言葉** | **一般的な動画編集の用語をそのまま使う**（利用者判断＝分かりやすさ最優先）。`§2-3` が禁じているのは **JSON・FFmpeg・LLM・templateId のような実装用語**であって、**動画編集の一般語（分割・ズーム・吸着・トリム）は対象外**と整理する。ただし**既に定着した言い換えは変えない**（見た目パターン／素材／部品／欄／差し込み口）。`06 §3` に注記する |
| 22 | 完了条件 | **初心者の3手順（①並べる ②長さを詰める ③文字と音を足す）が、案内なしで通ること**。チュートリアルで補わない |

## 結果・影響

### コード

- **新設**：`domain/timeline/edit.ts` に置く（素材・文字・図形）／幾何の setter ／分割。UI にキャンバスのオーバーレイと帯のドラッグ。

## 未解決の論点

0. **テンプレの中の幾何を「バラさずに」触りたい要望が出たら、決定8 の (a)**（per-要素の幾何上書き）を再訪する。
   そのときは schema のバンプと「見た目パターンを差し替えたら上書きはどうなるか」を同時に決めること。
1. **ドロップで列を自動で足すか**（最上段の上・列の間に落としたとき）。いまは「列を足して重ねてください」と文言で言っている。
2. **「間を詰める」**（隙間の一括処理）を持つか＝α-6 候補。
3. **帯のコピー&ペースト**（`Ctrl+C/V`）＝「同じものを足す」で当面足りるか。
4. **作業範囲（ループ・範囲書き出し）**＝nizima にはある。α-6 以降。
5. **列の音量・ソロ・列名の変更**＝要望が出たら。
6. **タッチ／ペン**＝対象外のまま（Windows デスクトップ前提）。
7. **固定が混ざった複数選択の移動の線引き**（実機前ゲートレビュー 2026-08-13 検出・#763 と同じレビュー回）＝
   **正典どうしが同じ述語に別の規則を持っている**。`06 §12.1` は「固定したものは『まとめて動かす』にも**混ぜない**」
   （＝除外して残りを動かす。場面編集の先例〔マーキー・ナッジ・グループ拡縮の除外〕と一貫）、本ADR決定15は
   「**1つでも置けなければ全体を断る**」。実装も入口で3様に割れている＝帯レーンのドラッグ＝`moveClips` が全体を断る
   （理由表示あり）／キャンバスのドラッグ＝固定を黙って除外して残りだけ動く（`06 §12.1` 準拠・理由表示なし）／
   矢印ナッジ＝何も動かず矢印はフレーム送りへ落ちる。**どれも根拠があるため実装ミスではなく決めの問題**。
