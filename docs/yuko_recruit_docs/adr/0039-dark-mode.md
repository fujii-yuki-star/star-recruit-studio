# ADR-0039: アプリの外枠のダークモード

- **状態**: Proposed
- **日付**: 2026-09-10
- **関連**: `CLAUDE.md §2-3`（技術用語を出さない）・`§4`（外部I/O は infrastructure）・[`ADR-0001`](0001-rendering-parity.md)（プレビュー＝書き出し）・[`ADR-0033`](0033-editor-panel-layout.md)（画面の好みは `localStorage`・`project.schema` に入れない）・[`ADR-0034`](0034-timeline-interaction-model.md) 決定14（画面の好みは覚える）・`06_UI_SPEC.md §3`（言い換え表）・#1108（利用者の実機指摘⑧）

## コンテキスト

利用者の実機指摘（2026-09-10）：

> ソフトを見るときに目がつらいのでダークモードの導入をお願いしたいです。

続けて射程が示された：

> プレビューと書き出しの絵は暗くしないはもちろんで、**ソフトの枠やボタンなどを目に優しい色で**
> ダークモード化するといった感じの**設定を追加**してほしい

### いまの状態（実測・2026-09-10）

| | 実測 |
|---|---|
| アプリの外枠の色 | **`src/styles/theme.css` の `:root` に 152 のトークンで集約済み**（基調＝白・薄い水色・青緑・淡い黄色） |
| 暗い側の定義 | **0 件**（`prefers-color-scheme` / `data-theme` / `color-scheme` を全文検索して 0） |
| `index.html` の `color-scheme` メタ | **無し** |
| `src/app/**/*.tsx` のトークン外の色 | **10 件**。⚠️ **うち 8 件は動画の中身の色**（`ColorPicker` の候補色・部品の既定色 `fillColor ?? "#cccccc"` など）で、**テーマで変えてはいけない**（ADR-0001）。残る 2 件は**吸着ガイドの色**（`SNAP_GUIDE_COLOR = "#ff3d8b"` が `FreeLayoutOverlay.tsx:74` と `TemplateLayerOverlay.tsx:43` に**同じ値で写してある**） |
| `timeline.css` のトークン外の色 | **0 件**（当初「10 件」と数えたのは誤り＝`#701` のような **Issue 番号**を色と数えていた） |

⚠️ **土台はできている。** 仕事の中心は「暗い版のトークンを足す」ことで、画面ごとに色を書き換える話ではない。

## 判断軸

1. **ADR-0001（プレビュー＝書き出し）を絶対に割らない**＝利用者が作っている動画の色は、画面の設定で1ピクセルも変わってはいけない
2. **§2-3**＝画面に出す語は「見た目」の言葉にする（`theme` / `ダークテーマ` のような実装語を出さない）
3. **ADR-0033/0034**＝画面の好みは覚えるが `project.schema` には入れない
4. **ADR-0034（独自の操作を発明しない）**＝切り替えの置き場・既定の決め方は、一般的なアプリの型に合わせる
5. **目に優しい**＝利用者の動機は「目がつらい」。真っ黒＋純白の最大コントラストは目的に反する

## 検討した選択肢

### 何を暗くするか

| 選択肢 | 評価 |
|---|---|
| (A1) **アプリの外枠だけ**（帯・欄・ボタン・文字・背景）。**キャンバスの中の絵は不変** | **採用**。利用者の指定どおりで、ADR-0001 とも両立する |
| (A2) キャンバスの中身も暗くする | **不採用**。プレビューと書き出しが食い違う（ADR-0001 違反）。そもそも動画の色は利用者が決めたもの |

### キャンバスの**外側**（動画の周りの余白・器）

| 選択肢 | 評価 |
|---|---|
| (B1) **暗くする** | **採用**。動画編集ソフトの型（周囲は暗い）で、明るい面積が減って目的（目が楽）に直接効く。**動画の絵そのものは不変**なので ADR-0001 に触れない |
| (B2) 明るいまま | 不採用。仕上がりの印象に近いという利点はあるが、**外枠を暗くした意味が薄れる**（いちばん面積の大きい面が明るいまま残る） |

⚠️ **B1 でも「動画の絵の見え方」は変わらない**＝周りの明るさが変わると人の目には印象が変わるが、
**焼かれる画素は同じ**。仕上がりの色を厳密に見たい人のために、**プレビューだけ明るい面に戻す道**は
「未解決の論点」に置く（いま作らない）。

### 既定

| 選択肢 | 評価 |
|---|---|
| (C1) **OS に合わせる**（`prefers-color-scheme`） | **採用**。一般的なアプリの型（ADR-0034）。利用者は「目がつらい」から求めているので、**設定を探さなくても効く**のが素直 |
| (C2) 明るいまま（選んだ人だけ暗く） | 不採用。既存利用者の見え方が変わらない利点はあるが、**求めた人が設定を探さないと救われない** |

⚠️ **C1 は「アプリの見え方が黙って変わる」**（OS が暗いと初回から暗い）。ただし**内容は変わらない**
（動画も文書も不変）ので、§2-5 の「黙って別の結果にしない」には触れない。設定で3択にして戻せる。

### 切り替えの置き場と選択肢

| 選択肢 | 評価 |
|---|---|
| (D1) **設定画面に「見た目」＝「OS に合わせる／明るい／暗い」の3択** | **採用**。利用者が「設定を追加してほしい」と言っている。3択は一般的な型で、**OS 追従から抜けられる**ことが大事（OS が暗くても明るく使いたい人がいる） |
| (D2) 見出しの行に切替ボタン | 不採用（いまは）。頻繁に切り替えるものではない。要望が出たら足す |

### 実装の形

| 選択肢 | 評価 |
|---|---|
| (E1) **`theme.css` に暗い版のトークンを1か所だけ置く**（`:root[data-theme="dark"]`）＝`<html data-theme>` は常に `light` / `dark` のどちらかになり、**「パソコンの設定に合わせる」は JS が解く**（`useAppearance.ts`） | **採用**。⚠️ **当初は `@media` と `[data-theme]` の両方に書く案だった**が、それだと**25個のトークンを二重に持つ**ことになり、**片方だけ直す事故**が必ず起きる（この repo の頻出の型）。実装時に改めた |
| (E1b) `@media (prefers-color-scheme: dark)` にも同じ値を書く | 不採用（上記のとおり二重管理になる） |
| (E2) 画面ごとに暗い版のクラスを足す | 不採用。トークンに集約してある利点を捨てる |

## 決定（Proposed）

1. **暗くするのはアプリの外枠だけ**。`layoutScene` / `layoutToSvg` が描く**動画の絵は不変**（ADR-0001）
2. **キャンバスの外側（余白・器）は暗くする**
3. **既定は「パソコンの設定に合わせる」**（OS 追従）。設定画面に**「見た目」＝ パソコンの設定に合わせる／明るい／暗い**の3択を置く
4. 選んだ結果は **`localStorage`**（`infrastructure/appSettings` 経由＝`CLAUDE.md §4`）。**`project.schema` には入れない**（ADR-0033）
5. **色は「目に優しい」側へ寄せる**＝純黒（`#000`）と純白（`#fff`）を本文に使わない。面は暗いグレー、文字は少し落とした白
6. 画面に出す語は **「見た目」「明るい」「暗い」「パソコンの設定に合わせる」**（§2-3＝`テーマ` `ダークモード` `ライト/ダーク` は出さない。⚠️ **「OS」も出さない**＝利用者は人事・非エンジニアなので技術寄りの略語を避ける・レビュー 🟡）

⚠️ **Proposed のまま実装を進める**（自動駆動の合意・2026-09-10）＝上の決定は**すべて元に戻せる**
（`project.json` に何も書かない／動画の絵に触れない／設定で3択に切り替えられる）。
**利用者の確認が要るのは決定3（既定を「パソコンの設定に合わせる」にするか）だけ**なので、そこを
**1つの値で切り替えられる形**（`APPEARANCE_DEFAULT`）にしておき、確認が取れた時点で
状態を Accepted へ動かす（**その際は `adr/README.md` の状態欄も同時に直す**）。

## 結果・影響

### コード

- `src/styles/theme.css`＝`:root[data-theme="dark"]` に暗い版を**1か所だけ**追加。明るい版・暗い版の両方に `color-scheme` を宣言する（スクロールバーや素の `<input>` が明るいまま残らないように）
- `infrastructure/appSettings.ts`＝見た目の設定の読み書き（`app.appearance`＝`"system" | "light" | "dark"`）。⚠️ **`getBooleanSetting` は使えない**（3値）ので、専用の読み書きを足す
- `useAppearance.ts`（新規）＝好みを**解いて** `document.documentElement` の `data-theme` に反映する。⚠️ **`"system"` でも属性は必ず入る**（`light` か `dark`）＝CSS の暗い版を1か所に保つため。`matchMedia` を購読して、パソコン側の設定が途中で変わっても追いつく。`App.tsx` がこれを持つ（設定画面を開いていなくても効かせる）
- 設定画面＝「見た目」の3択
- **吸着ガイドの色を1か所へ寄せる**（`FreeLayoutOverlay.tsx` と `TemplateLayerOverlay.tsx` に同じ値が写してある）。⚠️ これは**テーマとは別の話**だが、色の直書きとして同じ差分で片付ける

### 正典

- `06_UI_SPEC.md`＝設定画面に「見た目」の項目を追記（§15 の並びの先頭）。§3 の言い換え表に **`theme / dark mode / ライト・ダーク` → `見た目（パソコンの設定に合わせる・明るい・暗い）`** と **`OS` → `パソコン`** を足す
- **`project.schema` は不変**＝`schemaVersion` のバンプもマイグレーションも**不要**（§5）

### 検査

- **暗い版と明るい版で、同じトークンがすべて定義されていること**を機械で見る（片方だけ定義漏れがあると、その色だけ明るいまま残る）
- **動画の絵に使う色がテーマで変わらないこと**＝`ColorPicker` の候補色・部品の既定色がトークンを参照していないことを門番で留める（**いまは参照していない＝その状態を固定する**）

## 未解決の論点

1. **ゆうこ（マスコット）と同梱の絵**が暗い面で浮かないか（**実機で見る**）
2. **仕上がりの色を厳密に見たい人のために、プレビューの周りだけ明るく戻す道**を作るか（いまは作らない）
3. **小さな絵（サムネイル）の背景**＝一覧に並ぶ動画のサムネは白地の絵が多い。暗い面での見え方（**実機**）
4. **書き出し画面・公開前チェックの「注意」の色**が暗い面で十分に目立つか（`--color-warn` は濃い文字色なので、暗い面では反転が要る可能性）
5. **（ユーザー確認）** 決定3の「既定はパソコンの設定に合わせる」でよいか。**黙って暗くなる**のが困る場合は「明るいまま」を既定にする（`APPEARANCE_DEFAULT` を `light` にするだけ＝検査も1行）
