# ADR-0060: 拡張パック（見た目パターン・BGM・フォント・声・組み込み機能の鍵を後から足す）

- **状態**: Accepted（2026-10-13・利用者承認）
- **日付**: 2026-10-13
- **関連**: #1336（β「あなた向け会社説明」＝この仕組みで有効にする最初の機能・ADR-0061）／ADR-0017・0021（見た目パターンと既定素材）／ADR-0024（自己完結＝例外の扱い）／ADR-0035（素材ライブラリ）／ADR-0038（持ち込みフォント）／ADR-0003・0005（VOICEVOX とキャラ規約）／ADR-0042（外から操作する口）／`CLAUDE.md §2-6`（外部送信）／`13`（依存とライセンス）

## コンテキスト

利用者判断（2026-10-13）：β の「あなた向け会社説明」（#1336）を**社内版だけに出す**仕組みを考えたところ、
「**拡張パックを読み込む機能**を足し、β の機能もその拡張として入れたい。声をもっと用意したい・見た目パターンを増やしたいので、
拡張パックで足せると便利。**α の中で入れたい**」となった。

いまの作りの事実（調べた結果）：
- **見た目パターン**＝同梱は `sampleTemplates`（コードの中）・利用者のものは `appData/user_templates/<user_tmpl_NNN>.json`。
  場面は `templateId` だけを持ち、**見た目パターンは動画へコピーしない**（ADR-0024 決定6 の例外）。見つからなければ #547 の知らせ（黙って差し替えない）。
- **フォント**＝同梱 3 種（`FONT_CATALOG`）・持ち込みは `appData/user_fonts/`（ADR-0038＝動画へコピーしない）。`FontId` は schema の**パターン**（`user_font_NNN` まで）。
- **BGM**＝同梱 3 曲（`BGM_CATALOG`・schema の enum）と、素材ライブラリから動画へコピーする BGM（ADR-0035）。
- **声**＝VOICEVOX ENGINE 0.25.2 を同梱し、使う声の一覧は TS に**決め打ち**（`VOICE_CATALOG`）。同梱の声のモデルは 9 個に絞ってある（`prune-bundle.mjs`）。
  ENGINE は **`manage_library: false`**（後から声を入れる口が閉じたビルド）＝**声を後から足すには調べることがある**。
- **組み込み機能の切り替え**の前例＝`OPENH264_FEATURE_ENABLED`（ビルド時の定数）。
- SHA-256 の照合は `local_llm.rs`・`transcribe.rs` にある（同梱物の照合）。一般の「パック」の照合は無い。

## 判断軸

- **安全**＝パックは未署名で配られうる（社内 α は Drive 配布）。**パックからプログラムを動かさない**。
- **外へ送らない**（§2-6）＝パックは**利用者が選んだファイル**から入れる。アプリがネットから取りに行かない。
- **描画の核は1つ**（ADR-0001）・**書き出しの道も1つ**（ADR-0007）＝パックの中身も同じ道で描く。
- **正典を単一の参照元に**（§2-7）＝パックの形は schema で決め、検証してから使う（§2-2 の精神）。
- **権利**＝声・フォント・BGM は**ライセンスと表記**が要る（`13`）。パックが中身の権利を書き、About と書き出しの表記に出す。
- **外したときに作品が壊れて見えない**（ADR-0026④）＝パックを外すと使っている動画がどうなるかを、外す前に知らせる。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) 社内版を別ビルドにする | 配布物が2種類に増え、声・見た目パターンを足す道にならない。**不採用**（利用者判断） |
| (B) 設定の切り替えで社内向け機能を出す | 機能の出し入れはできるが、声・見た目パターンを足せない。**不採用**（利用者判断） |
| (C) **データだけの拡張パック**（中身は見た目パターン・素材・フォント・声のモデル・**組み込み機能の鍵**） | プログラムを持ち込まない＝安全。機能（β など）は**アプリに組み込み済み**で、パックが**有効にするだけ**。**採用** |
| (D) プログラム入りのプラグイン（JS を読み込む） | 未署名で配られると何でもできてしまう。描画・書き出しの道も割れる。**不採用** |

## 決定

### 決定1：パックは「データだけ」・機能は組み込み済みのものを有効にするだけ
- パックに入れられるのは **見た目パターン（＋既定素材）／BGM／フォント／声のモデル／組み込み機能の鍵** だけ。**プログラムは入れられない**。
- **組み込み機能**（最初は β の「あなた向け会社説明」＝ADR-0061）は**アプリの中にある**。パックの `features` に名前があり、そのパックが入っているときだけ画面に出る（左の帯の項目など）。
  ⚠️ 鍵は**秘密ではない**（誰でも書ける）＝「見せる・見せない」の切り替えであって、守りではない。守りが要る機能は鍵で出さない。

### 決定2：形は1ファイル（`.starpack`＝zip）＋ `manifest.json`
- `manifest.json`：`packId`（英小文字で始まる・英小文字／数字／単独の `_`・`__` と末尾の `_` は不可＝決定4 の境目のため。⚠️ 当初「`-`」と書いたが `templateId` の schema で使えず実装で改めた）・`name`・`version`・`publisher`・`minAppVersion`・`description`・
  `contents`（種類ごとの一覧）・`files`（中の全ファイルの相対パスと **SHA-256**）・`licenses`（中身ごとのライセンスと**表記**）。
- 正典は新しい schema `schemas/extension-pack.schema.json`（独立した `schemaVersion`＝`11.1` の流儀）。
- 中の見た目パターンは**今の `template.schema.json`** で検証する（パック用の別の形を作らない）。

### 決定3：入れる・外す・一覧は「設定」の「拡張パック」
- **入れる**＝利用者が `.starpack` を選ぶ → 展開前に manifest を読み、**中身・発行者・ライセンスを見せて**「入れる」を押してもらう
  （§2-6 の送信前確認と同じ「見せてから」の型）→ schema 検証・**SHA-256 照合**・`minAppVersion` 確認 → 全部通ったときだけ `appData/packs/<packId>/` へ置く（途中で失敗したら何も残さない）。
- **同じ packId の新しい版**＝置き換え（版を見せて確かめる）。古い版を入れようとしたら断る。
- **外す**＝そのパックの中身を使っている動画を数えて**先に知らせ**、了承で `appData/packs/<packId>/` を消す。
- 外へ取りに行かない（ネットの口を作らない）。

### 決定4：id の名前空間は「パックの名前＋中の名前」
- 見た目パターンと既定素材＝`pack_<packId>__<localId>`（⚠️ **実装で直した**＝最初は `pack.<packId>.<localId>` と書いたが、`templateId` の schema は `^[a-z0-9_]+$` で `.` を使えない。packId に `__` を禁じて境目を一意にした）、フォント＝~~`pack_font_<packId>_<localId>`~~（→ 下の追補で `pack_<packId>__<fontId>` に変えた）、BGM はパックの中のファイルを
  **素材ライブラリと同じ道で動画へコピー**（ADR-0035）＝schema の BGM enum を増やさない。
- ⚠️ フォントは schema の `FontId` パターンに足す（**project schema のマイナー版を上げる**・変換は要らない）。
- ⚠️ **追補（段階2の実装）：フォントも `pack_<packId>__<fontId>` にそろえた**（project 1.34・timeline 1.19）＝`pack_font_<packId>_<localId>` は
  ①packId が `_` を含めるので**境目が割れる**（`pack_font_a_b_c` がどのパックか決まらない）②段階1の判定（`isPackScopedId`／`packIdOfScopedId`）が
  `font_<packId>` という**別のパック**と読む。見た目パターンと文字の形は**別の欄**から指すので同じ頭でも重ならない。
  `fontId` は英小文字・数字・単独の `_`（`__` を使えない）・同じパックの中で重ならない（schema では表せないので `parsePackManifest` が断る）。
- 同梱・利用者・パックの id は**頭で分かれる**ので重ならない。同じ packId の別の版は同じ id のまま（置き換え）。

### 決定5：動画からの参照（自己完結の例外）
- **見た目パターン・フォント**＝今の利用者のものと同じく**動画へコピーしない**（ADR-0024 決定6 の例外に「パック」を足す）。
  パックを外すと、その見た目パターンの場面は #547 の知らせ（「見た目パターンが見つかりません…」）・フォントは `USER_FONT_MISSING` の流儀で知らせる＝**黙って別のものにしない**。
- **BGM**（段階2）＝使うときに**動画へコピー**（今の素材と同じ）＝パックを外しても鳴る。
- ⚠️ **追補（段階2の実装）：フォントは持ち込みと同じ一覧に並べる**＝選ぶ部品・公開前チェック・書き出しの門は持ち込みの一覧（`userFonts`／`userFontIds`）だけを見ており、
  パックの分を別に持つと**配り忘れた所だけ「見つからない」**になる（ADR-0038 で踏んだ形）。一覧では「拡張パック」と添える。
  読み込みは持ち込みと同じ `FontFace`（家族名＝id・バイト列で渡す）で、**外す・入れ直すと登録を外して読み直す**（外したパックの字で描き続けない）。
  外したあとの「見つからない」の知らせは、次の行動に**そのパックを入れ直す**を足した（`USER_FONT_MISSING`）。
  外す前の数え上げ（`projectUsesPack`）は**値がパックの頭で始まるか**だけを見る＝文字の形は `fontId` のほか種別ごとの上書きからも指すので、項目の名前を並べると足し忘れる。
  ⚠️ **同じ版のファイル名でも中身で見分ける**＝新しい版を入れたとき、置き場（packId・ファイル名）が同じでも SHA-256 が違えば登録を外して読み直す。読んでいる途中に外された字は登録しない。パックの読み直しが重なったときは**後から始めた1回だけ**を当てる。
  ⚠️ **入れるときに1ファイルの大きさを読むときと同じ上限で見る**（字 64MB・絵 20MB・見た目パターン 4MB）＝入ったのに読めない字を作らない（一覧に載って門を通り、描画は既定へ倒れる＝黙って別の字になる）。
  ⚠️ **持ち込みの一覧が読めないときは、パックの字だけを使う動画も書き出しを止める**（`USER_FONT_UNREADABLE`・PR レビュー 🟡 を受けて**そのままにした**）＝持ち込みとパックの「調べたか」を分けて書き出しの門へ配ると、呼ぶ所が4つあり、配り忘れた所では**外したパックの字が黙って通る**（別の字の動画が成功として出る）。止める側は ADR-0038 の安全側。選ぶ一覧には読めないときもパックの字を出す。
- ⚠️ **追補（段階1の実装）：見た目パターンの既定素材はコピーしない**＝利用者の見た目パターンの既定素材（`tmpl_asset_NNN`・ADR-0021）と同じく**見た目パターンの持ち物**として扱う（当初「写真はコピー」と書いたが、既定素材は見た目パターンと組で解決されるので、見た目パターンだけ残っても絵が欠けるだけ）。外すと場面は `TEMPLATE_NOT_FOUND` の知らせ。**利用者の見た目パターンへ複製したとき**は、パックの既定素材を利用者の素材（`tmpl_asset_NNN`）へ**コピーして付け替える**（パックを外しても複製は欠けない・PR レビュー 🟡）。

### 決定6：権利の表記
- パックの `licenses` を **About（このアプリについて）にパックごとに並べる**。声は**書き出しの表記**（`VOICEVOX:◯◯`）にも出す（今の声と同じ規則）。
- **ライセンスが書かれていない中身は入れない**（断る）。

### 決定7：段階（α の中で順に）
1. **段階1**＝パックの形・入れる／外す／一覧・照合・**見た目パターン（＋既定素材）**・**組み込み機能の鍵**（ADR-0061 の土台）。
2. **段階2**＝**BGM・フォント**（フォントを先に入れた＝段階2a。BGM は 2b）。
3. **段階3**＝**声**。⚠️ 同梱 ENGINE は後から声を入れる口が閉じている（`manage_library: false`）＝**調べてから決める**
   （ENGINE の版を上げる／モデルの置き場所を `appData` へ足す／起動の引数で別の置き場所を読ませる、のどれが通るか）。
   声はキャラごとに**規約の確認が要る**（ADR-0003）＝パックに入れる声の規約は**入れる前に法務で確かめる**。

## 結果・影響

- 正典：`schemas/extension-pack.schema.json`（新設）・`11`（パックの形と id の名前空間）・`project.schema.json` の `FontId`（段階2・マイナー版）・
  ADR-0024 決定6 の例外に「パック」を追記・`06`（設定の「拡張パック」・About の表記）・`13`（パックの中身の権利の扱い）・`15`（入れられない／外す前の知らせの文言）。
- コード：Rust に `packs` の入れる・外す・一覧・照合（zip の展開は**パスを外へ出さない**＝`..`・絶対パスを断る）／TS に manifest の検証・見た目パターンの合流（同梱・利用者・パックの順）・組み込み機能の登録表。
- 試験：manifest の schema（正常・異常）・SHA-256 の不一致・zip の外へ出るパス・`minAppVersion`・外す前の数え上げ・id の衝突・パックを外した後の知らせ。

## 未解決の論点

- **声の足し方**（段階3）＝上の3案のどれが ENGINE 0.25.2 で通るか（調査）。声の規約（法務）。
- **パックを作る道具**＝最初は開発側が作る（`scripts/` に作る道具）。利用者が作れるようにするかは後で。
- **パックの署名**＝今は SHA-256 で壊れ・改ざんの検出まで。発行者の確かめ（署名）は、外へ配るときに決める。
- **縦の版の見た目パターン**＝パックの見た目パターンにも横・縦の組（ADR-0012・0057）を求めるか（求めないと縦の版で見つからない）。
