# ADR-0042: 持ち込みの AI が使う「口」＝起動の引数で、取り込みと書き出しまで通す

- **状態**: Accepted
- **日付**: 2026-09-17（**Accepted** 2026-09-17・実装が入ったのを見て利用者が承認）
- **関連**: [`ADR-0041`](0041-external-agent-operability.md)（誰に許すか）／[`ADR-0001`](0001-rendering-parity.md)／[`ADR-0007`](0007-detailed-edit-mode.md)／[`ADR-0024`](0024-non-destructive-editing-model.md)／[#1184](https://github.com/fujii-yuki-star/star-recruit-studio/issues/1184)

## 背景

ADR-0041 で「**利用者が持ち込む AI にソフトを操作させてよい**」と決めた。本 ADR は**その口をどう開けるか**を決める。

⚠️ **α に入れる**（2026-09-17・利用者判断）。

> **β では極力社内専用機能を付け加えるだけにしたいので、書き出し口や取込口は α 内にやっておきたい**

＝**β の性格を「社内向けの積み増し」に保つ**ため、誰でも使う土台は α で閉じる。

### いま、どこまで届いているか（実測・2026-09-16）

| やること | いま |
|---|---|
| プロジェクトを**組み立てる** | **できる**＝`project.json` を書けば、正典 schema もアプリの読み込みも通る |
| **声を入れる** | **できる**＝同梱 VOICEVOX の API を叩き、`voices/clip_NNN.wav` を置く |
| **置き場へ入れる** | ⚠️ `%APPDATA%\…\projects\` に**フォルダを置く**しかない（場所を知っている必要がある） |
| **書き出す** | ❌ **人がダイアログを押さないと終わらない**（`ExportScreen.tsx` が保存先を先に聞く） |

＝**足りないのは最後の2つだけ**。

## 論点

1. **口の形**＝常駐の待ち受け（HTTP/ソケット）か、**起動の引数**か。
2. **画面を出すか**＝見えないところで走らせるか。
3. **二重起動**＝利用者が開いている最中に AI が起動したら。
4. **結果の返し方**＝AI がどうやって成否を知るか。

## 決定

### ① 口は**起動の引数**（待ち受けは作らない）

```
stario.exe --import <フォルダ>            取り込んで、その動画を開く
stario.exe --export <動画のid> --out <道>  その動画を書き出す
stario.exe --quit-when-done                終わったら閉じる（上のどちらかと一緒に）
```

⚠️ **待ち受けを作らない**＝ポートを開けると、**このソフトを入れただけで外から触れる面**ができる。
AI は**同じパソコンでソフトを起こせる**のだから、待ち受けは要らない（§2-6 の精神）。

### ② **画面は出す**（見えないところで走らせない）

絵を作っているのは WebView（ADR-0001＝描画核は1つ）なので**窓は要る**。加えて、
**見えないまま失敗すると人が気づけない**＝「動いているつもりで何も出ていない」を作らない。
→ **窓は出し、自動で進む**。`--quit-when-done` を付けたときだけ、終わったら閉じる。

### ③ **単一インスタンス**にし、動いていれば**引数をそちらへ渡す**

⚠️ **書き出しは `project.json` を保存する**（#256）ので、**2つ動くと後から保存した方が勝つ**。
→ 2つ目は**起こさない**。すでに動いていれば**引数だけ渡す**。
⚠️ **渡された側は、いま動画を開いていたら断る**＝
「いま動画を開いています。閉じてから、もう一度お試しください。」（§2-5＝次の行動）。
**黙って上書きしない**（ADR-0026④）。

> ⚠️ **当初は「未保存の編集を抱えていたら断る」と書いていた**（2026-09-17 の実装で改めた・PR レビュー ℹ️）。
> **このアプリに「直したが保存していない」を表す印が無い**＝自動保存があるので `saveStatus` は
> **直したばかりでも `saved`** になりうる。無い印を推測で作らず（§9-2）、**開いていたら断る**という
> **安全側**へ倒した。⚠️ **断るのは渡された回だけ**（自分で起こした回は、まだ何も開いていない）。

### ③-2 ⚠️ **渡された回は、終了コードで判定できない**

渡された側（すでに動いているアプリ）が受けても断っても、**引数を渡した2つ目のプロセスは
単一インスタンスの仕組みがすぐ終わらせる**ので、頼んだ側のコマンドは**結果に関わらず終了コード 0** で返る。

→ **`--export` を確実に判定したいなら、アプリを開いたままにしない**（頼む側の作法）。
⚠️ **断りは画面に出る**ので、人には分かる。

### ④ 結果は**終了コード**と、**画面に出るのと同じ文**で返す

| 終了コード | 意味 |
|---|---|
| `0` | できた |
| `1` | できなかった（理由は画面の文と、うまくいかないときの記録に出す） |
| `2` | 引数が読めない・足りない（⚠️ **`1` と分ける**＝**指定の書き間違い**と**やってみて駄目だった**は直し方が違う） |

⚠️ **生の技術語を標準出力へ吐かない**（§2-3 の精神）＝出すのは**画面と同じ文**。
⚠️ **印の綴り（`--import` など）は断りに出す**（PR #1191 レビュー 🟡・ここだけの例外）＝
直すのは**頼んだ側**（人か、その人の AI）なので、**どの指定が悪いか**が分からないと直せない。
§2-3 が禁じているのは**実装の言葉**（`templateId` 等）で、**利用者が自分で書いた指定**は
「自分が打った文字」＝実装の露出ではない、と整理した。

### ⑤ 中身は**画面と同じ道**を通す

- **書き出し**＝`ExportScreen` の `startExport` を**そのまま**使い、**保存先を聞く所だけ**引数で置き換える。
  ⚠️ **別の書き出し経路を作らない**（ADR-0007）。**人の操作を待つのは保存先の1か所だけ**であることは、
  `startExport`（`ExportScreen.tsx:181-455`）を通読して確かめた（PR #1191 レビューでも別途裏取り済み）。
  ⚠️ **公開前チェックの画面は「関門」ではない**（同レビュー ℹ️）＝`startExport` から呼ばれておらず、
  通らなくても書き出せる。止める判定（`blockingItems` / `capabilityBlocked` / `exportLock`）は
  **`startExport` の中で自動で効く**ので、引数の道でも同じだけ止まる。
- **成否は「Rust へ伝えてから閉じる」**（同レビュー ℹ️）＝絵を作るのは WebView なので、成否を知っているのも WebView。
  **終わったことを伝えるコマンドを1つ足し**、Rust が `AppHandle::exit(コード)` を呼ぶ。
  ⚠️ **画面が勝手に閉じない**＝閉じる判断は `--quit-when-done` を読んだ Rust 側に置く（判断を2か所に置かない）。
- **取り込み**＝既存の取り込み（素材ごとコピー＝ADR-0024）に載せ、**検証を必ず通す**（ADR-0041 条件1）。
  読み込みは形だけ／相互参照は書き出しのところで断る、という**既存の二段**にそのまま乗る。

### ⑥ `--import` は**新しい信頼の境目**なので、そこだけは書き足す

⚠️ **既存の取り込みの前提と違う**（PR #1191 レビュー ℹ️・重要）＝いまの `import_asset_path` は
**「開く」ダイアログが返した道**を前提にした守りで、`--import` は**呼ぶ側が丸ごと決める文字列**が入ってくる。

**決定**：

1. **読む側は広く許す**＝フォルダは `canonicalize` してから使う（リンクやジャンクションはここで解ける）。
   実在しない・`project.json` が無いなら**断る**（§2-5＝次の行動を出す）。
   ⚠️ **ネットワーク上の道も断らない**＝断る理由が無い（**中身はどうせ手元へコピーする**）。
2. **書く側は狭く固定する**＝**書き込むのは `projects/<新しい id>/` の下だけ**。ここが本当の守り。
   ⚠️ **「AI に新しい力を与える」訳ではない**＝AI は元から自分でファイルを読める。
   守るべきなのは**アプリが自分の持ち場の外へ書かないこと**。
3. **中身を信用しない**＝`project.json` が持つ相対パスは、**既存の `is_safe_rel_path` に通す**
   （`..` や絶対パスで持ち場の外を指せない）。⚠️ **4つ目の写しを作らない**＝既存の関数を呼ぶ。


## 追補1（2026-09-17・実機で確かめて分かったこと）

実際に exe を叩いて測ったら、**決定④と⑤が効いていませんでした**。どちらも直し、ここに残します。

### ⚠️ ④-2 `AppHandle::exit(code)` は**終了コードを捨てる**

| 試したこと | 期待 | 直す前 |
|---|---|---|
| `--nonsense --quit-when-done` | `2` | **0** |
| `--export <居ない動画> --out …` | `1` | **0** |
| 正常な書き出し | `0` | 0 |

**原因**＝`tauri-runtime-wry 2.11` の `request_exit` は `ControlFlow::Exit`（**0 固定**）を使っており、
コードを運ぶ `ExitWithCode` を使っていません（ライブラリの実装を読んで確認）。
⚠️ **成功と失敗が区別できない**＝頼んだ AI から見ると、**何もしていない回も成功に見えます**。

**直し方**＝`finish_startup_job` が**自分で** `std::process::exit(code)` する。
⚠️ **落とす前に後片づけを必ず通す**＝自分で落とすと `RunEvent::ExitRequested` が走らないので、
通さないと同梱 ENGINE が居残り（#149）、書き出し中なら `ffmpeg.exe` が孤児になる（#380）。
後片づけは `shutdown_side_processes` として**1か所へ出し**、終わる道2つの両方から呼びます
（書き写すと、片方の道で閉じたときだけ居残りが出る＝結び付けにくい壊れ方）。

⚠️ **戻しても単体テストは緑のまま**（プロセスの終了コードはテストに出ない）ので、
**書き方そのもの**を門番で留めました（`src/test/startupExitCodeGuard.test.ts`）。

### ⚠️ ⑤-2 **タイムライン形式の動画は、そもそも書き出せなかった**

`--export <タイムライン形式> --out …` は **3秒で何もせず終了コード 0**、ファイルは出来ませんでした。

**原因**＝決定⑤（画面と同じ道を通す）を**場面形式の画面にしか通していなかった**。
`runExport` は `loadProject` → 書き出しの画面、という一本道でした。

⚠️ **ここが塞がっていると ADR-0041 の枠②が成立しません**＝
「利用者が持つ AI にタイムラインを書かせる」と決めたのに、**書いたものを書き出す口が無い**。

**直し方**＝一覧の `format` で行き先を選ぶ（取り込みと同じ流儀＝開いてから「形式が違う」と断らない）。
タイムライン形式は `openTimelineProject` → タイムラインの画面で、**人が押したときと同じ `exportTimelineVideo`** を通す。
保存先の置き換えも**その1か所だけ**（決定⑤のまま）。

⚠️ **締めは「終わった姿」で決める**＝タイムラインの書き出しは抜け道が多い（断る門・中止・失敗）ので、
出口ごとに締めを書き足すと**書き漏らした出口で永久に待たれます**（場面形式では出口が10か所あった）。
待ってから `exportRun.phase` を**1回だけ**見る形にすれば、**出口が増えても漏れません**。

### 教訓

⚠️ **「単体テストが緑」と「実機で通る」は別**＝④は**ライブラリの中で**捨てられており、
⑤-2 は**片方の形式にしか道が無い**という抜けでした。どちらも机の上では緑でした。


## 追補2（2026-09-17・#1194 の通し試験で見つけた穴）

### ⚠️ **画面が担っていた役目は、画面を読まない道では誰も担わない**

外の AI が**読み上げのセリフを書いた**文書を `--export` すると、実機でこうなりました：

| | 実測 |
|---|---|
| 終了コード | **0**（成功） |
| 出来た動画 | **−91 dB＝完全な無音** |

⚠️ **ナレーションは一度も鳴っていません**。頼んだ AI には**成功に見えます**。

**なぜこうなるか**＝未生成の読み上げは**書き出しを止めません**。
⚠️ **場面形式も同じ**です（公開前チェックの「読み上げの声」は `severity:"action"` だが `blocksExport` ではない）
＝**形式で割れてはいません**（ADR-0026②）。

**本当の穴は、この ADR が開けた口にあります**＝公開前チェックが「要対応」として**人に見せて**いたものが、
**起動の引数で走る回**（決定②で窓は出すが、**誰も読まない**）では**消える**。

### ④-3 **頼まれた回は「要対応」を断りにする**

**決定**＝起動の引数で走る回は、公開前チェックが「要対応」と言うものを**断る理由として扱う**。
⚠️ **人が押した回の挙動は変えない**（画面が知らせる形のまま）。
⚠️ **「警告」と「要対応」を混ぜない**＝使っていない素材のような警告では止めない
（止めると、頼んだ側は**直しようのない断り**を受け取る）。

⚠️ **「要対応」を全部止めるのではありません**（PR #1208 レビュー）＝基準は
**「黙って別の結果になるもの」**です。「字幕が長い（短くすると読みやすくなります）」のような**助言**で止めると、
頼んだ側は**直しようのない断り**を受け取ります。

**いまの対象（2つ）**：

| | 止める理由 |
|---|---|
| 読み上げの声が作られていない（`STARTUP_VOICE_NOT_READY`） | そのぶんが**無音のまま焼き込まれる**（実測 −91dB） |
| **使っている**素材のファイルが見つからない（`STARTUP_ASSET_MISSING`） | **その場面が黙って抜けた動画**になる |

⚠️ **使っていない素材は数えません**＝消えていても動画は変わらないので、断ると行き止まりになります。
⚠️ **タイムライン形式では素材を二重に数えません**＝そちらは `TIMELINE_EXPORT_ASSET_UNREADABLE` で既に止まるので、
ここでも数えると**同じ状態に2つの断りが並びます**。

### ⑦ **声を作る口**（`--make-voices <動画の番号>`）

この ADR の口は `--import` と `--export` だけで、**#1184 の題「作る→声→書き出す」の真ん中が通れません**でした。

```
stario.exe --make-voices <動画の番号> --quit-when-done    声を作って閉じる
```

- ⚠️ **人が押したときと同じ道を通す**（ADR-0007）＝画面の「まとめて作る」と同じ関数を呼ぶ。
  別の経路を作ると、**声の設定の解決（`11 §6` 継承）が二重になる**。
- ⚠️ **単独でのみ受ける**＝取り込みや書き出しと混ぜると、**どこまで進んだかが終了コード1つでは表せない**。
- ⚠️ **終わったかは「残りが 0 か」で見る**＝途中で失敗した回を「できた」で返さない。

**使い方**（外の AI の通し）:

```
stario.exe --import  <フォルダ>          --quit-when-done   # 取り込む
stario.exe --make-voices <番号>          --quit-when-done   # 声を作る
stario.exe --export <番号> --out <道>    --quit-when-done   # 書き出す
```

⚠️ **3回に分けるのは意図です**＝1回にまとめると、**どこで失敗したかが終了コードから読めません**。

## 採らなかった案

| 案 | なぜ採らないか |
|---|---|
| **常駐の待ち受け（HTTP/WebSocket）** | 入れただけで**外から触れる面**ができる。AI は同じ機械でソフトを起こせるので必要が無い |
| **画面を出さない（headless）** | 描画核が WebView にある（ADR-0001）ので窓は要る。加えて**失敗が見えない** |
| **Rust だけで書き出す** | 絵を作るのは WebView＝**描画核の二重化**になる（ADR-0001 が禁じている当のもの） |
| **2つ目を普通に起こす** | 書き出しが保存を伴うので、**後から保存した方が勝つ**（利用者の編集が消える） |
| **AI 専用の簡易フォーマット** | 正典 schema が既に AI 向けの入口になっている（実測済み）。増やすと**二重管理**になる |

## 結果

- **α で入れる**＝①〜⑥。
- ⚠️ **利用者に確認済み**（2026-09-17）＝決定③で画面から見て変わるのは
  「**2つ目の窓が開かなくなる**」と「**編集中に AI が書き出そうとすると断られる**」の2点。**問題なしと回答**。
- **書く側の契約**（置き場・ID 採番・素材の相対パス・声のファイル名と `status`・検証の掛け方・失敗の返り方）を
  1枚にまとめる（[#1184](https://github.com/fujii-yuki-star/star-recruit-studio/issues/1184) ③）。⚠️ **いまはどこにも書いていない**。
- β は**社内向けの積み増し**に専念できる。
