# ADR-0036: ブランドキット（最小形）＝会社の既定フォント・色・ロゴ

- **状態**: Accepted
- **日付**: 2026-08-26
- **関連**: `#351`（α-6）／[`ADR-0035`](0035-user-asset-library.md)（素材ライブラリ・**本 ADR と対**）／[`ADR-0017`](0017-template-authoring-editor.md)（ユーザーテンプレのグローバル化）／[`ADR-0021`](0021-template-owned-assets.md)（テンプレ既定素材）／[`ADR-0024`](0024-non-destructive-editing-model.md) 決定6（自己完結）／[`ADR-0033`](0033-editor-panel-layout.md)（画面の好みは `appSettings`）／`CLAUDE.md §2-5`（**黙って別の見た目に差し替えない**）／`#161`（同梱フォント）／`#261`（持ち込みフォント）

## コンテキスト

同じ会社の動画を作るたびに、フォント・色・ロゴを毎回選び直している。会社の**ブランド一貫性**をグローバルに保ち、新しい動画に既定として効かせたい（#351）。

**α-6 は最小形に絞る**（利用者決定 2026-07-02）＝**既定フォント（`fontId`）／ブランドカラー（数色）／ロゴ素材**の3つだけ。フル版（字幕・テロップのスタイル、BGM の傾向、複数キット）は β へ。

### 現状（実コードで確認・2026-08-26）

| | 状態 |
|---|---|
| グローバル設定の置き場 | `src/infrastructure/appSettings.ts`＝**`localStorage`**（VOICEVOX 接続先・話者・欄の配置）。**ファイルではない** |
| グローバルなファイルの置き場 | `userTemplateFs.ts`（`appData/user_templates/`）／`templateAssetFs.ts`（`user_templates/assets/`） |
| 色の候補 | `ColorPicker.tsx:15-17` の**固定18色**（会社の色を足す口が無い） |
| 既定フォント | `videoSettings.fontId`（`project.schema:62`）＝**プロジェクトごと**。グローバルな既定は無い |

### ⚠️ ADR-0035 に書いた記述の訂正が要る

[`ADR-0035`](0035-user-asset-library.md) は、素材ライブラリで**参照でなくコピー**を採る理由として「**『一元管理して全プロジェクトへ反映』のニーズは #351 ブランドキットが担う**」と書いた。しかし **#351 の射程は「新規プロジェクトへ既定適用」**であり、**既存のプロジェクトには遡及しない**。

つまり、コピー方式を採った結果として「**ロゴを1か所直したら既存の動画にも反映される**」道は**いまどこにも無い**。ADR-0035 の当該記述は言い過ぎであり、本 ADR の決定に合わせて訂正する（下記「結果・影響」）。

## 判断軸

1. **黙って差し替えない**（`CLAUDE.md §2-5`・#547）＝既存の動画の見た目が、利用者の操作なしに後から変わってはいけない。**過去に書き出した動画と、いま書き出し直した動画が違う絵になる**のは最悪の形。
2. **プロジェクト自己完結**（ADR-0024 決定6・ADR-0035 で追認）。
3. **棚を増やさない**＝ADR-0035 で `user_assets/` を作るので、ロゴのためだけに第3の置き場を建てない。
4. **`project.schema` を触らない**（#351 本文の「project.json 原則不変」）。

## 検討した選択肢

### 論点1：ブランドキットの保存先

| 選択肢 | 評価 |
|---|---|
| (1-A) すべて `appSettings`（`localStorage`） | 色とフォント id は載るが、**ロゴのファイルが載らない**。`localStorage` は端末ローカルで**バックアップも移行もされない**＝会社のブランドという性質に合わない。**不採用** |
| **(1-B) `appData/brandkit.json`（ファイル）＋ロゴは ADR-0035 のライブラリを指す** | 色・フォント id・**ロゴの `lib_asset_NNN`** を持つだけの小さな JSON。`userTemplateFs` と同型。**ロゴの実体はライブラリに置く**ので棚が増えない。**採用（推奨）** |
| (1-C) `brandkit.json` ＋ ブランドキット専用のロゴ置き場 | ライブラリと役割が重なる第3の棚ができる（同じロゴが2か所に）。**不採用** |

### 論点2：新規プロジェクトへの適用のしかた

| 選択肢 | 評価 |
|---|---|
| **(2-A) 作成時にコピー（既定として焼き込む）** | `videoSettings.fontId` に既定フォントを入れ、ロゴは**ライブラリから素材としてコピー**（ADR-0035 の取り込みと同じ経路＝`asset_NNN` を採番）。以後そのプロジェクトは**自己完結**し、ブランドキットを変えても影響を受けない。**採用（推奨）** |
| (2-B) 参照（プロジェクトはキットを指すだけ） | 自己完結が壊れ、キットを直すと**過去の動画の見た目が黙って変わる**（判断軸1 に真正面から抵触）。**不採用** |

### 論点3：**既存プロジェクトへの反映**（本 ADR の要・ADR-0035 の訂正に直結）

| 選択肢 | 評価 |
|---|---|
| (3-A) 持たない（新規のみ） | 最小。ただし「ロゴを差し替えたい」動機に**何も答えない**＝ADR-0035 が #351 に渡した役割が宙に浮く |
| (3-B) 自動で反映 | **判断軸1 に抵触**（黙って差し替える）。過去に書き出した動画と再書き出しが違う絵になる。**不採用** |
| **(3-C) 明示操作で適用し直せる**＝「この動画にブランドを適用する」（確認つき・取り消し可） | 利用者が**その動画に対して**選んだときだけ変わる＝黙って変わらない。ADR-0035 が渡した役割にも答えられる。既存の「まとめて標準にする」（#547・`freeContentHiddenBySwitch` の流儀）と**同型の導線**で、**何がいくつ変わるかを先に見せる**。**採用（推奨）** |

### 論点4：色の出しかた

ブランドカラーは **`ColorPicker` の候補の先頭**に出す（既定18色の前に「この会社の色」の段を置く）。**既定色を置き換えない**（ブランド色だけになると普通の色が選べない）。

### 論点5：AI 入力に含めるか

**特別な規則は要らない**。決定2（コピー）により、ロゴは取り込んだ時点で**普通のプロジェクト素材**になるため既存経路（`assetSendText`／送信前確認＝§2-6）に乗る。色とフォントは AI の入力語彙ではない（AI は `ai-video-plan` を返すだけで見た目を決めない＝§2-1）。

## 決定（Accepted・2026-08-26 利用者承認）

1. **保存＝`appData/brandkit.json`**（`userTemplateFs` と同型）。中身は**既定 `fontId` ／ ブランドカラー（数色）／ ロゴ1つの `lib_asset_NNN`**。**ロゴの実体はライブラリ（ADR-0035）に置き、キットは指すだけ**。
2. **新規プロジェクトへは作成時にコピー**（`videoSettings.fontId` へ既定フォント／ロゴはライブラリからの取り込みと同じ経路で `asset_NNN` を採番）。⇒ **`project.schema` は不変**。
3. **既存プロジェクトへは「明示操作で適用し直せる」**（確認つき・取り消し可・**何がいくつ変わるかを先に見せる**）。**自動反映はしない**（§2-5）。
4. **色は `ColorPicker` の候補の先頭に足す**（既定18色は残す）。
5. **AI の扱いに特別な規則を作らない**。

6. **ロゴは1つだけ覚える**（利用者決定）。⚠️ **これは「会社の既定として何枚おぼえておくか」の話**＝プロジェクト側も素材ライブラリも `logo` 素材を**いくつでも持てる**ので、白抜き版・正方形版などが要る動画では**ライブラリから取り込めばよい**（キットが指すのは「新しい動画に最初から入れておく1枚」）。複数キットは β のフル版へ。

**利用者承認（2026-08-26）＝2点とも決着。**
- **決定3 は YES**＝**既存プロジェクトへの「適用し直し」を α-6 に入れる**。これにより ADR-0035 が #351 へ渡した役割（会社の資産を1か所で持ち、既存の動画にも反映できる道）が実際に成立する。⚠️ ただし**反映は明示操作のときだけ**＝自動で遡及はしない（§2-5）。
- **ロゴは1つ**（決定6）。

## 結果・影響

### コード

- 新設＝`src/infrastructure/brandKitFs.ts`（`userTemplateFs.ts` と同型）＋ Rust コマンド。パス検証は `src-tauri/src/lib.rs` の `is_safe_template_id` と同型。
- 画面＝設定に「ブランド」（フォント／色／ロゴの登録）。**技術用語を出さない**（§2-3）＝言い方は `uiLabels` に集約。
- 新規作成の導線（ホーム→新規）で既定を焼き込む。**押した瞬間に作らない**流儀（ADR-0032 決定15＝向きを先に聞く）と同じ画面に乗る。
- 決定3 の導線は **#547 の「まとめて標準にする」と同型**（件数つきの確認・取り消し可）。

### 正典

- **`project.schema` は不変**（決定2 の帰結）。`template.schema` も不変。
- `brandkit.json` は**プロジェクトの正典ではない**（アプリの持ち物）＝`schemas/` には置かず、形は本 ADR と実装で定める。⚠️ **`11 §1` の3スキーマ（project/template/ai-video-plan）は増やさない**。
- **[`ADR-0035`](0035-user-asset-library.md) の記述を訂正**＝「一元管理して**全プロジェクトへ反映**」→「**新規プロジェクトへの既定適用**と、**既存へは明示操作での適用し直し**」。**自動で遡及はしない**ことを明記する。
- `CLAUDE.md §11` に本 ADR を **Accepted** として1行追記（本 PR で実施）。
