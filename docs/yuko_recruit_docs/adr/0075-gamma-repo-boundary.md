# ADR-0075: すたりおMV（γ）をこのリポジトリに同居させる境界

- **状態**: Accepted（2026-11-25・利用者判断＝再監査で示した推奨4点すべて）
- **日付**: 2026-11-25
- **関連**: ADR-0074（γ の設計の大枠＝同じリポジトリの別アプリ・周辺だけ共有）／#1337 §15（着手時の最初の仕事＝①再監査 ②共有部品の抽出 ③境界の ADR 化 ④build の分離 ⑤γ の schema ⑥γ0.1）／`CLAUDE.md`／調査 [`archive/research/2026-11-stario-mv-repo-audit.md`](../archive/research/2026-11-stario-mv-repo-audit.md)

## コンテキスト

2026-11-25、利用者が γ への着手を判断した（#1337）。着手前の再監査（読み取りのみ・凍結点 develop `dec9aadf`）で分かったこと：

- **リポジトリはどこを見ても「ルート＝α ただ1つ」**の作り。ルートの `package.json`／`vite.config.ts`（1420 番固定）／`index.html`／`tsconfig.json`、`src-tauri/` が1つ、CI 4本（`src-tauri` 決め打ち）、配布スクリプト、門番テスト（`src` を丸ごと歩き件数を実数で固定）、資料・スキル・レビュア。
- **ルートの `CLAUDE.md` は毎セッション全文が読まれ**、§2（AI は動画を作らない・テンプレ駆動・技術用語を出さない）・§5（`part_NNN` の採番）・§10・§11 が γ の方針（ADR-0074）と食い違う。γ の作業中に当てはめると、正しい設計を誤って押し返す。
- 共有できる部品は多い（窓なし起動・空き容量・開く関門・記録・素材の取り込み・whisper・持ち込みフォント・画面の小部品・hooks・SRT/VTT など）が、**どれも α の中から直に使う形**で、置き場の決め打ち・β の一時の動画への寄り道・文言ファイル（`uiLabels.ts`）の α 型への依存・ソース本文を読む検査がある。
- FFmpeg（`ffmpeg.rs` 9,847 行）のうち汎用は推定約 1,500 行。残りは α の「場面を焼いてつなぐ」書き出しそのもの。
- α を `apps/` へ移す（モノレポ化）と、門番・スクリプト・CI・資料のリンクが数十か所壊れる＝ADR-0074 の「α を変えない」と衝突する。

## 判断軸

- **α を変えない**（ADR-0074）＝α の門番・スクリプト・CI・正典を書き換えずに γ を足す。
- **γ の作業で α の正典を誤って当てはめない**（AI 駆動開発の前提＝毎回読まれる規約が食い違うと推測で埋められる）。
- 二重管理の害が出るまでは、共有の仕組みを作り込まない（必要になった順に切り出す）。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) **α は1ファイルも動かさず、`apps/stario-mv/` に γ を独立して新設** | α の門番・スクリプト・CI・正典を書き換えない。共有は当面「参照」か「小さな写し」。**採用** |
| (B) ルートを npm／Cargo のワークスペース親にし、α はルートに残す | 共有は最初から正しくできるが、Cargo.lock と target がルートへ移り、α の配布手順・版の整合の門番・CI・監査が壊れる。不採用 |
| (C) 最初から α を `apps/stario/` へ移す（完全なモノレポ） | 最終形はきれいだが、α を大きく変える。不採用 |

## 決定

### 決定1：置き方＝α は動かさず `apps/stario-mv/` に独立して新設する

- γ は `apps/stario-mv/` に、**独自の** `package.json`・lock・`vite.config.ts`（α と別のポート）・`index.html`・`tsconfig.json`・`src/`・`src-tauri/`（`Cargo.toml`・`Cargo.lock`・`tauri.conf.json`・識別子・productName・インストーラーの設定）を持つ。npm／Cargo のワークスペースにはしない。
- ルート側で変えるのは、**α の道具が γ を拾わないための除外**（vitest・eslint・`.gitignore`）と、**γ 用の CI の新設**（`apps/stario-mv/**` に絞る）だけ。α の門番の走査範囲は変えない。

### 決定2：共有は「参照＋小さな写し」から始め、本格的な切り出しは後で

1. **同梱物とフォントは参照で共有**：γ の `bundle.resources` から `src-tauri/resources/ffmpeg`・`transcribe` を指す（ファイルは動かさない・VOICEVOX と local_llm は指さない＝ADR-0074 決定1）。`public/fonts` も同様。
2. **小さく安定した部品は γ 側へ写す**（窓なし起動・空き容量・`isTauri`・hooks・純粋関数など。数百行規模）。**写した元（α のパス）を γ 側に記録**して、どれが写しかを追えるようにする。
3. **FFmpeg まわりは γ 側で新しく書く**（α を手本にする）。γ の書き出しは GPU で描いたコマを受け、透過付きの形式でも書き出す＝α の書き出しとは別物。
4. **本格的な切り出し**（`crates/`・`packages/` へ移して α からも使う）は、写しの二重管理の害が出たとき、または α を大きく触る機会（一般配布の前の整理など）に、**ADR を1本立てて1つの PR でまとめて行う**。

### 決定3：γ の規約・資料・ADR は別の場所・別の番号

- γ の規約：`apps/stario-mv/` の直下に置く CLAUDE.md。④で作る。
- γ の資料：`docs/stario_mv_docs/`（`schemas/`・`adr/`・`guides/` など）。
- γ の ADR は **`MV-0001` から振る**。α の ADR 一覧（`docs/yuko_recruit_docs/adr/`）には足さない＝α の資料の大きさの門番・索引の門番に影響しない。
- ⚠️ 例外：**α と γ の両方にかかる決定**（この ADR のようにリポジトリの運用を決めるもの、ADR-0074 のように γ の存在を α の正典へ書くもの）は α の側に置く。
- γ 用の門番・スキル・レビュアは γ 用に作る（α のものは α の正典を前提にしているため・再監査 §2）。

### 決定4：ルートの `CLAUDE.md` の冒頭に、γ の除外を書く

- 「`apps/stario-mv/**` と `docs/stario_mv_docs/**` では γ の規約が優先し、本ファイルの §2・§4・§5・§10・§11 は当てはめない」旨を冒頭に置く。
- そのために **`CLAUDE.md` の文字数の上限を 16,000 → 16,500 字に上げる**（`src/test/canonIndexGuard.test.ts` の `CLAUDE_MAX_CHARS`）。理由＝γ の同居でリポジトリの前提そのものが変わり、その除外は毎セッション読まれる場所にしか置けない（ADR 本体へ移すと、読まれずに当てはめられる）。上げ幅は除外の数行分に限る。
