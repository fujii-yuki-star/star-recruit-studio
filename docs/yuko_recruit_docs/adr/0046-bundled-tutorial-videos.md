# ADR-0046: チュートリアル映像を同梱する（AI がソフトを操作して録り、仮想カーソルと声を後から足す）

- **状態**: Accepted
- **日付**: 2026-09-24（技術検証 → 提案 → **同日、利用者判断で確定**）
- **関連**: [`ADR-0042`](0042-agent-entrypoints.md)（外の AI が使う口）／[`ADR-0025`](0025-credit-display-modes.md)（クレジットの出し方）／[`ADR-0026`](0026-alpha4-behavior-consistency.md)（黙って別の結果にしない）／[`ADR-0013`](0013-h264-via-media-foundation.md)（LGPL 構成に `libx264` は無い）／[`ADR-0005`](0005-voicevox-bundling.md)・[`ADR-0003`](0003-narration-voice.md)（声）／[`ADR-0024`](0024-non-destructive-editing-model.md)（同梱物の例外）／[`ADR-0032`](0032-timeline-project-format.md)（タイムライン形式）／`13 §4-5`（VOICEVOX とずんだもんの規約）／[#1194](https://github.com/fujii-yuki-star/star-recruit-studio/issues/1194)（長尺素材の通し試験）

## 背景

利用者から「**このソフトのチュートリアル映像をいくつか撮り、ソフトに同梱したい**」という要望がありました。
作り方の希望は次のとおりです。

> **AI にソフトを操作してもらって録画を回し、仮想カーソルを用いてチュートリアル映像の元を取る。
> それに AI で解説ナレーションを付けて完成させる。若干ユーモアも交えたものにしたい。**

いまアプリの「ヘルプ」は**準備中**（左の帯に出ているが押せない）で、**使い方を伝える手段がありません**。
利用者は人事・非エンジニアが前提（`CLAUDE.md §1`）なので、**文章より映像のほうが届く**という判断は妥当です。

## 技術検証（すべてこのパソコンで実測・2026-09-24）

**「録れるか」を先に確かめてから ADR を書く**という順序で進めました（利用者の指示）。

| 要る物 | 結果 | 実測 |
|---|---|---|
| 画面の録画 | ⭕ | 同梱 FFmpeg の `gdigrab`。⚠️ **`libx264` は入っていない**（LGPL 版）ので `h264_mf` で焼く |
| 実アプリの操作 | ⭕ | **WebView2 のリモートデバッグ**（CDP）。`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222` で起動すると `http://127.0.0.1:9222` が開く |
| 本物の入力 | ⭕ | `Input.dispatchMouseEvent`＝JS の `.click()` ではなく**人が押したのと同じ道**を通る |
| 押した位置を知る | ⭕ | `getBoundingClientRect()`＝**仮想カーソルを描くための座標**がそのまま採れる |
| 実カーソルを消す | ⭕ | `-draw_mouse 0` |
| ナレーション | ⭕ | VOICEVOX を同梱済み（`ADR-0005`） |

### ⚠️ 窓を名前で指定する取り込みは**使えない**（この検証の一番の収穫）

`gdigrab -i "title=すたりお"` で6秒録り、その間に CDP で画面を遷移させたところ、

- **CDP から見た画面**＝「どんな動画を作りますか？」（遷移している）
- **録画の全フレーム**＝「伝えたいことを、動画でやさしく届けましょう」（**6秒間ずっと古いまま**）

WebView2 は GPU 合成で描くので、**窓指定の取り込み（BitBlt）が更新を見られません**。
⚠️ **黙って古い絵が録れる**＝失敗として現れないので、これを知らずに撮ると**中身が嘘の教材**ができます。

→ **デスクトップから窓の矩形を切り出す**（`-i desktop` ＋ `-offset_x/-offset_y/-video_size`）に変えたところ、
**遷移後の画面が正しく写りました**。窓の位置と大きさは `GetWindowRect` で採れます。

### ⚠️ 「撮れたか」を確かめる道具も、2つ試して使えなかった

⚠️ **ここを知らないと、同じ2つを踏む**（#1226 の実装で実測）。

| 試した | 結果 |
|---|---|
| `mpdecimate`（重複コマを落とす） | ❌ **このビルドに無い**（LGPL 版） |
| `freezedetect` | ❌ **最後の区間を報告しない**（`freeze_end` が出ない）＝**5秒の静止画で 1.07秒**としか言わない＝**門が鳴らない** |

→ **生の画素を取り出して自分で比べる**。判定が純粋関数になるので、**そのまま検査できる**。
⚠️ **完全一致では見ない**＝h264 は不可逆で、**同じ画面でも1画素ずつ違う**
（完全一致で数えたら静止画5秒が「違う絵5枚」になった）。

### ⚠️ 「計算した値で描いて、同じ値で検査する」は、検査になっていない（#1227 で判明）

押した座標は**画面の中**の座標なので、録画（**窓の枠ごと**の切り出し）に描くには
**ずれ（`view`）を足す**必要があります。この `view` は `screenX - windowX` の**引き算で出した値**です。

⚠️ **焼いた絵を、その同じ `view` から作った期待値と比べても、検査になりません**＝
`view` が丸ごと間違っていても**両方が同じだけずれて辻褄が合う**。
**実測**＝`view` のずれを丸ごと落として焼いたところ、検査は `✓` を出しました。

→ **独立した物差しを1つ置く**：撮り始めに**画面いっぱいの目印**を焼き付け、
**録画そのものから中身の矩形を測って** `view` と突き合わせる（`checkViewAgainstVideo`）。
⚠️ **目印は焼く側が切り落とす**＝`usableFromSec` を記録に書き、`tutorialCursor` が
`trim` で頭を落とす（**切らないと、配る素材の頭に全画面のマゼンタが載る**）。

⚠️ **この物差しは、入れてすぐに2つの不具合を見つけました**（どちらも**エラーは出ない**種類）。
ただし**「機械が落とした」のは1つだけ**で、もう1つは**印字した実測値を人が読んで**気づいたものです
（許容の内側だったので門は鳴っていない）。**そこを混ぜて書かない**。

| 何が起きていたか | どう分かったか | 元を断った手 |
|---|---|---|
| 起動直後に窓の大きさがまだ動いており、**測った `view` が古い** | 高さ **767**（計算 800・差 33）＝**門が落とした** | **大きさが2回続けて同じになるまで待つ**（`stableWindowRect`） |
| 窓の下端が**タスクバーの下**に潜り、そこに**タスクバーが写る** | 高さ **793**（計算 800・差 7）＝**許容の内側**なので門は鳴らず、**印字を読んで**気づいた | 撮る前に**画面の使える範囲に収まっているか**を見る（`workArea`） |

⚠️ **後者の 7 画素は計算と合う**＝窓 `y=208` ＋ 題字の帯 31 ＋ 中身 800 = 1039 で、
使える範囲の下端 1032 を **7** 超えていた。**許容を広げて通さない／狭めて誤検出も出さない**＝
**原因の所（撮る前）で断つ**。あわせて、実測の印字は「一致」ではなく**ずれを数で**出す。

⚠️ **層で分けて見る**（どれか1つでは塞がらない）。

| 何がおかしいか | どこで捕まえるか |
|---|---|
| 座標を直す関数（`toVideoPoint`）の中身 | `scripts/lib/cursor.test.mjs`＝「**ずれを足さない**」「**拡大率を掛けてしまう**」の2つの**壊し方**で赤くなることを確認（実装は**ずれを足し、拡大率は掛けない**） |
| `view` の値そのもの（古い・ずれている） | **録画から実測**して突き合わせ（`tutorialRecord.mjs` → `viewVerdict`） |
| カーソルの絵・道筋・`overlay` の式 | 焼いた録画と元の録画を比べる（`tutorialCursor.mjs` → `markVerdict`） |

⚠️ **判定はすべて `scripts/lib/` に置く**＝ffmpeg を起こす所に書くと、**いちばん効かせたい判定が
変異チェックに掛からない**（実際に一度そうなっていた）。走らせる側に残すのは副作用だけ。

⚠️ **輪だけを見ない**＝押した瞬間の印（輪）は**左右対称で重心が押した点そのもの**なので、
そこだけ見ていると**カーソルが1画素も描かれていなくても通ります**。
**輪が出ていないあいだで、カーソルが止まっている時刻**（多くは**押す直前の溜め**）も見ます。
⚠️ **「1つでもあれば良い」にしない**＝押す間隔を詰めた台本では、この標本が**静かに痩せる**
（3回押しても1点しか見ない）。**押下ごとに1点**を要求します。

### ⚠️ 画面の拡大率は 100% でなければ撮れない

`window.screenX` は **CSS px**、`GetWindowRect` と `gdigrab` は**物理 px** なので、
**100% のときだけ単位が一致**します。「掛ければよい」は**推測**（どちらに掛けるかで結果が変わる）ので、
**100% 以外はその場で断る**ことにしました（#1226）。副モニタ（負の座標）も同様に断ります。

## 判断軸

1. **黙って別の結果にしない**（ADR-0026④）＝教材が**実物と違う画面**を見せない。これが最優先。
2. **実物を撮る**＝`isTauri()` が false のブラウザ（`npm run dev`）では、**選べても取り込めない・書き出せない**
   （⚠️ **選択そのものは動く**＝`useAssetPicker` がブラウザでは `<input type=file>` へ落とす。
   動かないのは**ネイティブの「開く」**と、`assetFs` の保存系〔`isTauri()` false で軒並み `null`〕と、
   `ffmpegExport`〔`invoke` 直呼び〕）。教材としては致命的なので、**必ず packaged のアプリ**を撮る。
3. **同梱物を増やす判断**＝`13`（権利台帳）に行が増える。⚠️ **声の可否は既に確認済み**（`ADR-0005`・#122）で、
   残るのは**クレジットの出し方**と**配布物の大きさ**。
4. **自分の製品で作る**＝編集はこのソフト自身でやる。足りない機能が最短で露見する（`#1194` と**狙いは同じ**だが、⚠️ **代わりにはならない**＝下記）。

## 検討した選択肢

### 操作の手

| 選択肢 | 評価 |
|---|---|
| (A) **WebView2 のリモートデバッグ（CDP）** | ⭕ **採用**。実アプリを操作でき、**押した座標が採れる**（仮想カーソルの素になる）。道具の追加インストールが要らない（実測で確認済み） |
| (B) `tauri-driver` ＋ WebdriverIO | △ Tauri 公式だが**未導入**（`cargo install` が要る）。できることは (A) とほぼ同じ |
| (C) 実入力の注入（nut.js・AutoHotkey） | ❌ **録画中このパソコンを占有**する。座標頼みで壊れやすい |
| (D) ブラウザ（`npm run dev`）＋ Playwright | ❌ **別物が写る**（判断軸2＝選べても取り込めない・書き出せない）。録画機能が標準にあるのは魅力だが、教材にならない |

### カーソル

| 選択肢 | 評価 |
|---|---|
| (A) **後から合成する（仮想カーソル）** | ⭕ **採用**。押す位置は CDP から採れるので、**等速で動き、押す前に少し溜める**といった読みやすい動きが作れる |
| (B) 実カーソルを写す | ❌ 手ブレ・行き過ぎ・迷いが必ず写る。(C) の入力注入とセットでしか成立しない |

### 声

| 選択肢 | 評価 |
|---|---|
| (A) **VOICEVOX（製品の既定の声）** | ⭕ **採用**。製品と声が揃う。**規約上の制限は無い**（下記） |
| (B) 自社で用意した声 | ❌ **製品の中の声と食い違う**（教材の声と、作った動画の声が別になる）。避ける理由が無い |

⚠️ **当初 (A) を「権利の確認が要る」と書いたのは誤りだった**（2026-09-24・利用者の指摘で訂正）＝
**音声を作るのは VOICEVOX** であり、**それを走らせる者（ここでは AI）が利用者**にあたる。
「開発者が作った音声だから別の行為」という読みは、規約の構造を取り違えていた。
⚠️ **既に洗い出し済み**＝`ADR-0005`「規約・ライセンスの根拠」（#122・2026-06-22）に条項レベルで記録があり、
`13 §9:150` は VOICEVOX を **`[x]`（事業側確認済み・2026-06-18）** としている。
⚠️ **私が危険側に倒れた原因**＝`13 §5` の「確認が必要な点（リリース前必須）」に、
**`ADR-0003` で解消済みの論点**（ずんだもんの声を「ゆうこ」の声として使う可否）が
**解消前の書きぶりのまま残っていた**。→ **本 PR（#1224）で直した**。`13` 全体の棚卸しは [#1230](https://github.com/fujii-yuki-star/star-recruit-studio/issues/1230) に残る。

## 決定

### ① チュートリアル映像を**同梱物として持つ**（「ヘルプ」から開ける）

⚠️ **外部の動画サイトへ置かない**＝このソフトは**社内・オフライン**で使われうる（`13`）ので、
再生に通信を要求しない。**同梱**にする。

### ② 撮り方は「**実アプリを CDP で操作 ＋ デスクトップを窓の矩形で切り出す**」

⚠️ **窓を名前で指定して撮らない**（上の実測）＝**黙って古い絵が録れる**ので、
**撮った素材は必ず「遷移が写っているか」を確かめてから使う**（検収の手順に入れる）。

### ③ カーソルは**後から合成する**

押した位置（`getBoundingClientRect`）を**操作の記録として残し**、それを元に描く。

### ④ 編集は**このソフト自身**でやる

素の録画を取り込み、タイムライン形式で切り、声と字幕と BGM を足して書き出す。

⚠️ **`#1194` の代わりにはならない**（PR #1224 レビュー 🟡＝当初そう書いたのは過大主張だった）＝
`#1194` の軸は「**取り込む素材が 30〜60 分**」「**100回規模のカット**」であって、**出来上がりの長さではない**。
数分の画面録画から作るチュートリアルは、**その軸を通らない**（取り込み時間・容量・カット回数）。
→ **切る経路は共有するが、#1194 は別途やる**。⚠️ ここを混ぜると、**#1194 を誤って閉じる**方に効く。

### ⑤ 声は**製品の既定のもの**（VOICEVOX）／クレジットは**映像にも焼く**

⚠️ **規約上の制限は無い**（上記）。

**クレジットは利用者が作る動画と同じ扱い**＝`VOICEVOX:＜キャラ名＞` を**映像の最初と最後**に焼く
（ADR-0025 の既定と揃える・**利用者判断 2026-09-24**）。

⚠️ **About だけに頼らない**＝ADR-0025 が「非表示」を許すときの前提は**概要欄運用の補助**だが、
**同梱する映像に概要欄は無い**。**配る物**なので、映像側にも出すほうが安全側。
⚠️ **違和感が出たら変える**（利用者判断＝「あとから変えてもらうことにします」）＝
**焼く/焼かないを決め打ちで固めない**。台本と同じ置き場に持ち、差し替えられるようにする。

### ⑥ ユーモアは**言葉と間で作る**

⚠️ **VOICEVOX の抑揚は細かく操れない**（速さ・高さ程度）＝**声色で転がす笑いは乗らない**。
台本の言葉選びと、カットの間で作る。**説明の正確さを笑いのために曲げない**（教材なので）。

## 結果・影響

### 正典・配布物

- `13`（依存とライセンス）に**同梱物の行が増える**（チュートリアル映像・その中の声）。
- ⚠️ `13 §5`／`17` の**解消済みの論点が残っていた**のを**本 PR で直した**＝**次に読む人がまた危険側に倒れる**（実際にこの ADR の初版がそうなった）。`13` 全体の棚卸しは #1230。
- `06`（画面）に**「ヘルプ」が準備中でなくなる**ことを書く。
- インストーラの大きさが増える（⚠️ **α は MSI 単独配布**＝`CLAUDE.md §11`。**どれだけ増やしてよいかは未決**）。

### schema

**変更なしの見込み**＝映像は同梱のファイルで、`project.json` には入らない。
（「どこまで見たか」を覚えるなら `localStorage`＝ADR-0033 の流儀。**それを持つかは未決**。）

### 作る物（コードとして残るもの）

⚠️ **これは製品の一部ではなく、作るための道具**（`scripts/`）。実体は次のとおり（#1226・#1227）。

| もの | 何 |
|---|---|
| `scripts/tutorialRecord.mjs` | 実アプリを操作して録る（`npm run tutorial:record`） |
| `scripts/tutorialCursor.mjs` | カーソルと輪を焼く（`npm run tutorial:cursor`・**#1227 で入る**） |
| `scripts/lib/cdp.mjs` | CDP の配線と**要素の探し方**（`uiProbe` と共有） |
| `scripts/lib/frames.mjs` | 録画が本当に動いているかをコマの中身で数える |
| `scripts/lib/cursor.mjs` | カーソルの絵・輪・動き・座標の対応（**#1227 で入る**） |
| `scripts/lib/plan.mjs` | 引数と台本と**記録**の読み取り |
| `scripts/lib/burnCheck.mjs` | 焼いた印と `view` の**判定**（**#1227 で入る**） |
| `docs/tutorials/*.json` | 台本 |

アプリの中に**操作される口を新設しない**＝リモートデバッグは**起動時の環境変数だけ**で開くので、
製品の実装は変わらない（ADR-0042 が「待ち受けは作らない」と決めたのと同じ姿勢）。

⚠️ **撮影中だけは口が開く**（PR #1224 レビュー ℹ️）＝ADR-0042 が避けた「入れただけで外から触れる面」が、
**撮影機に一時的にできる**。ただし **`127.0.0.1` のみ**・**撮影している開発機だけ**・
**配布物には出ない**（環境変数を付けて起動したときにしか開かない）。

## 未解決の論点

1. **何本・何を撮るか**（ユーザー確認）＝最初の1本は「写真を取り込んで30秒の動画を書き出す」を想定。
2. **画面での呼び名**（ユーザー確認）＝`06 §3` の置換表に「チュートリアル」は**無い**（禁止語ではないが定着語でもない）。
   ⚠️ **決めずに `06` を書くと、書く人が推測で決めることになる**（§9-2）。
3. **インストーラの大きさをどこまで増やしてよいか**（ユーザー確認）。
4. **録画の解像度と長さ**＝1280×800 で撮れることは確認済み。**配る解像度は未決**。
5. **「どこまで見たか」を覚えるか**（覚えるなら `localStorage`・ADR-0033）。
6. ⚠️ **撮影中はこのパソコンを占有する**＝デスクトップから切り出すので、
   **窓に重なる通知や別の窓がそのまま写る**。撮り直しの運用（検収）をどう回すかは未決。
