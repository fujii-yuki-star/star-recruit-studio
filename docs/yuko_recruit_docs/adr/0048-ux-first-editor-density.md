# ADR-0048: 編集画面は UI/UX を優先する（ADR-0047 の「触る所は変えない」「列は触らない」を外す）

- **状態**: Accepted
- **日付**: 2026-09-29
- **関連**: [`ADR-0047`](0047-editing-ui-density.md)（決定4・6 を置き換える）／[`ADR-0033`](0033-editor-panel-layout.md)（決定4 を広げる）／[`ADR-0034`](0034-timeline-interaction-model.md)（業界の型）／#1256（撮影前の見直し）／調査 [`2026-09-timeline-ux-density-rereview.md`](../archive/research/2026-09-timeline-ux-density-rereview.md)

## コンテキスト

撮影前の見直し（#1256）で、主要な動画編集ソフト（Premiere・Resolve・Final Cut・CapCut・Clipchamp・Filmora・
PowerDirector・Shotcut・Kdenlive・YMM4・Camtasia ほか）と情報密度を比べた（2026-09-29）。

**分かったこと**＝操作の大きさは既に業界並み（ボタン 29px・列 28px）。**画面の大きさに対して見える量が少ない**原因は
①**面積の配り方**（1920×1009 の実測で、並びの列の領域が窓の 24〜32%・仕上がり確認 8.7%・左の一覧 12.9%・
目印が無くても目印の欄が 124px）と、②**他社がどれも持つ道具が無い**（欄の一時最大化・列の高さ・尺ぴったりの全体表示）。

このうち次の4つは、**記録済みの決定とぶつかった**。

| 候補 | ぶつかった決定 |
|---|---|
| 目印が無いときは目印の欄を畳む（b2） | ADR-0047 決定4「触る所（押す物・場所・言葉）は変えない」 |
| 「選んだ部品」の上段のボタン13個を移す（b5） | ADR-0047 決定4 |
| 列の高さを変えられるようにする（c1） | ADR-0047 決定6「列（28px）は触らない」 |
| 配置の型（プリセット）を選べるようにする（c3） | ADR-0033 決定4（画面ごとに配置は1つ） |

利用者の判断（2026-09-29）：

> 「それらの食い違いに関しては UI/UX を優先で考え新しい候補で進めましょう。
> 変な宗教をもって UI/UX を縛るくらいなら、宗教を捨てて、UI/UX にこだわったソフトにするべきです。」

## 判断軸

1. **使い心地が目的、決まりは手段**＝過去の決定は、その時点の困りごとに対する**手当て**だった
   （決定4＝覚え直しを強いない／決定6＝#1104 で太帯が原因でないと切り分けた）。手当てが次の改善を止めるなら、手当てのほうを直す。
2. **業界の型**（ADR-0034）＝他社がどれも持つ道具は、利用者が**知っている前提**で探す。無いことが不便になる。
3. **決まりを外すときも記録する**＝黙って外さない。何を外し、何を残したかをここに残す。

## 決定

1. **編集画面の見た目と操作は UI/UX を優先する**。記録済みの UI の決まりが、業界の型に沿った改善や実測で示せる改善を止めるなら、
   **決まりのほうを ADR で改める**（この ADR がその最初の例）。
2. **ADR-0047 決定4 を外す**＝押す物・置き場所・言葉も、**理由（業界の型・実測）を添えれば変えてよい**。
   ⚠️ **残すもの**＝決定1（寸法の正を1か所）・決定3（見た目＝当たり判定）・決定5（クラス名だけの約束を作らない）。
3. **ADR-0047 決定6 を外す**＝**列の高さは利用者が変えられる**。既定は 28px のまま（#1104 で実機から決めた値）。
   値は画面の好みとして `localStorage` に持つ（ADR-0033 と同じ流儀＝`project.schema` には入れない）。
4. **ADR-0033 決定4 を広げる**＝画面ごとの配置は1つのまま、**用意した型（プリセット）へ一発で切り替えられる**ようにする。
   切り替えた結果は、いまの配置として記憶される（型そのものは記憶しない）。
5. **欄の一時最大化を入れる**（Premiere の `` ` ``・VEGAS の Ctrl+F11 と同じ型）。**記憶しない一時状態**なので ADR-0033 の配置の記憶には触れない。

## 追補（2026-09-29）：列の見出しの出す／固定（c4）

⚠️ **ADR-0033 決定9 は利用者自身の指摘**（「隠す・固定・消すの常時表示は邪魔」）で決まったので、本 ADR の「決まりを外す」とは
性質が違う＝**先に確認した**。利用者判断＝A（常に出す）と B（普段は隠す）の中間の「**静かな常設**」で実装し、
**使ってみて今の状態が分かりにくければ A に寄せる**。

- 普段は見せない・押せない（見えない当たり判定を作らない）。見出しに乗せる／キーで入ると薄く出る。
- **変えた状態は常に濃く出す**＋**列の帯でも示す**（出さない＝薄く・固定＝斜線。帯の上にも斜線＝帯で埋まった固定の列が
  固定に見えなかったのを実装後の評価で見つけて直した）。
- 道具の行に「出さない列 N・固定 M」（押すとその列へ）。名前の全体は `title` で読める。
- 評価（ブラウザ版・1100×620・明暗両方）：状態はアイコン・帯・数の3つで読める。**押せることに気づくのは乗せたとき**（メニューの道は残る）。

## 結果・影響

- `CLAUDE.md §11`・`06_UI_SPEC.md §12.1` の ADR-0047 の書き方を直す（「触る所は変えない」「列は触らない」を消し、本 ADR を指す）。
- ADR-0047 の状態＝**Accepted／一部 Superseded（0048＝決定4・6）**。ADR-0033＝決定4 を本 ADR が広げた旨を追記。
- `schemas` / `11` は**変えない**（見た目の好みは文書に入らない）。`schemaVersion` 据え置き。

## 採らなかったもの

- **決まりは残し、例外として個別に許す**＝例外が積み上がると、どれが生きている決まりか読めなくなる。外すなら外す。
- **密度の切替（ゆったり／ふつう／詰める）**＝ADR-0047 の選択肢(D)。今回の困りごとは密度ではなく面積の配り方なので、引き続き採らない。
