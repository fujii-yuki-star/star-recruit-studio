# ADR-0038: ユーザー持ち込みフォント（`fontId` を同梱3種の enum から開く）

- **状態**: Accepted
- **日付**: 2026-08-26
- **関連**: `#261`（α-6）／`#161`（同梱フォント3種の選定）／`#793`（**将来の版の案内**・本 ADR と直結）／[`ADR-0036`](0036-brand-kit.md)（ブランドの既定フォント）／[`ADR-0035`](0035-user-asset-library.md)（アプリがグローバルに持つものの流儀）／[`ADR-0024`](0024-non-destructive-editing-model.md) 決定6（プロジェクト自己完結）／[`ADR-0001`](0001-rendering-parity.md)（パリティ）／`13 §6`（フォントの権利）／`CLAUDE.md §2-5`（黙って差し替えない）

## コンテキスト

フォントは**同梱の3種に固定**されている（`#161`）。利用者が自前のフォント（会社指定の書体など）を使えるようにしたい（#261）。

### 現状（実コード・実ファイルで確認・2026-08-26）

| | 状態 |
|---|---|
| 型 | `FontId = 'gen-interface-jp' \| 'gen-interface-jp-display' \| 'kaitou-yokoku-gothic'`（`src/domain/font/fontCatalog.ts:7`）＝**3値の union** |
| カタログ | `FONT_CATALOG`（同ファイル）＝id・表示名・`cssFamily`・用途 |
| 実体 | `public/fonts/*.ttf`（5ファイル）＋ OFL のライセンス文 |

| 書き出し | `renderer/export/loadExportFonts.ts` が **`FONT_CATALOG` を全部** `document.fonts.load()` する（**読み込み済みの字体しか焼けない**＝ADR-0032） |
| schema | **`project.schema.json` に enum が8か所**＝`videoSettings.fontId` ／ `Scene.fontId` ／ `FreeElement.fontId` ／ **`textFontIds` の5種別**（title/main/subtitle/caption/url） |
| schema（timeline） | **0か所**＝`timeline-project.schema.json` は `$ref` で project.schema を**共有**している（`FreeElement/properties/fontId`・`Scene/properties/textFontIds`）＝**直せば自動で追従する** |
| 参照コード | `FontId` を参照するファイルは **18**（テスト除く・`domain` / `renderer` / `app` にまたがる） |

### 権利の前提（`13 §6`・**本 ADR の要**）

正典は「**判定基準は『広く配布されているか』ではなく、ライセンスが“同梱・再配布・埋め込み”を許可しているか**」とし、**游ゴシック・メイリオ等は同梱・再配布不可**と明記している。

⚠️ **利用者が持ち込むフォントは、再配布できないものが多い。** ここが素材（写真・BGM）と決定的に違う＝写真は利用者の持ち物なのでプロジェクトに入れて渡せるが、**フォントを入れて渡すと再配布にあたりうる**。

## 判断軸

1. **権利**（`13 §6`）＝アプリが**フォントの再配布経路になってはいけない**。
2. **黙って差し替えない**（§2-5）＝フォントが無い環境で**別の字体に化けた動画**を成功として出さない。
3. **パリティ**（ADR-0001）＝プレビューと書き出しで同じ字が出る＝`loadExportFonts` が持ち込みフォントも読む。
4. **正典の単一参照**（§2-7）＝`FontId` と schema enum の対応を1か所に保つ。

## 検討した選択肢

### 論点1：フォントファイルの置き場

| 選択肢 | 評価 |
|---|---|
| (1-A) **プロジェクト内にコピー**（素材と同じ＝ADR-0024 決定6） | 自己完結して渡した先でも同じ字が出る。しかし**プロジェクトを渡す＝フォントを渡す**ことになり、**アプリが再配布経路になる**（判断軸1）。持ち込まれる書体の多くは再配布不可。**不採用** |
| **(1-B) グローバルに置く**（`appData/user_fonts/`）＝プロジェクトには入れない | ADR-0035（`user_assets/`）・ADR-0036（`brandkit.json`）と**同じ流儀**。**再配布経路にならない**。欠点＝プロジェクトを渡した先にフォントが無い＝**字が化ける**が、これは判断軸2 で「黙って化けさせない」ことで扱う（論点4）。**採用** |
| (1-C) 参照だけ（利用者のPC上の元の場所を指す） | ファイルを移動・削除されると壊れる。`#347`（再リンク）の対象が増える。アプリの管理外のパスを持ち歩くことになる。**不採用** |

> ⚠️ **これは素材（ADR-0035）と結論が同じでも、理由が違う。** 素材は「自己完結を守るためコピー」、フォントは「**再配布しないためコピーしない**」。同じ「コピー」という語で混同しないこと。

### 論点2：`FontId` の型と schema をどう開くか

| 選択肢 | 評価 |
|---|---|
| (2-A) enum に持ち込み分を足す | 利用者ごとに値が違うので **enum に書けない**。**不採用** |
| **(2-B) `string` にし、書式（pattern）で縛る** | 同梱＝現行の3値をそのまま維持／持ち込み＝**接頭辞で名前空間を分ける**（例 `user_font_NNN`＝`11 §2` の採番規約に合わせる）。`project.schema` の**8か所**を pattern へ。**`timeline-project.schema` は `$ref` 共有なので追従不要**。**採用** |

### 論点3：**旧版アプリとの関係（#793 と直結・実施順に影響）**

enum を開いた文書（`fontId: "user_font_001"`）は、**いまのアプリでは schema 検証に落ちる**。落ちたときの案内は現状「**この動画の内容が正しくありません。一覧から別の動画を選んでください**」＝**嘘**（壊れておらず、アプリを更新すれば開ける）。これは **#793 がまさに直そうとしている問題**。

⇒ **#793（将来の版の案内）を本件より先に実施する**。順序を逆にすると、更新前のアプリで開いた利用者に「壊れています」と言うことになる。

> ℹ️ `schemaVersion` のマイナーバンプは additive の慣例どおり。**同メジャーなら旧版も「版が新しい」と判定できる**ので、#793 が入っていれば「アプリを更新してください」と正しく案内できる。

### 論点4：フォントが見つからないとき（判断軸2）

`fontId` は指しているのに `user_fonts/` に実体が無い（別PC・削除・アプリ再インストール）。

| 選択肢 | 評価 |
|---|---|
| (4-A) 黙って既定フォントで描く | **文字数・折り返し・はみ出しが変わる**＝**プレビューと違う動画**が成功として出る。§2-5・ADR-0026④ に抵触。**不採用** |
| **(4-B) 知らせる**＝編集画面で「この字体が見つかりません」と出し、**書き出しは事前に断る** | `#346`（書き出し前チェックの拡張）に**検査項目として足す**。素材欠け（`#347`）と同じ扱い。**採用** |

> ⚠️ **描画そのものは既定へフォールバックしてよい**（画面が真っ白になるより良い）。禁じるのは**黙って書き出すこと**。

### 論点5：登録のしかた（描画・書き出しの両方に効かせる）

- 同梱＝`fonts.css` の静的 `@font-face`（現行のまま）。
- 持ち込み＝**`FontFace` API で動的に登録**する（`document.fonts.add`）。読み込み元は `user_fonts/` のファイル。
- `loadExportFonts` は **`FONT_CATALOG`（同梱）に加えて持ち込み分も読む**＝いまは同梱を全部読んでいるだけなので、**カタログの作り方を「同梱＋持ち込み」に変える**のが最小の変更（呼び出し側は不変）。

### 論点6：タイムライン形式の焼き出し（`bakedFilePaths`）

**フォントは運ばない**（ADR-0032 決定20 が運ぶのは素材の本体・動画の代表フレーム・作成済みの読み上げ音声）。焼き出しは**同じPC内で別文書を作る**操作なので、グローバルにあるフォントはそのまま効く。⇒ **変更なし**。

### 論点7：ブランドキット（ADR-0036）との関係

ブランドの既定フォントに**持ち込みフォントを選べる**ようにする（ADR-0036 の「他 Issue との関係」で整合を取ると書いた件）。`brandkit.json` が持つのは `fontId` の値だけなので、**論点2 で `string` に開けば自動で通る**＝ADR-0036 側の変更は不要。

### 論点8：AI 入力に含めるか

**特別な規則は要らない。** AI は `ai-video-plan` を返すだけで見た目（フォント）を決めない（§2-1）。`ai-video-plan.schema.json` に `fontId` の enum は**無い**（確認済み＝0か所）。

## 決定（Accepted・2026-08-26 利用者承認）

1. **フォントは `appData/user_fonts/` にグローバルに置く**（`user_assets/`・`brandkit.json` と同じ流儀）。**プロジェクトには入れない**＝**アプリを再配布経路にしない**（`13 §6`）。
2. **`FontId` を `string` に開き、書式で縛る**。同梱は現行の3値のまま／持ち込みは **`user_font_NNN`**（`11 §2` の採番規約）。`project.schema` の **enum 8か所**を pattern へ。**`timeline-project.schema` は `$ref` 共有なので追従不要**。`schemaVersion` はマイナーバンプ（additive・無変換移行）。
3. **#793（将来の版の案内）を先に実施する**（論点3）。順序を逆にすると、更新前のアプリで「壊れています」と嘘の案内をすることになる。
4. **フォントが見つからないときは知らせる**＝描画は既定へフォールバックしてよいが、**書き出しは事前に断る**（`#346` へ検査項目を足す・`15 §6` に文言を新設）。**黙って別の字体の動画を出さない**。
5. **持ち込みフォントも `loadExportFonts` で読む**（カタログを「同梱＋持ち込み」にする＝呼び出し側は不変・パリティを保つ）。
6. **焼き出しはフォントを運ばない**（同じPC内の操作なので不要）。
7. **ブランドキットは変更不要**（`fontId` が `string` になれば持ち込みフォントを既定にできる）。
8. **AI に特別な規則は要らない。**
9. **対応する形式は4つとも**＝`.ttf` / `.otf` / `.woff` / `.woff2`（利用者決定 2026-08-26）。`FontFace` API はいずれも扱えるので、形式で絞る技術的な理由が無い。
10. **権利の注意文は画面に出さない**（利用者決定 2026-08-26）。⚠️ **決定1 でアプリが再配布経路にならないようにしている**（フォントはグローバルに置き、プロジェクトにも焼き出しにも入れない）ため、注意文を出しても**利用者自身の行為への一般的な注意**にしかならない。アプリが権利上の経路を作らないことのほうが本質で、そちらは決定1 で担保している。⚠️ ただし **`13 §6` の「同梱するフォントは OFL 系のみ」は不変**＝**アプリが配るもの**の判定基準は従来どおり厳しく保つ。

**利用者承認（2026-08-26）＝2点とも決着。**
- **形式は4つとも**（決定9）。
- **権利の注意文は出さない**（決定10）＝決定1 が経路を断っているため。

## 結果・影響

### コード

- 新設＝`src/infrastructure/userFontFs.ts`（`appData/user_fonts/` の取り込み・一覧・削除。`templateAssetFs.ts` と同型・パス検証は `is_safe_*` の流儀）。
- `domain/font/fontCatalog.ts`＝`FontId` を `string` へ。**同梱カタログ（静的）と持ち込みカタログ（動的）を合わせて解決する関数**を1か所に置く（§2-7）。
- 登録＝`FontFace` API で動的に `document.fonts.add`（画面と書き出しの両方が同じ登録を見る）。
- `renderer/export/loadExportFonts.ts`＝読む対象を「同梱＋持ち込み」に。
- 画面＝設定に「文字の書体」（取り込み・一覧・削除）。**技術用語を出さない**（§2-3）。
- **`FontId` を参照する 18 ファイル**（テスト除く）を確認しながら開く。

### 正典

- `project.schema.json`＝**enum 8か所を pattern へ**＋ `schemaVersion` マイナーバンプ（additive・移行不要）。`persistence.ts` の `PROJECT_SCHEMA_VERSION` と docstring も同時に（⚠️ **#513 が指摘している docstring のズレを増やさない**）。
- `timeline-project.schema.json`＝**変更不要**（`$ref` 共有）。ただし**追従することをテストで固定**する（must-accept に持ち込み `fontId` の例を足す）。
- `11 §2.1` の ID 採番表へ **`user_font_NNN`** を追記。
- `13 §6` に**持ち込みフォントは再配布しない**（プロジェクトにも焼き出しにも入れない）方針を追記。
- `15 §6` に**フォントが見つからないとき**の文言を新設（決定4）。
- `CLAUDE.md §11` に本 ADR を **Accepted** として1行追記（本 PR で実施）。

### 実施順への影響（**#857 を更新する**）

**#793 → #261 の順**（決定3）。#857 では #793 が段階1-1・#261 が段階5-2 なので**現状の順で矛盾しない**が、**依存であることを明記**する（#261 を前倒しするなら #793 も一緒に動かす）。

## 未解決の論点

> ✅ **利用者確認の2点は決着済み**（2026-08-26）＝**形式は4つとも**（決定9）／**権利の注意文は出さない**（決定10・決定1 が再配布経路を断っているため）。
- 太さ（Regular/Bold）の扱い＝同梱は 400/700 の2ファイルを別々に登録している。持ち込みで**1ファイルしか無いとき**に太字をどう出すか（合成太字に任せるか、無いと知らせるか）。
- 縦書き・可変フォント（variable font）は当面対象外でよいか。
