# ADR-0057: タイムライン形式の動画を、別の縦横比の版として複製する

- **状態**: Accepted（2026-10-08・利用者判断＝α に入れる・ADR から・#1386。写し方の規則は実装 AI が決めた＝実機で見て直す）
- **日付**: 2026-10-08
- **関連**: [`ADR-0012`](0012-aspect-ratio-and-portrait.md)（縦横は 16:9／9:16・場面形式の向き変更＝`orientationOps`）／[`ADR-0032`](0032-timeline-project-format.md)（タイムライン形式・決定16 焼き出しは別の新規）／[`ADR-0022`](0022-element-grouping.md)（まとまり）／複製の入口＝`duplicateProjectDoc`・`copyBakedFiles`／`11_TIMELINE_REFERENCE §7.6`／#1379 候補C

## コンテキスト

1本作った動画を、別の媒体（横の YouTube と縦のショート等）向けに作り直す手数を減らしたい（#1379 候補C・利用者判断 2026-10-08＝α）。

- **場面形式は既にできる**＝ホームの「複製」→ 下書き画面の向き変更（`orientationOps`＝各場面の見た目パターンを同じ種類・別の向きへ写す・合わない場面は知らせる）。
- **タイムライン形式にはどちらも無い**＝ホームの「複製」はタイムライン形式では押せない（`HomeScreen` が断る）し、向きを変える操作も無い。
  キャンバスは自由配置なので、**部品の位置・大きさを新しい画面へどう写すか**を決める必要がある。

## 判断軸

1. **元を壊さない**（焼き出し＝ADR-0032 決定16 と同じ＝別の新規を作る）。
2. **AI に頼らない・決まった規則で写す**（同じ入力は同じ結果＝#1379 の原則）。
3. **はみ出さない側へ倒す**（写した直後に画面の外へ出た部品があると、気づかないまま書き出す）。
4. **決めきれない所は具体的に知らせる**（§2-5・ADR-0026④＝黙って別の結果にしない）。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) 縦横の比で**引き伸ばす**（x・w は横の比、y・h は縦の比） | 不採用。絵・文字の縦横比が崩れる |
| (B) 元の画面を**収まるように縮めて**中央へ置く（倍率＝`min(新幅/旧幅, 新高/旧高)`） | **採用（その他の部品）**。はみ出さない。16:9⇄9:16 では 0.5625 倍に小さくなる＝あとで大きくする前提 |
| (C) 元の画面で**覆うように広げる**（`max`） | 不採用。端の部品が画面の外へ出る（判断軸3） |
| (D) 部品の種類ごとに規則を変える（画面いっぱい・字幕・見た目パターン） | **採用（Bと組み合わせ）**。背景や字幕は(B)だと用途を外れる |
| (E) 同梱の AI で写す | 不採用（判断軸2・#1379「AI による自動リフレームは必須にしない」） |

## 決定

**ホームの動画の行に「縦横を入れ替えた版を作る」を足す（タイムライン形式の動画だけ）**（⚠️ 一覧は向きを持たないので「縦の版／横の版」と言い分けず、入れ替える1つにした＝実装で確定）。押すと元を読み、**別の新しい動画**として素材・声ごと複製し（`copyBakedFiles`＝焼き出し・複製と同じ入口）、縦横を入れ替えて開く。⚠️ 同じ向きのままの複製（ホームの「複製」）もタイムライン形式で使えるようにする（同じ入口で向きを変えないだけ）。

写し方（新旧の画面 `W×H → W'×H'`・倍率 `s = min(W'/W, H'/H)`）：

1. **見た目パターンの部品**（`template`）＝**同じ種類（`category`）で新しい向きの見た目パターン**へ差し替える（場面形式の `orientationOps` と同じ選び方＝最初の一致）。中の差し込み口・文字は**同じ名前の層**へそのまま移る。⚠️ 新しい見た目に**無い層**へ入っていた素材・文字、合う見た目が無い部品は**そのまま残して数を知らせる**（勝手に消さない）。
2. **画面いっぱいの部品**（自由配置の部品で、箱が画面全体＝`x≈0, y≈0, w≈W, h≈H`）＝**新しい画面いっぱい**にする（背景の写真・動画・図形）。収め方（`fit`）・切り抜きは持ち越す。
3. **字幕の部品**（`subtitle`）＝**画面の中の相対位置と相対の幅**で写す（`x' = x/W·W'`・`w' = w/W·W'`・`y' = y/H·H'`）。**文字の大きさは変えない**（読みやすさを保つ＝折り返しが増えるのは許す）。
4. **その他の自由配置の部品**＝(B)＝旧画面を新画面の中央に縮めて置いたときの位置へ（中心 `cx' = (cx − W/2)·s + W'/2`、`w' = w·s`）。**中身も同じ倍率**（文字の大きさ・縁取り・角丸＝#1371 と同じ `scaleBakedContent` の流儀）。
5. **動き（キーフレーム）とまとまりの移動量**＝その部品に当てた規則と同じ倍率で掛ける（x/y のずれ）。大きさ（`scale`）・回転・濃さは比なのでそのまま。まとまりは**移動量に `s`** を掛ける（中の部品が(B)で写るため）。
6. **写した後に**、画面の外へ出た部品を数え、**開いた画面のお知らせ**で言う（⚠️ 実装で「画面の外」だけに絞った＝「端に寄った文字」は書き出し前の公開前チェックが引き続き見るので、ここで二重に言わない）。
7. 名前は「（元の名前）（縦）」／「（横）」。⚠️ 元の動画は一切書き換えない。

## 結果・影響

- **schema は変えない**（向きは `videoSettings.aspectRatio` が既にある・新しい項目なし）。
- コード：domain に純粋関数（`reorientTimelineDoc`・写し方の規則ごとに検査）、store にホームからの入口（複製と同じ予約・コピー・開く）、ホームの行に2つのボタン（タイムライン形式だけ）。
- 正典：`06`（ホーム）・`11_TIMELINE_REFERENCE §7.6.1.2`（向きを変えた複製の規則）。知らせの文（`reorientNotice`）は数の組み合わせで変わる**作ったあとの知らせ**なので `15 §6` の表には載せない（`subtitleImportedMessage` 等と同じ扱い・`errorStateTable` の除外に理由つき）。

## 未解決の論点

- **(B) の 0.5625 倍は小さい**＝縦の版では横の画面の内容が真ん中の帯に収まる。「主役の部品だけ大きく」等の工夫は、実機で見てから（ユーザー確認）。
- 見た目パターンの種類に新しい向きが無いとき（横型は一部の種類のみ）の扱いは「残して知らせる」で始める。
- 音だけの部品・読み上げは位置を持たないので何もしない（時間はそのまま）。
