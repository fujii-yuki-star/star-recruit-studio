# ADR-0049: 窓の外から落としたファイルを、並びへそのまま置く

- **状態**: Accepted
- **日付**: 2026-09-29
- **Issue**: #1260
- **関連**: [`ADR-0034`](0034-timeline-interaction-model.md)（決定2＝置き方は押す・運ぶの両方／決定10＝指した場所から動かさない／決定15＝まとめては全か無か）／[`ADR-0048`](0048-ux-first-editor-density.md)（UI/UX 優先）／[`ADR-0024`](0024-non-destructive-editing-model.md)（素材は取り込み時にコピー）／[`ADR-0020`](0020-undo-redo-model.md)（素材は取り消しに載らない）／調査 [`2026-09-os-drop-and-popout-research.md`](../archive/research/2026-09-os-drop-and-popout-research.md)

## コンテキスト

撮影前の再精査（2026-09-29）で、主要な動画編集ソフトと「ファイルの落とし方」を比べた。

- **窓の外（エクスプローラー）から落としたファイルを受けていたのは「取り込む」の枠だけ**（`useAssetPicker`）。
  並び（タイムライン）や窓のほかの場所へ落としても**何も起きなかった**。
- 他社は **並びへ落とすと「取り込み＋落とした場所へ置く」が1回で済む**のが普通
  （Premiere Pro・Final Cut Pro・VEGAS Pro・Shotcut・PowerDirector・YMM4・AviUtl）。
  置き先は**落とした列・落とした時刻**（再生位置ではない）。VEGAS は列の無い所へ落とすと列を作る。
- **仕上がり確認（プレビュー）へ窓の外から落とす**のは、どの製品でも公式の落とし先ではなかった
  （AviUtl は画面へ落とすと別扱いになり混乱の元）。
- 窓の外からの落としは Tauri が窓ごと受け、**絶対パスと座標**が来る（要素の `drop` には来ない）。
  座標で落とし先を当てる今のやり方が、Tauri の推奨どおり（`dragDropEnabled` は true のまま）。

利用者判断（2026-09-29）：「ドロップに関してはあなたの方で設計を組んで実装まで進めてよい（ADR と Issue は起票）」。

## 決定

1. **並びの列へ落とす**＝取り込んでから、**落とした列・落とした時刻**へ置く。
   - 置く規則は**アプリの中から素材を運んで落としたときと同じ関数**（`addVisualClip`／`addAudioClip`）。規則を増やさない。
   - **複数のファイル**は**ファイル名の順**（数字は数として）に取り込み、同じ列に**前から隙間なく**並べる。
   - **種類の合わないファイル**（映像の列へ落とした音など）は、その種類の**新しい列**へ、同じ時刻から置く。
     ⚠️ 既存の別の列へは入れない（決定10）。新しい列なら指した時刻は守られる。
2. **列の無い所（いちばん下の列より下・並びの箱の中）へ落とす**＝その種類の**新しい列を作って**置く（種類ごとに1本）。
3. **それ以外の場所（仕上がり確認を含む）へ落とす**＝**取り込むだけ**。
4. **全か無か**（決定15）＝1件でも置けなければ**何も置かず、理由を出す**。取り込みは済んでいる（素材は一覧に残る）。
5. **1回の取り消しで全部戻る**（置いた部品と足した列を同じ確定で入れる）。取り込んだ素材は取り消しの対象外（ADR-0020）。
6. **運んでいる間に行き先を見せる**＝列の上なら時刻の線、列の無い所なら「新しい列」の行、並びの外なら
   「離すと素材に取り込みます。並びの列の上で離すと、その場所に置けます」。
7. **「取り込む」の枠は自分で受ける**（`data-file-drop-zone`）＝画面の受け口はその上では手を出さない（二重に取り込まない）。
8. 時刻は**コマの格子へ落とすだけ**（再生位置用の `frameTimeSec` は尺で頭打ちにするので使わない）。

## 採らなかったもの

- **仕上がり確認へ落として画面の位置を決める**＝他社に前例が無く、窓の外からの落としでは列も時刻も決まらない。
- **押しのけ（挿入）**＝ADR-0034 決定11 のまま（重なる所へは置かずに断る）。
- **落とした瞬間に選ばせるメニュー**（PowerDirector の「上書き／挿入／…」）＝事務職の利用者には選択肢が重い。断る＋理由の方が読める。
- **エクスプローラーへ運んで書き出す**＝どの製品にも前例が無かった。

## 結果・影響

- `schemas` / `11` は変えない（置く規則は既存の関数のまま）。`schemaVersion` 据え置き。
- `06_UI_SPEC.md §12.1` に落とし方を書く。

## 未解決の論点

- ~~**ドラッグ中に「置けない」ことを出す**~~ → **#1272 で入れた**（2026-09-29）。入った瞬間（`enter`）のパスから
  **種類だけ**を出し、**必ず断られる時だけ**（部品の上〔いちばん短い部品でも重なる〕・固定／出さない列）置けない色と理由を出す
  （`fileDropHoverIssue`＝列の事情は置く関数と同じ `trackPlacementIssue`）。⚠️ **長さはまだ分からない**ので、
  離した後に「重なる」で断られることは残る（逆向き＝「断る色なのに置ける」は作らない。検査で両者の理由の一致を固定）。
  ⚠️ **`enter` を受けるようにしたので、購読側は `enter` で取り込みを始めない**（`useAssetPicker` も同じ）。
- **管理者として起動していると、窓の外からの落としは Windows に止められる**（Tauri の既知の制約）。
