# ADR-0066: 場面の切り替えの「ワイプ」「ズーム」を実際に描く

- **状態**: Accepted
- **日付**: 2026-10-20
- **関連**: [`ADR-0009`](0009-scene-transitions.md)（場面の切り替え・未解決2）／[`ADR-0032`](0032-timeline-project-format.md) 決定19（切り替えはキーフレームで焼く）／[`ADR-0001`](0001-rendering-parity.md)（プレビュー＝書き出し）／[`ADR-0026`](0026-alpha4-behavior-consistency.md)④／[`ADR-0043`](0043-alpha-beta-scope-and-general-backlog.md) ⑤（α-8）／#1474／`src/domain/project/sceneTransitions.ts`

## コンテキスト

場面の切り替え（`transition.in`）の値には `wipe` と `zoom` があり（`project.schema.json` の `Transition`・`template.schema.json` の `transitionIn`）、
見た目パターンの既定や手で書いた文書から入りうる。ところが**描かれるのはフェード**だった（`sceneTransitions.ts` の `DRAWN_TYPES` が
`none`/`fade`/`slide` だけで、ほかは `fade` へ丸めていた）＝**設定した意味どおりに出ない**（ADR-0026①④）。
画面の選び方（`TransitionTiles`）にも出していなかった。ADR-0043 ⑤で α-8（ソフトの完成）に入れた。

## 判断軸

- 業界の型（ADR-0034）＝ワイプは「境目がまっすぐ動いて次の場面が見えてくる」、ズームは「寄りながら次へ移る」。
- **プレビュー＝書き出し**（ADR-0001）＝書き出しが使う絵の式を、プレビューも同じ式で描く（近似で書き写さない）。
- 焼き出し（タイムライン形式へ）で**黙って別の絵にしない**（ADR-0026④・§2-5）。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) **書き出しは FFmpeg の `xfade` の既成（`wipeleft` 等・`zoomin`）、プレビューは同じ式を CSS で描く** | 書き出しの道は今の `fade`/`slide` と同じ（名前を許可するだけ）。式は実測で確かめられる。**採用** |
| (B) 自前の式（`xfade` の `custom`）で書き出す | 見え方を自由に決められるが、フィルタの式の書き方・速度・逃がし方の検証が別に要る。既成で足りるので不採用 |
| (C) いまのまま（フェードに丸める） | 設定した意味どおりに出ない。不採用 |

## 決定

1. **ワイプ**＝`wipe`＋向き（`direction`＝スライドと同じ欄・未指定は左）。書き出しは `xfade` の `wipeleft`／`wiperight`／`wipeup`／`wipedown`。
   **実測（2026-10-20・同梱の FFmpeg）**：境目は**一定の速さ**で動く（切り替えの進み q＝0→1）。
   - 左＝次の場面が**右から**見えてくる（`x > W·(1−q)` が次の場面）／右＝左から（`x < W·q`）
   - 上＝**下から**（`y > H·(1−q)`）／下＝上から（`y < H·q`）
   ＝「左へ」はスライドと同じく**画面が左へ流れる向き**（次の場面が右から入る）。
2. **ズーム**＝`zoom`（向きなし）。書き出しは `xfade` の `zoomin`。**実測で式と画素が一致**（誤差 0）：
   進み q に対し P＝1−q、`zf = smoothstep(0.5, 1, P)`・`a = smoothstep(0, 0.5, P)`。
   前の場面を**中心から 1/zf 倍に拡大**し（前半で寄り切る）、`a·拡大した前 + (1−a)·次` で混ぜる（後半で次へ溶ける）。
   `smoothstep(e0,e1,x) = t²(3−2t)`（t は 0〜1 に収めた `(x−e0)/(e1−e0)`）。
3. **プレビュー**（`transitionLayerStyles`）は上の式をそのまま描く＝ワイプは次の場面の `clip-path: inset(…)`、
   ズームは前の場面を上に重ねて `scale(1/zf)`（中心まわり）と不透明度 `a`。寄り切った後（zf＝0）は大きな倍率で代える
   （書き出しは中心の1画素の色＝実質同じ）。
4. **画面で選べるようにする**＝「画面の切り替え」の絵のタイルに**ワイプ（左へ／右へ／上へ／下へ）**と**ズーム**を足す。
5. **タイムライン形式へ焼き出すときはフェードとして焼き、知らせる**（`BAKE_TRANSITION_AS_FADE`）。
   理由＝焼き出しの付け先は多くが**まとまり（グループ）**で、まとまりには切り抜きもキーフレームの切り抜きも無く、
   ズームの中心もまとまりの箱の中心になる＝**同じ絵をキーフレームで表せない**。黙ってフェードにすると「設定と違う絵」を
   成功として出すので、焼く前・焼いた後の案内（既存の「持っていけなかったもの」）に載せる。
   `DrawnTransitionType` の網羅 switch（決定19 の仕掛け）は、ワイプ・ズームを**明示的にフェードへ**落とす枝として残す。

## 結果・影響

- コード：`sceneTransitions.ts`（`DRAWN_TYPES`・選び方の値 `wipe:<向き>`／`zoom`）／`buildExportScenes.ts`（`xfade` の名前）／
  Rust `ffmpeg.rs`（許可する名前に5つを足す）／`transitionLayerStyles.ts`／`TransitionTiles.tsx`／`SceneEditScreen.tsx`／`bake.ts`。
- 正典：`11 §3.4`（`transition` の表の「将来」を外す）／`05 §15`／`06`（切り替えのタイル）／`15 §6`（`BAKE_TRANSITION_AS_FADE` を1行）。
- schema は変えない（値はもともとある）。
- 既存の動画で `wipe`／`zoom` を持っていた場面は、**次に書き出すと絵が変わる**（フェード→ワイプ／ズーム）。これは
  「設定した意味どおりに出る」ようになる変化なので移行はしない（ADR-0026①）。

## 未解決の論点

- **タイムライン形式でワイプを作る道**（キーフレームの切り抜き＝業界の型では「切り抜きにキーフレームを打つ」）は無い。
  入れるなら共有の `$defs/Keyframe` に切り抜きを足し、まとまりにも効かせる設計が要る＝使われ方を見てから（今回の焼き出しは知らせで閉じる）。
