# ADR-0063: 文字の幅は同梱の字体の実測で見積もる（折返し・はみ出しの判定）

- **状態**: Accepted
- **日付**: 2026-10-19
- **関連**: [`ADR-0001`](0001-rendering-parity.md)（プレビュー＝書き出し・「残」2＝折返しをフォント実測へ）／[`ADR-0031`](0031-simultaneous-dual-voice.md)（同時字幕の帯の段）／[`ADR-0062`](0062-export-embed-font-subset.md)（書き出しの字体の埋め込み）／`05 §10`／`src/domain/text/textWrap.ts`

## コンテキスト

折返し・行数・「…」の切り詰め・はみ出しの判定は、`wrapText` が**文字幅の見積もり**（英数字＝0.55em・それ以外＝1.0em）で決めている。
描画（`sceneSvg`）・帯の段（`stackedSubtitleBands`）・公開前チェック（`truncatedTexts`・`subtitleOverflowsCanvas`）・焼き出し（`bake.ts`）が
同じ関数を通るので、**プレビューと書き出しは一致する**（ADR-0001）。ただし**実際の字体の幅とは合っていない**。

2026-10-19 の α 残件の洗い直しで、同梱の字体の字幅（`hmtx`／`unitsPerEm`）を実測した：

| 字体 | 英小文字 | 英大文字 | 数字 | 「あ」 | 漢字 |
|---|---|---|---|---|---|
| Gen Interface JP（標準） | 0.536 | 0.681 | 0.593 | 0.936 | 0.953 |
| Gen Interface JP（太字） | 0.563 | 0.701 | 0.621 | 0.936 | 0.953 |
| Gen Interface JP Display | 0.490 | 0.652 | 0.560 | 0.898 | 0.925 |
| 怪盗予告ゴシック | 0.789 | 0.900 | 0.770 | 1.036 | 平均 1.070（「社」1.305・「採」1.340） |

⇒ **英字の多い文字（社名など）や怪盗予告ゴシックは、枠からはみ出しても折り返さず、はみ出しの注意も出ない**（黙って見た目が化ける）。
逆に Gen Interface の日本語は見積もりより狭く、入るはずの字を早く折り返している。

## 判断軸

- **ADR-0001 を崩さない**＝描画と行数の計算（帯の段・はみ出し・切り詰め・焼き出し）が**必ず同じ字体の同じ字幅**で計算する。
- domain は純粋なまま（読み込みの時機で答えが変わらない＝焼き出しは保存されるので、そのときの状態で結果が変わってはいけない）。
- 持ち込み・拡張パックの字体で、**今より狭く見ることはしない**（今出ている注意を黙って消さない）。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (A) **同梱の字体の字幅表をビルド時に作り、どの字体かをアイテムに持たせて引く** | 純粋・決定的。描画と行数計算が同じフィールドから字体を引ける。表は数十KB。**採る** |
| (B) 実行時に Canvas の `measureText` で測る | domain が純粋でなくなる。字体の読み込み前後で答えが変わり、焼き出しの結果が時機で変わる。不採用 |
| (C) 英字の見積もりだけ上げる（例 0.55→0.7） | 怪盗予告ゴシックの日本語（20〜30% 広い）が直らない・Gen Interface の英小文字は逆に広すぎる。不採用 |
| (D) 呼び出し元がそれぞれ字体を解く | 解き方が場所ごとにずれる芽（帯の段と描画が食い違う＝ADR-0031 の重なり）。不採用 |

## 決定

1. **同梱の字体（`BUNDLED_FONT_FILES` の全ファイル）の字幅表**を `scripts/gen-font-metrics.ts` が `public/fonts/*.ttf` から作り、
   `src/domain/text/generated/bundledFontMetrics.ts` に置く（git に入れる＝差分をレビューで読める）。
   表は英数字・約物・かな・全角の区間は字ごと、CJK 統合漢字は「既定の幅＋違う字だけの一覧」、それ以外は今の見積もり（1.0em）。
   **字体に無い字**（代わりの字体で描かれる）も今の見積もり。
2. **どの字体かは、描画と同じ解き方で一度だけ決めてアイテムに持たせる**（`TextItem.textFont`）。
   描画（字体の名前）と折返し（字幅）が**同じフィールド**から出る＝食い違えない。帯の段・はみ出し・切り詰め・焼き出しも同じものを使う。
3. **持ち込み・拡張パックの字体**（字幅が同期で分からない）は**汎用の表**＝字ごとに「今の見積もり」と「Gen Interface JP 太字の実測」の大きい方
   ＝**今より狭く見ることはない**（広い欧文の見出し字体などはまだはみ出しうる＝残る近似）。
4. **詰め（カーニング）・合字・代わりの字体の字幅は近似のまま**（実際の幅は表の合計以下になる側＝はみ出しを見逃す向きではない）。
   ⚠️ 例外として**狭く見積もりうる**もの：表の外の漢字（CJK 拡張A・互換漢字・拡張B以降＝1.0em）を怪盗予告ゴシック（漢字の平均 1.07em）で描くとき。
   送り幅が本当に 0 の字（ゼロ幅の空白・結合用の濁点など）は「字体に無い」と同じ扱い＝1.0em（広く見る側・以前と同じ）。

## 結果・影響

- **既存の動画の折返しが変わる**（データは書き換えない＝移行は無い）。
  - Gen Interface の日本語：1行に入る字が少し増える（2行だった字幕が1行になることがある）。
  - 英大文字・数字の多い文字：今より早く折り返す。
  - 怪盗予告ゴシック：日本語・英字とも早く折り返す＝新たに「…」で切れたり、はみ出しの注意が出たりする（**これまで黙ってはみ出していた**もの）。
  - ⚠️ 焼き出し済みのタイムラインの動画は、字幕の箱の高さを古い行数で持っている＝行数が増えると「…」で切れることがある（画面の「切れている文字」の注意で気づける・#1464）。
- ADR-0001 の「残」2 をこの ADR で解く（同梱は実測・持ち込みは汎用の表・詰めと合字は近似）。`05 §10` に字幅の出どころを書き足す。
- 外向きの変更（呼ぶ側）：
  - `wrapText`・`stackedSubtitleBands`・`sceneDrawnLayouts`・`subtitleOverflowsCanvas`・`bakeLineSubtitles` は字体の引数を省略できない（渡し忘れを型で止める）。
  - `layoutScene` は `projectFontId` を受ける（省略できる＝検査用）。本番の呼び出しが渡していることは門番 `src/test/textFontThreadingGuard.test.ts` が見る。
  - 書き出しの `fontFamilyFor` は `projectFontId` に置き換えた。`layoutToSvg` の `fontFamily` は素材が無い枠の仮の文字だけに効く（文字アイテムは `TextItem.textFont`）。
  - 権利表示のピルは既定の字体に固定なので、字体を問わない見積もり（`charWidthEm`）のまま（決定4 の近似に含める）。
- 字体ファイルを差し替えたら `npm run gen:font-metrics` で作り直す（忘れると `fontMetrics.test.ts` の「字体ファイルとずれていない」が赤くなる）。作られた表は約66KB。
- 段階：①経路をつなぐ（全部の字体に今の見積もりの表＝絵が1バイトも変わらないことでつなぎ漏れを確かめる）→ ②実測の表へ差し替える（見た目の変化はここだけ）。

## 未解決の論点

- 持ち込み・拡張パックの字体を取り込むときに測って要約を保存し、同期で引けるようにするか（別の ADR）。
- 実機で `measureText` の合計と表の合計を代表の文で比べる（詰め・合字のぶん、実際は表以下になるはず）。
