# ADR-0016: 詳細編集の完全化（ロードマップ／アンブレラ）

- **状態**: Proposed（Draft・2026-06-26・α-3）— 段階方式は合意済み。各機能の EPIC ADR は本 ADR から分割して起票する。
- **日付**: 2026-06-26
- **関連**: [`adr/0007`](0007-detailed-edit-mode.md)（詳細編集2モード・FREE）/ [`adr/0008`](0008-free-layout-editor.md)（FREE 自由配置）/ [`adr/0001`](0001-rendering-parity.md)（描画パリティ・**場面内レイアウトは静止・単一フレーム**）/ [`adr/0004`](0004-rasterization-method.md)（SVG→PNG）/ [`adr/0009`](0009-scene-transitions.md)（トランジション）/ [`adr/0015`](0015-dialogue-timeline-model.md)（掛け合い・§10 を簡易タイミングへ部分解除した先例）/ `CLAUDE.md §10`（MVP外）・`§2-4`（テンプレ駆動）
- **対象**: α-3 〜（詳細編集の段階的完全化）。会社特化機能は本プログラムと分離し **β（新規画面）** で扱う。

---

## コンテキスト

ADR-0007 で「簡易/詳細の2モード（同一 project.json）＋自由配置は FREE テンプレに閉じ込め」を決定し、α-2 で FREE 編集の大半（複製/前面背面/図形/パーツ/要素ごとフォント/右クリック編集/詳細編集モード＝#172–#185）と掛け合いの簡易タイミング（#180）を実装した。

利用者要望により **「完全なる詳細編集」が α のメインに昇格**。ヒアリングで本社特化の要件が多数出たため、**α 系で“現状考案済みの汎用機能”を出し切り、β は会社専用の新規画面に注力**する方針（ユーザー合意）。「完全なる詳細編集」に含める範囲を確認した結果、以下 **4本すべて**が対象：

1. **① 枠内の磨き込み**（ADR-0007 の不変条件を維持したまま操作性・穴埋め）
2. **② テンプレ作成・編集エディタ**（利用者が見た目パターンを作る＝§10「本格テンプレ作成エディタ」の緩和）
3. **③ 場面横断タイムライン／複数トラック**（§10「完全自由タイムライン」の緩和）
4. **④ キーフレーム／場面内アニメ**（§10「キーフレーム」の緩和。**ADR-0001「場面内静止・単一フレーム描画」を置換**）

これは `§10` の編集系除外を**全面緩和**し、`ADR-0001` を④で **supersede** する大規模プログラムで、1 ADR・1フェーズには収まらない。本 ADR を**アンブレラ**として最終像・順序・supersede 方針を確定し、各機能を **EPIC ADR に分割**する（掛け合い＝ADR-0015＋PR-B〜G と同要領）。

## 検討した選択肢（進め方）

- **(A) α-3 で①〜④を全部実装** → フェーズが長大化し、④（描画作り直し）が最大リスク、各版が出荷不能に。**不採用**。
- **(B) 段階方式**【**採用**】: 重い③④は十分設計してから着手し、各版を出荷可能に保つ。

## 決定

> **詳細編集の完全化（①〜④）を最終像とし、段階的に進める。**
> - **α-3 ＝ ①②の実装 ＋ ③④の設計 ADR**（実装はしない）。
> - **α-4 以降 ＝ ③④の実装**。
> - `§10` の編集系除外を段階的に全面緩和し、**④の実装時に `ADR-0001` を後継 ADR（0019）で置換**（場面＝静止フレーム → per-frame レンダリング）。
> - **会社特化機能は本プログラムと独立**（β・新規画面）。

### ②までで崩さない不変条件
- **描画は1経路**（ADR-0004：SVG→PNG→FFmpeg）。①②は**静止フレームのまま**。④で per-frame へ拡張（ADR-0019 で確定）。
- **単一パイプライン**（ADR-0007 M-A）：AI→簡易→詳細→書き出しが同一 project.json／同一描画に乗る。テンプレ作成（②）も同パイプラインに乗せる（別データ・別描画を作らない）。

## 結果・影響

- **§10 改訂（段階的）**：編集系除外（本格タイムライン・キーフレーム・テンプレ作成エディタ）を**段階で解除**（②で作成・③④で設計→実装）。各段で `CLAUDE.md §10` を更新（ADR-0012/0015 と同型の注記）。**どの PR で注記を入れるかは未解決5で確定**。
- **§2-4 改訂（②実装時）**：テンプレ作成エディタ（②／ADR-0017 承認後）で `CLAUDE.md §2-4` を「**通常テンプレは座標固定（毎回座標を触らせない原則は通常編集で維持）／テンプレの作成・編集は専用エディタで行う**」に更新する。
- **ADR supersede**：④実装時に **ADR-0001 を ADR-0019 が置換**（描画 per-frame）。ADR-0007 は①②で拡張。
- **正典同期**：② でユーザーテンプレ保存（`template.schema`/`11`）、③④で project／描画モデル拡張（各 EPIC ADR で確定）。
- **β との分離**：会社特化（新規画面）は本プログラムと独立に進める（汎用コアを汚さない）。

## 未解決の論点 / 確認ポイント

1. **①の範囲・Undo/Redo**：上記ギャップで過不足ないか・優先順。特に **Undo/Redo は履歴スタック/Command の設計（domain 純粋性・app 状態管理への影響）を着手前に評価**し、非自明なら独立 ADR を立てる（他の①項目は ADR-0007 拡張で足りる）。
2. **②の深さ・採番**：既存テンプレの**複製＋微調整**まで？ **ゼロから作成**まで？ 開放するレイヤー種別はどこまで？ さらに **ユーザーテンプレの ID 形式・保存先（11 §2.1 を `user_tmpl_NNN` 等で拡張）** を ADR-0017 で確定（正典に無い採番を勝手に作らない＝§9-2）。
3. **③の統合**：タイムラインと既存（場面・掛け合い・トランジション・BGM）の統合方針（ADR-0018 で確定）。
4. **④の描画**：per-frame レンダリング（尺×fps）のコスト・パリティ再定義＝ADR-0001 置換の前提（ADR-0019 で確定）。
5. **EPIC ADR の起票順・正典注記の担当PR**：α-3 は **①サブPR → ②（ADR-0017）**、並行で **③（0018）・④（0019）の設計 ADR**。あわせて **§10/§2-4 の注記をどの PR で入れるかを確定**（例：① 最初のサブPR で §10 に本 ADR 注記／② ADR-0017 承認 PR で §2-4 ＋ §10〔テンプレ作成解除〕／③④ 各設計 ADR 承認 PR で §10〔タイムライン/キーフレーム解除〕）。「各段で更新」を担当PRに落として実行漏れを防ぐ。

> α-3 着手は **①のサブPR ＋ ②（ADR-0017 起票）** から。③④は本 α-3 では**設計 ADR のみ**。
