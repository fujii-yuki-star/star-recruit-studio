# ADR-0054: 動きを付けた部品をキャンバスで掴む＝本体は動き全体を平行移動、点はその時刻だけ（段階的）

- **状態**: Accepted（2026-10-05・利用者判断＝「推奨される段階的な組み合わせで」）
- **日付**: 2026-10-05
- **関連**: [`ADR-0019`](0019-keyframe-animation-model.md)（動きは「本来の状態からのずれ」＝相対値）／[`ADR-0034`](0034-timeline-interaction-model.md)（操作は業界の型・決定19＝見えない操作だけにしない）／[`ADR-0001`](0001-rendering-parity.md)（描画核は共有）／[`ADR-0026`](0026-alpha4-behavior-consistency.md)（②同じ概念を入口で割らない）／#746-4（`canvasHoldReason`）／UI/UX 監査 2026-10-02（🔴「動きを付けた部品はキャンバスで掴めない」）／調査 [`2026-10-drag-animated-part-research.md`](../archive/research/2026-10-drag-animated-part-research.md)

## コンテキスト

タイムライン形式の編集画面では、キーフレームで**動きを付けた部品はキャンバスで掴めない**（「仕上がり確認の上では動かせません…『動き』で調整してください」＝`TimelineProjectScreen.tsx` の `canvasHoldReason`・#746-4）。理由は、枠は**動きを足した後の描かれている場所**に出るのに、掴んだ結果は**素の箱**へ書き戻るので、動きのぶんだけ絵が飛ぶため。さらに、動きのずれが 0 の時刻では掴めてしまう（時刻によって掴める・掴めないが変わる割れ）。一方で、**矢印キーと「位置」の数値欄は動きの付いた部品でも素の箱を動かす**＝動き全体を平行移動しており、キャンバスのドラッグだけが道を持っていない。

利用者の希望（2026-10-05）：「掴んで動かせるようにしたい。ただし動きが崩壊するのは避けたい＝動き方をキープしつつ、例えば横移動して特定の位置で止まる動きなら、その止まる位置がずれる」。「有料ソフトの実挙動を調べたうえで検討したい」。

調査（上記 research）の要点：
- **有料ソフトの既定はほぼ全社「再生位置にキーを打つ／更新する」**（After Effects・Premiere・Resolve・Final Cut Pro・Filmora・PowerDirector・CapCut）。キーの間で掴むと、警告なく点が1つ増える＝**止まる位置は変わらない**。
- **「形を保って全体をずらす」は別の操作**として用意される（FCP・Motion は修飾キー、AE は全キー選択やヌル親、Premiere は「トランスフォーム」エフェクトの重ね）。
- **動きの道筋（軌跡と点）をキャンバスに描く**のは AE・FCP・Filmora・Canva・Fusion に共通。

## 判断軸

- **動きを崩さない**（利用者の希望）＝掴んだだけで点が増えて形が変わる、を既定にしない。
- **同じ概念を入口で割らない**（ADR-0026②）＝矢印キー・数値欄・キャンバスのドラッグが同じ結果になる。
- **見えない操作だけにしない**（ADR-0034 決定19）＝修飾キーでしか届かない機能を作らない。
- **描画核に触れない**（ADR-0001）＝データ・描画・書き出しを変えずに済む形を先に取る。

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| (1) ドラッグ＝**動き全体を平行移動**（素の箱へ差分を足す） | 希望そのもの（始まりも止まる位置も同じだけずれる）。矢印キー・数値欄と同じ＝割れが消える。データ・描画は無改造。⚠️ 業界の既定（再生位置にキー）と逆 |
| (2) ドラッグ＝**再生位置にキーを打つ**（業界の既定） | 型に素直。⚠️ キーの間で掴むと点が増えて形が変わる＝希望に合わない（止まる位置を変えるには、止まる点の時刻へ再生位置を合わせてから掴む手間） |
| (3) 既定は全体、**修飾キーで再生位置のキー**（逆も可） | 両方できる。⚠️ 修飾キーは見えない操作＝同じ機能をメニューにも置く必要（決定19）・説明と検査が2倍 |
| (4) キャンバスに**動きの道筋と点**を描き、**本体＝全体・点＝その時刻だけ** | 見えている物を掴むだけで両方に届く（修飾キー不要）。業界の「道筋」の見せ方と同じ。⚠️ 実装がいちばん重い（軌跡の描画・点の当たり判定・グループの動き・拡大回転） |

利用者に、図（右へ動いて2秒で止まる部品を、(1) と (2) で1秒・2秒の時刻に掴んだときの道筋）で説明して聞いた（2026-10-05）。回答＝「**推奨される段階的な組み合わせで**」＝段階1で (1)、段階2で (4)。

## 決定

1. **段階1：本体を掴む＝動き全体を平行移動**。掴んだ量（差分）を**素の箱**へ足す（`box + Δ`）。枠は描かれている場所（動きを足した後）に出したまま、確定は差分で行う＝**指と絵がずれない**。矢印キー・「位置」の数値欄と同じ規則（ADR-0026②）。`canvasHoldReason` の「動きがあるので掴めない」はやめる（時刻によって掴める・掴めないが変わる割れも消える）。
   - **大きさを変える取っ手・回す取っ手**も素の箱（`w`/`h`・角度）を変える＝倍率・回転の動きはそのまま掛かる。段階1で取っ手の扱いが割れるなら、取っ手だけ引き続き断ってよい（理由を出す）＝実装で決め、本 ADR の追補に残す。
   - **グループに動きが付いている**部品も同じ（グループの動きは中身に掛かる相対値）。
2. **段階2：動きの道筋と点を描き、点を掴むとその時刻の値だけ直す**。選んだ部品の位置の軌跡を線で、キーごとに点を描く（**編集用の重ね描き**＝仕上がり確認の上だけ・書き出しには出ない・描画核には入れない）。**本体を掴む＝全体（段階1のまま）**、**点を掴む＝そのキーの位置だけ**（時刻は変えない）。止まる位置だけ直したいときは終点の点を掴む。
3. **業界の既定（再生位置にキーを打つ）と違う理由**＝すたりおの動きは**最初から「本来の状態からのずれ」**（ADR-0019）なので、本体を動かせば動き全体が平行移動するのがデータの形に素直で、矢印キー・数値欄とも揃う。キーの間で掴んだだけで点が増えるのは、利用者の言う「崩壊」にあたる。業界の「その時刻だけ直す」は、段階2で**点を掴む**という見える操作で届ける（修飾キーにしない＝決定19）。
4. **知らせ**：段階1の時点で、動きの付いた部品を掴むと「動き全体がずれます（止まる位置だけ直すときは『動き』の欄で）」と一言出す（業界の既定に慣れた人の取り違えを減らす）。段階2で点を描いたら、この一言は「点を掴むとその時刻だけ直せます」に変える。

## 結果・影響

- `src/app/screens/TimelineProjectScreen.tsx`（`canvasHoldReason`・キャンバスの掴みの確定）・`FreeLayoutOverlay` 系（段階2の道筋と点）。データ（`timeline-project.schema.json`）・描画核・書き出しは**変えない**（段階1・2とも）。
- 正典：`06 §12.1`（キャンバスで掴む）・`15 §6`（掴めない理由の行が要らなくなるなら表から外す／新しい知らせを足す）・`uiLabels`（`canvasHoldMessage` 系）を実装の PR で同時に直す。
- ADR-0034 との関係：業界の型に合わせるのが原則（判断軸1）だが、本件は**データの形（相対値）と利用者の希望**から既定を変える例外＝本 ADR が理由を持つ。ADR-0034 の本文は変えない（追補で本 ADR を指す）。

## 未解決の論点

- 段階1で大きさ・回転の取っ手をどう扱うか（素の箱を変える／断る）＝実装で決めて追補。
- 段階2の道筋の描き方（位置だけか・拡大回転の付いた動きの見せ方・グループの動き）と、点の当たり判定の大きさ（ADR-0047 の寸法の正）。
- 段階2で「点の間を掴む（区間だけ動かす）」（Motion の型）を入れるか＝入れない前提で、要るかは実機で見てから。

## 追補（2026-10-05）：段階1の実装

- **掴んだ結果は自身の動きを逆にたどって素の箱へ書く**（`baseBoxPatchFromShown`・`src/renderer/timelineLayout.ts`）＝中心まわりの拡縮 → 平行移動 → 回転の足し算（`applyInterpolatedTransform`）の逆。**移動・大きさ・回転のどれも**同じ関数を通す（未解決の論点1「取っ手の扱い」はこれで決着＝断らない）。往復（戻した箱に動きを当て直すと置いた所に戻る）で検査した。
- **グループの変形が効いている部品は引き続き掴ませない**（`canvasHoldReason` の "group"）＝拡縮・回転の下では素の箱の 1px が画面の 1px にならない。
- 「動きが効いている部品は掴めない」の断り（`TIMELINE_CANVAS_HOLD_ANIMATION(_MANY)`）は**退役**。代わりに「位置・大きさ」の欄へ一言（`ANIMATED_DRAG_NOTE`＝決定4）。

## 追補（2026-10-05）：段階2の実装

- **道筋は部品の中心**で描く（`motionPathOf`・`src/domain/timeline/motionPath.ts`）＝動きの拡縮・回転は中心まわりなので、中心は素の箱の中心に位置のずれを足した所。補間は描画と同じ `interpolateKeyframes`＝線は実際の軌跡と一致する。等分 60＋キーの時刻を必ず通す。
- **点は位置（x か y）を持つキーだけ・帯の長さの中だけ**（外のキーは描かれない時刻＝掴むと `setKeyframe` が範囲へ寄せて別の時刻に点が増える）。拡縮・濃さだけの動きは描かない（一言は段階1のまま）。
- **点を引く＝そのキーの x/y だけ**（`keyPositionAfterDrag`）。掴んだ時点のキーフレームと合計の動きから毎回計算し直す（足し込まない）。⚠️ **持っていない軸は 1px 以上動かしたときだけ書き足す**（その時刻に描かれている値から）＝横へ引いただけで縦を書くと、縦の区切りが増えて**緩急の付き方が変わる**。戻したら外す（`null`）。
- **描くのは本体を掴めるときだけ**（グループの変形の下では出さない＝段階1と同じ線引き）。編集用の描き足し（`MotionPathOverlay`）＝描画核・書き出し・データは変えない。
- **ドラッグの作法は共有のもの**（`usePointerDrag` の冒頭）＝左ボタンだけ・掴んだ指だけ・`Escape`／`pointercancel` で元へ戻す・`registerExternalDrag` で数に入れる・消えたら締める。点は**焦点を取らない**（矢印キーは選んだ部品を動かすまま）。
- 未解決の論点2の残り：点の当たり判定は 12px（`timeline.css` の `.motion-path-key`）＝寸法の正への寄せは ADR-0047 の続きで見る。拡大・回転の動きの見せ方・グループの動きの道筋・「点の間を掴む」は入れていない（実機で要るか見てから）。
