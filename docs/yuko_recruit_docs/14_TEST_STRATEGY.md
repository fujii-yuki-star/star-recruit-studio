# 14. 自動テスト戦略

> 本書は**自動テスト**の戦略。人が目視で確認する受け入れ観点は `08_TEST_PLAN.md`（両者は補完関係：08＝人が確認する観点、14＝機械が守る不変条件）。`CLAUDE.md §7` のDefinition of Doneを具体化する。
> 目的は **AIエージェントが安全に反復できる安全網**を用意すること。正典（`11`/`12`/`schemas`）の規則を実行可能なテストに落とし、仕様と実装の乖離を防ぐ。

---

## 1. 方針

- **ドメインの純粋ロジックを高被覆で自動テスト**する（検証・変換・計算・解決）。
- **正典の規則＝テストケース**。`11`/`12` に書いた規則は対応するテストを持つ。
- **決定論性を最優先**：AI・音声・時刻・乱数・FFmpegの非決定性をテストから排除する（§4）。
- fixtures（`fixtures/`）を実装ターゲット兼期待値として使う。

## 4. 決定論性（フレーキー防止）

- `AiProvider` / `VoiceProvider` は **Mock** で固定出力（fixtures）。実APIは原則叩かない。
- **時刻はDI**（`createdAt` 等を注入）。**ID採番は連番関数を注入**（`Date.now`/乱数に依存しない＝`CLAUDE.md §3` の制約とも整合）。
- **実時間に依存させない**（#645）。対話テストで「押した時刻」を見る判定（二度押し＝`DOUBLE_TAP_MS`）は、
  実機ではブラウザが**押した瞬間**の時刻をイベントに載せるが、`fireEvent` は**呼んだ瞬間**の実時刻になる。
  1回目と2回目の間に走る React の再描画が経過時間に混ざるので、負荷が高いとしきい値を超えて落ちる。
  **`src/test/pointer.ts` の `doubleTap`/`pointerDownAt` で時刻を固定して送る**（`timeStamp` は読み取り専用
  なので、イベントを作ってから差し替える）。**時刻に 0 は使わない**＝React の合成イベントは
  `event.timeStamp || Date.now()` なので**falsy な時刻は実時刻に化け**、1回目だけ実時刻・2回目は指定値になって
  差が負になる（＝間隔を空けたのに二度押し扱い）。ヘルパーが弾く。
  素の並び（`pointerdown → pointerup → pointerdown`）がテストに増えていないかは **`src/test/doubleTapGuard.test.ts`
  が機械的に見張る**（新しく書かれたらそこで落ちる＝口頭の申し送りにしない）。しきい値そのもの（時間ガード）は
  時刻を明示できるようになったので **`FreeLayoutOverlay.test.tsx` で境界（300ms＝入る／400ms＝入らない）を検証**している。
- **1件だけまれに落ちるのはタイムアウトを疑う**（#645）。原因は状態漏れではなく **vitest の既定 5 秒**で、
  画面まるごとを jsdom で描くテストが並列実行の負荷で超えていた（実測 8.1 秒・単体では1秒未満）。
  `vite.config.ts` の `testTimeout`/`hookTimeout` を **30 秒**にしてある＝「遅いことを許す」ためではなく、
  **本当に固まったものだけを捕まえる**ための上限。落ちたときは `Error: Test timed out in …ms.` が出るので、
  **アサーション失敗と読み違えないこと**（本物の退行と区別できない赤を放置しない・ADR-0026④）。
- **同じ規則が2か所にあるものは、機械で突き合わせる**（PR #922）。⚠️ **表を両側に置くだけでは足りない**＝
  それぞれが自分の表としか比べないので、**片方に増やしても相手は赤くならない**（素材の種類の一覧が実際に
  そうなっていた＝コメントは「テストで同値性を固定してある」と書いていたのに固定できていなかった）。
  **相手の本文をそのまま読んで突き合わせる**（`assetLibrary.test.ts` が `src-tauri/src/lib.rs` の
  `is_known_asset_type` の並びを取り出して `ASSET_TYPES` と比べる）＝どちらを増やしても、もう片方を
  直すまで赤いまま。**読めなくなったとき（書き方が変わったとき）は黙って緑にせず落とす**
  ＝空振りする検査は「検査が無い」より悪い（守られている顔をする）。
- **説明文（JSDoc）を別の宣言から奪わない**（PR #922）。既存の `export const X` の**すぐ上**へ差し込むと、
  `X` に付いていた `/** … */` が差し込んだ側へ移り、`X` は説明を失う。⚠️ **型でも lint でも守れない**
  （どちらの並びも文法として正しく、動作も変わらない）＝**`src/test/jsdocAttachGuard.test.ts` が
  「説明文が2つ並ぶ形」をファイルごとに数え、現状を上限として増えたら落とす**（ratchet）。
  ⚠️ **ファイル名の許可リストにしない**＝いちばん触るファイルほど載ることになり、そこでの再発を素通しする。
  落ちたら差し込んだ位置の1つ上を見て、奪った説明文を本来の宣言のすぐ上へ戻す。
- **FFmpegのエンコードは非決定的**。よって：
  - 画像一致は **中間PNG／抽出フレーム**（ffmpegで1フレーム抽出）で比較する。
  - 最終MP4は「生成成功・尺・解像度・ストリーム構成（映像/音声）」を `ffprobe` で検査する（バイト一致は求めない）。

## 5. Golden-file 運用（描画）

- 初回生成 → **人がレビュー** → コミット。差分しきい値（例：相違ピクセル割合 < 0.1%）。
- フォント差で揺れるため、**同梱フォントを固定**しCIランナーにも導入（`13 §6`）。
- 失敗時は `expected / actual / diff` 画像を出力して原因を追えるようにする。
- 対象：各標準テンプレ × 代表シーン（動画なし＝1枚PNG、動画あり＝下/上PNG）。

---

## 6. fixtures 運用

- `docs/yuko_recruit_docs/fixtures` を `test/fixtures` へ取り込む（コピー or 参照）。
- **F で実証した検証（ajv＋相互参照）を常設テスト化**（`fixtures/README.md` の検証骨子）。
- **異常系fixtures**を追加する：壊れたAI出力、不在templateId/assetId、空セリフ、長すぎる字幕、合計尺超過、未対応schemaVersion 等（`15` のエラーコードと対応）。

---

## 7. カバレッジ

- `domain`（変換・検証・計算・解決）：**高被覆**（目安 行90%＋／分岐重視）。CIで閾値強制。
- `infrastructure` / `app`：スモーク中心（薄く）。
- 数値・enumのハードコード禁止（`CLAUDE.md §6`）に対するlintも併用。

---

## 8. CI

- **PR必須（速い層）**：lint＋型チェック＋Unit＋Schema。
- **任意/夜間（重い層）**：Golden、FFmpeg/VOICEVOX 結合スモーク、E2E。
- 秘密情報を使うテストはCIのsecretで管理。実APIキーをリポジトリ・fixturesに置かない（`13 §7`）。

---

## 9. Definition of Done との対応

`CLAUDE.md §7` のDoDを満たすには、変更が触れた**カタログ（§3）該当行のテストが緑**であること。新しい規則を正典へ追加したら、本書のカタログにも行を足し、テストを用意する。
