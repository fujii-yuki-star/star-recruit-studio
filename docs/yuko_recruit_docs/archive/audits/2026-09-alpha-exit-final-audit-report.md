### 🔴2 `src/domain/timeline/freeze.ts:92` — parity — **止めた絵の時刻が正準を通らない**

止める側は `freezeSourceSec` ＝ `sourceStartSec + (t − clip.startSec) × speed`。
プレビューと書き出しは **コマ番号から導く**＝`videoSourceSecAt`（`src/domain/timeline/video.ts:371`）。

⚠️ **正準関数の JSDoc 自身が危険を書いている**（`video.ts:367-369`）：

> **書き出しと同じコマ番号から導く**＝別々の式で出すと、置いた位置が格子（1/fps）に乗っていないとき
> プレビューと書き出しで**別のコマ**になる（実測で最大1.5コマ×速さのずれ）

**そして置いた位置は格子に乗らない**＝`src/domain/timeline/edit.ts` に量子化は**1か所も無い**
（`frameTimeSec`／`quantize`／`snapToFrame` いずれも grep で 0 件）。置くのも分けるのも生の秒。

⚠️ **`frameTimeSec(doc, atSec)` を通しているのは再生位置だけ**（`timelineStore.ts:1272`）で、
**クリップ開始の丸め**は別の話なので効かない。既存検査（`freezeFrame.test.ts:71-73`）は
`startSec=2`＝格子上だけなので緑のまま。速さの既定も食い違う（正準は `effectiveSpeed`／こちらは `?? 1`）。

→ 直す方向：`freezeSourceSec` を廃し、`videoSourceSecAt(placement, frameTimeSec(doc, atSec), fps)` を呼ぶ。

`CONFIRMED`（正準関数の注記＋`edit.ts` に量子化が無いことを実地確認）

### 🔴3 `src/app/components/timeline.css:432` — ux-model — **目印の旗が目盛り行の下に隠れる**

- 旗は `.timeline-marker { position:absolute; top:0; z-index:4 }`、ボタンは `top:0; height:12px`
- 目盛り行は `.timeline-row:first-child { position:sticky; top:0; z-index:6; background:var(--color-surface) }`（#1104）
- **旗は目盛り行の子ではなく兄弟**（`TimelineProjectScreen.tsx:3614` の `.timeline-inner` 直下に、
  行の `map` の**後ろ**で描かれる）
- `.timeline-inner`（`timeline.css:87`）は `position: relative` **だけ**＝積み重ね文脈を作らない

→ 4 < 6 で**旗は不透明な目盛り行の下に塗られる**。当たり判定も上の行が取るので、
押すと「その位置へ跳ぶ」ではなく**ルーラーのシーク**になる。

⚠️ **#1138 で 🔴 と判定して直した状態に戻っている**＝「印は時間軸の上に見える」（ADR-0034 決定1）が
効かず、**目印は一覧からしか辿れない**。同じ理由で再生ヘッドの掴み手（`z-index:3`）も隠れる。

⚠️ `timeline.css:127-131` の**重なりの段の注記（1〜5）が 6 段目を足したときに更新されていない**＝
この見落としの跡。

→ 直す方向：目印と再生位置を目盛り行より上の段へ（`z-index: 7` 相当）、または目印を目盛り行の中に描く。

`CONFIRMED`（DOM の入れ子・積み重ね文脈・旗の寸法を実地確認）
