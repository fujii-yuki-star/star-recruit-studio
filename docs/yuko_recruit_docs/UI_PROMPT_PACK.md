# UIプロンプトパック（ChatGPT / V0 用）

ChatGPT（レイアウト案・ワイヤー）や V0（Reactたたき台）に貼って使う、**仕様準拠のUIを得るためのプロンプト**。下の「コピー範囲」をそのまま貼り、必要なら画面名を絞って依頼する。

- 正典：[06_UI_SPEC](06_UI_SPEC.md)（画面）／[16_GLOSSARY](16_GLOSSARY.md)（用語）／[CLAUDE.md §2](../../CLAUDE.md)（絶対原則）。返ってきた成果物はこれらに照合して採否を判断する。
- V0出力は **Vite + Tauri + React/TS の SPA** へ適合させる前提（`"use client"`・Next.js専用機能・サーバコンポーネントは除去）。Tailwind/shadcn は採用するなら別途ADRで決める。
- **プレビュー（動画描画）面はプレースホルダ**でよい。実描画は [ADR-0001](adr/0001-rendering-parity.md) のレンダラ担当。

```text
あなたはUIデザイナー兼フロントエンド実装者です。Windows向けデスクトップアプリ（React + TypeScript の SPA、Vite/Tauri）の画面を設計します。Next.js専用機能やサーバーコンポーネントは使わないでください。文言はすべて日本語。

# プロダクト
採用担当者が会社情報と写真・動画を入力すると、AIが動画の構成案とマスコット「ゆうこ」のセリフを作り、ソフトがテンプレート（見た目パターン）に沿って自動で動画を組み立て、プレビューとMP4保存ができる「採用動画づくり支援ソフト」。

# 利用者
非技術者の採用・人事担当者。ITに詳しくない前提。

# 絶対に守るUIルール
- 技術用語をUIに出さない（禁止例：JSON, テンプレート, レンダリング, バリデーション, アセット, スロット, Provider, LLM, API, エクスポート）。
- 次の言い換えを使う：
  - 見た目パターン（×テンプレート） / 素材（×アセット） / 場面（×シーン） / パート / 表示場所（×スロット）
  - 動画を書き出す・保存する（×レンダリング/エクスポート） / 仕上がり確認（×プレビュー） / 内容チェック（×バリデーション）
  - セリフ・ゆうこの声（×ナレーション） / 使用するAI（×プロバイダ）
- 操作は「ウィザード形式」と「場面カード（シーンカード）形式」を中心に、座標やタイムラインを触らせない（配置は見た目パターンが決める）。
- エラーは原因でなく「次の行動」を示す（例：×「テンプレートが不正」→ ○「この場面の見た目パターンが見つからないため、標準を使います」）。
- AIの結果は「動画のたたき台」として見せ、ユーザーが確認・修正してから動画化する。

# 作ってほしい画面（各画面：レイアウト＋主要コンポーネント）
1. ホーム：新しい動画を作る／最近のプロジェクト／見た目パターンを管理／設定
2. 作成ウィザード（ステップ）：①動画の目的を選ぶ ②会社情報を入力 ③写真・動画を追加 ④ゆうこの声を設定 ⑤「ゆうこに動画案を作ってもらう」
3. AI送信確認：送る情報の一覧（会社情報／目的／素材の説明／画像サムネイル／動画の代表フレーム）と「元の動画ファイルは送信しません」。ボタン：送信して動画案を作る／キャンセル
4. 動画案確認：AIが作った構成を「台本表」で表示（列：順番／パート／場面／使う素材／セリフ／見た目）。操作：この内容で確認／セリフを直す／素材を変更／見た目を変更／作り直す／場面を追加・削除
5. 場面編集：左＝素材一覧、中央＝仕上がり確認（プレビュー面はプレースホルダ）、下＝場面カード一覧、右＝選択中の場面の編集（場面名／見た目パターン／使用素材／セリフ／字幕／表示時間／ゆうこの表示）
6. 仕上がり確認：再生範囲（この場面だけ／このパートだけ／全体）、再生・停止・シークバー
7. 書き出し（保存）：保存先／動画サイズ／字幕あり・なし／BGMあり・なし／ファイル名、進捗表示（「場面 3 / 12 を処理中」）
8. 見た目パターン管理：一覧（サムネイル）・追加・サンプル表示・削除
9. 設定：使用するAI／APIキー／送信確認の表示／ゆうこの声／保存先

# サンプルデータ（モックに使う）
- 会社名：株式会社サンプル（IT、業務システム開発）／募集：エンジニア（新卒）／強み：相談しやすい環境・若手が成長しやすい
- 台本表の例：
  1 はじめに｜挨拶｜会社外観｜「こんにちは、ゆうこです。今日は株式会社サンプルの魅力を紹介します。」｜オープニング
  2 会社紹介｜オフィス｜オフィス写真｜「明るく相談しやすい雰囲気の職場です。」｜写真紹介
- マスコット「ゆうこ」は画面内の案内役（立ち絵）。常時表示ではなく見た目パターンによって出る・出ないが変わる。

# トーン・見た目
クリーンでフラット、親しみやすく業務に馴染む。情報量は詰め込みすぎない。デスクトップ幅（1280px以上）を主対象。日本語フォント前提。

# 出力
各画面について、レイアウト構成と主要コンポーネントを提示してください（V0の場合は React + TypeScript コンポーネントとして。状態は仮データでよい）。
```

## ツール別メモ

- **ChatGPT**：上記を貼り「まずワイヤーフレーム（枠とラベル）で全画面、その後 各画面を1枚ずつ詳細化」と段階指示すると整理しやすい。画像生成より「HTML/簡易レイアウト＋説明」の方が再利用しやすい。
- **V0**：1画面ずつ依頼すると精度が上がる（例：「作成ウィザードのStep2 会社情報入力フォーム」）。出力は下地として受け取り、(1) `"use client"`/Next専用APIを除去、(2) 文言が用語ルールに沿うか確認、(3) 状態は後で `domain` の型へ配線。
- 返ってきた良い案は `docs` 配下にスクショ/コードで残し、最終的に [06_UI_SPEC](06_UI_SPEC.md) と突き合わせて採用する。
