# 15. エラー・状態モデル

> 散在していたエラー表示・状態（音声生成／レンダリング等）を一元化する正典。`schemas/project.schema.json` の `Warning`（`code`/`message`/`field`/`severity`/`autoFixed`）の **`code` 語彙はここで定義**する。
> ユーザー向け文言の原則（原因でなく次の行動）は `01 §15.5`・`05 §17`・`06 §16` を統合。

---

## 1. 状態の一覧（永続 / 実行時）

| 状態 | 値（enum） | 永続/実行時 | 出典 |
|---|---|---|---|
| `narration.status` | none / pending / generated / failed | **永続**（Scene内） | `11 §3.5` |
| `renderStatus` | idle / preparing / rendering / encoding / done / error / unsupported / cancelled | 実行時（書き出しジョブ） | `11 §3.5` |
| `aiGenerationStatus` | idle / sending / generating / validating / done / failed | 実行時（AIジョブ） | 本書 |

> `aiGenerationStatus` と `renderStatus` は**ジョブの実行時状態**で、`project.json` には持たない（MVP）。`narration.status` のみシーンに永続する。

## 2. 状態遷移図

### 2.1 音声生成（シーン単位）

```text
none ──(セリフ確定/生成指示)──▶ pending ──(生成成功)──▶ generated
  ▲                               │
  │                               ├──(失敗)──▶ failed ──(再試行)──▶ pending
  │                               ├──(失敗・作り始める前が generated)──▶ generated へ戻す（#755-3）
  │                               │
  ├───────(一括作成を中止)─────────┘
  │
  └──────────(セリフ変更で要再生成)────────── generated
```

- `generated` のシーンのセリフを変更したら `none`（または `pending`）へ戻す＝**再生成が必要**な状態にする（`01 §8.5`）。
- 失敗は該当シーンのみ。他シーンの音声は維持。
- **声の一括作成（全場面）はいつでも中止できる**（#547 P2-6・書き出しの中止＝§2.3 と同じ「エラーではない中立状態」）。意味は
  「**これ以上新しく作らない**」だけで、**できあがった声（`generated`）は取り消さない**。中止後は同じボタンでそのまま続きを作れる。
- 中止した時点の `pending` は、**実行中のぶんも含めてすべて `none` へ戻す**。残すと進捗が止まったまま固まり、`pending` を見て止まる
  書き出しのブロック（§4）も解けず、その行だけ作り直しもできない行き止まりになる（§2-5・ADR-0026④）。`pending` の行にはまだ音声が
  無いので失う物は無い。実行中だった合成は、届けばそのまま `generated` になる（作った音声は無駄にしない）。ただし
  **中止直後に作成をやり直すと、その行は作り直しになる**（後発の合成が正となり、先に走っていたぶんは使われない）。
  **中止直後に書き出しを始めた場合**も、届いた音声は書き込まず `none` に戻す（開始時のスナップショットに無い音声を足すと
  「画面だけ新・動画は無音」になるため＝#570 が優先。書き出し後に作り直せる）。
- `pending` は「そのとき合成が走っていた」という**実行時の状態**であり、保存や履歴に残す意味がない。読込（前回の合成中に閉じた）と
  取り消し/やり直し（作成中に別の編集をして積まれたスナップショット）でも `none` へ戻す＝**誰も作っていない準備中**を作らない。
- 中止を**実際に効かせる**ため、一括作成は同時に走る合成の数を絞る（全件を一度に投げると待機列が空になり、止めるものが無い
  ＝ボタンはあるのに止まらない・ADR-0026④）。進捗は「声 3/10」のように**行単位**で示し、中止後も分数を残す
  （作成済みが消えていないことが数字で分かる）。たたき台・場面編集・公開前チェックの3画面で同じ表示・同じ挙動にする（ADR-0026②）。

### 2.2 AI構成案生成

```text
idle ─(送信確認OK)─▶ sending ─▶ generating ─▶ validating ─▶ done
        │                                          │
        └─(キャンセル)─▶ idle                       └─(重大不適合/パース不能)─▶ failed
sending/generating ─(通信失敗)─▶ failed ─(再試行 / 手動作成 / 前回復元)─▶ …
```

- `validating` で軽微な問題は**自動補正**（`11 §9`）して `done`、重大なら `failed`（`12 §9.3`）。

### 2.3 書き出し（シーン単位 → 結合）

```text
idle ─(開始)─▶ running[ scene 1..N を順次レンダ → 結合 → 音声ミックス ] ─▶ completed
                     │
                     ├─(あるsceneで失敗)─▶ failed（失敗sceneを特定）
                     │      └─(そのsceneだけ再実行 / 中断)
                     └─(ユーザーが中止)─▶ cancelled ─(再実行)─▶ idle
```

- シーン単位レンダ（`05 §6`）。完了済みシーンの一時成果物は保持し、**失敗シーンのみ再実行**できる。
- **終わったことは書き出し画面以外でも知らせる**（#589）。書き出し中は他画面へ移動できる（§4）ため、終端で編集ロックの
  バナーが消えるだけだと**離席中に失敗しても「消えた＝成功して終わった」と誤読**し、書き出し画面へ戻るまで気づけない。
  アプリ共通の通知（成功/失敗/中止・失敗は読み上げにも割り込む）を**どの画面にいても**出し（独自ヘッダの画面も含む）、
  「書き出しの画面へ」で理由・保存先へ導く（§2-5）。**書き出し画面では出さない**（そこに結果がある）＝
  **開いた時点で既読**にし、「閉じる」でも消せる。次の書き出しを始めれば未読は落ちる＝古い通知を残さない（P3-11 と同じ轍を踏まない）。
- **終わった状態（completed/failed/cancelled）は次の書き出しまで残る**（実行時状態・§1）。進捗を全画面に出す（§4）ための保持だが、
  その結果**画面を離れて戻ると終わった結果が出続ける**。表示側で「**前回の書き出し**の結果」と分かる形にし、進捗そのもの
  （%・バー）はいま走っている書き出しにだけ出す（#547 P3-11・ADR-0026④＝そのあとの編集まで書き出し済みに見せない）。
  保存したファイルへの導線は残す（前回の結果でも、そのファイルの話としては正しい）。文言・出し分けは `06_UI_SPEC §13`。
- **書き出しはいつでも中止できる**（#380）：中止は「次の行動」を残す逃げ道（§4 の編集ロック中の唯一の抜け道）。中止すると走行中の変換プロセス（ffmpeg）を終了し、`cancelled`（＝エラーではない中立状態）にする。中止後は待たされず再実行できる（一時成果物は次回書き出し冒頭で掃除）。**書き出し中にアプリを閉じても変換プロセスは終了する**（プロセス残留＝orphan を防ぐ）。

## 3. 部分失敗時の挙動

| 場面 | 挙動 |
|---|---|
| 書き出し中に1シーン失敗 | 失敗シーンを特定（`05 §16`）。①そのシーンだけ再実行 ②中断 を選べる。完了分は破棄しない |
| 音声生成失敗 | 該当シーンのみ。**作り始める前が `generated`（＝いまの文の声が既にある）ならその印へ戻す**、それ以外は `failed`（#755-3）→ 再試行。他は維持。⚠️ **知らせは印に紐づけない**（据え置くと出なくなる＝無言の失敗） |
| AI生成失敗 | 前回 `ai/latest_result.json` から復元可（`12 §9.3`） |
| 一部素材が欠損 | 該当シーンに警告。書き出しは「該当箇所を空/代替」で続行可否を提示 |
| 動画スロットを配置できない（内部不整合／スロット・グループの非表示等で分割不可） | **黙って静止画化しない**（#434・ADR-0026）。書き出しは停止し「場面Nの動画を配置できませんでした。場面編集で置き直して再実行」を示す。公開前チェック（precheck）でも該当場面つきで事前警告する |
| 字幕が画面からはみ出す（同時字幕の段積み／1帯が大きすぎ・長すぎ） | **黙って画面外に切らない**（#533 P2・#563・ADR-0026④）。判定は**実描画と同じ `layoutScene`** を通す共有関数 `subtitleOverflowsCanvas`（全字幕層・全辺・回転/グループ transform/非表示込み）＝画面の見え方と警告が食い違わない。**掛け合いに限らず単独/逐次も対象**（#555 で場面ごとに字幕を拡大できるようになり到達性が上がった）。場面編集は**原因ごとに次の行動**を出し分け（同時＝セリフを減らす／1帯＝文字を小さくする・字幕を短くする・§2-5）、公開前チェックでも該当場面つきで事前警告する。**書き出しは止めない**（「直せば良くなる」警告側）。標準テンプレ×既定の体裁では推奨上限の倍の長さでも警告しない（ノイズを出さない＝回帰テストで固定） |
| 置いた字幕が何も表示しない（場面の字幕がオフ／字幕の文が空／対象に選んだ話者のセリフが無い） | **黙って出ないままにしない**（#547 P3-9・ADR-0026④）。自由配置の字幕は表示文を「対象」から解決するため、原因が要素の外（場面のスイッチ・セリフごとの字幕・話者の顔ぶれ）にあり、置いた本人には見えない。場面編集の字幕欄に**理由と次の行動**を出し、公開前チェックでも該当場面つきで事前警告する。**書き出しは止めない**（字幕1つが出なくても動画は作れる＝「直せば良くなる」警告側）。判定は描画と同じ単一の参照元（`subtitleSilentReason`→`freeSubtitleElementTexts`）＝画面の表示と警告が食い違わない |
| **書き出しが必ず失敗する項目が残っている**（見た目が見つからない／動画を配置できない／再生開始が「アニメの後」なのに再生されない） | 公開前チェックの主ボタン「このまま書き出す」を**押せなくする**（#547 P2-5）。保存先を選ばせた後に落とさない＝手戻りを作らない（ADR-0026④）。理由（どの項目か）と次の行動（上の「直す」から直す）を併記する。**見た目が見つからない場合は明示操作「まとめて標準にする」**でまとめて標準の見た目へ寄せられる（自動では置換しない＝§6 `TEMPLATE_NOT_FOUND` ②）。**「直せば良くなる」警告（声が未作成・字幕が長い・切り替えに飲み込まれる・切り替えが表示時間に収まらず短くした〔#727〕）では止めない**＝書き出せるのに押せない、を作らない。止める条件は書き出し側の停止条件（`buildExportScenes`）と**同値に保つ**（片方だけ変えると行き止まり／取りこぼしになる）。**同値は「同じ条件を書き写す」のではなく共有の述語を呼んで構造で担保する**（#588：再生開始＝アニメ後は `afterAnimNeverPlaysForSlots` を precheck・書き出しの両入口が呼ぶ。書き出しはスロットをコールバックで受け取るため、解決済みスロットを受ける形にしてある）。**実経路（実 `buildExportScenes`）で「precheck が挙げる ⟺ 書き出しが止まる」を突き合わせる回帰テスト**を置き、条件を書き直したドリフトが赤くなるようにする。**同じ述語（`exportBlockingItems`）を書き出し画面の「動画を保存」にも適用**する＝サイドバーから直行した経路でも同じ判定（ADR-0026②）。押下前に無効化して理由と次の行動（公開前チェックで直す）を出し、開始時は `beginExport` の前後2回の再確認でも同じ述語を使う。**この端末で書き出せない（h264 不可）**場合も同様に両画面で止める |

## 4. 排他制御（MVP）

- **書き出し（export）実行中**：プロジェクト編集をロックする（または読み取り専用スナップショットに対して実行）。ロックの唯一の抜け道は**「書き出しを中止」**（#380・§2.3）＝走行中の変換を止めてロックを解く。**書き出し中もどの画面へも移動できる**ため、ロック中は**全画面**で進捗（%＋いま何をしているか）と書き出し画面への復帰導線を出し、抜け道に到達できる状態を保つ（#547 P2-1）。進捗が書き出し画面にしか無いと、離れた利用者には止まったように見え、二重書き出しを誘発する（ADR-0026②）。
- **プレビュー再生中**：編集は可。変更は次回プレビューから反映。
- **音声生成中のシーン**：そのシーンのセリフ編集はキュー化 or 警告。
- **声の一括作成中**：書き出しは開始できない（開始時スナップショットに無音の場面が入るため・#570／ADR-0026④）。ロックの抜け道は
  **「声の作成を中止」**（§2.1）＝待機分を `none` へ戻して止め、そのまま書き出しへ進める。逆に**書き出し中は声を作らない**（同）。
- **タイムライン形式の書き出し開始**（#718）：始められない理由を**1つの述語**（`exportStartBlock`）で見る＝
  **素材の取り込み中／声を作っている最中／別形式の書き出し中／文書の中身の理由（`TIMELINE_EXPORT_*`）／
  この端末で書き出せない**。押す前に無効化して理由を出し、押したときの断りも同じ述語から来る（§3 の流儀）。
  とくに**声を作っている最中**は、始めてしまうと合成の着地が `TIMELINE_EDIT_EXPORTING` で撥ねられ、
  **作った声はファイルだけ残って文書に入らない**＝その読み上げが無い動画が成功として出る（ADR-0026④）。
  **直せる理由を先に出す**（この端末では書き出せない、は最後）＝直せば書き出せることに気づけるようにする。
- **タイムライン形式で画面を離れる**（#719）：**入口を問わず同じ関門を通す**（`navigationGuard`＝`App` の遷移が聞く）。
  保存が済んでいなければ**書き切ってから離れ**、失敗していたら**行き先つきで確認**する。**書き出し中は離れない**
  （進み具合も中止もこの画面の中にしかない）＝確認ではなく理由で断る。画面内のボタンだけに確認を付けると、
  サイドバーから素通しできる（実際にそうなっていた）。
- 同一プロジェクトの**同時多重編集は想定外**（MVP）。

## 5. エラー分類（taxonomy）

| 軸 | 値 |
|---|---|
| `severity`（`Warning.severity`） | `info` / `warning` / `error` / `fatal`（fatalは処理停止） |
| 回復性 | `auto-fixed`（自動補正済み） / `user-action`（要操作） / `retryable`（再試行可） / `fatal` |

**表示原則**：原因でなく**次の行動**を示す。技術詳細は詳細モード／ログのみ（`01 §15.5`）。自動補正は「3件を自動調整、1件は確認が必要」のように件数＋対応内容で見せる（`01 §6.7`）。

## 6. エラーコード体系（`Warning.code` 語彙）

- 命名：`DOMAIN_REASON`（大文字スネーク。例 `TEMPLATE_NOT_FOUND`）。`schemas` 上は自由文字列だが、**実装は本表の語彙を使う**。
- 代表コード（増えうる。追加時は本表へ）：

| code | severity | 既定の自動対応 | ユーザー向け文言（例） | 由来 |
|---|---|---|---|---|
| `TEMPLATE_NOT_FOUND` | warning（②は公開前チェックで「要対応」として出す＝`PrecheckItem` 側の値。`Warning.severity` は §5 の3値） | **状況で分ける**。①**取り込み時**（AI出力→場面への変換）は同category・同orientationへ**自動補正**（`12 §8`・§2-2 の「検証→自動補正→変換」。場面はまだ作り立てで、失われる作り込みが無い）。②**既存の場面**が後から解決できなくなった場合は**自動では置換しない**＝書き出しを停止し公開前チェックで該当場面を示す。標準へ寄せるのは**利用者の明示操作**「まとめて標準にする」（作り込んだ配置が黙って別物に化けるのを防ぐ）。③**マイ見た目の削除と同時**は、開いているプロジェクトの使用場面を標準へ置換する（#458・孤立参照を作らない）。これは削除確認で**影響する場面数を先に示した**うえでの明示操作として成立させる（他プロジェクトの場面は②に落ちる） | ①この場面の見た目パターンが見つからないため、標準を使います ②この場面の見た目パターンが見つかりません。場面編集で選び直すか、「まとめて標準にする」で標準の見た目に変えてください | `11 §9`・`12 §8`・#547 |
| `TEMPLATE_ORIENTATION_MISMATCH` | info（補正時）/ warning（補正不可時） | 同category・同orientation へ置換（**取り込み時はマイ見た目を当て先にしない**＝ADR-0017／利用者の向き変更ではマイ見た目も可） | 動画の向きに合う見た目に調整しました | `ADR-0012` / `11 §9` |
| `ASSET_NOT_FOUND` | warning | null＋候補提示 | 使う写真・動画が見つかりません。選び直してください | `05 §17` |
| `ASSET_FILE_MISSING` | warning | 選び直し導線 | 素材ファイルが見つかりません | `05 §17` |
| `REQUIRED_SLOT_EMPTY` | warning | — | この場面に必要な写真・動画が未設定です | `11 §8 V6` |
| `DURATION_CLAMPED` | info | clamp | 表示時間を見やすい長さに調整しました | `11 §9` |
| `TEXT_OVERFLOW` | warning | 短縮提案 | 文字が表示範囲に収まりません。短くできます | `05 §17` |
| `POSE_FALLBACK` | info | 既定yukoへ | ゆうこの表情を標準に調整しました | `12 §8.3` |
| `NARRATION_EMPTY` | warning | 生成前に警告 | セリフが空です。入力してください | `08 §10` |
| `VOICE_ENGINE_UNAVAILABLE` | error | 設定確認導線 | ゆうこの声の準備ができていません。設定を確認してください | `05 §17` |
| `VOICE_GENERATION_FAILED` | error | 該当シーン再試行 | ゆうこの声の作成に失敗しました。もう一度お試しください（**前の声がそのまま使えるときは** `KEPT_PREVIOUS_VOICE_SUFFIX`＝「前に作った声はそのまま使えます。」を添える・#755-3） | 添え書きの条件＝**印を据え置いた**かつ**鳴らす材料がある**（印だけで言うと、読み込めていない声にも「使えます」と言う） |
| `AI_RESPONSE_INVALID` | error | 再生成/手動 | 動画案の作成に失敗しました。もう一度お試しください。手動でも始められます | `12 §9.3` |
| `EXPORT_FAILED` | error | 失敗シーン特定/リトライ | 動画の保存に失敗しました。ログを確認してください | `05 §17` |
| `FFMPEG_NOT_FOUND` | fatal | — | 動画の保存機能の準備が不足しています | `08 §10` |
| `BGM_FILE_BROKEN` | warning | BGMなしで続行を提示 | BGMを読み込めませんでした。BGMなしで続けられます | `08 §10` |
| `TOTAL_DURATION_EXCEEDED` | warning | — | 動画が長すぎます。場面を減らすか短くしてください | `11 §8 V9` |

| `FREE_ELEMENT_INVALID_SIZE` | warning | — | 配置した要素の大きさが正しくありません。幅と高さを設定し直してください | `ADR-0008 §8` |

## 7. ログ

- **ユーザー表示（次の行動）と技術ログを分離**。技術詳細は詳細モード／ログファイルへ。
- 書き出し失敗時はFFmpegのコマンドと標準エラーをログ保存（`05 §6,§17`）。
- AI送受信は `ai/history`（`12`）。**APIキー・秘密情報・元動画ファイルはログに残さない**（`13 §7`）。

## 8. リカバリUX

- **生成中でも完了したシーンから確認できる**（`06 §17`）。長尺はパート単位で確認。
- 失敗時の導線：**再試行 / 手動作成 / 前回AI結果の復元**（`12 §9.3`）。
- **失敗の導線は生成中の画面に閉じない**（#590）。生成が `failed` のまま他の画面（たたき台／公開前チェック／
  仕上がり確認／書き出し）へ移っても、**どの画面でも理由と同じ2択（再試行／手動作成）を出す**。
  場面が0件なのは同じでも「まだ作っていない」と「作ろうとして失敗した」は別の状態で、後者を
  「まだ場面がありません」とだけ言うと原因も次の行動も分からない（`§2-5`）。
- **「場面が1つも無い」ときの表示は4画面で共有する**（#590・ADR-0026②）。見分けは
  **未作成（`idle`）／作成中（`generating`）／失敗（`error`）／場面0（`ready`）**の4状態で、
  次の行動は**場面を作れる画面（たたき台）へ送る**か、その画面自身が作れるなら**その場で場面を追加**。
  0件でも会社情報・素材は残っているので、空状態から**今の内容を捨てる**導線（新規作成）は
  未作成（`idle`）のときだけに限る。
- 自動補正の結果は `Scene.warnings[]` に蓄積し、件数＋対応内容を非技術語で提示（`01 §6.7`）。
