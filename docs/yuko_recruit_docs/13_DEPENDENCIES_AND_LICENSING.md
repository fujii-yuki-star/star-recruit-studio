## 3. FFmpeg

### 事実（執筆時点）
- FFmpeg は **LGPL 2.1+**。ただし `--enable-gpl` / `--enable-nonfree` を付けると **GPL/非フリー** 扱いになり、アプリ全体に強い義務が及ぶ。
- LGPL遵守の定石：**`--enable-gpl` を付けずにビルド**、FFmpegライブラリは**動的リンク**、配布バイナリに対応する**FFmpegのソースを提供**（同梱 or 入手手段の明示）。
- **H.264 はFFmpegのライセンスとは別に特許**の論点がある。H.264エンコード/配布には特許ライセンス（MPEG-LA系）が関係しうる。Cisco の **OpenH264**（`--enable-libopenh264`）は Cisco が実行時取得分の特許料を負担する方式で、LGPLビルドと両立し商用回避策になりうる。

> ⚠️ **同梱している pin は LGPL v3**（`--enable-version3`・2026-09-24 に実物で確認）＝
> `FFmpeg_SOURCE.md` の buildconf と、同梱の `src-tauri/resources/ffmpeg/LICENSE.txt`（LGPLv3 本文）、
> `AboutScreen` の表示（「LGPL v3」）が一致している。**この資料が「LGPL 2.1+」と書いていたのは誤り**
> （PR #1240 レビュー 🔴）。LGPL 2.1 と v3 は義務が別物なので、以後は**同梱物は v3**として扱う。

### 決定（[`adr/0002`](adr/0002-ffmpeg-codec.md)・Accepted）

> H.264は **OpenH264採用**（Cisco配布バイナリでAVC特許料をカバー＝**自前の特許ライセンス不要**）。FFmpegは **LGPLビルド＋動的リンク**。エンコーダは概ね Constrained Baseline（採用動画には十分）。

> **更新（2026-06-18・[`adr/0013`](adr/0013-h264-via-media-foundation.md) / PR#116）**: H.264 の**主経路は Media Foundation（`h264_mf`・OS提供）**へ変更（実機スパイクで確証）。**OpenH264 はフォールバック**に降格。以下の OpenH264 関連の遵守事項・必須クレジットは「フォールバックを採用する場合」に適用される。MF 主経路では Cisco 必須クレジットは発生しない（FFmpeg LGPL 表記は両経路で共通）。

遵守事項：
1. **LGPLビルド＋動的リンク**で同梱（GPLオプションを使わない）。
2. 配布物に **FFmpegのソース入手手段** と **LGPLライセンス文** を含める（§の「クレジット/ライセンス画面」）。
3. H.264 は **Media Foundation（h264_mf）を主経路として採用**（[`adr/0013`](adr/0013-h264-via-media-foundation.md)・実機検証済）。OpenH264 はフォールバック。自前の特許ライセンス取得は行わない（完成 H.264 の MPEG-LA 許諾要否は規格軸の別論点＝§9）。
4. FFmpeg は `infrastructure/ffmpeg` 越しに呼ぶ（`CLAUDE.md §4`）。バージョンを固定し記録する。

### 決まっていなかった点と、その結末

> ⚠️ **「未決定」のまま残さない**（#1230）＝決着したら結末を書く。下の2つはどちらも決着済み。

- ~~同梱FFmpegの**正確なビルド構成**（有効化するエンコーダ／OpenH264の採否）~~
  → ⚠️ **決定**：BtbN の **`win64-lgpl-shared`（動的リンク）を pin して同梱**（#119）。
  **H.264 は `h264_mf`（Media Foundation）が主経路**、**OpenH264 はフォールバック**（ADR-0013・実機検証済）。
  ソース提供は `FFmpeg_SOURCE.md`、ライセンス本文は `src-tauri/resources/ffmpeg/LICENSE.txt` を同梱。
- ~~配布形態（インストーラ同梱 / 初回DL）~~

## 4. VOICEVOX

### 事実（執筆時点）
- 商用・非商用ともに利用可能。**クレジット表記が必須**（基本形式「**VOICEVOX:キャラクター名**」、例「VOICEVOX:ずんだもん」）。アプリの場合は**紹介・アバウト画面等に記載**。
- **VOICEVOX（ソフト）の規約と、各キャラクター（権利者）の規約は別物**で、使うキャラの規約が優先。
- クレジット表記をしない商用利用は、VOICEVOX側で**1キャラ毎に有償契約**（執筆時点で40万円＋税の案内あり）。

### 推奨
1. アプリ内に **クレジット/ライセンス画面**を必ず設け、`VOICEVOX:ずんだもん`（および使用キャラ全て）を表示（**必須要件・不変**）。書き出し動画へのクレジットは #153 で常時焼き込み実装済だが、**[`adr/0025`](adr/0025-credit-display-modes.md)（α-6）で表示方式を選べる**（常時/最初/最後/両方/非表示・既定=最初と最後）へ改める。**About 画面のクレジットは必須として維持**し、非表示選択時は概要欄運用の補助（注意＋使用 VOICEVOX 一覧のコピー導線）を用意する。
2. VOICEVOX エンジンは **同梱し、アプリ起動時に自動起動**する（[`adr/0005`](adr/0005-voicevox-bundling.md) で決定。同梱・再配布条件は確認済み）。実装は `infrastructure/voicevox` 越しの**接続（ローカルエンジン）**で進め、`VoiceProvider` で抽象化（`CLAUDE.md §4`）。接続先設定は別ポート/別PC向けの上級者用フォールバックとして残す。
3. バージョン・接続先を設定画面に持つ（`06_UI_SPEC.md §15`・`15.2`）。

### 決定（[`adr/0005`](adr/0005-voicevox-bundling.md)・§5）
- ✅ エンジンを**同梱＋アプリ起動時に自動起動**（接続先設定はフォールバック）。同梱・再配布条件は確認済み（**ENGINE の組み込み再配布は許諾内**・根拠は [`adr/0005`](adr/0005-voicevox-bundling.md)「規約・ライセンスの根拠」＝#122）。
- ✅ 既定キャラ＝**ずんだもん**（ナレーター用途・§5 / `adr/0003`）。**#177 で規約確認済みの VOICEVOX 標準キャラから選択可へ拡張**（選択キャラを「VOICEVOX:＜キャラ名＞」で常時クレジット・カタログ `domain/voice/voiceCatalog.ts` で統制・`adr/0003`「更新」）。
- ~~残（実装・配布の詳細）: 同梱ビルド選定（CPU/GPU・サイズ）／プロセス管理（ポート競合・起動待ち・終了）~~
  → ⚠️ **#149／#151 で実装＋packaged 検証済**（CPU 版 v0.25.2 に固定）。
  **残るのは配布時の最終法務確認だけ**（ADR-0005 未解決論点）。

## 5. ずんだもん（音源）と「ゆうこ」の関係

> ✅ **決定（[`adr/0003`](adr/0003-narration-voice.md)）**：ずんだもんは **ナレーター音声（VOICEVOX:ずんだもん）** として用いる。ゆうこ（自社保有マスコット）の“固有の声”とは称さない。これにより「別キャラの声を当てる／なりすまし」の懸念は解消し、**標準的なVOICEVOX利用**に整理された。残るは標準コンプライアンス（**常時クレジット表示**・原作者の承認を装わない・規約通読）。

本製品は **画面上のマスコットが「ゆうこ」**（自社保有）で、**ナレーション音声が「ずんだもん」**（VOICEVOX）という構成。以下は背景の整理。

- 企業利用も一定条件下で可能とされるが、**商業出版等は別途ライセンス**が必要になる場合がある。

| 論点 | 結末 |

| 1. **ずんだもんの声を「ゆうこ」の声として用いる**ことの可否 | ✅ **論点ごと消えた**（[`adr/0003`](adr/0003-narration-voice.md)）＝ずんだもんは**ナレーター音声**（`VOICEVOX:ずんだもん`）として用い、**ゆうこの“固有の声”とは称さない**。これで「別キャラの声を当てる／なりすまし」は起きない＝**標準的な VOICEVOX 利用**に整理された |

## 6. フォント

### 方針
- 日本語の**テキスト・字幕描画はWeb描画**（ADR-0001）で行うため、**アプリ同梱フォントを preview/export で同一指定**する必要がある（パリティのため）。
- **判定基準は「広く配布されているか」ではなく、ライセンスが“同梱・再配布・埋め込み”を許可しているか**。推奨は **SIL Open Font License (OFL) 1.1** 系（例：Noto Sans JP、M PLUS。広く使われ再配布可）。
- ⚠️ **Windows標準フォント（游ゴシック・メイリオ等）は同梱・再配布不可**。パリティ用に同梱するフォントには使わない（OS依存にすると環境差でパリティが崩れる）。

## 7. 外部AI APIキーの取り扱い（セキュリティ）

### 要件
- APIキーは **OSの安全な保管領域**（Windows資格情報マネージャ／OSキーチェーン、Tauri の keyring 系）に保存する。**`project.json` や設定ファイルへ平文保存しない。**
- キーを **AIへ送るペイロード本文に含めない**（認証ヘッダのみ）。ログ・AI履歴（`ai/history`）にも残さない。
- リポジトリ・サンプル・fixtures に実キーを**コミットしない**（`.env.example` 等のプレースホルダのみ）。
- 「誰が鍵を管理するか（個人/社内共通）」「社内利用時の外部AI利用ルール」は運用方針として要決定（`01 §19`）。
