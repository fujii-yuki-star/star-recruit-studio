# 設計判断を記録する（ADR）

「正典に無い」「既存の決定を変える」に当たったときの作業。

## いつ書くか

| 状況 | どうする |
|---|---|
| 正典に無い仕様に出会った | **推測で埋めない**（`CLAUDE.md §9-2`）。利用者に確認するか ADR を提案する |
| enum・フィールドを増やしたい | ADR（`CLAUDE.md §9-2`） |
| 既に Accepted の決定を変えたい | **勝手に変えない**。改訂案を出して承認をもらう |
| 実装の細かい選択（名前・分割） | ADR は要らない。コードのコメントで足りる |
| 権利・ライセンスの判断 | **書かない**＝事業側の判断（`13 §6`） |

## 必読

| 資料 | 範囲 |
|---|---|
| [`adr/0000-template.md`](../yuko_recruit_docs/adr/0000-template.md) | 全文（雛形） |
| [`adr/README.md`](../yuko_recruit_docs/adr/README.md) | 一覧と状態（5,826字） |
| 関係する既存 ADR | `adr/README.md` の一覧から当てる |

## 書くときの決まり

- **状態を動かすときは2点を同時に直す**（ADR-0032 の反省）
  1. ADR 本文の `状態`
  2. [`adr/README.md`](../yuko_recruit_docs/adr/README.md) の状態欄
  ⚠️ **2026-09-08 に3点から2点へ減りました**＝`CLAUDE.md §11` を索引に戻し、**状態を持たなくした**ため。
  門番（`src/test/canonIndexGuard.test.ts`）が「`CLAUDE.md` に状態が書かれていないこと」と
  「一覧に全 ADR が載っていること」を見ています。
- **他の ADR の状態も引き金になる**＝supersede すると相手側の記述も動く
- **決定だけでなく「採らなかった案とその理由」を書く**＝後から同じ案を再提案しないため（ADR-0032 は「未検討の案があった」ことが起点）
- **利用者に聞いた選択肢と回答を本文に残す**（ADR-0034 の流儀）

## 読まない

- `01`〜`10`（背景。必要なら該当節だけ）
- 大きい正典の全文（`11`・`06`・`15` は**関係する節だけ**）

## 終わったら

**ADR を書いてからコードを書く**（`CLAUDE.md §8`）。実装が終わったら状態を Accepted へ動かす（上の2点同時）。
